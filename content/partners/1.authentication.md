# Authentication

All Protegey API requests require authentication using API keys.

## API Key Structure

Protegey uses a dual-key system for enhanced security:

- **Public Key**: Used to identify your organization (`pk_live_...` or `pk_sandbox_...`)
- **Secret Key**: Used to authenticate requests (`sk_live_...` or `sk_sandbox_...`)

### Key Prefixes

| Environment | Public Key Prefix | Secret Key Prefix |
|-------------|------------------|-------------------|
| Sandbox | `pk_sandbox_` | `sk_sandbox_` |
| Production | `pk_live_` | `sk_live_` |

::callout{icon="i-lucide-shield-alert" color="red"}
**Never expose your secret key** in client-side code, public repositories, or logs.
::

## Making Authenticated Requests

Include your secret key in the `Authorization` header:

```bash
curl https://api.protegey.com/v1/signals \
  -H "Authorization: Bearer sk_live_your_secret_key" \
  -H "Content-Type: application/json"
```

## Environment Separation

Protegey maintains strict separation between sandbox and production environments:

- **Sandbox keys** only work with `sandbox-api.protegey.com`
- **Production keys** only work with `api.protegey.com`
- Keys are **not interchangeable**

## Key Rotation

For security, rotate your API keys regularly:

1. Generate a new key in the Partner Portal
2. Update your application to use the new key
3. Verify the new key works correctly
4. Revoke the old key

::callout{icon="i-lucide-info" color="blue"}
**Best Practice**: Rotate keys every 90 days or immediately if compromised.
::

## IP Allowlisting

For additional security, you can restrict API access to specific IP addresses:

1. Navigate to **Settings** > **Security** in the Partner Portal
2. Add allowed IP addresses or CIDR ranges
3. Save changes

::callout{icon="i-lucide-alert-triangle" color="amber"}
Requests from non-allowlisted IPs will receive a `403 Forbidden` response.
::

## Rate Limiting

API keys are subject to rate limits based on your subscription tier. See [Rate Limits & Quotas](/partners/limits-and-quotas) for details.

## Key Management Best Practices

1. **Use environment variables**: Never hardcode keys in source code
2. **Separate keys per environment**: Use different keys for dev, staging, and production
3. **Monitor key usage**: Review API logs for unauthorized access
4. **Rotate regularly**: Implement a key rotation schedule
5. **Revoke compromised keys**: Immediately revoke any exposed keys

## Troubleshooting

### 401 Unauthorized

**Cause**: Invalid or missing API key

**Solution**: Verify your key is correct and included in the Authorization header

### 403 Forbidden

**Cause**: IP address not allowlisted or key revoked

**Solution**: Check IP allowlist settings or verify key status

### 429 Too Many Requests

**Cause**: Rate limit exceeded

**Solution**: Implement exponential backoff and review [rate limits](/partners/limits-and-quotas)

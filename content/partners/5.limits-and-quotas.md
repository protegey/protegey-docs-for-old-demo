# Rate Limits & Quotas

Centry enforces rate limits to ensure fair usage, system stability, and protection against abuse.

## Rate Limit Tiers

Rate limits are applied per partner and vary by subscription tier:

| Tier | Requests/Minute | Requests/Hour | Requests/Day | Burst Allowance |
|------|----------------|---------------|--------------|-----------------|
| **Sandbox** | 100 | 5,000 | 10,000 | 150 |
| **Starter** | 1,000 | 50,000 | 100,000 | 1,500 |
| **Professional** | 5,000 | 250,000 | 500,000 | 7,500 |
| **Enterprise** | Custom | Custom | Custom | Custom |

::callout{icon="i-lucide-info" color="blue"}
**Burst Allowance**: Short-term spike capacity for handling traffic surges. Not sustained.
::

## Rate Limit Headers

Every API response includes rate limit information in the headers:

```http
HTTP/1.1 200 OK
X-RateLimit-Limit: 1000
X-RateLimit-Remaining: 847
X-RateLimit-Reset: 1673024400
X-RateLimit-Tier: professional
```

### Header Descriptions

- `X-RateLimit-Limit`: Maximum requests allowed in the current window
- `X-RateLimit-Remaining`: Requests remaining in the current window
- `X-RateLimit-Reset`: Unix timestamp when the limit resets
- `X-RateLimit-Tier`: Your current subscription tier

## Handling Rate Limit Errors

When you exceed your rate limit, the API returns a `429 Too Many Requests` response:

```json
{
  "error": "rate_limit_exceeded",
  "message": "Rate limit exceeded. Please retry after 60 seconds.",
  "retry_after": 60,
  "limit": 1000,
  "window": "minute"
}
```

### Best Practices

1. **Monitor headers**: Check `X-RateLimit-Remaining` before making requests
2. **Implement backoff**: Use exponential backoff when receiving 429 responses
3. **Cache responses**: Reduce redundant API calls where possible
4. **Batch requests**: Combine multiple queries when supported
5. **Respect retry_after**: Wait the specified duration before retrying

### Example: Exponential Backoff

```javascript
async function makeRequestWithBackoff(url, maxRetries = 3) {
  for (let i = 0; i < maxRetries; i++) {
    const response = await fetch(url);
    
    if (response.status === 429) {
      const retryAfter = response.headers.get('Retry-After') || Math.pow(2, i);
      await new Promise(resolve => setTimeout(resolve, retryAfter * 1000));
      continue;
    }
    
    return response;
  }
  
  throw new Error('Max retries exceeded');
}
```

## Fair Use Policy

Beyond hard rate limits, Centry monitors for abuse patterns:

### Prohibited Behaviors

- **Credential sharing**: API keys must not be shared across organizations
- **Excessive polling**: Use webhooks instead of polling for updates
- **Scraping**: Systematic data extraction is prohibited
- **Load testing**: Contact support before conducting load tests

### Abuse Detection

Centry automatically detects and responds to:

- Unusual traffic patterns
- Repeated failed authentication attempts
- Suspicious query patterns
- Violation of acceptable use terms

::callout{icon="i-lucide-alert-triangle" color="red"}
**Warning**: Detected abuse may result in temporary API suspension or account termination.
::

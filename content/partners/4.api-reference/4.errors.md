# Errors

Centry uses standard HTTP response codes to indicate the success or failure of an API request.

## HTTP Status Codes

| Code | Status | Description |
|------|--------|-------------|
| `200` | OK | Request succeeded. Response contains the result. |
| `201` | Created | Resource successfully created (e.g., Signal). |
| `202` | Accepted | Request accepted for asynchronous processing. |
| `400` | Bad Request | Validation failed. Check the error message. |
| `401` | Unauthorized | Key is missing or invalid. |
| `403` | Forbidden | Key valid but permission denied (scope/IP issue). |
| `404` | Not Found | Resource does not exist. |
| `429` | Too Many Requests | Rate limit exceeded. |
| `500` | Server Error | Something went wrong on our end. |
| `503` | Unavailable | Service is down for maintenance. |

## Error Response Format

All errors follow a standard JSON structure:

```json
{
  "error": {
    "code": "validation_error",
    "message": "The request payload was invalid.",
    "details": [
      {
        "field": "entity_type",
        "message": "Must be one of: email, phone, ip"
      }
    ],
    "request_id": "req_123abc"
  }
}
```

### Common Error Codes

- `validation_error`: Payload did not match schema.
- `authentication_error`: API key issues.
- `permission_error`: Access denied.
- `rate_limit_error`: Throttled.
- `server_error`: Internal failure.

::callout{icon="i-lucide-life-buoy" color="blue"}
**Support**: If you encounter a persistent 500 error, please contact support and provide the `request_id`.
::

# Webhooks

Webhooks allow Protegey to push intelligence to your systems in real-time. This is useful for async workflows or monitoring entity status changes.

## Event Taxonomy

We support several event types that you can subscribe to in the Partner Portal.

| Event Type | Description | Payload Key |
|------------|-------------|-------------|
| `signal.created` | A new signal was added to the network for an entity you actively monitor. | `signal` |
| `risk_score.changed` | The score for a monitored entity crossed a defined threshold (e.g., became HIGH). | `risk_change` |
| `trust_score.updated` | Your own Partner Trust Score has changed (e.g., dropped due to false positives). | `trust_score` |
| `list.match` | An entity matched a specific Watchlist or Blocklist. | `match` |

## Payload Schema

All webhooks share a standardized envelope.

```typescript
interface WebhookPayload {
  id: string; // Unique event ID (evt_...)
  type: EventType;
  created_at: string; // ISO 8601
  data: Record<string, any>; // Event-specific data
}
```

### Example: Risk Score Changed

```json
{
  "id": "evt_abc123",
  "type": "risk_score.changed",
  "created_at": "2026-01-12T15:00:00Z",
  "data": {
    "entity_type": "email",
    "entity_value": "user@example.com",
    "old_score": 40,
    "new_score": 85,
    "trigger": "new_signal_received",
    "source_signal_id": "sig_8x9s7..."
  }
}
```

## Security: Signature Verification

Protegey signs every webhook request to verify its authenticity.

### Verification Headers

| Header | Description |
|--------|-------------|
| `X-Centry-Signature` | The HMAC-SHA256 signature of the request body. |
| `X-Centry-Event` | The event type (e.g., `fraud_case.created`). |
| `X-Centry-Delivery-ID` | Unique UUID for the delivery attempt. |
| `X-Centry-Timestamp` | Unix timestamp of when the webhook was sent. |

### Verifying Signatures

To verify a webhook, compute the HMAC-SHA256 signature of the raw request body using your **Webhook Secret** (available in the Partner Portal).

**Typescript Example:**

```typescript
import crypto from 'crypto';

const webhookSecret = 'whsec_...'; 

function verifyWebhook(body: string, signature: string) {
  // 1. Compute expected signature
  const computedSignature = crypto
    .createHmac('sha256', webhookSecret)
    .update(body) // Raw request body string
    .digest('hex');

  // 2. Compare with secure timing check
  if (computedSignature !== signature) {
    throw new Error('Invalid signature');
  }
  
  return true;
}
```

## IP Whitelisting

Webhooks will always originate from one of the following static IP addresses. We recommend allowing only these IPs on your webhook ingress.

- `34.11.23.45`
- `34.11.23.46`
- `35.22.11.99`

## Retry Policy

Protegey uses an exponential backoff strategy for failed webhook deliveries.

| Attempt | Delay |
|---------|-------|
| 1 | Immediate |
| 2 | 1 minute |
| 3 | 5 minutes |
| 4 | 30 minutes |
| 5 | 1 hour |
| 6 | 6 hours |

**Note**: If the endpoint fails consistently for 24 hours, the webhook subscription will be automatically disabled.

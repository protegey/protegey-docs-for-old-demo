# Signals API

The Signals API enables partners to submit fraud indicators to the network.

::callout{icon="i-lucide-shield-alert" color="amber"}
**Production Access Required**: You must have active production keys to post live signals. Sandbox signals do not affect network scores.
::

## Endpoint

```http
POST /api/v1/signals
```

## Request Schema

### Headers

| Header | Value | Required |
|--------|-------|----------|
| `Content-Type` | `application/json` | Yes |
| `X-Centry-Key` | `cny_live_...` | Yes |

### Body Parameters

```json
{
  "entity_type": "email",
  "entity_value": "fraudster@example.com",
  "signal_code": "ACCOUNT_TAKEOVER",
  "occurred_at": "2026-01-12T14:30:00Z",
  "metadata": {
    "ip_address": "1.2.3.4",
    "user_agent": "Mozilla/5.0..."
  }
}
```

| Field | Type | Description | Required | Rules |
|-------|------|-------------|----------|-------|
| `entity_type` | string | The type of entity being flagged. | Yes | `email`, `phone`, `ip`, `device_id`, `crypto_address` |
| `entity_value` | string | The identifier value. | Yes | Must be hashed if `metadata.hashed=true`. |
| `signal_code` | string | Standard fraud reason code. | Yes | See [Signal Codes](#signal-codes). |
| `occurred_at` | string | ISO 8601 Timestamp. | Yes | Cannot be future dated. Max 90 days past. |
| `metadata` | object | Additional context. | No | Max 5KB. No PII allowed. |

### Signal Codes

| Code | Meaning |
|------|---------|
| `ACCOUNT_TAKEOVER` | Verified unauthorized access to an existing account. |
| `SYNTHETIC_IDENTITY` | Identity created using a mix of real and fake info. |
| `FIRST_PARTY_FRAUD` | "Bust out" or intentional non-payment. |
| `STOLEN_FINANCIALS` | Use of stolen credit card or bank credentials. |
| `BOT_ATTACK` | high-velocity automated activity. |

## Response

```json
{
  "id": "sig_8x9s7a6d5f",
  "status": "accepted",
  "processed_at": "2026-01-12T14:30:01Z"
}
```

### Response Codes

- `202 Accepted`: Signal received and queued for processing.
- `400 Bad Request`: Validation failure (check error message).
- `401 Unauthorized`: Invalid API key.
- `429 Too Many Requests`: Rate limit exceeded.

## Best Practices

1.  **Async Submission**: Do not block your user flow on signal submission. Fire and forget.
2.  **Batching**: Use the `/signals/batch` endpoint for bulk submissions (docs coming soon).
3.  **Accuracy**: Only submit `CONFIRMED` or `HIGH_CONFIDENCE` signals. Submitting false positives will degrade your Trust Score.

# Production Guide

Production is the live environment where real decisions are made.

::callout{icon="i-lucide-alert-triangle" color="red"}
**Warning**: Actions in Production have real consequences. Signals submitted here will affect risk scores for other partners.
::

## Go-Live Checklist

Before switching your API keys to Production (`cen_live_`), verify:

1. [ ] **Error Handling**: confirm your app fails gracefully (e.g., "fail open" or "fail closed") if the API returns 500 or times out.
2. [ ] **Timeout Config**: Set your HTTP client timeout to **2000ms** (recommended) or aligned with your SLA.
3. [ ] **Retry Logic**: Implement exponential backoff for 429 and 5xx errors.
4. [ ] **Async Processing**: Ensure signal submissions (writes) are done asynchronously to avoid blocking user flows.

## Shadow Mode (Recommended)

When first going live, we recommend running in **Shadow Mode** for 1-2 weeks.

1. Call the Protegey API for every transaction.
2. Log the `risk_score` and `recommendation` to your database.
3. **Do not block** users based on the score yet.
4. After 1 week, compare Protegey's recommendations against your actual fraud outcomes.
5. Tune your thresholds and then enable active blocking.

### Rate Limits
Production rate limits are significantly higher than Sandbox but are enforced strictly.
- **Bursting**: We support short bursts (up to 2x quota) for <5 seconds.
- **Headers**: Check `X-RateLimit-Remaining` to monitor your usage.

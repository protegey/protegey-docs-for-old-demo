title: API de Surveillance des Transactions (Transaction Monitoring)
description: Référence API complète pour la surveillance, la gestion et l'analyse des transactions de fraude en temps réel.
---

L'API de Surveillance des Transactions permet aux partenaires de surveiller le flux de transactions, de prendre des décisions de fraude (approuver, refuser, signaler) et d'analyser les tendances de risque au sein de leur écosystème.

::callout{type="info"}
**Accès aux fonctionnalités** : La surveillance des transactions est disponible pour les abonnements Professional et supérieurs. Elle fournit une vue d'ensemble en temps réel de tous les signaux entrants traités par le moteur de risque de Protegey.
::

## Authentification

Tous les points de terminaison de surveillance des transactions nécessitent une authentification par jeton OAuth2 Bearer :

```bash
Authorization: Bearer VOTRE_JETON_D_ACCES
```

## Limites de Débit

- **Lister les Transactions** : 1000 requêtes par minute
- **Décisions (Individuelles/Groupées)** : 500 requêtes par minute
- **Analytics** : 200 requêtes par minute
- **Exportation de Données** : 10 requêtes par heure

## Lister les Transactions (Flux de signaux)

**GET** `/api/v1/transaction-monitoring`

Récupère une liste paginée de toutes les transactions (signaux) traitées pour votre organisation partenaire.

### Paramètres de Requête (Query Parameters)

| Paramètre | Type | Requis | Par défaut | Description |
|-----------|------|--------|------------|-------------|
| `status` | string | Non | all | Filtrer par statut de décision : `pending`, `approved`, `declined`, `flagged` |
| `risk_level` | string | Non | all | Filtrer par niveau de risque : `low`, `medium`, `high`, `critical` |
| `event_type` | string | Non | all | Filtrer par type d'événement (ex : `p2p_transfer`) |
| `start_date` | string | Non | - | Date de début (ISO 8601) |
| `end_date` | string | Non | - | Date de fin (ISO 8601) |
| `page` | integer | Non | 1 | Numéro de la page |
| `per_page` | integer | Non | 50 | Éléments par page (max 100) |

### Exemple de Requête

```bash
curl -X GET "https://api.protegey.com/api/v1/transaction-monitoring?status=pending&risk_level=high" \
  -H "Authorization: Bearer VOTRE_JETON_D_ACCES" \
  -H "X-Centry-Environment: sandbox"
```

### Exemple de Réponse

**Succès (200 OK)** :

```json
{
  "data": [
    {
      "id": "sig_abc123",
      "transaction_id": "TXN-20260203-001",
      "event_type": "p2p_transfer",
      "amount": 1500.00,
      "currency": "USD",
      "risk_score": 82,
      "risk_level": "high",
      "status": "pending",
      "actor_hashed_id": "hash_0244567890",
      "created_at": "2026-02-03T14:30:00Z"
    }
  ],
  "meta": {
    "current_page": 1,
    "last_page": 45,
    "total": 2240
  }
}
```

## Prendre une Décision

**POST** `/api/v1/transaction-monitoring/{signalId}/decide`

Prendre une décision manuelle sur une transaction en attente.

### Corps de la Requête

| Champ | Type | Requis | Description |
|-------|------|--------|-------------|
| `decision` | string | Oui | `approved`, `declined`, `flagged`, `mark_suspicious` |
| `reason` | string | Non | Commentaire sur la décision (max 500 caractères) |
| `confidence` | float | Non | Confiance dans la décision (0.0 à 1.0) |

### Exemple de Requête

```bash
curl -X POST "https://api.protegey.com/api/v1/transaction-monitoring/sig_abc123/decide" \
  -H "Authorization: Bearer VOTRE_JETON_D_ACCES" \
  -H "Content-Type: application/json" \
  -d '{
    "decision": "declined",
    "reason": "Fraude confirmée par vérification manuelle",
    "confidence": 0.95
  }'
```

### Exemple de Réponse (200 OK)

```json
{
  "success": true,
  "message": "Décision enregistrée avec succès",
  "data": {
    "signal_id": "sig_abc123",
    "decision": "declined",
    "decided_by": 42,
    "decided_at": "2026-02-03T15:00:00Z"
  }
}
```

## Décisions Groupées (Bulk Decisions)

**POST** `/api/v1/transaction-monitoring/bulk-decide`

Appliquer une décision à plusieurs transactions à la fois.

::callout{icon="i-lucide-zap" color="amber"}
**Enterprise uniquement** : Cette fonctionnalité nécessite un abonnement Enterprise. Max 100 transactions par requête.
::

### Corps de la Requête

| Champ | Type | Requis | Description |
|-------|------|--------|-------------|
| `signal_ids` | array | Oui | Liste des ID de signaux |
| `decision` | string | Oui | `approved`, `declined`, `flagged` |
| `reason` | string | Oui | Raison commune pour le groupe |

### Exemple de Requête

```bash
curl -X POST "https://api.protegey.com/api/v1/transaction-monitoring/bulk-decide" \
  -H "Authorization: Bearer VOTRE_JETON_D_ACCES" \
  -d '{
    "signal_ids": ["sig_1", "sig_2", "sig_3"],
    "decision": "approved",
    "reason": "Approbation groupée pour les transactions à faible risque vérifiées"
  }'
```

## Meilleures Pratiques

### Surveillance en Temps Réel

Mettre en œuvre un mécanisme de scrutation efficace pour le flux de transactions en temps réel :

```typescript
class TransactionMonitor {
  private lastPollTime: Date;

  async pollNewTransactions() {
    const transactions = await client.transactionMonitoring.list({
      status: 'pending',
      start_date: this.lastPollTime.toISOString(),
      sort_by: 'created_at',
      sort_order: 'desc',
      per_page: 50
    });

    this.lastPollTime = new Date();

    for (const tx of transactions.data) {
      await this.processTransaction(tx);
    }
  }

  startPolling(intervalMs = 5000) {
    setInterval(() => this.pollNewTransactions(), intervalMs);
  }
}
```

### Flux de Décision

Utiliser un flux de décision structuré :

```typescript
async function reviewTransaction(signalId: string) {
  // 1. Obtenir les détails
  const transaction = await client.transactionMonitoring.get(signalId);

  // 2. Obtenir le détail du risque
  const breakdown = await client.transactionMonitoring.riskBreakdown(signalId);

  // 3. Trouver des transactions similaires
  const similar = await client.transactionMonitoring.findSimilar(signalId, {
    threshold: 0.8
  });

  // 4. Analyser et décider
  const decision = analyzeRisk(transaction, breakdown, similar);

  // 5. Enregistrer la décision
  await client.transactionMonitoring.decide(signalId, {
    decision: decision.type,
    reason: decision.reason
  });
}
```

### Optimisation des Performances

Optimiser pour les environnements à haut volume :

```typescript
// Utiliser des opérations groupées (Bulk) pour plus d'efficacité
const pendingTransactions = await client.transactionMonitoring.list({
  status: 'pending',
  per_page: 100
});

// Filtrer le faible risque pour auto-approbation
const autoApprove = pendingTransactions.data.filter(
  tx => tx.risk_score < 40
);

if (autoApprove.length > 0) {
  await client.transactionMonitoring.bulkDecide({
    signal_ids: autoApprove.map(tx => tx.id),
    decision: 'approved',
    reason: 'Approbation auto : faible score de risque'
  });
}
```

## Gestion des Erreurs

### Erreurs Courantes

**401 Unauthorized** :
```json
{
  "error": {
    "code": "authentication_error",
    "message": "Jeton d'accès invalide ou expiré"
  }
}
```

**403 Forbidden** :
```json
{
  "success": false,
  "message": "La décision groupée nécessite un abonnement Enterprise"
}
```

**422 Unprocessable Entity** :
```json
{
  "message": "Les données fournies sont invalides.",
  "errors": {
    "decision": ["La décision sélectionnée est invalide. Doit être : approved, declined, flagged, mark_suspicious"]
  }
}
```

**429 Too Many Requests** :
```json
{
  "error": {
    "code": "rate_limit_error",
    "message": "Limite de débit dépassée. Veuillez réessayer dans 60 secondes.",
    "retry_after": 60
  }
}
```

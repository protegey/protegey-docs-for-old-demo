---

L'API de Contrôles Sandbox fournit un accès programmatique à la gestion de l'environnement sandbox, vous permettant de réinitialiser les données sandbox, de générer des signaux de démonstration et d'exécuter des simulations de fraude en plusieurs étapes pour les tests et la validation de l'intégration.

::callout{type="info"}
**Sandbox uniquement** : Tous les points de terminaison de cette API sont **exclusifs à la sandbox**. Ils renverront `403 Forbidden` s'ils sont appelés dans l'environnement de production. Niveau d'accès : **Lecture/Écriture** (disponible sur tous les forfaits).
::

## Authentification

Tous les points de terminaison de contrôle de la sandbox nécessitent une authentification par jeton OAuth2 Bearer :

```bash
Authorization: Bearer VOTRE_JETON_D_ACCES
X-Centry-Environment: sandbox
```

::callout{type="warning"}
**En-tête d'environnement requis** : Vous devez explicitement définir l'environnement sur `sandbox` en utilisant l'en-tête `X-Centry-Environment` ou le paramètre de requête `?environment=sandbox`. Les points de terminaison de contrôle de la sandbox ne fonctionneront pas en production.
::

## Limites de Débit

- **Réinitialiser la Sandbox** : 10 requêtes par heure
- **Générer des signaux de démo** : 3 requêtes par heure
- **Lister les modèles** : 60 requêtes par minute
- **Lister les scénarios** : 60 requêtes par minute
- **Exécuter une simulation** : 5 requêtes par heure

## Réinitialiser la Sandbox

**POST** `/api/v1/partner/sandbox/reset`

Réinitialiser les données de la sandbox avec un contrôle granulaire sur ce qui est supprimé. Cela vous permet de repartir de zéro ou d'effacer sélectivement certains types de données tout en en préservant d'autres.

### Corps de la Requête

| Champ                 | Type    | Requis | Par défaut | Description                                    |
| --------------------- | ------- | ------ | ---------- | ---------------------------------------------- |
| `reset_signals`       | boolean | Non    | false      | Supprimer tous les signaux sandbox             |
| `reset_entities`      | boolean | Non    | false      | Supprimer toutes les entités de fraude sandbox |
| `reset_relationships` | boolean | Non    | false      | Supprimer toutes les relations entre entités   |
| `reset_alerts`        | boolean | Non    | false      | Supprimer toutes les alertes sandbox           |
| `preserve_api_keys`   | boolean | Non    | true       | Conserver les clés API (recommandé)            |
| `reset_audit_logs`    | boolean | Non    | false      | Supprimer les journaux d'audit sandbox         |
| `reset_usage`         | boolean | Non    | false      | Réinitialiser les mesures d'utilisation        |

::callout{type="success"}
**Valeurs par défaut intelligentes** : Si vous appelez ce point de terminaison avec un corps vide `{}`, rien n'est supprimé. Il s'agit d'un mécanisme de sécurité nécessitant une activation explicite pour chaque type de données.
::

### Exemples de Requête

**Réinitialisation totale (tout sauf les clés API)** :

```bash
curl -X POST "https://api.protegey.com/api/v1/partner/sandbox/reset" \
  -H "Authorization: Bearer VOTRE_JETON_D_ACCES" \
  -H "X-Centry-Environment: sandbox" \
  -H "Content-Type: application/json" \
  -d '{
    "reset_signals": true,
    "reset_entities": true,
    "reset_relationships": true,
    "reset_alerts": true,
    "reset_audit_logs": true,
    "reset_usage": true,
    "preserve_api_keys": true
  }'
```

**Réinitialiser uniquement les signaux** (conserver les dossiers, entités, alertes) :

```bash
curl -X POST "https://api.protegey.com/api/v1/partner/sandbox/reset" \
  -H "Authorization: Bearer VOTRE_JETON_D_ACCES" \
  -H "X-Centry-Environment: sandbox" \
  -H "Content-Type: application/json" \
  -d '{
    "reset_signals": true
  }'
```

**Réinitialiser pour un nouveau cycle de test** (effacer les signaux et alertes, conserver les entités) :

```bash
curl -X POST "https://api.protegey.com/api/v1/partner/sandbox/reset" \
  -H "Authorization: Bearer VOTRE_JETON_D_ACCES" \
  -H "X-Centry-Environment: sandbox" \
  -H "Content-Type: application/json" \
  -d '{
    "reset_signals": true,
    "reset_alerts": true,
    "reset_usage": true
  }'
```

### Exemple de Réponse

**Succès (200 OK)** :

```json
{
  "success": true,
  "message": "Les données de la sandbox ont été réinitialisées avec succès."
}
```

**Codes de Statut** :

- `200 OK` - Réinitialisation terminée avec succès
- `401 Unauthorized` - Jeton d'authentification invalide ou manquant
- `403 Forbidden` - Pas dans l'environnement sandbox
- `429 Too Many Requests` - Limite de débit dépassée (10 requêtes/heure)
- `500 Internal Server Error` - L'opération de réinitialisation a échoué

::callout{type="danger"}
**Opération irréversible** : La réinitialisation de la sandbox est permanente et ne peut être annulée. Les données supprimées ne peuvent pas être récupérées. À utiliser avec prudence.
::

## Générer des signaux de démo

**POST** `/api/v1/partner/sandbox/generate-demo-signals`

Générer des signaux de démonstration réalistes à partir de modèles prédéfinis pour tester les règles de détection de fraude, les flux de gestion des dossiers et la logique d'intégration.

### Corps de la Requête

| Champ       | Type    | Requis | Par défaut | Description                                                |
| ----------- | ------- | ------ | ---------- | ---------------------------------------------------------- |
| `template`  | string  | Oui    | -          | Nom du modèle (ex : `transaction/account_takeover`)        |
| `count`     | integer | Non    | 20         | Nombre de signaux à générer (1-100)                        |
| `overrides` | object  | Non    | {}         | Surcharges de variables pour la personnalisation du modèle |

### Exemples de Requête

**Génération de base de signaux de démo** :

```bash
curl -X POST "https://api.protegey.com/api/v1/partner/sandbox/generate-demo-signals" \
  -H "Authorization: Bearer VOTRE_JETON_D_ACCES" \
  -H "X-Centry-Environment: sandbox" \
  -H "Content-Type: application/json" \
  -d '{
    "template": "transaction/account_takeover",
    "count": 50
  }'
```

**Avec surcharges de variables** (forcer un numéro de téléphone spécifique) :

```bash
curl -X POST "https://api.protegey.com/api/v1/partner/sandbox/generate-demo-signals" \
  -H "Authorization: Bearer VOTRE_JETON_D_ACCES" \
  -H "X-Centry-Environment: sandbox" \
  -H "Content-Type: application/json" \
  -d '{
    "template": "transaction/stolen_financials",
    "count": 10,
    "overrides": {
      "PHONE_NUMBER": "0244123456",
      "TRANSACTION_AMOUNT": 50000,
      "COUNTRY_CODE": "US"
    }
  }'
```

**Générer des signaux de risque critique** (pour le test d'alertes) :

```bash
curl -X POST "https://api.protegey.com/api/v1/partner/sandbox/generate-demo-signals" \
  -H "Authorization: Bearer VOTRE_JETON_D_ACCES" \
  -H "X-Centry-Environment: sandbox" \
  -H "Content-Type: application/json" \
  -d '{
    "template": "transaction/account_takeover",
    "count": 20,
    "overrides": {
      "TRANSACTION_AMOUNT": 75000,
      "source_confidence": 0.95
    }
  }'
```

### Exemple de Réponse

**Succès (200 OK)** :

```json
{
  "success": true,
  "data": {
    "signals_generated": 50,
    "template": "transaction/account_takeover",
    "signal_ids": ["sig_abc123", "sig_def456", "sig_ghi789", "..."]
  },
  "message": "Génération réussie de 50 signaux de démonstration"
}
```

**Limite de débit dépassée (429)** :

```json
{
  "success": false,
  "message": "Limite de génération de démo dépassée. Veuillez attendre une heure ou réinitialiser votre sandbox."
}
```

**Codes de Statut** :

- `200 OK` - Signaux générés avec succès
- `401 Unauthorized` - Authentification invalide
- `403 Forbidden` - Pas dans l'environnement sandbox
- `422 Unprocessable Entity` - Nom du modèle ou nombre invalide
- `429 Too Many Requests` - Limite de débit dépassée (3 requêtes/heure)
- `500 Internal Server Error` - Échec de la génération des signaux

### Limites de Débit

La génération de signaux de démonstration est limitée à **3 requêtes par heure** pour assurer la stabilité du système. Si vous avez besoin de générer plus de signaux :

1. **Réinitialisez votre sandbox** (efface le compteur de limite de débit)
2. **Utilisez le simulateur CLI** (pas de limites de débit) : `php artisan centry:simulate-signals`
3. **Attendez que la fenêtre de limite de débit expire** (1 heure après la première requête)

::callout{type="info"}
**Pourquoi des limites de débit ?** : La génération de signaux de démonstration déclenche l'ensemble du pipeline de détection de fraude (scoring, alertes, liaison d'entités, etc.). Les limites de débit évitent les abus de sandbox et garantissent une allocation équitable des ressources.
::

## Exécuter une simulation

**POST** `/api/v1/partner/sandbox/simulate`

Exécuter une simulation de scénario de fraude en plusieurs étapes. Les scénarios génèrent des séquences coordonnées de signaux liés qui se déroulent au fil du temps, mimant les modèles d'attaque du monde réel.

::callout{type="warning"}
**Fonctionnalité planifiée** : La simulation de scénarios en plusieurs étapes est actuellement en cours de développement (Phase 2, T2 2026). Ce point de terminaison renverra une erreur de fonctionnalité non disponible jusqu'à la fin de l'implémentation.
::

### Corps de la Requête

| Champ         | Type   | Requis | Description                                                                      |
| ------------- | ------ | ------ | -------------------------------------------------------------------------------- |
| `scenario_id` | string | Oui    | Identifiant du scénario (provenant du point de terminaison `/scenarios`)         |
| `mode`        | string | Non    | Mode d'exécution : `realtime`, `fast-forward`, `immediate` (défaut : `realtime`) |
| `overrides`   | object | Non    | Surcharges de variables de scénario                                              |

### Exemple de Requête

```bash
curl -X POST "https://api.protegey.com/api/v1/partner/sandbox/simulate" \
  -H "Authorization: Bearer VOTRE_JETON_D_ACCES" \
  -H "X-Centry-Environment: sandbox" \
  -H "Content-Type: application/json" \
  -d '{
    "scenario_id": "sim_swap_drainage",
    "mode": "fast-forward",
    "overrides": {
      "SCENARIO_PHONE": "0244123456"
    }
  }'
```

### Exemple de Réponse

**Succès (200 OK)** :

```json
{
  "success": true,
  "data": {
    "batch_id": "scenario_1738598400_abc123"
  },
  "message": "La simulation a démarré avec succès."
}
```

**Fonctionnalité non disponible (501 Not Implemented)** :

```json
{
  "success": false,
  "message": "La simulation de scénarios en plusieurs étapes n'est pas encore disponible. Prévue pour : T2 2026."
}
```

**Codes de Statut** :

- `200 OK` - Simulation démarrée avec succès
- `401 Unauthorized` - Authentification invalide
- `403 Forbidden` - Pas dans l'environnement sandbox
- `422 Unprocessable Entity` - ID de scénario invalide
- `429 Too Many Requests` - Limite de débit dépassée (5 requêtes/heure)
- `500 Internal Server Error` - Échec du démarrage de la simulation
- `501 Not Implemented` - Fonctionnalité pas encore disponible

## Meilleures Pratiques

### Flux de travail des tests en Sandbox

**Flux de test d'intégration recommandé** :

```javascript
const client = new ProtegeyClient({ apiKey: "VOTRE_CLE_SANDBOX" });

// 1. Commencer avec une page blanche
await client.sandbox.reset({
  reset_signals: true,
  reset_alerts: true,
  reset_entities: true,
  preserve_api_keys: true,
});

// 2. Générer des données de test
await client.sandbox.generateDemoSignals({
  template: "transaction/account_takeover",
  count: 50,
});

// 3. Tester votre logique d'intégration
const signals = await client.transactionMonitoring.list();
for (const signal of signals.data) {
  await processSignal(signal);
}

// 4. Vérifier les résultats
const cases = await client.cases.list();
const alerts = await client.alerts.list();

// 5. Nettoyer après le test
await client.sandbox.reset({ reset_signals: true });
```

### Stratégie de sélection de modèles

**Choisissez des modèles en fonction de vos objectifs de test** :

| Objectif du test           | Modèle recommandé                                | Pourquoi                                                   |
| -------------------------- | ------------------------------------------------ | ---------------------------------------------------------- |
| Seuil des alertes          | `transaction/account_takeover`                   | Génère des signaux à haut risque (10 % critique)           |
| Règle de vélocité          | `transaction/stolen_financials` + surcharges     | Utilisez le même numéro de téléphone pour tous les signaux |
| Gestion des dossiers       | `transaction/synthetic_identity`                 | Scénarios complexes nécessitant une enquête                |
| Liaison d'entités          | `identity/phone_verification_failure`            | Crée des profils d'entités avec plusieurs signaux          |
| Détection transfrontalière | N'importe quel modèle + surcharge `COUNTRY_CODE` | Forcer des transactions transfrontalières                  |

### Exemples de surcharges de variables

**Tester les contrôles de vélocité** (même acteur, plusieurs transactions) :

```javascript
// Générer 10 signaux avec le même numéro de téléphone
await client.sandbox.generateDemoSignals({
  template: "transaction/account_takeover",
  count: 10,
  overrides: {
    PHONE_NUMBER: "0244123456",
    TRANSACTION_AMOUNT: 5000,
  },
});

// Devrait déclencher une alerte de vélocité
const alerts = await client.alerts.list({
  alert_type: "velocity_check",
});
```

**Tester la détection d'anomalie de montant** (transactions de haute valeur) :

```javascript
await client.sandbox.generateDemoSignals({
  template: "transaction/stolen_financials",
  count: 5,
  overrides: {
    TRANSACTION_AMOUNT: 150000, // Bien au-dessus du seuil
    source_confidence: 0.9, // Haute confiance
  },
});

// Devrait déclencher des alertes d'anomalie de montant
const alerts = await client.alerts.list({
  severity_level: "critical",
});
```

### Stratégie de réinitialisation sélective

**Flux de développement** (préserver les entités entre les tests) :

```bash
# Réinitialiser les signaux et alertes, conserver les entités pour la continuité
curl -X POST "https://api.protegey.com/api/v1/partner/sandbox/reset" \
  -H "Authorization: Bearer $TOKEN" \
  -H "X-Centry-Environment: sandbox" \
  -d '{"reset_signals": true, "reset_alerts": true}'
```

## Gestion des Erreurs

### Codes d'Erreur Courants

| Code de Statut              | Erreur                       | Cause                                      | Solution                                          |
| --------------------------- | ---------------------------- | ------------------------------------------ | ------------------------------------------------- |
| `403 Forbidden`             | `Not in sandbox environment` | Appelé depuis la production                | Ajouter l'en-tête `X-Centry-Environment: sandbox` |
| `422 Unprocessable Entity`  | `Invalid template`           | Le nom du modèle n'existe pas              | Lister les modèles disponibles d'abord            |
| `422 Unprocessable Entity`  | `Count out of range`         | Compte < 1 ou > 100                        | Utiliser un nombre entre 1 et 100                 |
| `429 Too Many Requests`     | `Rate limit exceeded`        | Trop de requêtes dans la fenêtre de temps  | Attendre ou réinitialiser la sandbox              |
| `500 Internal Server Error` | `Reset operation failed`     | Échec de la transaction en base de données | Réessayer ou contacter le support                 |

## FAQ

**Q : Quelle est la différence entre les signaux de démo et les signaux réguliers ?**
R : Les signaux de démo sont marqués avec les métadonnées `generated_by: centry_demo` et suivent des modèles prédéfinis avec un profilage de risque dynamique. Ils sont identiques aux signaux réguliers dans le traitement mais sont clairement marqués à des fins de test.

**Q : Puis-je générer plus de 100 signaux à la fois ?**
R : Non, la limite est de 100 par requête. Pour des tests à plus gros volume, effectuez plusieurs requêtes (sous réserve des limites de débit) ou utilisez le simulateur CLI : `php artisan centry:simulate-signals`.

**Q : La réinitialisation de ma sandbox affectera-t-elle mes données de production ?**
R : Non. Les environnements sandbox et production sont physiquement séparés au niveau du schéma de la base de données. Les opérations sandbox n'affectent jamais les données de production.

**Q : Puis-je personnaliser les modèles de signaux ?**
R : Pas via l'API actuellement. Vous pouvez utiliser les `overrides` pour personnaliser les variables du modèle par requête. Des modèles personnalisés peuvent être ajoutés dans `storage/app/signal-templates/` (nécessite un accès au backend).

**Q : Pourquoi y a-t-il une limite de débit sur la génération de signaux de démo ?**
R : La génération de signaux de démo déclenche tout le pipeline de détection de fraude. Les limites de débit garantissent une allocation équitable des ressources et évitent les abus.

**Q : Combien de temps faut-il pour générer des signaux ?**
R : La génération est synchrone et se termine généralement en 2 à 5 secondes pour 20 à 50 signaux.

**Q : Que se passe-t-il si j'atteins la limite de débit ?**
R : Vous recevrez une réponse `429 Too Many Requests`. Vous pouvez soit attendre une heure, soit réinitialiser votre sandbox.

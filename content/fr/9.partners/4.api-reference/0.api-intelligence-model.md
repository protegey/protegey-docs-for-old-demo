Protegey expose trois points d'accès pour les différentes étapes du cycle de vie de l'intelligence contre la fraude. Comprendre lequel utiliser — et pourquoi — est le fondement d'une intégration bien conçue.

## Deux Couches d'Intelligence

L'API est organisée autour de deux couches d'intelligence distinctes :

### Évaluation (Sans État)

Scoring en temps réel de données brutes ou non liées. Aucune entité n'est créée ou mise à jour. Peut être appelé à chaque requête sans effets secondaires.

- Entrée : identifiants bruts (email, téléphone, appareil, compte, composite)
- Sortie : `risk_score`, `risk_level`, `confidence`, `explanations[]`, `recommendation`
- Objectif de latence : **< 100ms**
- À utiliser pour : le filtrage préalable de nouveaux utilisateurs, le scoring avant l'embarquement, les décisions de paiement en temps réel

### Évaluation Approfondie (Avec État)

Intelligence approfondie sur une entité connue dans le graphe. Requiert que l'entité existe déjà (suite à une ingestion de signal ou une résolution d'entité préalable). Retourne un package d'intelligence complet incluant l'historique comportemental, le voisinage réseau et le contexte de conformité.

- Entrée : UUID d'entité ou identifiant lié
- Sortie : contrat de scoring complet + `profile`, `network`, `history`
- Objectif de latence : **< 500ms**
- À utiliser pour : l'investigation d'un utilisateur signalé, l'enrichissement d'un dossier, la revue de transactions à haute valeur

---

## Vue d'Ensemble des Trois Points d'Accès

| Point d'accès | Type | Objectif | Latence |
|---|---|---|---|
| `POST /api/v1/signals` | Avec état | Ingérer des événements dans le graphe d'entités | Sans risque asynchrone |
| `POST /api/v1/evaluate` | Sans état | Scorer des données brutes/non liées en temps réel | < 100ms |
| `POST /api/v1/risk/assess` | Avec état | Package d'intelligence d'entité approfondi | < 500ms |

## Le Modèle de Graphe d'Entités

Les signaux sont la matière première. Les entités sont l'intelligence persistante.

Lorsqu'un signal arrive, Protegey :

1. **Valide** l'événement par rapport au schéma UFES v2
2. **Résout** les identifiants vers les entités existantes (ou en crée de nouvelles)
3. **Exécute les détecteurs** (vélocité, valeur aberrante, échange de SIM, appareil, déplacement)
4. **Fusionne les scores** à travers les dimensions comportementale, réseau, contextuelle et historique
5. **Met à jour** le profil de risque de l'entité et les arêtes du graphe

Avec le temps, chaque entité accumule un historique comportemental, un voisinage réseau et un dossier de conformité — rendant `/risk/assess` progressivement plus riche.

---

## Flux d'Intelligence Progressive

```
Entrée Brute → POST /evaluate → (resolve_entity: true) → Entité → POST /risk/assess
                ↓ sans état                                          ↓ avec état
           Verdict immédiat                               Package d'intelligence complet
```

L'option `resolve_entity: true` dans `/evaluate` indique à Protegey de lier l'entrée évaluée à une entité existante si une correspondance est trouvée. L'UUID de l'entité résolue est retourné et peut immédiatement être utilisé avec `/risk/assess` pour une évaluation plus approfondie.

---

## Quand Utiliser Quel Point d'Accès

### Utiliser `/signals` quand :
- Vous signalez un événement de fraude confirmé ou un rejet de débit
- Vous alimentez le graphe avec du contexte comportemental au fil du temps
- Vous soumettez des signaux pour le partage d'intelligence au niveau réseau
- Vous n'avez pas besoin d'un verdict synchrone (déclenchement et oubli avec idempotence)

### Utiliser `/evaluate` quand :
- Vous scorez un email, un téléphone ou un appareil lors de la création de compte
- Vous filtrez préalablement un utilisateur avant qu'il n'apparaisse dans votre système
- Vous prenez des décisions de paiement ou de règlement en temps réel
- Vous souhaitez un verdict sans créer d'entité persistante

### Utiliser `/risk/assess` quand :
- Vous examinez une entité signalée depuis votre file d'alertes
- Vous enrichissez un dossier de fraude ouvert avec le contexte complet
- Vous construisez un workflow d'investigation nécessitant l'historique comportemental
- Des transactions à haute valeur nécessitent le package d'intelligence complet

## Aperçu de l'Abstraction SDK

Le SDK Protegey à venir exposera des méthodes composites correspondant à ce modèle :

```typescript
// Sans état — encapsule POST /evaluate
await protegey.evaluateEmail("user@example.com");
await protegey.evaluatePhone("+233244123456");
await protegey.evaluateDevice({ fingerprint: "fp_abc123" });

// Avec état — encapsule POST /risk/assess
await protegey.assessEntity("ent_uuid_here");

// Composite — evaluate + resolve + assess en un seul appel
await protegey.assessByEmail("user@example.com");
// → evaluate → resolve_entity: true → assess
```

Les méthodes composites gèrent automatiquement la chaîne evaluate → resolve → assess, retournant le package d'intelligence complet même pour les entités jamais vues auparavant.

L'API des Signaux permet aux partenaires de soumettre des indicateurs de fraude au réseau Protegey. Chaque signal est **validé et évalué de manière synchrone** — un verdict de risque est retourné dans la même réponse HTTP. Le traitement asynchrone (liaison au graphe, enrichissement des entités, génération d'alertes) se poursuit en arrière-plan.

::callout{icon="i-lucide-shield-alert" color="amber"}
**Accès Production Requis** : Vous devez avoir des clés de production actives pour publier des signaux réels. Les signaux sandbox n'affectent pas les scores du réseau.
::

## Point de terminaison (Endpoint)

```http
POST /api/v1/signals
```

### En-têtes (Headers)

| En-tête           | Valeur                         | Requis     |
| ----------------- | ------------------------------ | ---------- |
| `Content-Type`    | `application/json`             | Oui        |
| `X-Centry-Key`    | `cen_live_sk_...`              | Oui        |
| `Idempotency-Key` | Clé unique (64 caractères max) | Recommandé |

## UFES v2 — Le Seul Format Supporté

Toutes les nouvelles intégrations doivent utiliser **UFES v2** (`schema_version: "2.0"`). Les formats legacy et v1 ont été supprimés du pipeline d'ingestion.

### Champs Requis

| Champ                     | Type    | Description                                                                    |
| ------------------------- | ------- | ------------------------------------------------------------------------------ |
| `schema_version`          | `"2.0"` | Doit être exactement `"2.0"`                                                   |
| `event_type`              | string  | Type d'événement libre (ex : `MOBILE_MONEY_SEND`, `LOGIN_FAILURE`, `SIM_SWAP`) |
| `timestamp`               | string  | Datetime ISO 8601                                                              |
| `source`                  | object  | Métadonnées de la source de soumission                                         |
| `source.confidence_score` | number  | 0.0–1.0 — votre niveau de confiance que cet événement est lié à la fraude      |
| `primary_actor`           | object  | L'entité effectuant l'action                                                   |
| `primary_actor.entity_id` | string  | Votre identifiant interne stable pour cette entité                             |

::callout{icon="i-lucide-info" color="blue"}
`event_category` est **optionnel** — il est automatiquement dérivé de `event_type` lorsqu'il est omis (ex : `TRANSFER` → `transaction`, `LOGIN` → `auth`, `SIM_SWAP` → `auth`). Fournissez-le explicitement uniquement si la dérivation automatique ne correspond pas à votre cas d'usage.
::

### Schéma Complet

```typescript
interface UFESv2Signal {
  // ── Enveloppe (requis) ───────────────────────────────────────────
  schema_version: "2.0";
  event_type: string; // ex : "MOBILE_MONEY_SEND", "SIM_SWAP", "LOGIN_FAILURE"
  timestamp: string; // ISO 8601

  // ── Enveloppe (optionnel) ────────────────────────────────────────
  event_category?: "transaction" | "auth" | "kyc" | "fraud_signal" | "system";
  flow_type?: "payment" | "auth" | "kyc"; // auto-inféré depuis event_category si omis
  trace_id?: string; // votre identifiant de traçage inter-systèmes

  // ── Source ───────────────────────────────────────────────────────
  source: {
    confidence_score: number; // 0.0–1.0, requis
    integration_channel?: "api" | "batch" | "stream";
    partner_user_id?: string; // votre référence interne
    ip_address?: string; // IP de l'utilisateur soumettant — alimente le détecteur IMPOSSIBLE_TRAVEL
  };

  // ── Acteur principal (requis) ────────────────────────────────────
  primary_actor: {
    entity_id: string; // requis — votre identifiant stable pour cet acteur
    entity_type?: "individual" | "business" | "account" | "device";
    hashed_id?: string; // HMAC-SHA256 des PII canoniques, pour la liaison au graphe
    identifiers?: {
      region?: string; // Code pays ISO 3166-1 alpha-2 (ex : "GH")
      sim_changed_at?: string; // ISO 8601 — alimente le détecteur SIM_SWAP_PROXIMITY
      [key: string]: string | undefined;
    };
    device?: {
      fingerprint?: string; // empreinte d'appareil (255 caractères max) — alimente NEW_DEVICE_ACCESS
      user_agent?: string; // chaîne UA brute (512 caractères max), conservée comme piste d'audit
    };
    risk_flags?: string[]; // ex : ["high_velocity", "new_device"]
  };

  // ── Entités liées (optionnel) ────────────────────────────────────
  related_entities?: Array<{
    entity_id: string;
    entity_type?: string;
    relationship_type?:
      | "sender"
      | "receiver"
      | "beneficiary"
      | "shared_device"
      | "linked_account"
      | "mule"
      | "director"
      | "proxy";
  }>;

  // ── Payload d'événement (optionnel, données spécifiques à la catégorie) ─
  event_payload?: {
    amount?: number;
    currency?: string;
    reference_id?: string;
    geo_location?: { lat: number; lng: number };
    [key: string]: any;
  };

  // ── Blocs d'intelligence partenaire (optionnel, piste d'audit uniquement) ─
  risk_intelligence?: {
    risk_score?: number;
    risk_level?: "low" | "medium" | "high" | "critical";
    risk_factors?: string[];
    model_version?: string;
  };
  compliance_context?: {
    jurisdiction?: string;
    regulatory_flags?: string[];
    screening_results?: Record<string, any>[];
  };
  decision_context?: {
    final_decision?: "approve" | "deny" | "review" | "block" | "escalate";
    decision_timestamp?: string;
    decision_rationale?: string;
    policy_id?: string;
  };

  metadata?: Record<string, any>;
}
```

### Dérivation Automatique de la Catégorie d'Événement

Lorsque `event_category` est omis, Protegey le dérive depuis `event_type` :

| `event_category` | Valeurs `event_type` auto-associées                                                                                                           |
| ---------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| `auth`           | `LOGIN`, `LOGIN_SUCCESS`, `LOGIN_FAILURE`, `SIM_SWAP`, `ACCOUNT_TAKEOVER`, `ACCOUNT_UPDATE`, `MFA_BYPASS`, `PASSWORD_RESET`, `DEVICE_ANOMALY` |
| `transaction`    | `PAYMENT`, `TRANSFER`, `WITHDRAWAL`, `MOBILE_MONEY_SEND`, `CARD_FRAUD`, `PAYMENT_FRAUD`                                                       |
| `kyc`            | `ACCOUNT_CREATE`, `ACCOUNT_OPENING`, `KYC_CHECK`, `DOCUMENT_VERIFY`, `IDENTITY_THEFT`                                                         |
| `fraud_signal`   | Tout le reste                                                                                                                                 |

## Champs Requis par les Détecteurs

Protegey exécute **cinq détecteurs** sur chaque signal. Certains détecteurs nécessitent des champs spécifiques pour se déclencher. Fournir ces champs maximise la qualité de votre évaluation de risque.

| Détecteur                    | Champ requis                    | Où le fournir                                         |
| ---------------------------- | ------------------------------- | ----------------------------------------------------- |
| `RAPID_TRANSACTION_VELOCITY` | ID de l'acteur + signaux passés | `primary_actor.entity_id`                             |
| `LARGE_OUTLIER_TRANSACTION`  | Montant de la transaction       | `event_payload.amount` + `event_payload.currency`     |
| `SIM_SWAP_PROXIMITY`         | Horodatage du changement de SIM | `primary_actor.identifiers.sim_changed_at` (ISO 8601) |
| `NEW_DEVICE_ACCESS`          | Empreinte d'appareil            | `primary_actor.device.fingerprint`                    |
| `IMPOSSIBLE_TRAVEL`          | Adresse IP de soumission        | `source.ip_address`                                   |

::callout{icon="i-lucide-zap" color="primary"}
**Enrichissez chaque signal** : Fournir `source.ip_address`, `primary_actor.device.fingerprint` et `primary_actor.identifiers.sim_changed_at` là où cela est applicable augmente significativement la précision de détection — notamment pour les schémas de SIM swap et de prise de contrôle de compte fréquents dans la fraude mobile money africaine.
::

## Hachage des PII

Protegey **ne stocke jamais les PII en clair**. Tous les identifiants personnels doivent être hachés avant soumission en utilisant **HMAC-SHA256 avec votre clé réseau**.

::callout{icon="i-lucide-lock" color="amber"}
**Votre clé réseau n'est pas votre clé API.** Il s'agit d'un secret distinct disponible dans le Portail Partenaire sous **Paramètres › Confidentialité › Clé Réseau**. Effectuez sa rotation indépendamment de vos clés API.
::

### Forme Canonique Avant Hachage

Normalisez toujours les identifiants avant le hachage pour garantir une liaison cohérente au graphe :

| Type                  | Forme Canonique                | Exemple            |
| --------------------- | ------------------------------ | ------------------ |
| Téléphone (MSISDN)    | E.164                          | `+233241234567`    |
| Email                 | minuscules, sans espaces       | `user@example.com` |
| Identifiant de compte | tel quel (sans transformation) | `ACC-00123456`     |
| Identité nationale    | majuscules, sans espaces       | `GHA-12345678`     |

### Exemples de Code

**Node.js :**

```javascript
const crypto = require("crypto");

function hashIdentifier(value, networkKey) {
  const canonical = value.toLowerCase().trim(); // normalise first
  return crypto
    .createHmac("sha256", networkKey)
    .update(canonical)
    .digest("hex");
}

const networkKey = process.env.PROTEGEY_NETWORK_KEY;
const hashedPhone = hashIdentifier("+233241234567", networkKey);
// → 64-char hex string, e.g. "a3f8b2c1d9e7..."
```

**Python :**

```python
import hmac, hashlib, os

def hash_identifier(value: str, network_key: str) -> str:
    canonical = value.lower().strip()
    return hmac.new(network_key.encode(), canonical.encode(), hashlib.sha256).hexdigest()

network_key = os.environ["PROTEGEY_NETWORK_KEY"]
hashed_phone = hash_identifier("+233241234567", network_key)
```

**PHP :**

```php
function hashIdentifier(string $value, string $networkKey): string
{
    $canonical = strtolower(trim($value));
    return hash_hmac('sha256', $canonical, $networkKey);
}

$networkKey = env('PROTEGEY_NETWORK_KEY');
$hashedPhone = hashIdentifier('+233241234567', $networkKey);
```

## Réponse

### Succès (`201 Created`)

L'ingestion du signal est **synchrone** — l'évaluation du risque s'exécute en ligne et est retournée immédiatement.

```json
{
  "success": true,
  "data": {
    "signal_id": "9df4a3b1-c2e3-4f56-a789-b0c1d2e3f456",
    "event_type": "MOBILE_MONEY_SEND",
    "timestamp": "2026-02-25T10:30:00+00:00",
    "risk_score": 0.78,
    "risk_level": "high",
    "detectors_triggered": [
      "RAPID_TRANSACTION_VELOCITY",
      "LARGE_OUTLIER_TRANSACTION"
    ],
    "taxonomy": "mobile_money_fraud"
  },
  "message": "Signal received and assessed"
}
```

### Niveaux de Risque

| `risk_level` | Plage de `risk_score` | Action recommandée                                          |
| ------------ | --------------------- | ----------------------------------------------------------- |
| `critical`   | ≥ 0.8                 | Bloquer immédiatement, ouvrir une investigation             |
| `high`       | 0.6 – 0.79            | Exiger une vérification supplémentaire ou mettre en attente |
| `medium`     | 0.4 – 0.59            | Authentification renforcée ou révision manuelle             |
| `low`        | 0.2 – 0.39            | Autoriser avec surveillance                                 |
| `minimal`    | < 0.2                 | Autoriser — signal de fraude faible                         |

### Détecteurs

| ID du Détecteur              | Ce qu'il détecte                                                                 |
| ---------------------------- | -------------------------------------------------------------------------------- |
| `RAPID_TRANSACTION_VELOCITY` | Fréquence de transaction inhabituellement élevée sur une courte période          |
| `LARGE_OUTLIER_TRANSACTION`  | Montant de transaction bien au-dessus de la ligne de base historique de l'acteur |
| `SIM_SWAP_PROXIMITY`         | Transaction de haute valeur dans les 24h suivant un changement de SIM            |
| `NEW_DEVICE_ACCESS`          | Activité depuis une empreinte d'appareil jamais vue pour cet acteur              |
| `IMPOSSIBLE_TRAVEL`          | Impossibilité géographique entre deux événements consécutifs                     |

### Erreur de Validation (`422 Unprocessable Content`)

```json
{
  "message": "The primary_actor.entity_id field is required.",
  "errors": {
    "primary_actor.entity_id": [
      "The primary_actor.entity_id field is required."
    ]
  }
}
```

### Erreurs de Validation Courantes

| Erreur                                                                        | Cause                                                                       |
| ----------------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| `primary_actor.entity_id is required`                                         | Payload UFES v2 sans `primary_actor.entity_id`                              |
| `event_category must be one of: auth, transaction, kyc, fraud_signal, system` | Valeur de catégorie invalide — ou omettez-la pour la dérivation automatique |
| `flow_type must be one of: kyc, payment, auth`                                | `flow_type` explicite hors de l'enum autorisé                               |
| `primary_actor.device.fingerprint may not be greater than 255 characters`     | Tronquez l'empreinte à 255 caractères                                       |
| `related_entities.0.relationship_type is invalid`                             | Type de relation inconnu                                                    |
| `source.integration_channel is invalid`                                       | Canal absent de `api, batch, stream`                                        |

## Idempotence

Utilisez l'en-tête `Idempotency-Key` pour réessayer sans risque les requêtes échouées sans créer de signaux en double.

**Règles :**

- La clé doit être unique par signal logique (UUID recommandé)
- Maximum 64 caractères
- Les clés sont limitées au périmètre du partenaire et expirent après 24 heures
- Les réponses `4xx` ne sont jamais mises en cache — réessayer un mauvais payload ne rejoue pas une erreur en cache
- En cas de relecture, la réponse inclut `X-Idempotency-Replayed: true`

**Exemple — réessai avec backoff exponentiel :**

```javascript
async function submitSignal(payload, idempotencyKey, retries = 3) {
  for (let attempt = 0; attempt < retries; attempt++) {
    try {
      const response = await fetch("https://api.protegey.com/v1/signals", {
        method: "POST",
        headers: {
          "Content-Type": "application/json",
          "X-Centry-Key": process.env.PROTEGEY_SECRET_KEY,
          "Idempotency-Key": idempotencyKey, // same key on every retry
        },
        body: JSON.stringify(payload),
      });

      if (response.ok) return await response.json();
      if (response.status < 500)
        throw new Error(`Client error: ${response.status}`);

      // 5xx — wait and retry
      await new Promise((r) => setTimeout(r, Math.pow(2, attempt) * 1000));
    } catch (err) {
      if (attempt === retries - 1) throw err;
    }
  }
}

// Generate key once, before the first attempt
const signalKey = crypto.randomUUID();
await submitSignal(payload, signalKey);
```

::callout{icon="i-lucide-info" color="blue"}
**Bonne pratique** : Générez la clé d'idempotence **avant** d'envoyer la première requête. Stockez-la avec le signal dans votre système afin de pouvoir réutiliser la même clé à chaque réessai, quel que soit le temps écoulé.
::

## Normalisation du Téléphone

Lorsque vous soumettez un signal contenant un numéro de téléphone via `primary_actor.identifiers.msisdn`, le système le convertit automatiquement au format canonique E.164 avant le hachage et la liaison au graphe.

### Marchés Pris en Charge

| Pays               | Code ISO | Exemples de Formats Locaux    | Résultat (E.164) |
| ------------------ | -------- | ----------------------------- | ---------------- |
| **Ghana**          | `GH`     | `024 123 4567`, `241234567`   | `+233241234567`  |
| **Nigeria**        | `NG`     | `0803 123 4567`, `7012345678` | `+2348031234567` |
| **Sénégal**        | `SN`     | `077 123 45 67`, `771234567`  | `+221771234567`  |
| **Côte d'Ivoire**  | `CI`     | `07 01 23 45 67`              | `+2250701234567` |
| **Kenya**          | `KE`     | `0712 345678`                 | `+254712345678`  |
| **Afrique du Sud** | `ZA`     | `082 123 4567`                | `+27821234567`   |
| **Maroc**          | `MA`     | `06 12 34 56 78`              | `+212612345678`  |
| **Égypte**         | `EG`     | `010 1234 5678`               | `+201012345678`  |

::callout{icon="i-lucide-lightbulb" color="primary"}
**Bonne Pratique** : Fournissez toujours le `identifiers.region` de l'acteur (code pays ISO) lors de la soumission de numéros de téléphone. Cela garantit une précision de normalisation de 100 % pour les formats locaux ambigus ou se chevauchant.
::

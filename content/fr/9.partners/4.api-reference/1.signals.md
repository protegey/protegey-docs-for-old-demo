# API des Signaux

L'API des Signaux permet aux partenaires de soumettre des indicateurs de fraude au réseau. Les signaux sont ingérés de manière asynchrone et traités par le Moteur de Risque.

::callout{icon="i-lucide-shield-alert" color="amber"}
**Accès Production Requis** : Vous devez avoir des clés de production actives pour publier des signaux réels. Les signaux sandbox n'affectent pas les scores du réseau.
::

## Point de terminaison (Endpoint)

```http
POST /api/v1/signals
```

## Schéma de Requête

### En-têtes (Headers)

| En-tête | Valeur | Requis | Description |
|--------|-------|--------|-------------|
| `Content-Type` | `application/json` | Oui | Payload JSON standard. |
| `X-Centry-Key` | `cen_live_sk_...` | Oui | Votre clé secrète de production. |

### Paramètres du Corps (Body Parameters)

Le payload est structuré en objets `actor`, `event` et `transaction`.

```typescript
interface SignalRequest {
  actor: {
    hashed_id: string; // L'identifiant principal de l'entité (haché ou clair)
    device_fingerprint?: string;
    region?: string;
  };
  event: {
    type: string; // Le signal de fraude (ex : ACCOUNT_TAKEOVER)
    timestamp: string; // ISO 8601 (ex : 2026-01-12T14:30:00Z)
    channel?: string; // WEB, MOBILE, API, etc.
  };
  transaction?: {
    amount?: number;
    currency?: string; // ISO 4217 (3 caractères)
    geo_location?: {
      lat: number;
      lon: number;
    };
  };
  source_confidence?: number; // 0.0 à 1.0 (défaut : 0.5)
  metadata?: Record<string, any>;
}
```

### Règles de Validation

| Champ | Requis | Règles |
|-------|--------|-------|
| `actor.hashed_id` | **Oui** | Chaîne. L'identifiant de l'entité (ex : hachage SHA-256 ou valeur brute). |
| `event.type` | **Oui** | Doit correspondre à un code valide (ex : `ACCOUNT_TAKEOVER`, `SYNTHETIC_IDENTITY`). |
| `event.timestamp` | **Oui** | ISO 8601. Ne peut pas être dans le futur. |
| `transaction.currency` | Non | Doit comporter exactement 3 caractères si fourni. |
| `transaction.geo_location` | Non | `lat` et `lon` sont requis si l'objet existe. |
| `source_confidence` | Non | Flottant entre 0.0 et 1.0. |

## Normalisation du Téléphone

Protegey utilise une **Stratégie de Normalisation à Niveaux** pour garantir une haute qualité de données pour les entités basées sur le téléphone. Lorsque vous soumettez un signal avec un `actor_hashed_id` ou des métadonnées contenant un numéro de téléphone, le système le convertit automatiquement au format canonique E.164.

### Marchés pris en charge (Marchés primaires africains)

Le système fournit une normalisation stricte au format local pour les pays suivants :

| Pays | Code ISO | Exemples de Formats Locaux | Résultat (E.164) |
|---------|----------|-----------------------|----------------|
| **Sénégal** | `SN` | `077 123 45 67`, `771234567` | `+221771234567` |
| **Côte d'Ivoire** | `CI` | `07 01 23 45 67`, `0102030405` | `+2250701234567` |
| **Mali** | `ML` | `07123456`, `6123456` | `+2237123456` |
| **Burkina Faso** | `BF` | `54123456`, `76123456` | `+22654123456` |
| **Cameroun** | `CM` | `690123456` | `+237690123456` |
| **RD Congo** | `CD` | `810123456`, `990123456` | `+243810123456` |
| **Maroc** | `MA` | `06 12 34 56 78`, `612345678` | `+212612345678` |
| **Algérie** | `DZ` | `05 12 34 56 78`, `512345678` | `+213512345678` |
| **Tunisie** | `TN` | `21 123 456`, `98123456` | `+21621123456` |
| **Egypte** | `EG` | `010 1234 5678`, `1112345678` | `+201012345678` |
| **Ghana** | `GH` | `024 123 4567`, `241234567` | `+233241234567` |
| **Nigeria** | `NG` | `0803 123 4567`, `7012345678` | `+2348031234567` |

### Indice de Pays Optionnel (`actor.region`)

Si un modèle de numéro de téléphone est ambigu (ex : chevauchement de modèles entre le Maroc et l'Algérie), vous pouvez fournir un **Indice de Pays** optionnel via le champ `actor.region`.

::callout{icon="i-lucide-lightbulb" color="primary"}
**Meilleure Pratique** : Fournissez toujours l'`actor.region` (ISO 3166-1 alpha-2) si elle est connue. Cela garantit une précision de normalisation de 100 %.
::

```json
{
  "actor": {
    "hashed_id": "0612345678",
    "region": "MA" // Garantit la normalisation comme numéro marocain (+212)
  }
}
```

## Exemples

### 1. Soumission Standard

```bash
curl -X POST "https://api.protegey.com/v1/signals" \
  -H "Content-Type: application/json" \
  -H "X-Centry-Key: cen_live_sk_..." \
  -d '{
    "actor": {
      "hashed_id": "e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855",
      "region": "US"
    },
    "event": {
      "type": "ACCOUNT_TAKEOVER",
      "timestamp": "2026-01-12T14:30:00Z",
      "channel": "MOBILE"
    },
    "source_confidence": 0.9,
    "metadata": {
      "detection_method": "behavioral_biometrics"
    }
  }'
```

### 2. Signal de Transaction

```bash
curl -X POST "https://api.protegey.com/v1/signals" \
  -H "Content-Type: application/json" \
  -H "X-Centry-Key: cen_live_..." \
  -d '{
    "actor": {
      "hashed_id": "user@example.com"
    },
    "event": {
      "type": "STOLEN_FINANCIALS",
      "timestamp": "2026-01-12T14:30:00Z"
    },
    "transaction": {
      "amount": 4500.00,
      "currency": "USD",
      "geo_location": {
        "lat": 37.7749,
        "lon": -122.4194
      }
    }
  }'
```

## Réponse

### Réponse de Succès (`201 Created`)

```json
{
  "success": true,
  "data": {
    "signal_id": "9df4a3b1-...",
    "status": "received",
    "event_type": "ACCOUNT_TAKEOVER",
    "timestamp": "2026-01-12T14:30:00+00:00"
  },
  "message": "Signal reçu et mis en attente pour traitement"
}
```

### Réponse d'Erreur (`422 Unprocessable Content`)

```json
{
    "message": "Le champ event.type est obligatoire.",
    "errors": {
        "event.type": [
            "Le champ event.type est obligatoire."
        ]
    }
}
```

L'API Risk & Compliance as a Service (RCaaS) fournit des outils de conformité LCB-FT intégrés directement dans le pipeline de signaux Protegey. Chaque signal est automatiquement évalué contre les listes de sanctions, les bases de données PPE, les profils de risque géographique et les règles de surveillance des transactions AML.

## Tableau de Bord de Conformité

```http
GET /api/v1/partner/compliance/dashboard
Authorization: Bearer {token}
```

```json
{
  "open_sars": 3,

  "screened_entities": 1240,
  "sanctions_matches": 2,
  "high_risk_jurisdictions_flagged": 8,
  "upcoming_calendar_events": 5
```

## Filtrage des Sanctions

### Obtenir le profil de sanctions d'une entité

```http
GET /api/v1/partner/compliance/sanctions/{entityId}
Authorization: Bearer {token}
```

```json
{
  "entity_id": 42,
  "entity_name": "Jean Dupont",
  "is_sanctioned": false,
  "is_pep": true,
  "pep_designation": {
    "type": "government_official",
    "country_code": "CI",
    "source": "osint_un",
    "effective_from": "2022-01-01"
  },
  "osint_matches": [],
  "last_screened_at": "2026-02-18T04:00:00Z",
  "risk_level": "high"
}
```

### Re-filtrer une entité

Déclenche un re-filtrage immédiat sur les données OSINT les plus récentes :

```http
POST /api/v1/partner/compliance/sanctions/{entityId}/rescreen
Authorization: Bearer {token}
```

## Rapports d'Activité Suspecte (RAS)

### Lister les RAS

```http
GET /api/v1/partner/compliance/sars
Authorization: Bearer {token}
```

Paramètres de requête : `status` (`draft`, `under_review`, `filed`, `archived`), `per_page`

```json
{
  "data": [
    {
      "id": "sar_abc123",
      "reference_number": "SAR-20260218-00042",
      "status": "under_review",
      "entity_id": 42,
      "narrative": "L'entité a présenté un comportement de fractionnement sur 3 comptes...",
      "transaction_total": 45000.0,
      "currency": "XOF",
      "created_at": "2026-02-15T10:00:00Z",
      "filed_at": null
    }
  ]
}
```

### Créer un RAS (Brouillon)

```http
POST /api/v1/partner/compliance/sars
Authorization: Bearer {token}
Content-Type: application/json
```

```json
{
  "entity_id": 42,
  "reason": "Fractionnement détecté : 12 transactions juste en dessous du seuil de déclaration",
  "case_id": "case_uuid_optionnel"
}
```

Un récit est généré automatiquement à partir des enregistrements `AmlTransactionFlag` de l'entité. Vous pouvez le modifier avant soumission.

### Mettre à jour le récit d'un RAS

```http
PUT /api/v1/partner/compliance/sars/{sarId}
Authorization: Bearer {token}
Content-Type: application/json
```

```json
{
  "narrative": "Récit d'investigation mis à jour..."
}
```

### Soumettre pour révision

```http
POST /api/v1/partner/compliance/sars/{sarId}/review
Authorization: Bearer {token}
```

### Déposer un RAS

Nécessite le rôle `analyst` ou supérieur.

```http
POST /api/v1/partner/compliance/sars/{sarId}/file
Authorization: Bearer {token}
```

Cycle de vie du RAS : `draft` → `under_review` → `filed` → `archived`

## Signalements de Transactions

Les signalements sont créés automatiquement par `TransactionMonitoringRulesService` pour chaque signal traité.

### Lister les signalements

```http
GET /api/v1/partner/compliance/transaction-flags
Authorization: Bearer {token}
```

Paramètres de requête : `rule_key`, `entity_id`, `from`, `to`, `per_page`

```json
{
  "data": [
    {
      "id": "flag_abc123",
      "signal_id": "sig_xyz789",
      "entity_id": 42,
      "rule_key": "structuring",
      "rule_description": "Transactions multiples juste en dessous du seuil de déclaration",
      "risk_contribution": 0.85,
      "flagged_at": "2026-02-18T10:00:00Z",
      "metadata": {
        "transaction_count": 8,
        "window_hours": 24,
        "threshold": 500000
      }
    }
  ]
}
```

**Clés de règle :** `structuring`, `velocity_breach`, `round_number`, `high_risk_jurisdiction`

## Cycle de vie du SAR

Les SAR suivent une machine à états stricte. Chaque transition dispose d'un endpoint dédié :

```
draft → under_review → filed
      ↘              ↘ closed
```

| Étape | Endpoint | Description |
|------|----------|-------------|
| 1. Créer | `POST /compliance/sars` | Calcule automatiquement les totaux de transactions à partir des récents indicateurs AML de l'entité |
| 2. Narratif | `POST /compliance/sars/{id}/narrative` | Génère un narratif à partir des 10 événements d'indicateurs AML les plus récents |
| 3. Révision | `POST /compliance/sars/{id}/review` | Fait passer de `draft` à `under_review` |
| 4. Dépôt | `POST /compliance/sars/{id}/file` | Fait passer de `under_review` à `filed`, génère la charge utile réglementaire + la piste d'audit |
| 5. Preuves | `GET /compliance/sars/{id}/evidence` | Exporte les indicateurs de risque + indicateurs AML (sans données personnelles) |

#### Générer un narratif

```http
POST /api/v1/partner/compliance/sars/{uuid}/narrative
```

Génère un narratif à partir des 10 indicateurs AML les plus récents de l'entité. Le narratif est modifiable — il s'agit d'un point de départ, non d'un brouillon définitif.

#### Exporter les preuves

```http
GET /api/v1/partner/compliance/sars/{uuid}/evidence
```

Retourne un paquet de preuves JSON contenant :
- Les indicateurs de risque (résultats des détecteurs, indicateurs AML, scores de risque)
- Les UUID des signaux contributifs
- Le hash de l'entité (HMAC-SHA256 — **pas** de données personnelles en clair)

::callout{type="warning"}
**Avis relatif aux données personnelles** : Le paquet de preuves utilise des identifiants d'entité hachés HMAC, et non des noms ou numéros de compte en clair. Vous devez substituer les hashes par les identités réelles issues de vos enregistrements KYC avant de les soumettre à votre Cellule de Renseignement Financier (FIU).
::

## Déclencheur auto-STR

Lorsque les indicateurs AML `structuring` et `velocity_breach` se déclenchent tous deux dans les **72 heures** sur la même entité, un SAR est automatiquement créé avec le statut `draft` :

1. Votre équipe reçoit un événement webhook `compliance.sar.auto_drafted`
2. Le SAR apparaît sous **Conformité → SARs → Révision requise**
3. Les totaux de transactions pré-calculés et un narratif préliminaire sont inclus
4. Un responsable de la conformité doit réviser, modifier si nécessaire et déposer explicitement

Les SAR rédigés automatiquement ne sont jamais déposés automatiquement. La fenêtre de 72 heures et la période de déduplication de 7 jours sont configurables via vos paramètres de conformité.

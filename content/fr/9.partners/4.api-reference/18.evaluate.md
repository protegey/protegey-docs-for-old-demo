L'API Evaluate fournit un scoring de risque en temps réel sur votre graphe d'entités. Par défaut, elle est en lecture seule — lorsque `resolve_entity` est false (par défaut), aucune entité n'est créée ou mise à jour. Définissez `resolve_entity: true` pour résoudre et créer des entités à la demande.

::callout{icon="i-lucide-zap" color="primary"}
**Cas d'usage en temps réel** : `/evaluate` est optimisé pour des temps de réponse inférieurs à 100ms. Utilisez-le pour la vérification lors de la création de comptes, la pré-autorisation de paiements et les flux d'embarquement.
::

## Point d'Accès

```http
POST /api/v1/evaluate
```

### Authentification

```http
X-Centry-Key: cen_live_sk_...
```

### Limites de Débit

- 300 requêtes par minute (Standard)
- 1 000 requêtes par minute (Enterprise)

---

## Schéma de Requête

```typescript
interface EvaluateRequest {
  // ── Ce que vous évaluez (choisissez-en un ou fournissez plusieurs pour un composite) ──
  email?: string;        // plaintext — hashed internally before scoring
  phone?: string;        // E.164 format (e.g. "+233244123456")
  device?: {
    fingerprint: string;      // device fingerprint string
    user_agent?: string;      // raw UA string
    ip_address?: string;      // submitting IP for geo enrichment
  };
  account?: {
    account_id: string;       // your internal account identifier
    account_type?: "individual" | "business" | "wallet";
  };
  composite?: {
    // Evaluate multiple identifiers together — higher confidence result
    email?: string;
    phone?: string;
    device_fingerprint?: string;
    account_id?: string;
  };

  // ── Options ──────────────────────────────────────────────────────────────
  options?: {
    resolve_entity?: boolean;      // default: false — link to existing entity if found
    detect_duplicates?: boolean;   // default: false — check for synthetic ID patterns
    include_explanations?: boolean; // default: true — include explanations[] in response
  };

  // ── Contexte d'évaluation (facultatif, améliore la précision) ─────────────────────
  context?: {
    event_type?: string;           // e.g. "ACCOUNT_CREATION", "PAYMENT"
    amount?: number;               // transaction amount if relevant
    currency?: string;             // ISO 4217
    ip_address?: string;           // end-user IP (if not in device block)
    region?: string;               // ISO 3166-1 alpha-2
  };
}
```

### Types d'Évaluation

| Type | Champ(s) Requis | Facturé Comme |
|---|---|---|
| `email` | `email` | `fraud_account_check` |
| `phone` | `phone` | `fraud_account_check` |
| `account` | `account.account_id` | `fraud_account_check` |
| `device` | `device.fingerprint` | `device_behavioral_signals` |
| `composite` | `composite.*` (au moins 2) | `fraud_account_check` |
| `identity_verification` | _(prévu)_ | _(Phase 11)_ |

::callout{icon="i-lucide-info" color="blue"}
**Vérification d'identité** : Le type `identity_verification` (document + biométrie) est prévu pour la Phase 11. Il suivra le même contrat requête/réponse avec des champs supplémentaires. Les intégrations existantes ne seront pas affectées.
::

## Exemples de Requêtes

### Évaluation par Email

```bash
curl -X POST "https://api.protegey.com/api/v1/evaluate" \
  -H "Content-Type: application/json" \
  -H "X-Centry-Key: cen_live_sk_..." \
  -d '{
    "email": "user@example.com",
    "options": {
      "include_explanations": true
    }
  }'
```

```json
          "domain": "example.com",

        }
      }
    ],

    "recommendation": {
      "action": "review",
      "priority": "high"
    }
  }

```

### Champs de Réponse

| Champ | Type | Description |
|---|---|---|
| `risk_score` | float | Score de risque entre 0,0 et 1,0 |
| `risk_level` | string | `low`, `medium`, `high`, ou `critical` |
| `confidence` | float | Confiance dans le score, entre 0,0 et 1,0 |
| `entity` | object\|null | Entité résolue (uniquement si `resolve_entity: true` et une correspondance est trouvée) |
| `entity.uuid` | string | UUID de l'entité — à utiliser avec `/risk/assess` pour l'intelligence complète |
| `duplicate` | object\|null | Résultat de détection de doublons (uniquement si `detect_duplicates: true`) |
| `signals_summary` | object | Contexte agrégé des signaux. `total` reflète le nombre de signaux liés à cette entité dans le graphe — il augmente à mesure que vous ingérez des signaux pour le même acteur |
| `explanations` | array | Liste ordonnée des raisons scorées (gravité la plus élevée en premier) |
| `recommendation` | object | Action suggérée et priorité |

---

## Référence des Niveaux de Risque

| `risk_level` | `risk_score` | Réponse Suggérée |
|---|---|---|
| `low` | 0,00 – 0,20 | Autoriser — aucun signal significatif |
| `medium` | 0,21 – 0,50 | Authentification renforcée ou refus doux |
| `high` | 0,51 – 0,80 | Révision manuelle ou flux de défi |
| `critical` | 0,81 – 1,00 | Bloquer et enquêter |

## Schéma d'Intelligence Progressive

Lorsque `resolve_entity: true` est défini et qu'une entité est résolue, utilisez l'`entity.uuid` retourné pour récupérer immédiatement l'évaluation complète :

```javascript
const evalResult = await fetch("/api/v1/evaluate", {
  method: "POST",
  body: JSON.stringify({
    phone: "+233244123456",
    options: { resolve_entity: true }
  })
});

const { data } = await evalResult.json();

if (data.entity?.uuid && data.risk_level !== "low") {
  // Escalader vers l'évaluation complète
  const assessResult = await fetch(`/api/v1/risk/assess`, {
    method: "POST",
    body: JSON.stringify({ entity_uuid: data.entity.uuid })
  });
}
```

| Type d'Entrée | Métrique | Tarif |
|---|---|---|
| `email`, `phone`, `account`, `composite` | `fraud_account_check` | Voir [Plans & Tarifs](/partners/billing/plans) |

## Réponses d'Erreur

### Erreur de Validation (`422`)

```json
{
  "message": "At least one evaluation input is required.",
  "errors": {
    "input": ["Provide one of: email, phone, device, account, or composite."]
  }
}
```

### Erreurs Courantes

| Erreur | Cause |
|---|---|
| `At least one evaluation input is required` | Aucun champ d'entrée fourni |
| `composite requires at least 2 identifiers` | Un seul champ défini dans le bloc `composite` |
| `phone must be in E.164 format` | Téléphone sans le préfixe `+` et l'indicatif du pays |
| `device.fingerprint is required when using device evaluation` | Empreinte manquante dans le bloc device |

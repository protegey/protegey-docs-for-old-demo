title: API de Gestion d'Équipe (Team)
description: Référence API pour la gestion des membres de l'équipe, l'invitation d'utilisateurs et le contrôle de l'accès à votre organisation partenaire.
---

L'API de Gestion d'Équipe permet aux partenaires de gérer par programmation les membres de l'équipe de leur organisation, d'inviter de nouveaux utilisateurs et de contrôler l'accès à la plateforme Protegey.

::callout{type="info"}
**Restriction de fonctionnalité** : La gestion d'équipe est disponible pour les forfaits Business et Enterprise. **Niveau d'accès** : Lecture/Écriture (nécessite des privilèges d'administrateur).
::

## Authentification

Tous les points de terminaison de gestion d'équipe nécessitent une authentification par jeton OAuth2 Bearer avec des privilèges d'administrateur :

```bash
Authorization: Bearer VOTRE_JETON_D_ACCES
```

::callout{type="warning"}
**Accès Administrateur Requis** : Vous devez être authentifié en tant qu'administrateur partenaire pour utiliser ces points de terminaison. Les membres réguliers de l'équipe ne peuvent pas accéder aux API de gestion d'équipe.
::

## Limites de Débit

- **Lister les membres de l'équipe** : 60 requêtes par minute
- **Inviter un membre de l'équipe** : 20 requêtes par heure
- **Supprimer un membre de l'équipe** : 20 requêtes par heure

## Lister les membres de l'équipe

**GET** `/api/v1/partner/team`

Récupère une liste de tous les membres de l'équipe de votre organisation partenaire, incluant leurs rôles, leur statut et leurs informations d'activité.

### Exemple de Requête

```bash
curl -X GET "https://api.protegey.com/api/v1/partner/team" \
  -H "Authorization: Bearer VOTRE_JETON_D_ACCES"
```

### Exemple de Réponse

**Succès (200 OK)** :

```json
[
  {
    "id": 42,
    "name": "Sarah Johnson",
    "first_name": "Sarah",
    "last_name": "Johnson",
    "email": "sarah@example.com",
    "role": "Partner Administrator",
    "is_active": true,
    "created_at": "2025-11-15T09:00:00Z",
    "last_login_at": "2026-02-03T14:30:00Z"
  },
  {
    "id": 43,
    "name": "John Doe",
    "first_name": "John",
    "last_name": "Doe",
    "email": "john@example.com",
    "role": "Fraud Analyst",
    "is_active": true,
    "created_at": "2025-12-01T10:15:00Z",
    "last_login_at": "2026-02-02T16:45:00Z"
  }
]
```

### Champs de Réponse :

| Champ           | Description                                                   |
| --------------- | ------------------------------------------------------------- |
| `id`            | Identifiant unique de l'utilisateur                           |
| `name`          | Nom complet (prénom + nom)                                    |
| `first_name`    | Prénom                                                        |
| `last_name`     | Nom de famille                                                |
| `email`         | Adresse e-mail                                                |
| `role`          | Nom d'affichage du rôle de l'utilisateur                      |
| `is_active`     | Indique si le compte utilisateur est actif                    |
| `created_at`    | Date d'ajout de l'utilisateur à l'organisation                |
| `last_login_at` | Horodatage de la dernière connexion (null si jamais connecté) |

**Codes de Statut** :

- `200 OK` - Succès
- `401 Unauthorized` - Jeton d'authentification invalide ou manquant
- `403 Forbidden` - L'utilisateur n'appartient pas à un partenaire ou permissions insuffisantes

## Inviter un membre de l'équipe

**POST** `/api/v1/partner/team`

Invite un nouveau membre de l'équipe dans votre organisation partenaire. Un compte sera créé et l'utilisateur recevra des instructions d'invitation.

### Corps de la Requête

| Champ        | Type   | Requis | Description                         |
| ------------ | ------ | ------ | ----------------------------------- |
| `first_name` | string | Oui    | Prénom (max 255 caractères)         |
| `last_name`  | string | Oui    | Nom de famille (max 255 caractères) |
| `email`      | string | Oui    | Adresse e-mail (doit être unique)   |

::callout{type="info"}
**Attribution automatique de rôle** : Les nouveaux membres de l'équipe se voient automatiquement attribuer le rôle "Partner Administrator". La gestion des rôles sera disponible dans une future mise à jour.
::

### Exemple de Requête

```bash
curl -X POST "https://api.protegey.com/api/v1/partner/team" \
  -H "Authorization: Bearer VOTRE_JETON_D_ACCES" \
  -H "Content-Type: application/json" \
  -d '{
    "first_name": "Emma",
    "last_name": "Williams",
    "email": "emma@example.com"
  }'
```

### Exemple de Réponse

**Succès (201 Created)** :

```json
{
  "message": "Membre de l'équipe invité avec succès.",
  "user": {
    "id": 45,
    "name": "Emma Williams",
    "email": "emma@example.com",
    "role": "Partner Administrator",
    "is_active": true,
    "created_at": "2026-02-03T15:45:00Z"
  }
}
```

**Codes de Statut** :

- `201 Created` - Membre de l'équipe invité avec succès
- `400 Bad Request` - Corps de requête invalide
- `401 Unauthorized` - Authentification invalide
- `422 Unprocessable Entity` - Erreurs de validation (ex : e-mail déjà existant)

## Supprimer un membre de l'équipe

**DELETE** `/api/v1/partner/team/{id}`

Supprime un membre de l'équipe de votre organisation partenaire. Cela supprime définitivement le compte utilisateur.

::callout{type="danger"}
**Suppression définitive** : Cette action est irréversible. L'utilisateur perdra l'accès à toutes les données, dossiers et enquêtes du partenaire.
::

### Paramètres de Chemin (Path Parameters)

| Paramètre | Type    | Description                     |
| --------- | ------- | ------------------------------- |
| `id`      | integer | ID de l'utilisateur à supprimer |

### Exemple de Requête

```bash
curl -X DELETE "https://api.protegey.com/api/v1/partner/team/45" \
  -H "Authorization: Bearer VOTRE_JETON_D_ACCES"
```

**Codes de Statut** :

- `200 OK` - Membre de l'équipe supprimé avec succès
- `400 Bad Request` - Impossible de vous supprimer vous-même
- `401 Unauthorized` - Authentification invalide
- `404 Not Found` - Utilisateur non trouvé dans votre organisation

## Rôles des Utilisateurs

Protegey prend en charge le contrôle d'accès basé sur les rôles (RBAC) :

| Rôle                      | Description                     | Permissions                                                                |
| ------------------------- | ------------------------------- | -------------------------------------------------------------------------- |
| **Partner Administrator** | Accès complet à l'organisation  | Toutes les permissions (gestion équipe, dossiers, paramètres, facturation) |
| **Fraud Analyst**         | Enquête et gestion des dossiers | Voir/gérer les dossiers, alertes, entités ; pas d'accès admin              |
| **Read-Only Analyst**     | Accès en lecture seule          | Voir dossiers, alertes, signaux ; ne peut pas modifier                     |

## Meilleures Pratiques

### Flux d'intégration de l'équipe

**Invitation de groupe** :

```javascript
const newMembers = [
  { first_name: "John", last_name: "Doe", email: "john@example.com" },
  { first_name: "Jane", last_name: "Smith", email: "jane@example.com" },
];

for (const member of newMembers) {
  try {
    const result = await client.team.invite(member);
    console.log(`✅ Invité : ${result.user.email}`);
  } catch (error) {
    console.error(`❌ Échec : ${member.email} - ${error.message}`);
  }
}
```

### Audit et nettoyage

**Identifier les utilisateurs inactifs** :

```javascript
// Récupérer tous les membres
const team = await client.team.list();

// Trouver les utilisateurs inactifs (pas de connexion depuis 90 jours)
const ninetyDaysAgo = new Date();
ninetyDaysAgo.setDate(ninetyDaysAgo.getDate() - 90);

const inactiveUsers = team.filter((user) => {
  const lastLogin = new Date(user.last_login_at);
  return lastLogin < ninetyDaysAgo;
});
```

## Gestion des Erreurs

### Codes d'Erreur Courants

| Code de Statut             | Erreur                     | Cause                                             |
| -------------------------- | -------------------------- | ------------------------------------------------- |
| `400 Bad Request`          | `Cannot remove yourself`   | Tentative d'auto-suppression                      |
| `403 Forbidden`            | `Insufficient permissions` | Utilisateur non admin tentant la gestion d'équipe |
| `404 Not Found`            | `User not found`           | L'ID utilisateur n'existe pas dans l'organisation |
| `422 Unprocessable Entity` | `Email already taken`      | Adresse e-mail déjà enregistrée                   |

## FAQ

**Q : Puis-je assigner des rôles spécifiques lors de l'invitation ?**
R : Pas encore via l'API. Tous les utilisateurs invités reçoivent actuellement le rôle "Partner Administrator". Vous pouvez modifier les rôles manuellement dans le Portail Partenaire.

**Q : Qu'advient-il des dossiers assignés à un utilisateur supprimé ?**
R : Les dossiers restent dans le système mais deviennent non assignés. Il est préférable de réassigner les dossiers avant de supprimer des membres.

**Q : Combien de membres d'équipe puis-je avoir ?**
R : Les limites dépendent de votre forfait : Professional (5), Business (20), Enterprise (illimité).

**Q : Les membres supprimés comptent-ils dans la limite de mon forfait ?**
R : Non, seuls les utilisateurs actifs comptent.

**Q : Comment les e-mails d'invitation sont-ils envoyés ?**
R : Protegey envoie automatiquement des e-mails d'invitation avec les instructions de configuration. Assurez-vous que votre domaine ne bloque pas `noreply@protegey.com`.

---
title: API d'Intelligence des Acteurs (Actors)
description: Référence API pour l'intelligence au niveau de l'acteur, incluant l'historique des transactions, les profils de risque et l'analyse de réseau.
---

L'API d'Intelligence des Acteurs fournit des informations granulaires sur les acteurs individuels (numéros de téléphone, adresses e-mail, empreintes d'appareils, etc.) impliqués dans les transactions. Elle complète l'API d'Intelligence des Entités en se concentrant sur l'analyse des acteurs au niveau de la transaction plutôt que sur le suivi au niveau de l'entité.

::callout{type="info"}
**Restriction de fonctionnalité** : L'intelligence des acteurs est disponible pour les forfaits Professional et supérieurs. **Niveau d'accès** : Lecture seule.
::

## Authentification

Tous les points de terminaison d'intelligence des acteurs nécessitent une authentification par jeton OAuth2 Bearer :

```bash
Authorization: Bearer VOTRE_JETON_D_ACCES
```

## Limites de Débit

- **Historique de l'acteur** : 120 requêtes par minute
- **Profil de l'acteur** : 120 requêtes par minute
- **Acteurs liés** : 60 requêtes par minute

---

## Obtenir l'historique de l'acteur

**GET** `/api/v1/actors/{actorHashedId}/history`

Récupère l'historique des transactions pour un acteur spécifique identifié par son identifiant haché (numéro de téléphone, e-mail, empreinte d'appareil, etc.).

### Paramètres de Chemin (Path Parameters)

| Paramètre       | Type   | Description                                         |
| --------------- | ------ | --------------------------------------------------- |
| `actorHashedId` | string | Identifiant d'acteur haché (ex : `hash_0244567890`) |

### Paramètres de Requête (Query Parameters)

| Paramètre | Type    | Requis | Par défaut | Description                                       |
| --------- | ------- | ------ | ---------- | ------------------------------------------------- |
| `limit`   | integer | Non    | 50         | Nombre maximum de transactions à renvoyer (1-200) |

### Exemple de Requête

```bash
curl -X GET "https://api.protegey.com/api/v1/actors/hash_0244567890/history?limit=100" \
  -H "Authorization: Bearer VOTRE_JETON_D_ACCES"
```

### Exemple de Réponse

- `404 Not Found` - Acteur non trouvé ou aucune transaction

::callout{type="success"}
**Cas d'utilisation** : L'historique des acteurs est idéal pour enquêter sur des modèles suspects à travers plusieurs transactions. Utilisez ce point de terminaison lors de l'approfondissement d'une alerte ou d'un dossier pour comprendre la chronologie complète des transactions d'un acteur spécifique.

## Obtenir les acteurs liés

**GET** `/api/v1/actors/{actorHashedId}/related`

Découvre les acteurs liés à l'acteur spécifié via des attributs partagés (appareils, adresses IP, comptes, etc.). Utile pour découvrir des réseaux de fraude et des attaques coordonnées.

### Paramètres de Chemin (Path Parameters)

| Paramètre       | Type   | Description                |
| --------------- | ------ | -------------------------- |
| `actorHashedId` | string | Identifiant d'acteur haché |

### Exemple de Requête

```bash
curl -X GET "https://api.protegey.com/api/v1/actors/hash_0244567890/related" \
```

- `401 Unauthorized` - Authentification invalide
- `403 Forbidden` - Contexte partenaire requis
- `404 Not Found` - Acteur non trouvé

::callout{type="success"}
**Analyse de Réseau** : Les acteurs liés sont identifiés grâce à l'analyse de graphes des attributs partagés. Une force de relation élevée (>0,8) indique des connexions solides valant la peine d'être investiguées pour fraude coordonnée.

## Types d'Acteurs

Protegey suit divers types d'acteurs basés sur les identifiants de transaction :

| Type d'Acteur        | Description                            | Exemple d'Identifiant         |
| -------------------- | -------------------------------------- | ----------------------------- |
| `phone_number`       | Numéros de mobile/téléphone            | `hash_0244567890`             |
| `email`              | Adresses e-mail                        | `hash_email_john@example.com` |
| `device_fingerprint` | Empreintes de navigateur/appareil      | `fp_a1b2c3d4e5f6`             |
| `account_id`         | Identifiants de compte utilisateur     | `hash_account_12345`          |
| `ip_address`         | Adresses IP                            | `ip_192.168.1.1`              |
| `payment_method`     | BIN de carte, ID de portefeuille, etc. | `hash_payment_4532`           |

::callout{type="info"}
**Protection de la vie privée** : Tous les identifiants d'acteurs sont hachés ou masqués pour protéger la vie privée des clients tout en permettant la détection de modèles de fraude.
::

## Meilleures Pratiques

### Flux d'enquête

**Enquête complète sur l'acteur** :

```javascript
const actorId = "hash_0244567890";

// 1. Obtenir l'aperçu du profil de risque
const profile = await client.actors.getProfile(actorId);
console.log(`Score de risque : ${profile.data.risk_score}`);
console.log(
  `Total des transactions : ${profile.data.statistics.total_transactions}`,
);

// 2. Examiner l'historique des transactions
const history = await client.actors.getHistory(actorId, { limit: 100 });
const highRiskTransactions = history.data.filter(
  (tx) => tx.risk_level === "high",
);
console.log(`Transactions à haut risque : ${highRiskTransactions.length}`);

// 3. Découvrir le réseau de fraude
const related = await client.actors.getRelated(actorId);
const strongConnections = related.data.filter(
  (r) => r.relationship_strength > 0.8,
);
console.log(`Connexions réseau fortes : ${strongConnections.length}`);

// 4. Créer un dossier si justifié
if (profile.data.risk_score > 80 && strongConnections.length > 2) {
  await client.cases.create({
    title: `Enquête sur réseau de fraude : ${actorId}`,
    priority: "critical",
    description: `Réseau de fraude coordonné détecté avec ${strongConnections.length} acteurs liés`,
  });
}
```

### Reconnaissance de modèles

**Identifier l'abus de vélocité** :

```javascript
// Obtenir le profil de l'acteur
const profile = await client.actors.getProfile(actorId);

// Vérifier les indicateurs de vélocité
if (profile.data.statistics.velocity_last_24h > 10) {
  console.log("Avertissement : Vélocité de transaction anormale détectée");

  // Obtenir les transactions récentes
  const history = await client.actors.getHistory(actorId, { limit: 20 });

  // Analyser les intervalles de temps
  const timeGaps = calculateTimeGaps(history.data);
  const avgGap = timeGaps.reduce((a, b) => a + b) / timeGaps.length;

  if (avgGap < 600) {
    // Moins de 10 minutes en moyenne
    console.log("Critique : Modèle d'attaque automatisée détecté");
  }
}
```

## Types de Relation

| Type                      | Description                | Courant en cas de fraude                              |
| ------------------------- | -------------------------- | ----------------------------------------------------- |
| **shared_device**         | Même empreinte d'appareil  | ✅ Très courant - prise de contrôle de compte         |
| **shared_ip_address**     | Même adresse IP            | ✅ Courant - infrastructure partagée, réseaux de bots |
| **shared_account**        | Même identifiant de compte | ✅ Très courant - compromission de compte             |
| **shared_payment_method** | Même mode de paiement      | ⚠️ Moins courant - cartes volées, mules               |
| **shared_email**          | Même adresse e-mail        | ⚠️ Moins courant - clusters de fausses identités      |

::callout{type="warning"}
**Risque de Faux Positif** : Les adresses IP et les appareils partagés peuvent être légitimes (familles, cybercafés, VPN). Considérez toujours la force de la relation avant de signaler.
::

### Codes d'Erreur Courants

| Code de Statut             | Erreur                     | Cause                                           |
| -------------------------- | -------------------------- | ----------------------------------------------- |
| `401 Unauthorized`         | `Invalid token`            | Jeton expiré ou malformé                        |

| `404 Not Found`            | `Actor not found`          | Aucune transaction trouvée pour cet ID d'acteur |
| `422 Unprocessable Entity` | `Invalid limit`            | Limite hors plage (1-200)                       |

## FAQ

**Q : Quelle est la différence entre les acteurs et les entités ?**
R : Les acteurs sont des identifiants au niveau de la transaction (numéros de téléphone, e-mails, empreintes d'appareils). Les entités sont des profils persistants qui agrègent plusieurs identifiants d'acteurs en profils unifiés.

**Q : Comment les acteurs sont-ils hachés ?**
R : Les acteurs sont hachés en utilisant SHA-256 avec des sels spécifiques au partenaire. Les identifiants d'affichage sont masqués (ex : `0244******`).

**Q : Puis-je voir les identifiants d'acteurs originaux (non hachés) ?**
R : Uniquement dans le Portail Partenaire avec les permissions appropriées. Les réponses API utilisent des identifiants hachés/masqués.

**Q : Comment la force de la relation est-elle calculée ?**
R : Elle est calculée via des algorithmes d'analyse de graphes prenant en compte la fréquence des attributs partagés, la proximité temporelle et les modèles de transaction.

**Q : Puis-je bloquer des acteurs par programmation ?**
R : Pas directement. Vous pouvez mettre à jour le statut de l'entité associée via l'[API d'Intelligence des Entités](./entities), ce qui affecte tous les acteurs liés.

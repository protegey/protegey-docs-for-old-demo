L'API d'Évaluation des Risques vous permet de récupérer une décision de risque en temps réel pour une entité. Ce point de terminaison est conçu pour être appelé de manière synchrone pendant vos flux utilisateurs (ex : inscription, paiement).

## Point de terminaison (Endpoint)

```http
POST /api/v1/risk/assess
```

## Schéma de Requête

### En-têtes (Headers)

| En-tête        | Valeur             | Requis | Description                      |
| -------------- | ------------------ | ------ | -------------------------------- |
| `Content-Type` | `application/json` | Oui    | Payload JSON standard.           |
| `X-Centry-Key` | `cen_live_sk_...`  | Oui    | Votre clé secrète de production. |

### Paramètres du Corps (Body Parameters)

```typescript
interface RiskAssessmentRequest {
  entity_type: "email" | "phone" | "ip" | "device_id" | "crypto_address";
  identifier: string; // La valeur à évaluer (ex : adresse e-mail)
}
```

### Exemple de Requête

```bash
curl -X POST "https://api.protegey.com/v1/risk/assess" \
  -H "Content-Type: application/json" \
  -H "X-Centry-Key: cen_live_sk_..." \
  -d '{
    "entity_type": "email",
    "identifier": "fraudster@example.com"
  }'
```

## Schéma de Réponse

```typescript
interface RiskAssessmentResponse {
  decision: "ALLOW" | "REVIEW" | "BLOCK";
  risk_score: number; // 0-100
  reasons: string[]; // Liste des facteurs contributifs
}
```

### Logique de Décision

| Décision | Score de Risque | Signification          | Action Suggérée                                                  |
| -------- | --------------- | ---------------------- | ---------------------------------------------------------------- |
| `ALLOW`  | < 50            | Risque faible.         | Procéder à la transaction.                                       |
| `REVIEW` | 50 - 79         | Risque moyen.          | Déclencher une authentification forte (2FA) ou un examen manuel. |
| `BLOCK`  | >= 80           | Risque élevé/critique. | Refuser la transaction/l'inscription.                            |

### Exemple de Réponse

```json
{
  "decision": "BLOCK",
  "risk_score": 85,
  "reasons": ["VELOCITY_HIGH", "NETWORK_BLOCKLIST_MATCH"]
}
```

### Réponses d'Erreur

**400 Bad Request**

```json
{
  "message": "Le type d'entité doit être l'un des suivants : email, phone, ip, device_id, crypto_address."
}
```

**401 Unauthorized**

```json
{
  "message": "Authentification partenaire requise"
}
```

## Méthodologie de Scoring des Risques

### Facteurs de Scoring

L'évaluation des risques de Protegey prend en compte plusieurs indicateurs de fraude :

| Facteur                     | Poids  | Description                                                         |
| --------------------------- | ------ | ------------------------------------------------------------------- |
| **Vélocité**                | Élevé  | Fréquence des transactions dans des fenêtres de temps (1h, 24h, 7j) |
| **Analyse de Réseau**       | Élevé  | Liens avec des fraudeurs connus ou des entités suspectes            |
| **Détection d'Anomalies**   | Moyen  | Écart par rapport aux modèles de comportement historiques           |
| **Signaux Géographiques**   | Moyen  | Voyages impossibles, modèles transfrontaliers                       |
| **Signaux d'Appareil**      | Moyen  | Nouveaux appareils, discordances d'empreintes                       |
| **Comportement Historique** | Faible | Implication passée dans des fraudes, âge du compte                  |

### Plages de Score de Risque

| Score      | Niveau   | Recommandation d'Action                   |
| ---------- | -------- | ----------------------------------------- |
| **0-39**   | Faible   | Approuver automatiquement                 |
| **40-59**  | Moyen    | Authentification forte (2FA, SMS OTP)     |
| **60-79**  | Élevé    | Examen manuel requis                      |
| **80-100** | Critique | Bloquer la transaction, signaler l'entité |

### Codes de Raison (Reason Codes)

Le tableau `reasons` contient les indicateurs de fraude spécifiques détectés :

| Code de Raison             | Description                                                      |
| -------------------------- | ---------------------------------------------------------------- |
| `VELOCITY_HIGH`            | Fréquence excessive de transactions détectée                     |
| `AMOUNT_ANOMALY`           | Le montant de la transaction dépasse les modèles normaux         |
| `IMPOSSIBLE_TRAVEL`        | Incohérence géographique détectée                                |
| `DEVICE_NEW`               | Première transaction depuis cet appareil                         |
| `DEVICE_MISMATCH`          | L'empreinte de l'appareil ne correspond pas au modèle historique |
| `CROSS_BORDER`             | Transaction internationale depuis un pays à haut risque          |
| `NETWORK_BLOCKLIST_MATCH`  | Entité liée à un fraudeur connu                                  |
| `NETWORK_FRAUD_RING`       | Fait partie d'un réseau de fraude suspecté                       |
| `MULTIPLE_FAILED_ATTEMPTS` | Échecs récents d'authentification                                |
| `STOLEN_CREDENTIALS`       | Les identifiants correspondent à une base de données de fuites   |

## Authentification

### Types de Clés API

L'évaluation des risques utilise l'authentification par clé API :

| Préfixe de Clé | Environnement | Cas d'Utilisation                       |
| -------------- | ------------- | --------------------------------------- |
| `cen_live_sk_` | Production    | Évaluations de production en temps réel |
| `cen_test_sk_` | Sandbox       | Tests et développement                  |

---

## Limites de Débit

- **Production** : 1000 requêtes par minute par partenaire
- **Sandbox** : 100 requêtes par minute par partenaire

## Meilleures Pratiques

### Modèles d'Intégration

**Évaluation Synchrone (Recommandé)** :

```javascript
// Pendant le flux de paiement/inscription
async function processTransaction(user, transaction) {
  // 1. Évaluer le risque en temps réel
  const assessment = await protegey.riskAssess({
    entity_type: "email",
    identifier: user.email,
  });

  // 2. Prendre une décision basée sur le risque
  if (assessment.decision === "BLOCK") {
    return {
      success: false,
      reason: "Transaction refusée pour des raisons de sécurité",
    };
  }

  if (assessment.decision === "REVIEW") {
    // Déclencher une authentification forte
    await sendTwoFactorCode(user.phone);
    return { success: false, reason: "Vérification supplémentaire requise" };
  }

  // 3. Procéder à la transaction
  return processPayment(transaction);
}
```

Les webhooks permettent à Protegey d'envoyer de l'intelligence à vos systèmes en temps réel. Ceci est utile pour les flux de travail asynchrones ou la surveillance des changements de statut des entités.

## Taxonomie des Événements

Nous prenons en charge plusieurs types d'événements auxquels vous pouvez vous abonner dans le Portail Partenaire.

### Événements de Base

| Type d'Événement | Description | Clé du Payload |
|------------------|-------------|----------------|
| `signal.created` | Un nouveau signal a été ajouté pour une entité que vous surveillez. | `signal` |
| `risk_score.changed` | Le score d'une entité surveillée a franchi un seuil (ex : passage à HIGH). | `risk_change` |
| `trust_score.updated` | Votre propre Score de Confiance Partenaire a changé. | `trust_score` |
| `list.match` | Une entité correspond à une Watchlist ou Blocklist spécifique. | `match` |

### Gestion des Dossiers

| Type d'Événement | Description | Clé du Payload |
|------------------|-------------|----------------|
| `case.created` | Nouveau dossier de fraude créé | `case` |
| `case.updated` | Statut, priorité ou attribution modifiés | `case` |
| `case.note_added` | Note ajoutée au dossier | `case`, `note` |
| `case.resolved` | Dossier marqué comme résolu | `case` |

### Gestion des Alertes

| Type d'Événement | Description | Clé du Payload |
|------------------|-------------|----------------|
| `alert.triggered` | Nouvelle alerte générée | `alert` |
| `alert.acknowledged` | Alerte acquittée par l'utilisateur | `alert` |
| `alert.resolved` | Alerte marquée comme résolue | `alert` |

## Schéma du Payload

Tous les webhooks partagent une enveloppe standardisée.

```typescript
interface WebhookPayload {
  id: string; // ID d'événement unique (evt_...)
  type: EventType;
  created_at: string; // ISO 8601
  data: Record<string, any>; // Données spécifiques à l'événement
}
```

### Exemple : Changement de Score de Risque

```json
{
  "id": "evt_abc123",
  "type": "risk_score.changed",
  "created_at": "2026-01-12T15:00:00Z",
  "data": {
    "entity_type": "email",
    "entity_value": "user@example.com",
    "old_score": 40,
    "new_score": 85,
    "trigger": "new_signal_received"
  }
}
```

## Sécurité : Vérification de la Signature

Protegey signe chaque requête webhook pour vérifier son authenticité.

### En-têtes de Vérification

| En-tête | Description |
|---------|-------------|
| `X-Centry-Signature` | La signature HMAC-SHA256 du corps de la requête. |
| `X-Centry-Event` | Le type d'événement (ex : `case.created`). |
| `X-Centry-Delivery-ID` | UUID unique pour la tentative de livraison. |
| `X-Centry-Timestamp` | Horodatage Unix du moment de l'envoi. |

---

## Politique de Relance (Retry Policy)

Protegey utilise une stratégie de backoff exponentiel pour les échecs de livraison.

| Tentative | Délai |
|-----------|-------|
| 1 | Immédiat |
| 2 | 1 minute |
| 3 | 5 minutes |
| 4 | 30 minutes |
| 5 | 1 heure |
| 6 | 6 heures |

**Note** : Si le point de terminaison échoue systématiquement pendant 24 heures, l'abonnement webhook sera automatiquement désactivé.

## Meilleures Pratiques

### Traitement Asynchrone

Répondez rapidement avec un `200 OK` et traitez le webhook de manière asynchrone pour éviter les timeouts.

```javascript
app.post('/webhooks/protegey', async (req, res) => {
  // 1. Vérifier la signature
  if (!verifyWebhook(req.rawBody, req.headers['x-centry-signature'])) {
    return res.status(401).send('Signature invalide');
  }

  // 2. Acquitter immédiatement
  res.status(200).send('OK');

  // 3. Traiter de manière asynchrone
  processWebhookAsync(req.body);
});
```

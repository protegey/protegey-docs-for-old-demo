## v1.8.0 (Actuelle)

_Publiée le : 2026-02-18_

### Moteur AML / Conformité (RCaaS) — Enterprise

Le pilier Risk & Compliance as a Service est désormais disponible pour les partenaires Enterprise disposant du flag `risk_and_compliance` activé.

- **Nouveau** : Filtrage des sanctions — les entités sont contrôlées contre les données du pipeline OSINT (listes de sanctions ONU, UE, UA) à chaque ingestion de signal
- **Nouveau** : Détection des PPE — signalement des Personnes Politiquement Exposées via correspondance de noms floue (≥85% de similarité) contre la base `pep_designations`
- **Nouveau** : Règles de surveillance des transactions — 4 règles AML évaluées par signal : fractionnement (montants juste en dessous des seuils de déclaration), dépassement de vélocité, transactions à montants ronds, juridiction à haut risque (liste grise/noire GAFI)
- **Nouveau** : Scoring de risque géographique — consultations du statut GAFI par pays (liste noire / liste grise / conforme) avec 30 profils de pays pré-configurés
- **Nouveau** : Workflow RAT — cycle de vie des Rapports d'Activités Typiques : brouillon → en révision → déposé → archivé, avec génération automatique de récit
- **Nouveau** : API de conformité — 14 nouveaux endpoints sous `GET/POST /api/v1/partner/compliance/*` (tableau de bord, filtrage des sanctions, RAT, calendrier de conformité, signalements de transactions, risque géo)
- **Nouveau** : Portail de conformité — 6 nouvelles pages dans le portail partenaire : Tableau de bord Conformité, Filtrage Sanctions, liste + détail RAT, Calendrier, Signalements de Transactions

## v1.7.0

_Publiée le : 2026-02-18_

### Gestion Multi-Endpoints de Webhooks

Le système de webhooks a été entièrement repensé. Les partenaires peuvent désormais enregistrer plusieurs endpoints webhook, chacun avec son propre secret, ses abonnements aux événements et son journal de livraison.

- **Nouveau** : `GET/POST /api/v1/partner/webhooks` — lister et créer des endpoints webhook
- **Nouveau** : `GET/PUT/DELETE /api/v1/partner/webhooks/{id}` — gérer les endpoints individuels
- **Nouveau** : `GET /api/v1/partner/webhooks/{id}/deliveries` — journal de livraison par endpoint
- **Nouveau** : `POST /api/v1/partner/webhooks/{id}/deliveries/{deliveryId}/retry` — relancer une livraison échouée
- **Nouveau** : `POST /api/v1/partner/webhooks/{id}/test` — envoyer un ping de test pour vérifier la configuration
- **Nouveau** : Secrets HMAC-SHA256 par endpoint — chaque endpoint dispose de son propre secret, affiché une seule fois à la création
- **Nouveau** : Abonnements aux événements par endpoint — choisir quels types d'événements chaque endpoint reçoit
- **En-têtes** : L'en-tête de signature est `X-Centry-Signature` ; les en-têtes de livraison sont `X-Centry-Event`, `X-Centry-Delivery-ID`, `X-Centry-Timestamp`
- **Changement** : Les endpoints sont automatiquement désactivés après **3 échecs de livraison consécutifs**
- **Nouveaux événements** : `alert.created`, `alert.status_changed`, `case.status_changed`, `case.priority_changed`, `case.assigned`, `entity.risk_changed`, `signal.ingested`

## v1.6.0

_Publiée le : 2026-02-17_

### Couche d'Orchestration des Décisions

- **Nouveau** : Moteur de politiques — définissez des politiques de fraude en YAML (global, réglementaire, partenaire) évaluées contre le `DecisionContext` complet en <5ms
- **Nouveau** : Calibration des seuils par partenaire — les seuils `critical`, `high`, `medium`, `low` sont désormais configurables par partenaire (remplace les valeurs codées en dur 0.8/0.6/0.4)
- **Nouveau** : Explicabilité des décisions — chaque alerte comporte désormais une explication à 3 niveaux : résumé lisible par le partenaire, détail de qualité réglementaire, et trace de débogage interne
- **Nouveau** : Routage des actions inter-partenaires — les décisions de politique (BLOCK, ESCALATE, SHARE) sont acheminées vers les partenaires destinataires via un filtrage de confiance et de consentement
- **Amélioration** : La lignée d'alerte (`GET /api/v1/partner/alerts/{id}/lineage`) inclut désormais la ventilation complète des scores de risque pondérés et les détails de correspondance de politique

## v1.5.0

_Publiée le : 2026-02-16_

### Moteur de Graphe d'Intelligence + Fusion de Risque Pondérée

- **Nouveau** : Hot Graph — chaque signal ingéré construit et maintient un graphe d'entités typées : nœuds ACTOR, ACCOUNT, DEVICE, MSISDN avec arêtes USES_DEVICE, USES_PHONE, SENT_TO, RECEIVED_FROM
- **Nouveau** : Fusion de Risque Pondérée — le score de risque final combine désormais 4 dimensions : Comportemental (35%), Réseau/Graphe (40%), Contextuel (15%), Historique (10%)
- **Nouveau** : Propagation du risque réseau — si les voisins à 1–2 sauts dans le graphe ont des scores de risque élevés, le score fusionné est amplifié (jusqu'à ×1,15)
- **Amélioration** : Le score de risque d'entité visible dans `GET /api/v1/partner/entities/{id}` reflète désormais un scoring fusionné multidimensionnel, pas seulement les signaux comportementaux
- **Amélioration** : La classification de sévérité des alertes utilise désormais le score fusionné complet, réduisant les faux négatifs pour la fraude en réseau (fraudes en anneau, comptes mules)

## v1.4.0

_Publiée le : 2026-02-14_

### Intelligence Collaborative + OSINT

- **Nouveau** : Partage d'alertes inter-institutions — les partenaires peuvent opter pour le partage d'alertes avec d'autres institutions via des accords bilatéraux. Trois niveaux de masquage : complet, partiel ou métadonnées uniquement
- **Nouveau** : `GET/PUT /api/v1/partner/intelligence-sharing/config` — configurer les préférences de partage
- **Nouveau** : `GET/POST /api/v1/partner/intelligence-sharing/agreements` — gérer les accords de partage bilatéraux
- **Nouveau** : `GET /api/v1/partner/intelligence-sharing/received` — flux de renseignements reçus (paginé)
- **Nouveau** : Boîte de réception des avis réglementaires — les régulateurs peuvent diffuser des avis à tous les partenaires connectés d'une juridiction
- **Nouveau** : `GET /api/v1/partner/advisories` — boîte de réception avec compteur de non lus
- **Nouveau** : `GET /api/v1/partner/advisories/{uuid}` — détail d'un avis (marqué comme lu à la consultation)
- **Nouveau** : Ingestion OSINT — les listes de sanctions ONU, UE et UA sont ingérées quotidiennement à 03h00 UTC et comparées aux profils d'entités via résolution d'entité floue
- **Nouveau** : Enforcement SemVer — les versions de détecteurs et les entrées de taxonomie appliquent désormais le versionnage sémantique à l'enregistrement

## v1.3.0

_Publiée le : 2026-02-11_

- **Nouvelle fonctionnalité** : Endpoint de lignée d'alerte — `GET /api/v1/partner/alerts/{uuid}/lineage` retourne la chaîne d'audit complète (détecteurs, features, ventilation du scoring) pour chaque alerte. Alimente l'UI "Expliquer cette alerte" du Portail Partenaire.
- **Nouvelle fonctionnalité** : Registre de taxonomie — les catégories de fraude sont désormais gérées en base de données et liées aux détecteurs. Les scores de sévérité reflètent une taxonomie de fraude compositionnelle plutôt que des mappings codés en dur.
- **Nouvelle fonctionnalité** : Classification de fraude multi-étiquettes — un signal peut désormais recevoir plusieurs labels de taxonomie (ex : `identity.account_takeover` + `device.anomaly`).
- **Amélioration** : Les enregistrements d'exécution des détecteurs (table `detector_executions`) permettent une analyse du taux de faux positifs par détecteur.
- **Correctif** : Le filtrage par date dans les analytics retourne désormais les bons résultats lorsque les paramètres `from`/`to` sont des chaînes date uniquement (ex : `2026-02-11`).
- **Correctif** : La réinitialisation du sandbox ne retourne plus une erreur 500 lorsque des signaux ont des enregistrements dépendants dans des tables liées.

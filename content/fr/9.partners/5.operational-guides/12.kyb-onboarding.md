Le système KYB vous permet de vérifier les clients professionnels avant leur intégration. Vous concevez le formulaire d'admission, envoyez un lien d'invitation signé, examinez les documents soumis et prenez une décision d'approbation — avec filtrage AML automatique en arrière-plan.

::callout{icon="i-lucide-building-2" color="blue"}
**Pour qui** : Responsables conformité et équipes d'intégration qui ont besoin d'un processus d'admission structuré et traçable pour les clients professionnels.
::

---

## Comment ça fonctionne

```
Le partenaire crée le questionnaire
        ↓
Le partenaire envoie l'invitation → Le candidat reçoit un lien e-mail
        ↓
Le candidat complète le formulaire + téléverse les documents → Soumet
        ↓
En arrière-plan : Filtrage des risques AML (sanctions + PPE)
        ↓
Le partenaire examine les réponses, les documents et le résultat du filtrage
        ↓
Décision : Approuvé / Rejeté / Informations supplémentaires requises
        ↓
Si approuvé : Entité créée dans le graphe Protegey
              Dossier EDD créé automatiquement si haut risque
```

## Étape 1 — Concevoir votre questionnaire

Rendez-vous dans **KYB → Questionnaires → Nouveau questionnaire** dans le portail partenaire, ou utilisez l'[API Questionnaires](../api-reference/kyb#gestion-des-questionnaires).

### Sections et types de questions

Organisez les questions en sections nommées (ex. « Identité de l'Entreprise », « Actionnariat », « Conformité »). Chaque question possède un type :

| Type | Utilisation |
|---|---|
| `text` | Réponses courtes (noms, numéros d'immatriculation) |
| `textarea` | Réponses longues (descriptions, explications) |
| `boolean` | Questions Oui/Non |
| `select` | Choix unique parmi une liste |
| `multi_select` | Choix multiples |
| `number` | Valeurs numériques |
| `date` | Dates |

### Questions conditionnelles

Les questions peuvent être masquées jusqu'à ce qu'une réponse précédente les rende pertinentes. Ex. : « Nom du bénéficiaire effectif (>25 %) » n'apparaît que si la question booléenne précédente est répondue « Oui ».

### Identifiant de filtrage

Marquez **une** question avec `is_screening_identifier: true`. La réponse à cette question (généralement le nom commercial enregistré) est celle qui sera filtrée contre les sanctions et PPE lors de l'approbation. Sans ce marquage, le filtrage AML est ignoré.

### Pièces justificatives requises

Configurez les types de documents que les candidats doivent téléverser. Définissez `is_required: true` pour les documents obligatoires.

### Versionnage et verrouillage

::callout{type="warning"}
**Un questionnaire se verrouille automatiquement dès l'envoi de la première invitation.** Les questionnaires verrouillés ne peuvent plus être modifiés. Pour effectuer des changements, utilisez **Cloner** — cela crée une nouvelle version modifiable.
::

## Étape 2 — Envoyer une invitation

Rendez-vous dans **KYB → Invitations → Envoyer une invitation**, ou `POST /api/v1/partner/kyb/invites`.

Indiquez l'adresse e-mail du candidat, son nom et le questionnaire à utiliser. Chaque lien :
- Est **à usage unique** — ne peut pas être réutilisé après soumission
- **Expire dans 30 jours** — les invitations expirées affichent `status: expired` et ne peuvent être reprises
- Ouvre le questionnaire directement sans que le candidat n'ait besoin d'un compte Protegey

Si une invitation expire avant la soumission, envoyez-en une nouvelle. Le nouveau lien génère un jeton distinct.

---

## Étape 3 — L'expérience candidat

Le portail candidat (`/apply/{token}`) est un formulaire multi-étapes autonome. Les candidats n'ont pas besoin d'un compte Protegey.

**Ce que le candidat voit :**

1. **Navigation par sections** — barre latérale gauche avec indicateur de progression
2. **Questions conditionnelles** — les questions masquées n'apparaissent qu'une fois la réponse de contrôle fournie
3. **Téléversement de documents** — zone de glisser-déposer par type de document
4. **Reprise de session** — les réponses sont sauvegardées de manière incrémentale ; le candidat peut fermer le navigateur et reprendre plus tard avec le même lien
5. **Soumission** — le portail valide les questions et documents obligatoires avant d'autoriser la soumission

---

## Étape 4 — Examiner une candidature

Les candidatures apparaissent dans **KYB → Candidatures** une fois soumises. Filtrez par statut pour vous concentrer sur les examens en attente.

**La vue détaillée affiche :**
- Toutes les réponses (question par question, dans l'ordre des sections)
- Documents téléversés (avec liens de téléchargement)
- Résultat du filtrage AML (score de risque, indicateur PPE)
- Historique complet des événements
- Notes de l'examinateur des tours précédents

### Prendre une décision

| Décision | Résultat |
|---|---|
| `approved` | Candidature clôturée. Entité créée dans le graphe Protegey. Dossier EDD créé automatiquement si haut risque. |
| `rejected` | Candidature clôturée définitivement. Candidat notifié par e-mail. |
| `more_info_required` | Candidature réouverte. Candidat reçoit un e-mail avec vos notes et un lien pour resoumettre. |

`approved` et `rejected` sont **terminaux** — la décision ne peut pas être modifiée par la suite.

## Étape 5 — Filtrage des risques et EDD

### Filtrage automatique

Lors de la soumission, le nom de l'entreprise (de la question `is_screening_identifier`) est automatiquement filtré contre :
- **Listes de sanctions** — listes consolidées ONU, UE et UA
- **Bases PPE** — registre des Personnes Politiquement Exposées

### Déclenchement automatique de la Diligence Renforcée (EDD)

Lorsque vous **approuvez** une candidature, un filtrage final est exécuté. Si l'une de ces conditions est remplie, un dossier de fraude haute priorité est automatiquement créé :

- `risk_score > 0.75`
- `is_pep = true`
- `sanctions.is_matched = true`

::callout{icon="i-lucide-shield" color="amber"}
**L'EDD ne bloque pas l'approbation.** Le statut de la candidature passe à `approved` quelle que soit l'EDD déclenchée. Le dossier est un workflow de conformité parallèle pour votre équipe.
::

### Création de l'entité

À l'approbation, l'entreprise est matérialisée en tant que `FraudEntity` dans le graphe Protegey. Les signaux futurs impliquant la même entité seront liés à cette entité automatiquement, offrant un profil de risque continu dès l'intégration.

---

## Flux de resoumission

Lorsque vous demandez des informations supplémentaires :

1. Statut de la candidature → `more_info_required`
2. Le candidat reçoit un e-mail avec un lien de reprise
3. Le candidat voit vos notes d'examinateur sur la page statut du portail
4. Le candidat met à jour ses réponses et/ou documents et resoumet
5. Statut de la candidature → retour à `submitted`
6. Les notes d'examinateur précédentes sont effacées

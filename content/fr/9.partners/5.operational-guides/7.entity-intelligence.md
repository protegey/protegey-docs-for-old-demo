## Vue d'ensemble

### Qu'est-ce qu'une entité ?

Une **entité** représente un acteur de fraude unique identifié par des identifiants hachés :
- Hash du numéro de téléphone
- Hash de l'e-mail
- Empreinte d'appareil
- Adresse IP
- Adresse de portefeuille crypto

### Entité vs Acteur vs Signal

| Concept | Description | Cardinalité |
|---------|-------------|-------------|
| **Signal** | Événement de fraude unique | Une transaction |
| **Acteur** | Participant à la transaction | Un par signal |
| **Entité** | Identité de fraude unique | Plusieurs signaux, une entité |

**Relation** :
```
Entity (hash_0244567890)
  ├── Signal 1 (TXN-001, Risk: 87)
  ├── Signal 2 (TXN-002, Risk: 92)
  └── Signal 3 (TXN-003, Risk: 45)
```

## Profils d'entités

### Composants du profil

**Informations d'identité** :
- UUID de l'entité (identifiant unique)
- Type d'entité (phone, email, device, IP, crypto_address)
- Identifiant haché (préservation de la vie privée)
- Nom affiché (masqué pour la confidentialité : `0244******`)

**Évaluation du risque** :
- Score de risque actuel (0-100)
- Niveau de risque (faible, moyen, élevé, critique)
- Historique du risque (évolution du score dans le temps)
- Score de confiance (précision de la prédiction)

**Données comportementales** :
- Nombre total de transactions
- Date de première détection
- Date de dernière détection
- Schémas de transaction
- Métriques de vélocité

**Suivi du statut** :
- Statut actuel (new, monitoring, flagged, confirmed, cleared)
- Historique des statuts
- Raisons des changements de statut

**Intelligence réseau** :
- Entités liées (acteurs connectés)
- Score de risque réseau
- Attributs partagés (appareil, IP, etc.)

## Cycle de vie du statut d'une entité

### Flux de statuts

```
new → monitoring → flagged → confirmed
                      ↓           ↓
                false_positive  cleared
```

| Statut | Description | Quand l'utiliser |
|--------|-------------|-----------------|
| **new** | Entité récemment découverte | Première transaction détectée |
| **monitoring** | Sous observation | Risque faible à moyen, aucune action encore |
| **flagged** | Activité suspecte détectée | Score de risque élevé, enquête nécessaire |
| **confirmed** | Acteur frauduleux vérifié | L'enquête a confirmé la fraude |
| **false_positive** | Signalement incorrect | L'enquête a montré une activité légitime |
| **cleared** | Précédemment signalé, maintenant sûr | Fraude résolue, acteur réhabilité |

---

### Gestion des statuts

#### Signaler une entité

Marquer une entité comme suspecte :

```typescript
await client.entities.updateStatus('ent_xyz789', {
  status: 'flagged',
  reason: 'Multiple high-risk transactions detected. Device fingerprint shared with known fraudster.',
  confidence: 'high'
});
```

**Quand signaler** :
- Score de risque ≥ 80
- Plusieurs signaux à risque élevé
- Connexions réseau à des fraudeurs confirmés
- Anomalies de vélocité
- Correspondances avec des listes de blocage

---

#### Confirmer une fraude

Vérifier une entité comme fraudeur confirmé :

```typescript
await client.entities.updateStatus('ent_xyz789', {
  status: 'confirmed',
  reason: 'Investigation confirmed account takeover. Customer verified unauthorized activity. Evidence: case #CS-2026-001',
  actions_taken: [
    'blocked_globally',
    'reversed_transactions',
    'notified_network_partners',
    'law_enforcement_referral'
  ]
});
```

**Quand confirmer** :
- L'enquête a prouvé la fraude
- Le client a confirmé une activité non autorisée
- Preuves collectées (captures d'écran, journaux)
- Seuil légal atteint
- Schéma établi sur plusieurs signaux

---

#### Marquer comme faux positif

Lever le signalement incorrect d'une entité :

```typescript
await client.entities.updateStatus('ent_xyz789', {
  status: 'false_positive',
  reason: 'Verified with customer - high-value purchase was legitimate. Customer provided proof of funds and explained unusual pattern (property purchase).',
  tuning_notes: 'Consider whitelisting verified high-net-worth customers for large transactions.'
});
```

**Quand marquer comme faux positif** :
- Le client a vérifié la transaction comme légitime
- L'enquête n'a trouvé aucun indicateur de fraude
- Une erreur technique a causé le faux signalement
- La règle métier était trop agressive

---

#### Lever le signalement d'une entité

Réhabiliter une entité précédemment signalée :

```typescript
await client.entities.updateStatus('ent_xyz789', {
  status: 'cleared',
  reason: 'Fraud resolved. Customer account recovered and secured. 6 months of clean transaction history since incident.',
  review_date: '2026-08-01' // Optional: schedule periodic review
});
```

**Quand lever le signalement** :
- Incident de fraude résolu
- Compte récupéré
- Historique propre étendu (6+ mois)
- Client vérifié et sécurisé

## Score de risque

### Comment les scores de risque sont calculés

**Facteurs de risque de base** (0-100) :
- Schémas de transaction (30%)
- Métriques de vélocité (25%)
- Connexions réseau (20%)
- Comportement historique (15%)
- Signaux appareil/IP (10%)

**Ajustements du score** :
- **Multiplicateur de confiance** : 0,8–1,2 selon la qualité des données
- **Effet réseau** : +0–20 selon les connexions frauduleuses
- **Pondération historique** : Les signaux les plus récents ont plus de poids
- **Ajustement du volume** : Un nombre plus élevé de transactions = score plus fiable

### Plages de score de risque

| Score | Niveau de risque | Recommandation d'action |
|-------|-----------------|------------------------|
| **0-39** | Faible | Surveiller, autoriser les transactions |
| **40-59** | Moyen | Vérification renforcée (2FA, confirmation par e-mail) |
| **60-79** | Élevé | Examen manuel requis |
| **80-89** | Très élevé | Bloquer avec option d'examen |
| **90-100** | Critique | Bloquer immédiatement, enquêter |

---

### Historique du risque

Suivre l'évolution du risque d'une entité dans le temps :

```typescript
const riskHistory = await client.entities.riskHistory('ent_xyz789', {
  start_date: '2025-12-01',
  end_date: '2026-02-03'

// Visualize risk trend
riskHistory.data.forEach(point => {
  console.log(`${point.date}: ${point.risk_score} (${point.signal_count} signals)`);

```

**Cas d'usage** :
- Identifier les schémas de fraude en escalade
- Valider la décision de confirmation de fraude
- Détecter la progression de la réhabilitation
- Analyser l'efficacité des interventions

## Analyse réseau

### Relations entre entités

Les entités sont liées sur la base d'attributs partagés :

**Types de liens** :
- **Lien d'appareil** : Même empreinte d'appareil
- **Lien IP** : Même adresse IP ou sous-réseau
- **Lien comportemental** : Schémas de transaction similaires
- **Lien temporel** : Transactions à des heures similaires
- **Lien géographique** : Mêmes schémas de localisation

### Découvrir les connexions réseau

**API** :
```typescript
const entity = await client.entities.get('ent_xyz789');

console.log(`Network Risk Score: ${entity.network_risk_score}`);
console.log(`Linked Entities: ${entity.linked_entities_count}`);

// Get linked entities
entity.network_links.forEach(link => {
  console.log(`  - ${link.entity_uuid}: ${link.link_type} (strength: ${link.strength})`);
});
```

**Force du lien** :
- **0,9–1,0** : Très fort (plusieurs attributs partagés)
- **0,7–0,89** : Fort (2–3 attributs partagés)
- **0,5–0,69** : Modéré (1–2 attributs partagés)
- **< 0,5** : Faible (un seul attribut partagé)

### Détection des réseaux de fraude

Identifier les réseaux de fraude coordonnés :

```typescript
async function detectFraudRing(entityUuid) {
  const entity = await client.entities.get(entityUuid);

  // High network risk suggests fraud ring
  if (entity.network_risk_score > 80) {
    console.log('Potential fraud ring detected!');

    // Get all linked entities
    const linkedEntities = await Promise.all(
      entity.network_links.map(link =>
        client.entities.get(link.entity_uuid)
      )
    );

    // Count confirmed fraudsters in network
    const confirmedFraudsters = linkedEntities.filter(
      e => e.status === 'confirmed'
    ).length;

    console.log(`Network size: ${linkedEntities.length}`);
    console.log(`Confirmed fraudsters: ${confirmedFraudsters}`);

    // If multiple confirmed fraudsters, flag entire network
    if (confirmedFraudsters >= 3) {
      for (const linked of linkedEntities) {
        if (linked.status === 'new' || linked.status === 'monitoring') {
          await client.entities.updateStatus(linked.uuid, {
            status: 'flagged',
            reason: `Part of fraud ring with ${confirmedFraudsters} confirmed fraudsters`
          });
        }
      }
    }
  }
}
```

## Bonnes pratiques

### 1. Revues de statut régulières

**Examiner les entités signalées chaque mois** :
```typescript
async function reviewFlaggedEntities() {
  const flagged = await client.entities.list({
    status: 'flagged',
    flagged_before: thirtyDaysAgo // Flagged >30 days ago
  });

  for (const entity of flagged.data) {
    // Check recent activity
    const recentSignals = await client.signals.list({
      actor_hash: entity.identifier,
      created_after: thirtyDaysAgo
    });

    // No recent fraud? Consider clearing
    if (recentSignals.data.every(s => s.risk_score < 60)) {
      await client.entities.updateStatus(entity.uuid, {
        status: 'false_positive',
        reason: '30 days of clean transactions - likely false positive'
      });
    }
  }
}
```

### 3. Exploiter l'intelligence réseau

**Utiliser les connexions réseau pour la détection précoce** :
```typescript
async function monitorNetworkRisk(entityUuid) {
  const entity = await client.entities.get(entityUuid);

  // Check if connected to known fraudsters
  for (const link of entity.network_links) {
    const linkedEntity = await client.entities.get(link.entity_uuid);

    if (linkedEntity.status === 'confirmed' && link.strength > 0.7) {
      console.warn(`Entity linked to confirmed fraudster (strength: ${link.strength})`);

      // Auto-flag if strong connection
      if (entity.status === 'new') {
        await client.entities.updateStatus(entityUuid, {
          status: 'flagged',
          reason: `Strong network link (${link.strength}) to confirmed fraudster ${linkedEntity.uuid}`
        });
      }
    }
  }
}
```

### 4. Suivre l'évolution du risque

**Surveiller les entités avec un risque croissant** :
```typescript
async function detectEscalatingRisk() {
  const entities = await client.entities.list({
    status: 'monitoring',
    min_risk_score: 50
  });

  for (const entity of entities.data) {
    const history = await client.entities.riskHistory(entity.uuid, {
      start_date: thirtyDaysAgo,
      end_date: today
    });

    // Calculate risk trend
    const firstScore = history.data[0].risk_score;
    const lastScore = history.data[history.data.length - 1].risk_score;
    const increase = lastScore - firstScore;

    // Flag if risk increased significantly
    if (increase > 20) {
      console.warn(`Entity ${entity.uuid} risk increased by ${increase} points`);

      await client.entities.updateStatus(entity.uuid, {
        status: 'flagged',
        reason: `Risk score increased from ${firstScore} to ${lastScore} over 30 days`
      });
    }
  }
}
```

### 6. Croiser avec les dossiers

**Lier les entités aux dossiers d'enquête** :
```typescript
async function investigateEntity(entityUuid) {
  const entity = await client.entities.get(entityUuid);

  // Check if entity is involved in existing cases
  const relatedCases = await client.cases.list({
    search: entity.identifier
  });

  if (relatedCases.data.length > 0) {
    console.log(`Entity involved in ${relatedCases.data.length} cases`);

    // Review case outcomes for entity status
    const resolvedCases = relatedCases.data.filter(c => c.status === 'resolved');

    if (resolvedCases.some(c => c.resolution.includes('Confirmed fraud'))) {
      // Update entity status based on case findings
      await client.entities.updateStatus(entityUuid, {
        status: 'confirmed',
        reason: `Confirmed fraud in case ${resolvedCases[0].uuid}`,
        evidence_case_id: resolvedCases[0].uuid
      });
    }
  }
}
```

### 7. Utiliser le statut pour la prise de décision

**Règles de décision automatisées basées sur le statut de l'entité** :
```typescript
async function makeTransactionDecision(signal) {
  // Check entity status
  const entities = await client.entities.list({
    search: signal.actor.hashed_id
  });

  if (entities.data.length > 0) {
    const entity = entities.data[0];

    switch (entity.status) {
      case 'confirmed':
        // Auto-block confirmed fraudsters
        return {
          decision: 'declined',
          reason: 'Known fraudster - Entity status: confirmed'
        };

      case 'flagged':
        // Require additional verification
        return {
          decision: 'review',
          reason: 'Flagged entity - Manual review required'
        };

      case 'false_positive':
        // Lower threshold for previously cleared entities
        if (signal.risk_score < 70) {
          return {
            decision: 'approved',
            reason: 'Previously false positive, acceptable risk'
          };
        }
        break;

      case 'cleared':
        // Trust rehabilitated entities slightly more
        if (signal.risk_score < 65) {
          return {
            decision: 'approved',
            reason: 'Cleared entity with acceptable risk'
          };
        }
        break;
    }
  }

  // Default: Use risk score
  return signal.risk_score >= 80 ? 'declined' : 'approved';
}
```

## Scénarios courants

### Scénario 1 : Nouvelle entité à risque élevé

```typescript
async function handleNewHighRiskEntity(signal) {
  // 1. Check if entity exists
  let entity = await client.entities.list({
    search: signal.actor.hashed_id
  });

  if (entity.data.length === 0) {
    console.log('New entity detected with high risk');

    // Wait for entity to be created by system
    await sleep(2000);

    entity = await client.entities.list({
      search: signal.actor.hashed_id
    });
  }

  const entityData = entity.data[0];

  // 2. Flag if high risk
  if (signal.risk_score >= 80) {
    await client.entities.updateStatus(entityData.uuid, {
      status: 'flagged',
      reason: `First transaction high risk (score: ${signal.risk_score}). Risk factors: ${signal.risk_factors.map(f => f.factor).join(', ')}`
    });

    // 3. Create case for investigation
    await client.cases.createFromSignal(signal.id, {
      priority: 'high',
      category: signal.event_type,
      description: `New entity flagged with high-risk first transaction`
    });
  }
}
```

### Scénario 2 : Découverte d'un réseau de fraude

```typescript
async function investigateFraudRing(suspectedEntityUuid) {
  // 1. Get suspected entity
  const entity = await client.entities.get(suspectedEntityUuid);

  // 2. Get network connections
  const networkEntities = await Promise.all(
    entity.network_links
      .filter(link => link.strength > 0.7) // Strong links only
      .map(link => client.entities.get(link.entity_uuid))
  );

  // 3. Analyze network
  const confirmedFraudsters = networkEntities.filter(e => e.status === 'confirmed');
  const flaggedEntities = networkEntities.filter(e => e.status === 'flagged');

  console.log(`Network Analysis:
Total Entities: ${networkEntities.length}
Confirmed Fraudsters: ${confirmedFraudsters.length}
Flagged: ${flaggedEntities.length}
Avg Risk Score: ${networkEntities.reduce((sum, e) => sum + e.risk_score, 0) / networkEntities.length}`);

  // 4. If fraud ring pattern detected
  if (confirmedFraudsters.length >= 2) {
    console.log('Fraud ring detected - flagging entire network');

    // Create master case
    const masterCase = await client.cases.create({
      title: `Fraud Ring Investigation - ${networkEntities.length} Connected Entities`,
      priority: 'critical',
      category: 'FRAUD_RING',
      description: `Network of ${networkEntities.length} entities with ${confirmedFraudsters.length} confirmed fraudsters`
    });

    // Flag all connected entities
    for (const connectedEntity of networkEntities) {
      if (connectedEntity.status === 'new' || connectedEntity.status === 'monitoring') {
        await client.entities.updateStatus(connectedEntity.uuid, {
          status: 'flagged',
          reason: `Part of fraud ring with ${confirmedFraudsters.length} confirmed fraudsters. Investigation case: ${masterCase.uuid}`
        });
      }
    }
  }
}
```

### Scénario 3 : Réhabilitation d'une entité

```typescript
async function rehabilitateEntity(entityUuid) {
  const entity = await client.entities.get(entityUuid);

  // Check if entity has been clean for 6 months
  const recentSignals = await client.signals.list({
    actor_hash: entity.identifier,
    created_after: sixMonthsAgo
  });

  const allClean = recentSignals.data.every(s => s.risk_score < 50);
  const avgRiskScore = recentSignals.data.reduce((sum, s) => sum + s.risk_score, 0) / recentSignals.data.length;

  if (allClean && entity.status === 'flagged') {
    console.log(`Entity ${entityUuid} has 6 months clean history`);

    await client.entities.updateStatus(entityUuid, {
      status: 'cleared',
      reason: `Entity rehabilitation - 6 months clean transaction history. Avg risk score: ${avgRiskScore.toFixed(1)}/100. Total clean transactions: ${recentSignals.data.length}`,
      review_date: moment().add(3, 'months').format('YYYY-MM-DD') // Schedule follow-up review
    });
  }
}
```

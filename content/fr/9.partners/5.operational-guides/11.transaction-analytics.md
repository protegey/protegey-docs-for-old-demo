# Analytique des transactions

La suite d'analytique des transactions offre aux équipes de conformité et d'exploitation une visibilité quantitative sur les volumes de signaux, les distributions de risque, le débit décisionnel et les performances des analystes. Tous les endpoints d'analytique sont limités au périmètre partenaire et respectent votre contexte sandbox/production.

---

## Vue d'ensemble

La suite d'analytique comprend 14 endpoints regroupés en quatre catégories :

| Catégorie | Endpoints | Cas d'usage |
|----------|-----------|----------|
| **Volume et tendances** | Séries temporelles, comparaison | Suivre le volume de signaux dans le temps, variations semaine sur semaine |
| **Distribution** | Distribution des risques, temps de décision | Comprendre la répartition des scores de risque, la latence décisionnelle |
| **Comportements** | Carte de chaleur, facteurs de risque | Identifier les plages horaires à risque, les principales catégories de fraude |
| **Performance de l'équipe** | Performance des réviseurs, statistiques de file d'attente | Surveiller le débit des analystes et la qualité des décisions |

Tous les endpoints acceptent les paramètres de date `from` et `to` au format ISO 8601. La plage par défaut est les 30 derniers jours.

---

## Volume et tendances

### Volume en série temporelle

```http
GET /api/v1/transaction-monitoring/analytics/time-series
```

Retourne le nombre de transactions journalier ou horaire et les scores de risque moyens sur la période demandée.

**Paramètres** :

| Paramètre | Type | Description |
|-----------|------|-------------|
| `from` | date | Date de début (ISO 8601) |
| `to` | date | Date de fin (ISO 8601) |
| `granularity` | string | `hour`, `day`, `week` — défaut `day` |
| `risk_level` | string | Filtrer par `low`, `medium`, `high`, `critical` |

**Réponse** :
```json
{
  "data": [
    {
      "date": "2026-03-01",
      "total_transactions": 1247,
      "flagged": 89,
      "avg_risk_score": 34.2,
      "risk_levels": {
        "low": 1045,
        "medium": 123,
        "high": 65,
        "critical": 14
      }
    }
  ],
  "summary": {
    "total_transactions": 38257,
    "total_flagged": 2741,
    "flag_rate": 7.16
  }
}
```

### Comparaison de périodes

```http
GET /api/v1/transaction-monitoring/analytics/comparison
```

Compare deux périodes (actuelle et précédente) sur le volume, le taux d'indicateurs et le score de risque moyen. Utile pour détecter les anomalies semaine sur semaine dans l'activité frauduleuse.

**Paramètres** : `current_from`, `current_to`, `prior_from`, `prior_to`

## Analyse de distribution

### Distribution des scores de risque

```http
GET /api/v1/transaction-monitoring/analytics/distribution
```

Retourne un histogramme des scores de risque sur la période sélectionnée. Utilisez cette fonctionnalité pour calibrer les paramètres de seuil et comprendre la répartition des scores.

**Réponse** :
```json
{
  "data": {
    "buckets": [
      { "range": "0-9", "count": 8420 },
      { "range": "10-19", "count": 6215 },
      { "range": "20-29", "count": 4830 },
      { "range": "30-39", "count": 3120 },
      { "range": "40-49", "count": 2890 },
      { "range": "50-59", "count": 2410 },
      { "range": "60-69", "count": 1870 },
      { "range": "70-79", "count": 1340 },
      { "range": "80-89", "count": 920 },
      { "range": "90-100", "count": 622 }
    ],
    "mean": 31.4,
    "median": 24.0,
    "p95": 78.0,
    "p99": 91.0
  }
}
```

### Distribution des temps de décision

```http
GET /api/v1/transaction-monitoring/analytics/decision-time
```

Affiche la distribution du temps de prise de décision pour toutes les transactions révisées. Utile pour le suivi des SLA et l'identification des goulots d'étranglement dans la file d'attente de révision.

**La réponse inclut** : `p50_seconds`, `p90_seconds`, `p99_seconds`, `mean_seconds`, `reviewed_count`

## Comportements

### Carte de chaleur d'activité

```http
GET /api/v1/transaction-monitoring/analytics/heatmap
```

Retourne une matrice 7×24 (jour de la semaine × heure de la journée) du volume de transactions et des scores de risque moyens. Permet d'identifier les plages horaires à haut risque (par exemple, pics nocturnes, pointes du week-end).

**Réponse** :
```json
{
  "data": {
    "matrix": [
      {
        "day": "monday",
        "hours": [
          { "hour": 0, "count": 12, "avg_risk": 71.2 },
          { "hour": 1, "count": 8, "avg_risk": 68.5 }
        ]
      }
    ],
    "peak_hour": { "day": "friday", "hour": 23, "avg_risk": 82.1 }
  }
}
```

### Ventilation des facteurs de risque

```http
GET /api/v1/transaction-monitoring/analytics/risk-factors
```

Agrège les détecteurs les plus fréquemment déclenchés, les indicateurs AML et les catégories de taxonomie sur la période sélectionnée. Utilisez cet endpoint pour identifier les principaux schémas de fraude dans votre population de transactions.

**Réponse** :
```json
{
  "data": {
    "top_detectors": [
      { "detector": "RAPID_TRANSACTION_VELOCITY", "trigger_count": 892, "pct": 32.5 },
      { "detector": "LARGE_OUTLIER_TRANSACTION", "trigger_count": 741, "pct": 27.0 }
    ],
    "top_taxonomy": [
      { "category": "payment.structuring", "count": 654, "pct": 23.8 }
    ],
    "top_aml_flags": [
      { "flag_type": "velocity_breach", "count": 1102, "pct": 40.2 }
    ]
  }
}
```

## Performance de l'équipe

### Performance des réviseurs

```http
GET /api/v1/transaction-monitoring/analytics/reviewer-performance
```

Métriques par analyste : décisions prises, temps de révision moyen, taux de faux positifs et précision (lorsque les résultats de référence sont disponibles).

::callout{type="info"}
Requiert le plan **Business** ou **Enterprise**. L'identité du réviseur est liée aux comptes utilisateurs OAuth2.
::

**Réponse** :
```json
{
  "data": [
    {
      "reviewer_uuid": "usr_01HZ...",
      "reviewer_name": "Kofi Mensah",
      "decisions_made": 342,
      "avg_review_seconds": 147,
      "approve_rate": 0.61,
      "reject_rate": 0.39,
      "escalation_rate": 0.08
    }
  ]
}
```

### Métriques de performance (statistiques de file d'attente)

```http
GET /api/v1/transaction-monitoring/analytics/performance
```

Métriques globales de la file d'attente : nombre de révisions en attente, âge moyen de la file, taux de dépassement SLA et débit.

## Utilisation des analytiques pour la calibration des seuils

L'endpoint de distribution est particulièrement utile pour calibrer vos seuils de score de risque :

1. Exécutez `GET /analytics/distribution` sur 30 jours de données de production
2. Identifiez le score `p95` — c'est votre limite naturelle de risque `high`
3. Définissez votre seuil de politique `BLOCK` à `p99` pour minimiser les faux positifs
4. Examinez `risk-factors` pour identifier les détecteurs générant du bruit plutôt que du signal

Les modifications de seuil prennent effet immédiatement via le moteur de politique de décision et ne nécessitent pas de déploiements de code.

## Décisions Groupées sur les Transactions

::callout{icon="i-lucide-lock" color="orange"}
Disponible sur les plans **Enterprise** avec la fonctionnalité `bulk_decisioning` activée.
::

Pour les opérations à volume élevé — tempêtes d'alertes, files d'examen en fin de journée, réponses à des fraudes coordonnées — l'endpoint de décision groupée vous permet d'approuver ou de bloquer plusieurs transactions en un seul appel API :

```http
POST /api/v1/transaction-monitoring/bulk-decide
```

**Corps de la requête :**

```json
{
  "transaction_ids": ["TXN-001", "TXN-002", "TXN-003"],
  "decision": "block",
  "reason": "Attaque de vélocité coordonnée — acteur bloqué sur toutes les transactions en attente",
  "decision_type": "automated"
}
```

| Champ | Type | Valeurs |
|-------|------|---------|
| `transaction_ids` | string[] | Jusqu'à 100 par appel |
| `decision` | string | `approve` · `block` · `review` |
| `reason` | string | Note d'audit — obligatoire pour les décisions `block` |
| `decision_type` | string | `manual` · `automated` · `hybrid` |

`decision_type` affecte le poids d'entraînement du modèle. Marquez les décisions automatisées (`automated`) séparément des décisions validées par un analyste pour que le pipeline d'entraînement puisse pondérer plus fortement les labels vérifiés par des humains.

**Cas d'usage à volume élevé :**

- **Réponse à une tempête d'alertes** — lorsque `GET /analytics/time-series` montre un pic, récupérez les transactions `pending` concernées et bloquez-les en lots de 100
- **Vidage de la file en fin de journée** — traitez la file de faible risque en fin de journée en approuvant en groupe les transactions sous votre seuil `p50`
- **Nettoyage post-incident** — après la clôture d'un dossier de fraude coordonnée, bloquez en groupe toutes les transactions liées au même hash d'acteur

## Export

Toutes les données d'analytique peuvent être exportées en CSV via :

```http
POST /api/v1/transaction-monitoring/export
```

Cet endpoint retourne une URL signée pour télécharger le jeu de données complet des transactions de la période sélectionnée, adapté à une analyse hors ligne dans Excel ou Python.

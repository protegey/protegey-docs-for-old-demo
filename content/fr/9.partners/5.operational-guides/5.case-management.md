La gestion des dossiers dans Protegey offre un flux de travail structuré pour enquêter sur les signaux de fraude, collaborer avec votre équipe et conserver une piste d'audit complète de toutes les activités d'investigation.

::callout{icon="i-lucide-folder-open" color="blue"}
**Des enquêtes sur la fraude simplifiées** : Convertissez les signaux à haut risque en dossiers, ajoutez des notes d'investigation, joignez des preuves et suivez l'état jusqu'à la résolution.
::

---

## Vue d'ensemble

### Qu'est-ce qu'un dossier ?

Un **dossier de fraude** est un enregistrement d'investigation structuré qui :

- Est lié à un ou plusieurs signaux de fraude
- Contient des notes et des conclusions d'investigation
- Suit les preuves (captures d'écran, documents, journaux)
- Maintient le statut et la priorité
- Enregistre l'historique complet de toutes les activités
- Prend en charge la collaboration et l'attribution au sein de l'équipe

### Quand créer un dossier

Créez des dossiers pour les signaux nécessitant :

- **Une investigation manuelle** : Signaux à haut risque (score ≥ 80) nécessitant l'examen d'un analyste
- **Un motif multi-signaux** : Plusieurs signaux connexes suggérant un réseau de fraude
- **Un litige client** : L'utilisateur affirme que son activité légitime a été signalée comme fraude
- **De la documentation** : Fraude complexe nécessitant une collecte de preuves détaillée
- **Une escalade** : Signaux nécessitant l'intervention d'un analyste senior ou des forces de l'ordre

## Cycle de vie d'un dossier

### Flux de statut

```
open → in_progress → resolved → closed
         ↓
      on_hold
```

| Statut          | Description                              | Actions disponibles                                          |
| --------------- | ---------------------------------------- | ------------------------------------------------------------ |
| **open**        | Nouveau dossier en attente d'attribution | Attribuer, ajouter des notes, démarrer l'investigation       |
| **in_progress** | Investigation en cours                   | Ajouter des preuves, mettre à jour les conclusions, résoudre |
| **on_hold**     | En pause (en attente d'informations)     | Reprendre, ajouter des notes, clore                          |
| **resolved**    | Investigation terminée                   | Ajouter des notes de résolution, clore                       |
| **closed**      | Dossier archivé                          | Consultation uniquement (lecture seule)                      |

### Niveaux de priorité

| Priorité     | Description               | SLA de réponse | À utiliser quand                                  |
| ------------ | ------------------------- | -------------- | ------------------------------------------------- |
| **low**      | Investigation non urgente | 72 heures      | Motifs à faible risque, surveillance proactive    |
| **medium**   | Investigation standard    | 24 heures      | Signaux à risque moyen, acteurs récidivistes      |
| **high**     | Examen urgent nécessaire  | 4 heures       | Signaux à haut risque, impact sur le client       |
| **critical** | Action immédiate requise  | 1 heure        | Fraude confirmée, attaque active, montants élevés |

## Création de dossiers

### Méthode 1 : À partir d'un signal (recommandée)

Créez un dossier directement à partir d'un signal à haut risque :

**Portail partenaire** :

1. Accédez à la Surveillance des transactions
2. Cliquez sur un signal à haut risque
3. Cliquez sur le bouton « Créer un dossier »
4. Le dossier est pré-rempli avec les données du signal

**API** :

```typescript
const fraudCase = await client.cases.createFromSignal("sig_abc123", {
  description: "High-value cross-border transfer requires investigation",
  priority: "high",
  category: "ACCOUNT_TAKEOVER",
});

console.log(`Case created: ${fraudCase.uuid}`);
```

**Données du signal copiées** :

- ID de transaction
- Score et niveau de risque
- Hash de l'acteur
- Montant et devise de la transaction
- Métadonnées (appareil, IP, pays)
- Facteurs de risque ayant déclenché la détection

---

### Méthode 2 : Création manuelle

Créez un dossier sans signal associé :

**Portail partenaire** :

1. Accédez aux Dossiers
2. Cliquez sur le bouton « Nouveau dossier »
3. Remplissez les détails du dossier
4. Attribuez à un analyste (facultatif)

**API** :

```typescript
const fraudCase = await client.cases.create({
  title: "Investigation: Account Takeover - 2026-02-03",
  description:
    "Customer reported unauthorized transactions on account ending in 4532. Investigating access pattern and transaction history.",
  priority: "high",
  category: "ACCOUNT_TAKEOVER",
  assigned_user_id: 42, // Optional
});
```

### Catégories de dossiers

Choisissez la catégorie de fraude la plus pertinente :

| Catégorie              | Description                      | Exemples                                                                   |
| ---------------------- | -------------------------------- | -------------------------------------------------------------------------- |
| **ACCOUNT_TAKEOVER**   | Accès non autorisé à un compte   | Bourrage d'identifiants, hameçonnage, échange de SIM                       |
| **IDENTITY_THEFT**     | Utilisation d'une identité volée | Identité synthétique, documents volés                                      |
| **PAYMENT_FRAUD**      | Transactions frauduleuses        | Cartes volées, fraude amicale, rétrofacturations                           |
| **MONEY_LAUNDERING**   | Mouvements de fonds suspects     | Structuration, empilement, placement                                       |
| **SOCIAL_ENGINEERING** | Schemes de manipulation          | Arnaques sentimentales, arnaques à l'investissement, usurpation d'identité |
| **OTHER**              | Autres types de fraude           | Précisez dans la description                                               |

## Flux de travail d'investigation

### Étape 1 : Attribution du dossier

**Attribuer à un analyste** :

```typescript
await client.cases.update(caseUuid, {
  assigned_user_id: 42,
});
```

**Règles d'attribution automatique** (à configurer dans le portail) :

- **Tour à tour** : Distribuer équitablement au sein de l'équipe
- **Par compétences** : Orienter selon l'expertise par catégorie de fraude
- **Par charge de travail** : Attribuer à l'analyste ayant le moins de dossiers ouverts
- **Par priorité** : Les dossiers critiques vont aux analystes seniors

---

### Étape 2 : Investigation et prise de notes

Ajoutez des notes d'investigation au fil de votre travail :

**API** :

```typescript
await client.cases.addNote(caseUuid, {
  content: `## Initial Findings

- Reviewed account activity for last 30 days
- Login from new device (iPhone 14) in Lagos, Nigeria
- Previous logins always from Accra, Ghana
- 3 high-value transfers within 2 hours of login
- Customer phone number unreachable (possible SIM swap)

## Next Steps
- Contact customer via email for verification
- Check if mobile carrier reported SIM change
- Review linked accounts for similar patterns`,
  visibility: "internal", // or 'external' for customer-facing notes
});
```

**Types de notes** :

- **Notes d'investigation** : Conclusions, analyse, prochaines étapes
- **Communication client** : Enregistrements des contacts avec le client
- **Référence externe** : Liens vers des systèmes externes (CRM, billetterie)
- **Résumé des preuves** : Description des preuves jointes

**Bonnes pratiques** :

- Utilisez Markdown pour la mise en forme
- Incluez des horodatages pour les événements clés
- Référencez les preuves par nom de fichier
- Documentez la justification des décisions
- Mettez à jour les notes après chaque session d'investigation

---

### Étape 3 : Collecte de preuves

Joignez des preuves à l'appui des dossiers :

**Types de preuves acceptés** :

- Captures d'écran (PNG, JPG)
- Journaux de transactions (CSV, JSON)
- Enregistrements de communications (TXT, PDF)
- Documents d'identité (PDF, JPG — expurgez les données sensibles !)
- Journaux système (TXT, LOG)
- Enregistrements vidéo (MP4 — preuve de simulation de fraude)

**API** :

```typescript
// Upload evidence
const evidence = await client.cases.attachEvidence(caseUuid, {
  file: await fs.readFile("screenshot_fraudulent_transaction.png"),
  filename: "screenshot_fraudulent_transaction.png",
  description: "Screenshot showing unauthorized transfer of GHS 15,000",
  type: "screenshot",
});

// List all evidence
const allEvidence = await client.cases.listEvidence(caseUuid);
```

**Bonnes pratiques pour les preuves** :

- **Expurgez les données personnelles** : Supprimez les données sensibles du client avant de téléverser
- **Nommage clair** : Utilisez des noms de fichiers descriptifs (ex. `2026-02-03_login_logs.csv`)
- **Contexte** : Ajoutez une description expliquant la pertinence de la preuve
- **Chaîne de traçabilité** : Documentez qui a collecté la preuve et quand
- **Limites de taille** : 10 Mo max par fichier, 50 Mo total par dossier

---

### Étape 4 : Mises à jour du statut

Mettez à jour le statut du dossier à mesure que l'investigation avance :

**Transitions de statut courantes** :

```typescript
// Start investigation
await client.cases.update(caseUuid, {
  status: "in_progress",
});

// Pause for customer response
await client.cases.update(caseUuid, {
  status: "on_hold",
  notes: "Awaiting customer response to verification email",
});

// Resume investigation
await client.cases.update(caseUuid, {
  status: "in_progress",
  notes: "Customer confirmed unauthorized activity",
});

// Resolve case
await client.cases.update(caseUuid, {
  status: "resolved",
  resolution:
    "Confirmed fraud. Account secured, funds recovered, law enforcement notified.",
});

// Archive case
await client.cases.update(caseUuid, {
  status: "closed",
});
```

---

### Étape 5 : Résolution et clôture

**Types de résolution** :

| Résolution                | Description                               | Actions prises                                                     |
| ------------------------- | ----------------------------------------- | ------------------------------------------------------------------ |
| **Fraude confirmée**      | Fraude vérifiée                           | Bloquer l'acteur, annuler les transactions, notifier les autorités |
| **Faux positif**          | Activité légitime                         | Mettre en liste blanche l'acteur, ajuster les seuils de risque     |
| **Preuves insuffisantes** | Impossible de déterminer                  | Aucune action, continuer la surveillance                           |
| **Litige client**         | Le client affirme la légitimité           | Examiner l'historique du client, vérifier l'identité               |
| **Erreur technique**      | Erreur système ayant causé le signalement | Corriger le bug, retraiter le signal                               |

**Documentation de résolution** :

```typescript
await client.cases.update(caseUuid, {
  status: "resolved",
  resolution: `## Investigation Summary
Confirmed account takeover via SIM swap fraud.

## Evidence
- Customer confirmed unauthorized SIM replacement on 2026-02-02
- Device fingerprint changed from known iPhone to new Android device
- IP geolocation changed from Accra (normal) to Lagos (unusual)
- Transaction velocity (5 transfers in 2 hours) highly anomalous

## Actions Taken
- Account access disabled pending customer verification
- Transactions reversed (GHS 45,000 total)
- Customer contacted via email - account reset link sent
- Mobile carrier notified of fraudulent SIM swap
- Actor phone number (0244xxxxxx) added to blocklist
- Law enforcement notified (case #NG-2026-0203-001)

## Prevention
- Enabled 2FA requirement for account changes
- Added SIM swap detection rule
- Updated velocity thresholds for Nigeria-origin transactions
- Customer education sent regarding SIM security

## Resolution
Confirmed fraud. All funds recovered. Account secured.`,
  priority: "low", // Downgrade priority after resolution
});
```

## Collaboration en équipe

### Gestion des attributions

**Attribuer un dossier à un membre de l'équipe** :

```typescript
await client.cases.update(caseUuid, {
  assigned_user_id: 43,
  notes: "Escalating to senior analyst for complex pattern analysis",
});
```

**Scénarios de réattribution** :

- **Changements d'équipe** : Réattribuer les dossiers ouverts lorsqu'un analyste termine son service
- **Escalade** : Transférer les dossiers complexes aux analystes seniors
- **Spécialisation** : Orienter vers l'analyste ayant une expertise spécifique (ex. fraude aux cryptomonnaies)
- **Équilibrage de la charge de travail** : Redistribuer si un analyste est surchargé

## Filtrage et recherche

### Filtrer les dossiers

**Par statut** :

```typescript
const openCases = await client.cases.list({ status: "open" });
const inProgressCases = await client.cases.list({ status: "in_progress" });
```

**Par priorité** :

```typescript
const criticalCases = await client.cases.list({ priority: "critical" });
```

**Par attribution** :

```typescript
// My assigned cases
const myCases = await client.cases.list({ assigned_to_me: true });

// Unassigned cases
const unassigned = await client.cases.list({ unassigned: true });

// Specific user's cases
const userCases = await client.cases.list({ assigned_user_id: 42 });
```

**Par plage de dates** :

```typescript
const recentCases = await client.cases.list({
  opened_after: "2026-02-01",
  opened_before: "2026-02-03",
});
```

**Par catégorie** :

```typescript
const atoCases = await client.cases.list({ category: "ACCOUNT_TAKEOVER" });
```

---

### Rechercher dans les dossiers

**Recherche en texte intégral** :

```typescript
// Search in title, description, notes
const results = await client.cases.list({
  search: "SIM swap Lagos",
});
```

**Conseils de recherche** :

- La recherche porte sur le titre, la description et toutes les notes
- Utilisez des guillemets pour les expressions exactes : `"GHS 15,000"`
- Recherchez par ID de transaction : `TXN-20260203-001`
- Recherchez par hash d'acteur : `hash_0244567890`

## Bonnes pratiques

### 1. Créer les dossiers rapidement

**Ne tardez pas à lancer l'investigation** :

```typescript
// ✅ GOOD: Create case immediately for high-risk signals
if (signal.risk_score >= 80) {
  await client.cases.createFromSignal(signal.id, {
    priority: "high",
    category: "ACCOUNT_TAKEOVER",
  });
}

// ❌ BAD: Waiting days before creating case
// Evidence may be lost, actors may continue fraud
```

---

### 2. Documenter en détail

**Incluez les informations essentielles** :

- Ce qui a déclenché l'investigation
- Les preuves examinées
- L'analyse et les conclusions
- La justification des décisions
- Les actions prises
- Les enseignements tirés

**Documentation insuffisante** :

```
Status: Resolved
Resolution: Fraud confirmed.
```

**Bonne documentation** :

```markdown
## Investigation Summary

Confirmed SIM swap account takeover targeting high-value account.

## Timeline

- 2026-02-02 14:00: SIM swap completed (mobile carrier confirmed)
- 2026-02-02 14:15: Login from new device (Lagos, Nigeria)
- 2026-02-02 14:30-16:30: 5 unauthorized transfers (GHS 45,000 total)
- 2026-02-03 09:00: Customer reported unauthorized activity

## Evidence

- Mobile carrier confirmation of SIM replacement
- IP logs showing geographic change (Accra → Lagos)
- Device fingerprint change (iPhone 12 → Android Unknown)
- Transaction velocity 10x normal pattern
- Customer verification via email confirmed unauthorized access

## Actions Taken

- Account disabled for security review
- All transactions reversed (GHS 45,000)
- Actor phone number added to global blocklist
- Law enforcement notified (Case #NG-2026-0203-001)
- Customer account secured with enhanced 2FA

## Prevention

- Implemented SIM swap detection rule
- Enhanced velocity checks for Nigeria-origin transactions
- Customer education on SIM security best practices

## Resolution

Confirmed fraud. Funds recovered. Account secured. Actor blocked.
```

---

### 3. Utiliser les priorités correctement

**Directives de priorité** :

- **Critique** : Fraude active, client bloqué, montants élevés (>10 000 $), risque réputationnel
- **Haute** : Fraude récente (<24h), montants moyens (1 000 $–10 000 $), acteur récidiviste
- **Moyenne** : Signaux plus anciens, faibles montants (<1 000 $), premier incident
- **Faible** : Surveillance proactive, cas pédagogiques, analyse des tendances

---

### 4. Exploiter les catégories

**Une catégorisation précise permet** :

- L'orientation vers des analystes spécialisés
- Des analyses par catégorie
- L'identification des tendances de fraude
- Le reporting réglementaire

---

### 5. Mettre le statut à jour régulièrement

**Maintenez le statut à jour** :

- Mettez à jour dans l'heure suivant le début de l'investigation
- Passez à `on_hold` si vous attendez des informations (ne laissez pas en `in_progress`)
- Résolvez rapidement lorsque l'investigation est terminée
- Clôturez après 30 jours d'inactivité (après résolution)

---

### 6. Collaborer efficacement

**Utilisez les attributions pour** :

- Une propriété claire
- La visibilité de la charge de travail
- La responsabilisation
- Le suivi des escalades

**Utilisez les notes pour** :

- Les informations de passation
- Les mises à jour entre équipes
- Poser des questions à l'équipe
- Documenter les discussions

---

### 7. Maintenir la chaîne de traçabilité des preuves

**Gestion des preuves** :

- Collectez les preuves rapidement (les journaux peuvent expirer)
- Documentez la source et la méthode de collecte
- Expurgez les données personnelles sensibles avant le téléversement
- Incluez le contexte pour chaque élément de preuve
- Maintenez l'ordre chronologique

## Scénarios courants

### Scénario 1 : Triage d'un signal à haut risque

```typescript
async function triageHighRiskSignal(signal) {
  // 1. Create case from signal
  const fraudCase = await client.cases.createFromSignal(signal.id, {
    priority: signal.risk_score >= 90 ? "critical" : "high",
    category: signal.event_type,
  });

  // 2. Add initial triage note
  await client.cases.addNote(fraudCase.uuid, {
    content: `## Triage Assessment
Risk Score: ${signal.risk_score}/100
Risk Level: ${signal.risk_level}

## Key Risk Factors:
${signal.risk_factors.map((f) => `- ${f.factor}: ${f.description}`).join("\n")}

## Next Steps:
- Review actor history
- Check similar transactions
- Contact customer if needed`,
  });

  // 3. Assign based on expertise
  const analyst = await findAnalystForCategory(signal.event_type);
  await client.cases.update(fraudCase.uuid, {
    assigned_user_id: analyst.id,
  });

  return fraudCase;
}
```

### Scénario 2 : Réseau de fraude multi-signaux

```typescript
async function investigateFraudRing(signals) {
  // 1. Create master case
  const masterCase = await client.cases.create({
    title: `Fraud Ring Investigation - ${signals.length} Related Signals`,
    description: `Investigating coordinated fraud pattern across ${signals.length} signals sharing device fingerprints and IP addresses.`,
    priority: "critical",
    category: "ACCOUNT_TAKEOVER",
  });

  // 2. Document pattern
  await client.cases.addNote(masterCase.uuid, {
    content: `## Pattern Identified
- ${signals.length} signals within 24 hours
- Shared device fingerprint: ${signals[0].metadata.device_fingerprint}
- Same IP range: 41.XX.XX.XX
- Total exposure: GHS ${signals.reduce((sum, s) => sum + s.transaction.amount, 0).toLocaleString()}

## Affected Accounts
${signals.map((s) => `- ${s.actor.hashed_id} - GHS ${s.transaction.amount}`).join("\n")}`,
  });

  // 3. Link all signals to case (via notes)
  for (const signal of signals) {
    await client.cases.addNote(masterCase.uuid, {
      content: `Related signal: ${signal.id} - Risk Score: ${signal.risk_score}`,
    });
  }

  return masterCase;
}
```

### Scénario 3 : Litige client

```typescript
async function handleCustomerDispute(signal, customerMessage) {
  // 1. Create case for investigation
  const disputeCase = await client.cases.createFromSignal(signal.id, {
    priority: "high",
    category: "CUSTOMER_DISPUTE",
    description: `Customer disputes fraud flag. Claims legitimate activity.`,
  });

  // 2. Document customer claim
  await client.cases.addNote(disputeCase.uuid, {
    content: `## Customer Claim
"${customerMessage}"

## Signal Details
- Risk Score: ${signal.risk_score}
- Risk Factors: ${signal.risk_factors.map((f) => f.factor).join(", ")}

## Investigation Plan
1. Review customer account history (last 6 months)
2. Verify device fingerprint matches known devices
3. Check IP geolocation against customer address
4. Review similar patterns in account
5. Contact customer for additional verification if needed`,
  });

  // 3. Assign to senior analyst
  await client.cases.update(disputeCase.uuid, {
    assigned_user_id: await getSeniorAnalyst(),
    priority: "high",
  });

  return disputeCase;
}
```

## Métriques et rapports

### Indicateurs clés des dossiers

**Suivez les performances** :

- **Total des dossiers** : Volume global
- **Dossiers ouverts** : Charge de travail actuelle
- **Temps de résolution moyen** : Indicateur d'efficacité
- **Dossiers par priorité** : Répartition de l'urgence
- **Dossiers par catégorie** : Ventilation par type de fraude
- **Taux de clôture** : % de dossiers résolus par rapport aux dossiers créés
- **Performance des analystes** : Dossiers par analyste, temps de résolution moyen

**API** (via les points de terminaison analytiques) :

```typescript
const metrics = await client.analytics.cases({
  start_date: "2026-02-01",
  end_date: "2026-02-28",
});

console.log(`Total Cases: ${metrics.total}`);
console.log(`Avg Resolution Time: ${metrics.avg_resolution_hours} hours`);
console.log(`Top Category: ${metrics.by_category[0].category}`);
```

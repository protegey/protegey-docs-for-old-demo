# Règles de conformité et seuils AML

Le moteur AML/CFT de Protegey applique un ensemble de règles structurées en couches, dérivé de la Recommandation 16 du FATF (virements), de la Recommandation 7 (sanctions) et des orientations nationales sur les seuils pour plus de 20 devises africaines et internationales majeures. Cette page explique comment ces règles s'appliquent à vos signaux et comment interpréter les indicateurs de conformité.

::callout{type="info"}
Les fonctionnalités AML/RCaaS requièrent le plan **Enterprise**. Le tableau de bord de conformité est accessible depuis `/compliance` dans le portail partenaire.
::

---

## Seuils FATF multi-devises

Chaque devise dispose d'un seuil indépendant calibré sur la valeur locale équivalente FATF. Les seuils s'appliquent à :

1. **Transaction unique** — déclencheur de déclaration (équivalent CTR)
2. **Détection de structuration** — fenêtre d'agrégation sur 24 heures
3. **Dépassement de vélocité** — fenêtre de mouvement rapide sur 1 heure

## Classification par niveau FATF

| Niveau | Description | Posture réglementaire |
|------|-------------|-------------------|
| **Tier 1** | États membres FATF — évaluation mutuelle complète | Confiance la plus élevée dans les seuils |
| **Tier 2** | Organismes régionaux de type FATF (GIABA, ESAAMLG) | Calibré sur les orientations régionales |
| **Tier 3** | Juridictions sous surveillance renforcée | Seuils plus bas, examen accru |
| **Liste noire** | Juridictions à haut risque selon le FATF | Toutes les transactions signalées quelle que soit leur valeur |

Les juridictions sur liste noire déclenchent automatiquement un indicateur AML `high_risk_jurisdiction` et sont acheminées vers l'examen SAR quel que soit le montant de la transaction.

## Détection de structuration

La structuration (schtroumpfage) survient lorsqu'un client fractionne une transaction déclarable en montants plus petits afin d'éviter le seuil de déclaration.

**Logique de détection** :
- Le moteur agrège toutes les transactions pour le même `entity_id` dans une fenêtre glissante de 24 heures
- Si l'agrégat dépasse le seuil de `structuration` (95 % de la limite de transaction unique) sur 3 transactions ou plus, un indicateur `structuring` est levé
- La fenêtre est limitée à l'entité — la coordination inter-entités est détectée via le moteur graphique, non par les règles de structuration

**Champs de l'indicateur** :
```json
{
  "flag_type": "structuring",
  "evidence": {
    "transaction_count": 4,
    "aggregate_amount": 9700.00,
    "currency": "USD",
    "window_hours": 24,
    "threshold": 9500.00
  }
}
```

## Corrélation auto-STR

Lorsque les indicateurs AML `structuring` **et** `velocity_breach` se déclenchent tous deux dans les 72 heures sur la même entité, le moteur rédige automatiquement un rapport de transaction suspecte (SAR/STR) :

1. Un SAR est créé avec le statut `draft`
2. Les totaux des transactions sont pré-calculés à partir des signaux signalés
3. Votre équipe reçoit une notification webhook (`compliance.sar.auto_drafted`)
4. Le SAR apparaît dans le tableau de bord de conformité sous **SARs → Révision requise**

Votre équipe révise et édite le narratif avant le dépôt. Consultez l'[API Compliance](/partners/api-reference/compliance) pour le cycle de vie complet du SAR.

::callout{type="warning"}
Les SAR rédigés automatiquement ne sont pas déposés automatiquement auprès des régulateurs. Un responsable de la conformité doit revoir et déclencher explicitement le dépôt via `POST /compliance/sars/{id}/file` ou le tableau de bord.
::

## Détection des montants ronds

La règle `round_number` signale les transactions dont les montants sont des chiffres ronds exacts (par exemple 5 000 $, 10 000 $) combinés à une géographie à haut risque ou à un appareil vu pour la première fois. Les montants ronds sont disproportionnellement associés à la structuration et à l'activité de mules financières.

Cette règle a un score de confiance plus faible que la structuration (0,45 contre 0,75) et ne déclenche pas par elle-même un auto-STR.

## Dépassement de vélocité

Un indicateur de dépassement de vélocité se déclenche lorsqu'une entité déplace plus que le seuil horaire dans une fenêtre de 60 minutes. Ceci est distinct du détecteur `RAPID_TRANSACTION_VELOCITY` :

| Composant | Type de seuil | Périmètre |
|-----------|----------------|-------|
| Indicateur AML `velocity_breach` | Montant libellé en devise | Pipeline de conformité |
| Détecteur `RAPID_TRANSACTION_VELOCITY` | Nombre de transactions (≥10/h) | Pipeline de détection de fraude |

Les deux peuvent se déclencher sur le même signal et contribuer indépendamment au score de risque et à l'examen SAR.

## Révision des indicateurs de conformité

Accédez à **Conformité → Indicateurs de transactions** pour réviser tous les indicateurs AML. Chaque indicateur affiche :
- Le type d'indicateur et le score de confiance
- Les preuves (montants, compteurs, fenêtre)
- Les signaux liés
- Le statut auto-STR (le cas échéant)

Utilisez `GET /api/v1/partner/compliance/transaction-flags` pour récupérer les indicateurs de manière programmatique. Consultez l'[API Compliance](/partners/api-reference/compliance) pour les options de filtre et le schéma de réponse.

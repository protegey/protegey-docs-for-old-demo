# Guide de la Production

La Production est l'environnement réel où les décisions effectives sont prises.

::callout{icon="i-lucide-alert-triangle" color="red"}
**Attention** : Les actions en Production ont des conséquences réelles. Les signaux soumis ici affecteront les scores de risque pour les autres partenaires.
::

## Liste de Contrôle avant Mise en Service

Avant de basculer vos clés API vers la Production (`cen_live_sk_...`), vérifiez les points suivants :

1. [ ] **Gestion des Erreurs** : Confirmez que votre application échoue gracieusement (ex : mode ouvert "fail open" ou mode fermé "fail closed") si l'API retourne une erreur 500 ou expire.
2. [ ] **Configuration du Délai d'Attente (Timeout)** : Réglez votre délai d'attente client HTTP sur **2000ms** (recommandé) ou alignez-le avec votre SLA.
3. [ ] **Logique de Réessai (Retry)** : Implémentez un mécanisme de temporisation exponentielle pour les erreurs 429 et 5xx.
4. [ ] **Traitement Asynchrone** : Assurez-vous que les soumissions de signaux (écritures) sont effectuées de manière asynchrone pour éviter de bloquer les flux utilisateurs.

## Mode Ombre (Shadow Mode) - Recommandé

Lors de la première mise en service, nous recommandons de fonctionner en **Mode Ombre** pendant 1 à 2 semaines.

1. Appelez l'API Protegey pour chaque transaction.
2. Enregistrez le `risk_score` et la `recommendation` dans votre base de données.
3. **Ne bloquez pas** encore les utilisateurs en fonction du score.
4. Après une semaine, comparez les recommandations de Protegey avec vos résultats réels de fraude.
5. Ajustez vos seuils puis activez le blocage actif.

### Limites de Débit
Les limites de débit en Production sont nettement plus élevées qu'en Sandbox mais sont appliquées strictement.
- **Requêtes excédentaires (Bursting)** : Nous acceptons des pics de courte durée (jusqu'à 2x le quota) pendant <5 secondes.
- **En-têtes** : Consultez `X-RateLimit-Remaining` pour surveiller votre utilisation.

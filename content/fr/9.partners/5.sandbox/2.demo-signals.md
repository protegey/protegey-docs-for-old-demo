Si vous n'avez pas encore de données de signaux réelles, vous pouvez utiliser notre **Générateur de Signaux de Démo** pour remplir votre sandbox avec des scénarios réalistes.

## Comment générer des signaux

1. Naviguez vers **Sandbox > Demo Signals** dans le Portail Partenaire.
2. Sélectionnez un **Modèle de Signal** (ex : Prise de contrôle de compte / Account Takeover).
3. Choisissez un **Volume Prédéfini** (5, 20 ou 100 signaux).
4. Cliquez sur **Generate Signals**.

## Modèles Disponibles

| Modèle | Scénario |
|--------|----------|
| **Account Takeover** | Simule des connexions suspectes et une activité de compte non autorisée. |
| **Stolen Financials** | Simule des transactions utilisant des moyens de paiement compromis. |
| **Synthetic Identity** | Simule une inscription avec des données d'identité fausses ou manipulées. |
| **Phone Verification Failure** | Simule des échecs répétés dans les flux 2FA/KYC. |
| **External Fraud Report** | Simule des rapports entrants provenant de réseaux de partenaires externes. |

## Profilage Dynamique des Risques

Le générateur de signaux de démo utilise le **profilage dynamique des risques** pour créer des scénarios de test réalistes. Chaque signal se voit automatiquement attribuer un profil de risque qui influence plusieurs variables :

### Distribution des Risques
| Niveau de Risque | Probabilité | Caractéristiques |
|------------------|-------------|------------------|
| **Critique** | 10% | Montants élevés (15k-50k $), transactions transfrontalières, haute confiance (0,85-0,99) |
| **Élevé** | 20% | Montants proches des seuils (9k-14k $), transfrontalier, confiance moyenne-élevée (0,75-0,90) |
| **Moyen** | 30% | Montants modérés (1k-5k $), transactions locales, confiance moyenne (0,50-0,75) |
| **Faible** | 40% | Petits montants (10-500 $), transactions locales, haute confiance (0,80-0,99) |

### Comment fonctionne le profilage des risques

Le système surcharge automatiquement les variables du modèle en fonction du profil de risque sélectionné :

**Montants des Transactions :**
- **Critique** : 15 000 $ - 50 000 $ (déclenche la détection d'anomalie de montant)
- **Élevé** : 9 000 $ - 14 000 $ (proche des limites de seuil)
- **Moyen** : 1 000 $ - 5 000 $ (fourchette normale)
- **Faible** : 10 $ - 500 $ (petites transactions typiques)

**Indicateurs Géographiques :**
- **Critique/Élevé** : Transactions transfrontalières (code pays différent de votre pays partenaire)
- **Moyen/Faible** : Transactions locales (même pays que le partenaire)

**Confiance de la Source :**
- **Critique** : 0,85 - 0,99 (haute confiance qu'il s'agit d'une fraude)
- **Élevé** : 0,75 - 0,90 (confiance modérément élevée)
- **Moyen** : 0,50 - 0,75 (incertain)
- **Faible** : 0,80 - 0,99 (haute confiance qu'il s'agit d'une opération légitime)

::callout{type="info"}
**Pourquoi c'est important** : Le système de profilage des risques garantit que votre sandbox dispose d'un mélange réaliste de signaux de fraude, vous permettant de tester les seuils d'alerte, la priorisation des dossiers et les flux d'enquête dans des conditions réelles.
::

## Surcharge de Variables

Bien que le système applique automatiquement le profilage des risques, vous pouvez surcharger des variables spécifiques lors de l'utilisation directe de l'API :

```bash
POST /api/v1/partner/sandbox/generate-demo-signals
{
  "template": "account_takeover",
  "count": 10,
  "overrides": {
    "TRANSACTION_AMOUNT": 25000,
    "PHONE_NUMBER": "+233240000000",
    "COUNTRY_CODE": "GH"
  }
}
```

## Limites de Débit

Pour garantir la stabilité du système, la génération de signaux de démo est limitée à **3 requêtes par heure** par partenaire via le point de terminaison HTTP. Pour des tests de volume plus important, utilisez l'outil CLI [Simulateur d'API](./api-simulator) ou la fonctionnalité de [Simulation de Scénarios](./scenarios).

## Visualisation des Résultats

Une fois générés, les signaux apparaîtront dans vos **Signal Logs** avec un tag de source `Simulator` et les métadonnées `generated_by: centry_demo`. Vous pouvez filtrer les journaux par environnement et par source pour isoler les données de démo.

### Métadonnées du Signal
Chaque signal de démo inclut des métadonnées de suivi :
```json
{
  "metadata": {
    "generated_by": "centry_demo",
    "demo_batch": 1738598400,
    "demo_sequence": 1,
    "demo_risk_intent": "critical"
  }
}
```

Cela vous permet de :
- Filtrer les signaux de démo des données de test réelles
- Suivre les lots de génération de signaux
- Analyser la précision de la distribution des risques
- Déboguer des scénarios spécifiques

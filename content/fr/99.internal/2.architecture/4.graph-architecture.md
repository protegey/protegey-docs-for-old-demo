# Architecture graphique

## Vue d'ensemble

Le graphe chaud est un référentiel de relations entre entités en temps réel, implémenté sur PostgreSQL (tables `graph_nodes` + `graph_edges`) avec un cache d'adjacence Redis pour une traversée en moins de 5 ms. Il est conçu pour les performances en chemin d'ingestion — chaque signal entrant dans le système met à jour le graphe de manière synchrone dans le pipeline `IngestSignalAction`.

---

## Modèle de données

### `graph_nodes`

```sql
id              bigserial PRIMARY KEY
partner_uuid    uuid NOT NULL
entity_uuid     uuid REFERENCES fraud_entities(uuid)
node_type       varchar(50)  -- phone_number, device, ip_address, account_id
external_id     varchar(255) -- HMAC-SHA256 of the actual identifier
risk_score      int DEFAULT 0
metadata        jsonb
created_at      timestamptz
updated_at      timestamptz

INDEX: (partner_uuid, node_type, external_id)
INDEX: (partner_uuid, risk_score DESC)
```

### `graph_edges`

```sql
id              bigserial PRIMARY KEY
partner_uuid    uuid NOT NULL
source_node_id  bigint REFERENCES graph_nodes(id)
target_node_id  bigint REFERENCES graph_nodes(id)
edge_type       varchar(50)  -- shared_device, shared_ip, co_occurrence, etc.
weight          float        -- 0.0–1.0 relationship strength
metadata        jsonb
first_seen_at   timestamptz
last_seen_at    timestamptz
signal_count    int DEFAULT 1

INDEX: (partner_uuid, source_node_id)
INDEX: (partner_uuid, target_node_id)
INDEX: (partner_uuid, edge_type, weight DESC)
```

## Cache d'adjacence Redis

Schéma de clé de cache : `graph:adj:{partner_uuid}:{node_id}`

Valeur de cache : tableau JSON de tuples `[target_node_id, edge_type, weight]` pour toutes les arêtes sortantes.

TTL : **15 minutes** (configurable via `config/graph.php`).

Le cache est rempli de manière paresseuse à la première traversée et invalidé lors de l'upsert d'une arête. Une tâche hebdomadaire `graph:rebuild-cache` pré-chauffe tous les graphes partenaires.

```php
// Cache key format
$key = "graph:adj:{$partnerUuid}:{$nodeId}";

// Read adjacency list
$adjacency = Cache::store('redis')->get($key);

// Write on cache miss
Cache::store('redis')->put($key, $adjacency, seconds: 900);
```

## Traversée BFS

La méthode `HotGraphService::getNeighborhood()` utilise un BFS itératif avec le cache Redis comme chemin de lecture principal :

```php
public function getNeighborhood(string $partnerUuid, int $nodeId, int $depth = 2): array
{
    $visited = [$nodeId];
    $queue   = [[$nodeId, 0]];
    $nodes   = [];

    while (!empty($queue) && count($nodes) < 200) {
        [$current, $currentDepth] = array_shift($queue);

        if ($currentDepth >= $depth) {
            continue;
        }

        $adjacency = $this->getAdjacency($partnerUuid, $current); // Redis or DB

        foreach ($adjacency as [$targetId, $edgeType, $weight]) {
            if (!in_array($targetId, $visited) && $weight >= 0.3) {
                $visited[]  = $targetId;
                $nodes[]    = ['id' => $targetId, 'depth' => $currentDepth + 1];
                $queue[]    = [$targetId, $currentDepth + 1];
            }
        }
    }

    return ['nodes' => $nodes, 'truncated' => count($nodes) >= 200];
}
```

**Élagage des arêtes** : Les arêtes avec un poids < 0,3 sont exclues de la traversée. Cela empêche les corrélations faibles (par exemple, ISP partagé au niveau pays) de gonfler la taille du voisinage.

## Protection IDOR

L'API graphique expose les valeurs `external_id` des nœuds (hashes HMAC des identifiants réels). Pour empêcher l'inférence d'entités inter-partenaires, toutes les valeurs `external_id` sont masquées avant d'être retournées à la couche API :

```php
protected function maskExternalId(string $externalId): string
{
    return substr($externalId, 0, 8) . '****';
}
```

Cela signifie que les consommateurs de l'API peuvent reconnaître leurs propres entités (en comparant les 8 premiers caractères à leurs enregistrements de hash locaux) mais ne peuvent pas reconstruire les hashes complets ni faire correspondre des entités entre comptes partenaires.

Toutes les requêtes graphiques sont filtrées par `partner_uuid` au niveau de la base de données — il est architecturalement impossible de traverser les nœuds graphiques d'un autre partenaire.

## Formule de propagation du risque

```php
$propagatedRisk = 0;
$totalWeight    = 0;

foreach ($neighbors as $neighbor) {
    $hopDecay    = pow(0.7, $neighbor['depth']); // 0.7 per hop
    $edgeWeight  = $neighbor['weight'];
    $contribution = $neighbor['risk_score'] * $edgeWeight * $hopDecay;
    $propagatedRisk += $contribution;
    $totalWeight    += $edgeWeight * $hopDecay;
}

$propagatedRisk = $totalWeight > 0 ? $propagatedRisk / $totalWeight : 0;

// Apply amplifier if any direct neighbor is high-risk
$highRiskCount = count(array_filter($neighbors, fn($n) => $n['risk_score'] > 80 && $n['depth'] === 1));
$amplifier     = min(15, $highRiskCount * 5); // max +15 pts
$networkScore  = min(100, $propagatedRisk + $amplifier);
```

## Intégration avec WeightedRiskFusionEngine

Le graphe chaud contribue le `network_score` (pondération 40 %) au score de risque final fusionné :

```
fused_score = (behavioral × 0.35) + (network × 0.40) + (contextual × 0.15) + (historical × 0.10)
```

`HotGraphService` est appelé de manière synchrone dans le chemin d'ingestion, après `FeatureEngineeringService` et avant `WeightedRiskFusionEngine`. Le calcul graphique doit s'achever dans la cible de 50 ms pour l'explicabilité.

## Notes opérationnelles

- **Taux de manque du cache graphique** : suivi dans l'endpoint `/health` sous `graph_cache_hit_rate`
- **Tâche de reconstruction hebdomadaire** : `graph:rebuild-adjacency-cache` — exécutée le dimanche à 02h00 UTC, utilise la file d'attente `graph`
- **Décroissance du poids des arêtes** : Non implémentée actuellement — les arêtes ne décroissent pas dans le temps. La Phase 12 introduira des poids d'arêtes avec décroissance temporelle dans le graphe froid
- **Déduplication des nœuds** : Les nœuds sont indexés sur `(partner_uuid, node_type, external_id)` — la même entité apparaissant via différents signaux ne crée pas de nœuds en double

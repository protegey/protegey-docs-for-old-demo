# API Advisory pour Régulateurs

Les régulateurs sont provisionnés en tant que comptes spéciaux avec `role: regulator` dans le système IAM. Ils accèdent à l'API de diffusion des avis via un client OAuth2 dédié. Cette page documente les endpoints à destination des régulateurs qui ne sont **pas** exposés dans la documentation de l'API partenaire.

---

## Authentification

Les comptes régulateurs utilisent le même flux OAuth2 que les partenaires, mais reçoivent un token avec le scope `regulator` :

```http
POST /oauth/token
{
  "grant_type": "client_credentials",
  "client_id": "{regulator_client_id}",
  "client_secret": "{regulator_client_secret}",
  "scope": "regulator"
}
```

---

## Endpoints

### Diffuser un avis

```http
POST /api/v1/regulator/advisories
Authorization: Bearer {regulator_token}
```

Crée et diffuse un avis à tous les partenaires dans le périmètre cible spécifié.

**Corps de la requête** :

```json
{
  "title": "FATF Mutual Evaluation — Enhanced Monitoring Required",
  "body": "All partners operating in jurisdictions under enhanced monitoring must implement additional transaction screening by 2026-04-01.",
  "severity": "high",
  "category": "regulatory_update",
  "target_scope": "all",
  "expires_at": "2026-04-30T23:59:59Z",
  "action_required": true,
  "action_deadline": "2026-04-01T00:00:00Z"
}
```

| Champ | Type | Description |
|-------|------|-------------|
| `title` | string | Max 255 caractères |
| `body` | string | Texte complet de l'avis (Markdown supporté) |
| `severity` | string | `critical`, `high`, `medium`, `low`, `info` |
| `category` | string | `regulatory_update`, `threat_intelligence`, `platform_notice`, `compliance_deadline` |
| `target_scope` | string | `all`, `enterprise`, ou un `partner_uuid` spécifique |
| `expires_at` | datetime | Date d'expiration de l'avis (optionnel) |
| `action_required` | boolean | Si les partenaires doivent accuser réception |
| `action_deadline` | datetime | Délai pour l'action requise (optionnel) |

**Réponse** : `201 Created` avec l'UUID de l'avis.

---

### Désactiver un avis

```http
PATCH /api/v1/regulator/advisories/{uuid}/deactivate
Authorization: Bearer {regulator_token}
```

Désactive immédiatement un avis — il disparaît de tous les portails partenaires et n'est plus comptabilisé dans les badges de non-lu. À utiliser lorsqu'un avis a été émis par erreur ou est remplacé.

**Réponse** : `200 OK` avec le statut mis à jour de l'avis.

---

### Statistiques de livraison

```http
GET /api/v1/regulator/advisories/{uuid}/stats
Authorization: Bearer {regulator_token}
```

Retourne les statistiques de livraison et d'accusé de réception pour un avis diffusé.

**Réponse** :

```json
{
  "data": {
    "advisory_uuid": "adv_01HZ...",
    "title": "FATF Mutual Evaluation — Enhanced Monitoring Required",
    "total_recipients": 47,
    "delivered": 47,
    "read": 38,
    "acknowledged": 29,
    "dismissed": 3,
    "pending_acknowledgement": 15,
    "action_required": true,
    "action_deadline": "2026-04-01T00:00:00Z"
  }
}
```

## Limites de débit

Les tokens régulateurs sont soumis à des limites de débit plus strictes que les tokens partenaires — la diffusion d'avis est une opération à fort taux de distribution.

| Endpoint | Limite | Fenêtre |
|----------|--------|---------|
| `POST /regulator/advisories` | 10 | par heure |
| `PATCH /regulator/advisories/{uuid}/deactivate` | 30 | par heure |
| `GET /regulator/advisories/{uuid}/stats` | 120 | par heure |

Le dépassement des limites retourne `429 Too Many Requests` avec un en-tête `Retry-After` (en secondes). Les requêtes de diffusion déclenchant un fan-out vers plus de 100 partenaires sont mises en file d'attente — la réponse est immédiate avec `202 Accepted` et l'UUID de l'avis ; la livraison est asynchrone.

---

## Codes d'erreur

| Code | HTTP | Signification |
|------|------|---------------|
| `advisory_not_found` | 404 | UUID inexistant ou appartenant à un autre régulateur |
| `advisory_already_deactivated` | 409 | L'avis est déjà inactif — la désactivation idempotente peut être relancée sans risque |
| `advisory_expired` | 422 | `expires_at` est dans le passé au moment de la diffusion |
| `invalid_target_scope` | 422 | `target_scope` n'est pas `all`, `enterprise` ou un UUID partenaire valide |
| `action_deadline_before_now` | 422 | `action_deadline` est dans le passé |
| `action_deadline_without_flag` | 422 | `action_deadline` fourni mais `action_required: false` |
| `regulator_scope_missing` | 403 | Le token ne porte pas le scope `regulator` |
| `regulator_account_suspended` | 403 | Compte régulateur inactif — contacter l'équipe Protegey ops |
| `broadcast_fan_out_failed` | 500 | Erreur de dispatch en file d'attente — l'avis a été sauvegardé mais les jobs de livraison n'ont pas été mis en file ; relancer via `php artisan advisories:retry-dispatch {uuid}` |

## Provisionnement du client OAuth

### Créer un compte régulateur

```bash
# 1. Créer l'utilisateur régulateur + enregistrement partenaire
php artisan make:regulator "{nom_institution}" "{email_admin}"
# Sortie : UUID régulateur, mot de passe généré (unique — transmettre via canal sécurisé)

# 2. Créer le client client_credentials OAuth2
php artisan passport:client --client --name="{nom_institution} Regulator Client"
# Sortie : client_id et client_secret — stocker dans 1Password sous "Regulator OAuth Clients"
# Ces valeurs sont affichées UNE SEULE FOIS ; Passport ne réexpose pas le secret après création

# 3. Assigner le scope regulator au client
php artisan passport:scope --client-id={client_id} --scope=regulator
```

### Rotation des identifiants client

Les secrets client ne peuvent pas être renouvelés sur place via Passport — le client doit être recréé :

```bash
# 1. Créer le client de remplacement
php artisan passport:client --client --name="{nom_institution} Regulator Client v2"

# 2. Assigner le scope
php artisan passport:scope --client-id={new_client_id} --scope=regulator

# 3. Partager les nouveaux identifiants avec le régulateur (canal sécurisé)

# 4. Après confirmation du régulateur, révoquer les anciens tokens
php artisan passport:purge --revoked
# Puis désactiver l'ancien client OAuth :
# UPDATE oauth_clients SET revoked = 1 WHERE id = {old_client_id};
```

**Fenêtre de rotation** : Prévoir au moins 48 heures de validité parallèle. Ne pas révoquer l'ancien client avant confirmation du régulateur que le nouveau fonctionne en production.

### Suspendre un compte régulateur

```bash
# Révoquer tous les tokens actifs immédiatement
php artisan passport:purge --revoked --client-id={client_id}

# Désactiver le client OAuth
# UPDATE oauth_clients SET revoked = 1 WHERE id = {client_id};

# Marquer l'enregistrement partenaire régulateur comme inactif
php artisan partner:deactivate {regulator_uuid} --reason="Suspendu selon ticket ops #OP-XXXX"
```

## Événements webhook

### `advisory.created`

Déclenché pour chaque partenaire dans le périmètre cible lors de la diffusion d'un avis.

```json
{
  "event": "advisory.created",
  "delivery_id": "del_01HZ...",
  "timestamp": "2026-03-19T08:00:00Z",
  "data": {
    "advisory_uuid": "adv_01HZ...",
    "title": "FATF Mutual Evaluation — Enhanced Monitoring Required",
    "severity": "high",
    "category": "regulatory_update",
    "action_required": true,
    "action_deadline": "2026-04-01T00:00:00Z",
    "expires_at": "2026-04-30T23:59:59Z",
    "issued_by": "Banque Centrale du Ghana",
    "issued_at": "2026-03-19T08:00:00Z"
  }
}
```

**Comportement fan-out** : Une diffusion `target_scope: all` à 47 partenaires avec en moyenne 1,8 endpoint webhook chacun génère ~85 jobs, tous sur la file `webhooks`. Surveiller via le tableau de bord des files (`/admin/queues`).

**Pas d'événement `advisory.deactivated`** : La désactivation ne déclenche pas de webhook — elle retire uniquement l'avis de l'UI du portail partenaire.

## Notes pour l'équipe d'exploitation

- Les comptes régulateurs sont provisionnés manuellement — voir la section **Provisionnement du client OAuth** ci-dessus
- `target_scope: all` envoie à TOUS les partenaires actifs quel que soit leur niveau de plan — à utiliser avec précaution ; cela déclenche ~85 jobs webhook pour un déploiement typique
- Les avis désactivés sont supprimés de manière logique — ils restent dans la base de données à des fins d'audit ; accessibles via le panneau admin à `/admin/advisories`
- Les statistiques de livraison incluent les comptes partenaires `sandbox` — filtrer par `is_sandbox: false` si nécessaire pour les rapports de conformité
- Le champ `body` des avis supporte le Markdown — les liens, le gras et les listes s'affichent dans le portail partenaire
- Relancer les diffusions d'avis échouées : `php artisan advisories:retry-dispatch {uuid}` — idempotent par endpoint partenaire

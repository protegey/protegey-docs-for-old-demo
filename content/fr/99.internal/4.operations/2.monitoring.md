# Surveillance & Santé

## Points de terminaison de santé

### Sonde de disponibilité : `/ready`

```http
GET /ready
```

Vérification légère de disponibilité. Vérifie uniquement la connectivité à la base de données. Temps de réponse cible < 100 ms. Utilisé par les équilibreurs de charge et les orchestrateurs de conteneurs pour les contrôles de préparation.

**Réponse (sain)** :
```json
{ "status": "ok", "db": "connected", "latency_ms": 4 }
```

**Réponse (dégradé)** :
```json
{ "status": "degraded", "db": "error", "error": "Connection timeout after 5000ms" }
```

HTTP 200 si sain, HTTP 503 en cas d'échec.

### Contrôle de santé approfondi : `/health`

```http
GET /health
Authorization: Bearer {internal-token}  # or admin session
```

Contrôle de santé complet sur tous les composants du système. La réponse est mise en cache pendant 30 secondes pour éviter les surcharges lors des sondages de surveillance.

**Réponse** :
```json
{
  "status": "ok",
  "timestamp": "2026-03-16T10:00:00Z",
  "cache_age_seconds": 12,
  "components": {
    "database": { "status": "ok", "latency_ms": 3, "pool_size": 10, "active_connections": 2 },
    "redis": { "status": "ok", "latency_ms": 1, "memory_used_mb": 142 },
    "queue": { "status": "ok", "pending": 14, "failed": 0, "workers": 4 },
    "reverb": { "status": "ok", "connections": 87 },
    "graph_cache": { "status": "ok", "hit_rate": 0.94, "keys": 2841 },
    "osint_ingestion": { "status": "ok", "last_run": "2026-03-16T03:00:00Z", "records_processed": 14209 }
  }
}
```

## Surveillance des files d'attente

### Tableau de bord des files d'attente

Disponible dans le panneau d'administration à `/admin/queue`. Fournit :
- Compteurs en attente/en cours/échoués/terminés par file d'attente
- Tableau des tâches échouées avec aperçu de l'exception
- Relance en un clic (tâche individuelle ou en masse par file d'attente)
- Purge des tâches échouées (nécessite le rôle `super_admin`)

### Noms des files d'attente

| File d'attente | Fonction | Nombre de workers |
|----------------|----------|-------------------|
| `default` | Travaux asynchrones généraux | 2 |
| `signals` | Tâches d'ingestion de signaux (haute priorité) | 4 |
| `graph` | Mises à jour des nœuds et arêtes du graphe | 2 |
| `osint` | Ingestion OSINT, recalcul de fraîcheur | 1 |
| `webhooks` | Envoi de webhooks sortants | 2 |
| `compliance` | Traitement des SAR et indicateurs AML | 1 |
| `notifications` | Envoi par e-mail et push Reverb | 2 |

### Guide de dépannage des tâches échouées

1. **Vérifier l'exception** : Administration → File d'attente → Échouées → développer la tâche → consulter le champ `exception`
2. **Causes courantes** :
   - `ModelNotFoundException` : L'entité a été supprimée entre la mise en file d'attente et l'exécution — peut être ignorée en toute sécurité
   - `ConnectionException` (Redis) : Redémarrage du pod Redis — la relance est sans risque
   - `CentryContextException` : Tâche envoyée sans liaison de contexte — corriger le dispatcher, ne pas relancer sans correction du code
3. **Relancer une tâche individuelle** : `php artisan queue:retry {job-id}`
4. **Relancer toutes les tâches** : `php artisan queue:retry all` — à utiliser avec précaution sur la file `signals`
5. **Purger après investigation** : `php artisan queue:flush`

## Suivi des tâches contextualisées

Toutes les tâches étendant `ContextAwareJob` sérialisent le `CentryContext` (UUID partenaire + schéma) au moment de l'envoi. Cela garantit :
- Les tâches s'exécutent contre le schéma PostgreSQL correct (`public` vs `sandbox`)
- Les tâches échouées peuvent être attribuées au bon partenaire dans les journaux
- Les métriques de file d'attente peuvent être partitionnées par partenaire pour la surveillance des SLA

**Vérification** : Si une tâche échoue avec des erreurs liées à `search_path` ou `schema`, vérifiez qu'elle étend `ContextAwareJob` (et non la classe de base Laravel `Job`).

```php
// Correct
class ProcessSignalJob extends ContextAwareJob { ... }

// Incorrect — utilisera le search_path par défaut
class ProcessSignalJob extends Job { ... }
```

## Seuils d'alerte

À configurer dans votre système de surveillance (Grafana / Datadog) contre le point de terminaison `/health` :

| Métrique | Avertissement | Critique |
|----------|--------------|---------|
| `queue.failed` | > 10 | > 50 |
| `queue.pending` (signals) | > 500 | > 2000 |
| `graph_cache.hit_rate` | < 0,80 | < 0,60 |
| `database.latency_ms` | > 50 ms | > 200 ms |
| `redis.latency_ms` | > 10 ms | > 50 ms |
| Ancienneté de `osint_ingestion.last_run` | > 26 h | > 50 h |

## Objectif

Le système Audit Lineage enregistre une chaîne de traçabilité complète pour chaque alerte :

```
Signal reçu
  └─> Détecteurs exécutés (detector_executions)
        └─> Sévérité scorée (scoring_breakdown dans les métadonnées signal)
              └─> Taxonomie assignée (taxonomy_assignments)
                    └─> Alerte générée
                          └─> Lignage enregistré (alert_lineage)
                                └─> Exposé via GET /alerts/{uuid}/lineage
```

Cela satisfait les exigences d'explicabilité réglementaire et permet aux partenaires de comprendre _pourquoi_ une alerte a été générée via la fonctionnalité « Expliquer cette alerte ».

---

## Schéma

### `detector_executions`

Une ligne par détecteur par signal. Enregistre le résultat de chaque exécution de détecteur.

| Colonne | Type | Description |
|---|---|---|
| `id` | ULID | Clé primaire |
| `signal_id` | ULID | FK → `signals.id` |
| `detector_id` | string | Identifiant du détecteur (ex. `LARGE_OUTLIER_TRANSACTION`) |
| `fired` | boolean | Si le détecteur s'est déclenché |
| `confidence` | float | Confiance du détecteur (0,0–1,0) |
| `risk_score` | float | Contribution au risque de ce détecteur |
| `evidence` | JSON | Preuves clé-valeur du détecteur |
| `reasoning` | text | Explication facultative en langage naturel |
| `version` | string | Version du détecteur au moment de l'exécution |

### `alert_lineage`

Une ligne par alerte. Stocke la chaîne complète.

| Colonne | Type | Description |
|---|---|---|
| `id` | ULID | Clé primaire |
| `alert_uuid` | string | FK → `fraud_alerts.uuid` |
| `signal_id` | ULID | FK → `signals.id` |
| `taxonomy_primary` | string | ID de catégorie de taxonomie primaire |
| `taxonomy_all` | tableau JSON | Toutes les catégories de taxonomie assignées |
| `detector_results` | JSON | Instantané de tous les résultats d'exécution de détecteur |
| `features` | JSON | Valeurs des features signal au moment de la détection |
| `base_severity` | float | Sévérité de base avant boost |
| `final_severity` | float | Score de sévérité final après calcul |
| `source_confidence` | float | Confiance de la source du signal |
| `anomaly_factor` | float | Multiplicateur de détection d'anomalie |
| `explanation` | text | Explication auto-générée en langage naturel |

## API du service

### `LineageTrackingService::recordDetectorExecutions(Signal $signal, array $results): void`

Upsert des lignes `detector_executions` pour tous les détecteurs exécutés sur le signal. Appelé depuis l'écouteur `CalculateSignalSeverity`.

### `LineageTrackingService::recordAlertLineage(...): AlertLineage`

Construit et sauvegarde un enregistrement `alert_lineage`. Automatiquement :

1. Lit `taxonomy_assignments` depuis le signal
2. Construit l'instantané du détecteur depuis `$detectorResults`
3. Extrait les features des métadonnées du signal
4. Génère une chaîne d'`explanation` en langage naturel

Appelé de façon non fatale depuis l'écouteur `GenerateAlertForSignal` (enveloppé dans try/catch pour éviter de bloquer la création d'alerte).

### `LineageTrackingService::getAlertLineage(string $alertUuid): ?AlertLineage`

Renvoie le modèle `AlertLineage` pour un UUID d'alerte, ou `null` si non trouvé.

## Intégration dans le pipeline

```
CalculateSignalSeverity (écouteur)
  1. Exécuter les détecteurs via DetectorRegistry::detectMany()
  2. lineageService->recordDetectorExecutions(signal, results)
  3. scoringService->calculateScoringBreakdown(signal, firedIds)
  4. signal->update(['metadata' => [..., 'scoring_breakdown' => $breakdown]])
  5. taxonomyRegistry->assignTaxonomy(signal, detectorResults)

GenerateAlertForSignal (écouteur)
  1. alertService->generateAlertIfNeeded(signal) → $alert
  2. lineageService->recordAlertLineage($alert->uuid, $signal, ...)
     (non fatal — enveloppé dans try/catch)
```

## API côté partenaire

**Endpoint** : `GET /api/v1/partner/alerts/{uuid}/lineage`
**Gate feature** : `alert_management`

- Renvoie HTTP 200 dans les deux cas (lignage existant ou non)
- `available: true` avec données de lignage complètes si l'enregistrement existe
- `available: false` avec message descriptif si pas d'enregistrement (alertes pré-existantes)

---

## Génération d'explication

L'explication en langage naturel est générée par `buildExplanation()` (méthode privée dans `LineageTrackingService`). Format :

```
Alerte générée car {détecteur1} s'est déclenché (confiance : {n}) [et {détecteur2} s'est déclenché (confiance : {n})].
Taxonomie : {catégorie_primaire} (primaire).
Sévérité finale : {final} (base : {base}, confiance : {conf}, anomalie : {anomalie}x).
```

---

## Conception non fatale

L'enregistrement du lignage est intentionnellement non fatal. Si `recordAlertLineage()` lève une exception, un avertissement est journalisé mais l'alerte est quand même créée. Cela empêche les échecs de suivi du lignage de bloquer les opérations de détection de fraude.

Surveillance : Vérifier `Log::warning('Failed to record alert lineage', ...)` dans les logs applicatifs si les données de lignage semblent manquantes pour les alertes récentes.

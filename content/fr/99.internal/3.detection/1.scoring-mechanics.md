## Fusion pondérée des risques (v2.0 — Actuelle)

À partir de la v1.5.0, le score de risque final est calculé par `WeightedRiskFusionEngine`, qui combine quatre dimensions de scoring indépendantes :

| Dimension | Poids | Source |
|---|---|---|
| Comportemental | **35%** | Pipeline NUFSS (agrégat de la chaîne de détecteurs) |
| Réseau | **40%** | `HotGraphService::getNeighborhoodRisk()` — 1 + 2 sauts |
| Contextuel | **15%** | Contributions des features resolver (géo, temps, nouveauté appareil) |
| Historique | **10%** | Historique des risques d'entité (fenêtre glissante 90 jours) |

**Formule du score fusionné :**

```
fused_score = (behavioral × 0,35) + (network × 0,40) + (contextual × 0,15) + (historical × 0,10)
```

**Amplification graphe** — appliquée après la fusion :

- Si `network_score > 0,7` ET `behavioral_score > 0,5` : multiplier par `1,15`
- Si un voisin à 2 sauts a `risk_score > 0,9` : ajouter `+0,05` fixe
- Le score amplifié est plafonné à `1,0`

Le DTO complet `WeightedRiskScore` est stocké dans `alert_lineage` avec les champs par dimension : `behavioral_score`, `network_score`, `contextual_score`, `historical_score`, `fused_risk_score`.

### Risque réseau (40% de poids)

Calculé par `HotGraphService::getNeighborhoodRisk(nodeId, hops=2)` :

```
NeighborhoodRiskResult {
    direct_neighbors: int,
    avg_risk: float,
    max_risk: float,
    high_risk_count: int,
    propagated_risk: float   ← utilisé comme networkScore
}
```

Décroissance par saut : les voisins à 1 saut contribuent à `0,7` de poids, à 2 sauts à `0,3`.

Clés de cache d'adjacence Redis : `graph:1hop:{tenantId}:{node_id}`, `graph:2hop:{tenantId}:{node_id}`. TTL : 15 minutes.

### Calibration des seuils

Les scores fusionnés sont classifiés en niveaux de gravité par `ThresholdCalibrationService` :

- Les partenaires ont des seuils configurables stockés dans `partner_threshold_profiles`
- Valeurs par défaut : critique ≥ 0,80, élevé ≥ 0,60, moyen ≥ 0,40, faible < 0,40
- Multiplicateurs temporels : `off_hours`, `weekend`, `salary_week` — appliqués avant classification
- Plancher réglementaire : impossible de classifier comme `faible` si score fusionné ≥ `regulatory_floor` (par défaut 0,35)

## Pipeline NUFSS (composante comportementale)

Le **Network-Unified Fraud Severity Score** alimente la dimension comportementale à 35%. Calculé dans `FraudScoringService` :

```
behavioral_score = base_risk × source_confidence × anomaly_factor
```

| Composante | Source | Plage |
|---|---|---|
| `base_risk` | Recherche dans le Taxonomy Registry par `event_type` + boost détecteur | 0,3 – 1,0 |
| `source_confidence` | Champ `source_confidence` du signal | 0,0 – 1,0 |
| `anomaly_factor` | Multiplicateur `AnomalyDetectionService` | 1,0 – 1,5 |

### Boost de gravité détecteur

Lorsque les détecteurs déclenchés recoupent les `detectors_required` d'une entrée de taxonomie, `base_risk` reçoit un boost proportionnel (jusqu'à +0,10) :

```php
$boost = min(0.10, $matchRatio * 0.10);
$baseSeverity += $boost;
// $matchRatio = count(intersection) / count(detectors_required)
```

Les 9 détecteurs actifs :

**Détecteurs mono-signal (5)** :

- `RapidVelocityDetector` — fréquence de transactions dans des fenêtres courtes
- `LargeOutlierTransactionDetector` — montant > 3σ par rapport à l'historique de l'entité
- `SimSwapProximityDetector` — MSISDN lié à un échange SIM récent
- `NewDeviceAccessDetector` — premier appareil pour un acteur
- `ImpossibleTravelDetector` — mouvement géographique impossible dans le temps écoulé

**Détecteurs multi-signaux et multi-acteurs (4 — Phase S)** :

- `SessionAnomalyDetector` — dérive comportementale intra-session (fréquence, variance des montants, cohérence appareil)
- `AttackChainDetector` — séquences d'attaque multi-étapes via `AttackChainRegistry` ; chaînes livrées : `ATO_SIM_SWAP` (60 min), `SOCIAL_TO_PAYMENT` (120 min)
- `BeneficiaryConcentrationDetector` — grand nombre d'émetteurs distincts vers un même bénéficiaire dans le graphe
- `AgentConcentrationDetector` — même logique appliquée aux nœuds AGENT ; signale les identifiants d'agents utilisés par de nombreux acteurs distincts

## Scoring des règles AML (Enterprise — flag `risk_and_compliance`)

`TransactionMonitoringRulesService` évalue 11 règles AML par signal et persiste des enregistrements `AmlTransactionFlag` :

| Règle | Détection | Ajoutée |
|---|---|---|
| `structuring` | Transactions multiples juste en dessous du seuil (avec multiplicateur compte jeune) | v1.8 |
| `velocity_breach` | Nombre ou volume de Tx dépasse le seuil AML dans la fenêtre | v1.8 |
| `round_number` | Montant suspect à valeur ronde | v1.8 |
| `high_risk_jurisdiction` | `country_code` sur liste grise/noire GAFI | v1.8 |
| `mobile_money_velocity` | Vélocité excessive sur les canaux mobile money | v1.11 |
| `cross_border_corridor` | Schéma de transactions transfrontalières à haut risque | v1.11 |
| `dormant_account_activation` | Compte dormant réactivé brusquement avec volume élevé | v1.14 |
| `auto_str_correlation` | Co-occurrence `structuring` + `velocity_breach` dans 72h → brouillon SAR automatique | v1.11 |
| `ctr_equivalent_threshold` | Dépasse le seuil CTR équivalent local | v1.14 |
| `duplicate_identity` | Empreinte appareil liée à plusieurs identifiants d'acteurs distincts | v1.14.5 |
| `device_farm_detection` | Empreinte appareil accumule des signaux de nombreux acteurs distincts dans une courte fenêtre | v1.14.5 |

Les flags AML ne modifient pas directement le score fusionné — ils créent des enregistrements `aml_transaction_flags` et peuvent déclencher la création de SAR ou des actions de politique ESCALATE.

## Historique des risques d'entité (composante historique — 10% de poids)

`HistoricalRiskService::getHistoricalScore(entity)` :

- Interroge `fraud_entity_risk_histories` pour les 90 derniers jours
- Renvoie une moyenne pondérée glissante (0,0–1,0)
- Utilisé comme dimension `historical_score` dans la fusion pondérée

---

## Décroissance temporelle (signaux d'entité historiques)

Le score de risque agrégé de l'entité (distinct du score fusionné par signal) utilise une décroissance exponentielle :

```
decay = e^(-0,1 × jours_depuis_événement)
```

- **Demi-vie** : ~7 jours
- **Âge maximum** : 90 jours (poids effectivement nul)

## Politique de réglage

Les modifications des poids de fusion, des seuils par défaut, de la constante de décroissance ou des sévérités de base de la taxonomie nécessitent l'**approbation du CTO** et un backtest complet sur le `golden_dataset`.

## Couche de confiance OSINT

Les résultats du filtrage OSINT sont évalués avant de contribuer aux décisions de risque. La formule de confiance composite :

```
confidence = (authority × 0,40) + (freshness × 0,25) + (corroboration × 0,20) + (specificity × 0,15)
```

**Scores d'autorité** (statiques par source, depuis `config/osint.php`) :
- Liste consolidée du Conseil de sécurité de l'ONU : 1,00
- UE/OFAC : 0,95
- Conseil de paix et de sécurité de l'UA : 0,85
- Notices rouges INTERPOL : 0,80
- Listes nationales des CRF des États membres FATF : 0,75
- GIABA/ESAAMLG : 0,65
- OHADA : 0,55

**Fraîcheur** : Décroissance exponentielle `exp(-jours/365)`. Demi-vie ~253 jours. Recalculée hebdomadairement.

**Corroboration** : `min(1,0 ; 0,4 + (sources - 1) × 0,2)` — source unique = 0,40, 4+ sources = 1,00.

**Spécificité** : Nom + date de naissance + nationalité + identifiant = 1,00 → nom seul = 0,40.

**Contribution au risque** :
```php
$riskContribution = $match->is_exact_match
    ? 100 * $match->confidence_score   // exact: up to 100 pts
    : 50  * $match->confidence_score;  // partial: up to 50 pts
```

Seuil : confiance < 0,3 → révision manuelle uniquement, aucune contribution au blocage automatique.

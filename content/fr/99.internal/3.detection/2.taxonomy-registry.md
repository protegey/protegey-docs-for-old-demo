## Objectif

Le Taxonomy Registry remplace les mappings codés en dur `event_type → sévérité` dans `FraudScoringService` par un système compositionnel basé en base de données et sensible aux détecteurs. Cela permet :

- Le réglage de la sévérité par domaine sans déploiements de code
- Le boost de sévérité sensible aux détecteurs (les détecteurs renforcent la confiance de la taxonomie)
- La classification multi-étiquettes (un signal peut appartenir à plusieurs catégories)
- Une catégorisation de fraude auditable et explicable

## Schéma

### `taxonomy_registry`

| Colonne | Type | Description |
|---|---|---|
| `id` | ULID | Clé primaire |
| `category_id` | string | Identifiant en notation pointée (ex. `identity.account_takeover`) |
| `domain` | string | Domaine de niveau supérieur (`identity`, `payment`, `social`, `device`, `geo`) |
| `name` | string | Nom lisible par l'humain |
| `description` | text | Description de la catégorie |
| `base_severity` | float | Sévérité de base NUFSS (0,0–1,0) |
| `detectors_required` | tableau JSON | IDs de détecteurs qui indiquent fortement cette catégorie |
| `event_type_mappings` | tableau JSON | Valeurs `event_type` qui mappent à cette catégorie |
| `version` | string | Version SemVer |

### `taxonomy_assignments`

| Colonne | Type | Description |
|---|---|---|
| `id` | ULID | Clé primaire |
| `signal_id` | ULID | FK → `signals.id` |
| `taxonomy_id` | ULID | FK → `taxonomy_registry.id` |
| `category_id` | string | Dénormalisé pour recherche rapide |
| `confidence` | float | Confiance d'assignation (0,0–1,0) |
| `is_primary` | boolean | Si c'est la classification primaire |
| `assignment_method` | string | `event_type_mapping` ou `detector_overlap` |

## API du service

### `TaxonomyRegistry::getSeverityForEventType(string $eventType): float`

Recherche la `base_severity` pour l'`event_type` d'un signal. Renvoie `0,5` en secours si non trouvé. Les résultats sont mis en cache 5 minutes.

### `TaxonomyRegistry::getSeverityWithDetectorBoost(string $eventType, array $firedDetectorIds): float`

Renvoie `base_severity` plus un boost de chevauchement détecteur (jusqu'à +0,10). Utilisé par `FraudScoringService`.

### `TaxonomyRegistry::assignTaxonomy(Signal $signal, array $detectorResults): array`

Écrit des lignes `taxonomy_assignments` pour le signal :

1. **Assignation primaire** : Dérivée du mapping `event_type`
2. **Assignations secondaires** : Entrées de chevauchement détecteur où la confiance de chevauchement ≥ 0,5

Renvoie le tableau des modèles `TaxonomyAssignment` créés.

## Points d'intégration

- **`FraudScoringService::calculateScoringBreakdown()`** — appelle `getSeverityWithDetectorBoost()`
- **écouteur `CalculateSignalSeverity`** — appelle `assignTaxonomy()` après scoring
- **`LineageTrackingService::recordAlertLineage()`** — lit `taxonomy_assignments` pour l'enregistrement de lignage
- **`TaxonomyRegistrySeeder`** — ensemence 13 entrées canoniques ; exécuter pendant `db:seed`

---

## Réglage

Pour ajuster la sévérité d'une catégorie de taxonomie, mettez à jour directement la colonne `base_severity` dans `taxonomy_registry`. Les modifications prennent effet après l'expiration du cache (5 minutes) sans déploiements de code.

Pour ajouter de nouvelles catégories, créez une migration ou un seeder qui insère dans `taxonomy_registry`. Ajoutez les `event_type_mappings` correspondants pour garantir la classification automatique des signaux.

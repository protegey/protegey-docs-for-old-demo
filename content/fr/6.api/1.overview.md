# Aperçu de l'API

L'API Protegey est une interface RESTful conçue pour la prise de décision en matière de fraude en temps réel et à haute performance.

::callout{icon="i-lucide-lock" color="amber"}
**Accès Public Restreint** : Cette section fournit un aperçu conceptuel. La documentation complète de l'API (terminaisons, schémas, codes d'erreur) est disponible uniquement pour les partenaires approuvés dans la [Documentation Partenaire](/fr/partners).
::

## Philosophie de Conception

### 1. Orientée Ressources
L'API est organisée autour de ressources standard :
- `Signals` (Signaux) : Indicateurs de fraude soumis par les partenaires.
- `Queries` (Requêtes) : Demandes d'évaluation des risques.
- `Entities` (Entités) : Objets en cours d'analyse (utilisateurs, appareils, paiements).

### 2. Sécurisée par Défaut
- Toutes les terminaisons nécessitent HTTPS (TLS 1.3).
- Authentification via des clés API à forte entropie.
- La validation des entrées est stricte ; les requêtes malformées sont rejetées immédiatement.

### 3. Performance d'Abord
- Conçue pour des chemins de décision en moins d'une seconde.
- Traitement asynchrone pour les opérations non bloquantes.
- Mise en cache globale à la périphérie (edge) pour les actifs statiques.

## Modèles d'Intégration

Nous prenons en charge deux modèles d'intégration principaux :

### Synchrone (Requête de Risque)
Idéal pour la prise de décision en temps réel (ex : connexion, paiement).
1. Votre serveur envoie une `Requête` avec les détails de l'entité.
2. Protegey répond instantanément avec un `Score de Risque` et une `Recommandation`.
3. Votre application autorise ou bloque l'utilisateur en fonction de la réponse.

### Asynchrone (Soumission de Signal)
Idéal pour le signalement de fraudes confirmées ou les mises à jour en arrière-plan.
1. Votre serveur envoie un `Signal` (ex : "Chargeback reçu").
2. Protegey accepte le signal (`202 Accepted`).
3. Le signal est traité et propagé au réseau de manière asynchrone.

## Environnements

Nous fournissons deux environnements strictement isolés :

| Environnement | Objectif | Données |
|---------------|----------|---------|
| **Sandbox** | Tests d'intégration et développement | Données synthétiques/fictives uniquement |
| **Production** | Protection contre la fraude en direct | Intelligence réseau réelle |

::callout{icon="i-lucide-alert-circle" color="blue"}
**Note** : Les données ne circulent pas entre les environnements. Un signal créé en Sandbox n'affectera pas les scores de risque en Production.
::

## Versionnage

L'API est versionnée pour garantir la stabilité.
- Version actuelle : `v1`
- Les modifications rétrocompatibles (ajout de champs) sont effectuées sans changement de version.
- Les changements cassants nécessitent une nouvelle version (ex : `/api/v2/`).

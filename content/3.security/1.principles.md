# Security Principles

Security is the foundation of the Protegey platform. We treat your data with the same level of care and rigor as you do.

## Data Isolation

Protegey utilizes a **Partner-Centric Data Model**.

- **Logical Separation**: Every partner's data is logically isolated using unique identifiers (Partner UUIDs) at the database level.
- **Strict Access Control**: Intelligence signals are aggregated to create network effects, but raw PII (Personally Identifiable Information) is never shared between partners.
- **Encryption**: All sensitive data is encrypted at rest using AES-256 and in transit using TLS 1.3.

## API Security

Access to the Protegey API is strictly controlled.

- **key-pair Authentication**: We use a dual-key system (Public ID + Secret Key) for server-side integration.
- **Scope Limitations**: API keys are scoped to specific environments (Sandbox vs. Production) and permissions (Read vs. Write).
- **Rotation**: Partners can rotate secrets instantly via the Partner Portal key management interface.

::alert{type="warning"}
Never expose your **Secret Key** in client-side code or public repositories. If a leak is detected, the key will be automatically revoked.
::

## Compliance & Privacy

We are committed to data privacy and regulatory compliance.

- **GDPR & CCPA**: We act as a Data Processor. We provide tools for you (the Data Controller) to fulfill Right to be Forgotten (RTBF) and Data Access Requests (DSAR).
- **Data Minimization**: We only store the minimum data necessary to assess fraud risk. We treat all fields as potentially sensitive.

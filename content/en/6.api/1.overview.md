## Three Core Endpoints

| Endpoint | Type | Purpose | Latency |
|---|---|---|---|
| `POST /api/v1/signals` | Stateful | Ingest fraud events into the entity graph | Async-safe |
| `POST /api/v1/evaluate` | Stateless | Score raw identifiers in real time | < 100ms |
| `POST /api/v1/risk/assess` | Stateful | Full entity intelligence package | < 500ms |

Use `/signals` to feed the graph over time. Use `/evaluate` for real-time screening without persistence. Use `/risk/assess` when you need the full intelligence picture for a known entity.

Full reference documentation is available to approved partners: [Intelligence Model](/partners/api-reference/api-intelligence-model) · [Evaluate API](/partners/api-reference/evaluate) · [Signals API](/partners/api-reference/signals) · [Entity API](/partners/api-reference/entities)

## Design Philosophy

### 1. Resource-Oriented

The API is organized around standard resources:

- `Signals`: Indicators of fraud submitted by partners.
- `Queries`: Requests for risk assessment.
- `Entities`: Objects being analyzed (Users, Devices, Payments).

### 2. Secure by Default

- All endpoints require HTTPS (TLS 1.3).
- Authentication via high-entropy API keys.
- Input validation is strict; malformed requests are rejected immediately.

### 3. Performance-First

- Designed for sub-second decisioning paths.
- Asynchronous processing for non-blocking operations.
- Global edge caching for static assets.

## Integration Patterns

We support two primary integration patterns:

### Synchronous (Risk Query)

Best for real-time decisioning (e.g., login, checkout).

1. Your server sends a `Query` with entity details.
2. Protegey responds instantly with a `Risk Score` and `Recommendation`.
3. Your application allows or blocks the user based on the response.

### Asynchronous (Signal Submission)

Best for reporting confirmed fraud or background updates.

1. Your server sends a `Signal` (e.g., "Chargeback received").
2. Protegey accepts the signal (`202 Accepted`).
3. The signal is processed and propagated to the network asynchronously.

## Environments

We provide two strictly isolated environments:

| Environment    | Purpose                             | Data                      |
| -------------- | ----------------------------------- | ------------------------- |
| **Sandbox**    | Integration testing and development | Synthetic/Mock data only  |
| **Production** | Live fraud protection               | Real network intelligence |

::callout{icon="i-lucide-alert-circle" color="blue"}
**Note**: Data does not flow between environments. A signal created in Sandbox will not affect Production risk scores.
::

## Versioning

The API is versioned to ensure stability.

- Current Version: `v1`
- Backwards-compatible changes (adding fields) are made without version bumps.
- Breaking changes require a new version (e.g., `/api/v2/`).

KYB is implemented as a self-contained domain under `apps/core/app/Domain/` (currently co-located with `PartnerManagement`). It has its own service layer, action orchestrators, and async job pipeline. It consumes `SanctionsMatchingService` and `PEPDetectionService` from the existing Compliance domain.

---

## Service Map

| Service | Responsibility |
|---|---|
| `KybInviteService` | Create invites, validate tokens, resolve questionnaire defaults |
| `KybProgressService` | Create/upsert draft applications, save incremental answers |
| `KybSubmissionService` | Validate required completeness, submit application, handle resubmission |
| `KybDecisionService` | Record decisions, enforce terminal-state guard, write audit event |
| `KybRiskScreeningService` | Screen business name against sanctions + PEP, compute `KybRiskProfile` DTO, materialize entity, trigger EDD |
| `KybDocumentService` | Store files to S3 (`kyb` disk), delete from S3, return metadata |
| `KybAuditService` | Append typed events to `kyb_application_events` with actor context |

---

## Action Orchestrators

Actions are thin orchestrators — they call services in order and dispatch async jobs.

```
SendKybInviteAction
  └─ KybInviteService::createInvite()       [locks questionnaire]
  └─ SendKybInviteEmailJob::dispatch()      [async]

SubmitKybApplicationAction
  └─ KybSubmissionService::submit()         [validates + sets status=submitted]
  └─ NotifyPartnerNewApplicationJob::dispatch()   [async email]
  └─ ScreenKybApplicantJob::dispatch()      [async — risk screening]

DecideKybApplicationAction
  └─ KybDecisionService::decide()           [records decision, logs audit event]
  └─ if approved:
       KybRiskScreeningService::screen()    [sync — final screen before entity creation]
       KybRiskScreeningService::materializeEntity()
       KybRiskScreeningService::triggerEddIfRequired()
  └─ NotifyApplicantDecisionJob::dispatch() [async email]
```

## Async Jobs

All jobs extend `ContextAwareJob` — partner context is serialized at dispatch time.

| Job | Trigger | Notes |
|---|---|---|
| `SendKybInviteEmailJob` | Invite created | Sends email with signed portal link |
| `NotifyPartnerNewApplicationJob` | Application submitted | Notifies partner team |
| `ScreenKybApplicantJob` | Application submitted | Background screening; logs result via `KybAuditService` |
| `NotifyApplicantDecisionJob` | Decision recorded | Sends outcome email to applicant; includes reviewer notes for `more_info_required` |

## Application State Machine

```
                       invite sent
                           ↓
                        [draft]  ← getOrCreateApplication()
                           ↓
               applicant submits form
                           ↓
                       [submitted]
                           ↓
              partner opens detail view
                           ↓
                    [under_review]
                    ↙          ↘            ↓
              [approved]    [rejected]  [more_info_required]
               (terminal)   (terminal)       ↓
                                    applicant resubmits
                                           ↓
                                       [submitted]  (loop)
```

`ApplicationStatus::isTerminal()` returns `true` for `approved` and `rejected`. `KybDecisionService::decide()` checks this guard and throws if a terminal application is redecided.

## Questionnaire Locking Invariant

`KybInviteService::createInvite()` calls `$questionnaire->update(['is_locked' => true])` immediately after creating the invite record, within the same DB transaction. This prevents any concurrent `PUT /questionnaires/{uuid}` from modifying a questionnaire that already has pending applicants.

`PUT /partner/kyb/questionnaires/{uuid}` checks `is_locked` and returns `409 Conflict` if true.

Cloning (`POST /{uuid}/clone`) deep-copies all questions under a new UUID and `version`, always with `is_locked: false`.

## Risk Screening Integration

`KybRiskScreeningService::screen(KybApplication $app)`:

1. Extracts the business name from the answer where `is_screening_identifier = true`
2. Calls `SanctionsMatchingService::screenName($businessName)` — returns match score + risk level
3. Calls `PEPDetectionService::checkName($businessName)` — returns `is_pep` + designation if found
4. Queries `FraudCase` for existing cases linked to the business name hash
5. Returns immutable `KybRiskProfile` DTO: `{ risk_score, is_pep, sanctions_matched, sanctions_risk_level }`

`KybRiskScreeningService::materializeEntity(KybApplication, KybRiskProfile)`:
- Creates a `FraudEntity` with type `organisation`, seeded with the business name HMAC hash
- Sets `risk_score` from `KybRiskProfile`
- Links `entity_uuid` back to the application

`KybRiskScreeningService::triggerEddIfRequired(KybApplication, KybRiskProfile)`:
- EDD trigger condition: `risk_score > 0.75 OR is_pep = true OR sanctions_matched = true`
- Creates a `FraudCase` with `priority: high`, linked to the entity and application UUID
- Logs `edd_triggered` event via `KybAuditService`

## Token Security

- Token: `bin2hex(random_bytes(32))` — 64-char hex, cryptographically random
- Stored in plaintext in `kyb_invites.token` (no PII, no need to hash)
- `ResolveKybToken` middleware validates: token exists + `isUsable()` (status not `expired` or `submitted`)
- Single-use: status transitions prevent re-use after submission

## Middleware and Permissions

```
// Applicant portal — public, token-authenticated
Route::middleware('kyb.token')->prefix('kyb/apply/{token}')->group(...)

// Partner management — OAuth + permission gates
Route::middleware(['auth:api', 'permission:kyb.invite'])->group(...)
Route::middleware(['auth:api', 'permission:kyb.review'])->group(...)
Route::middleware(['auth:api', 'permission:kyb.manage'])->group(...)
```

`ResolveKybToken` middleware resolves the `KybInvite` from the token URL segment and binds it to the request. All applicant portal controllers receive it via dependency injection.

## Audit Event Types

All events written by `KybAuditService::log()`:

| Event type | Actor | Payload |
|---|---|---|
| `submitted` | applicant | — |
| `resubmitted` | applicant | — |
| `decided` | partner_user | `{ decision, old_status, new_status }` |
| `screened` | system | `{ risk_score, is_pep, sanctions_matched }` |
| `entity_created` | system | `{ entity_uuid }` |
| `edd_triggered` | system | `{ case_uuid, trigger_reason }` |

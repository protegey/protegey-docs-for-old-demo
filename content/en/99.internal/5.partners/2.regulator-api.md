# Regulator Advisory API

Regulators are provisioned as special accounts with `role: regulator` in the IAM system. They access the advisory broadcast API via a dedicated OAuth2 client. This page documents the regulator-facing endpoints that are **not** exposed in the partner-facing API docs.

---

## Authentication

Regulator accounts use the same OAuth2 flow as partners but receive a token with the `regulator` scope:

```http
POST /oauth/token
{
  "grant_type": "client_credentials",
  "client_id": "{regulator_client_id}",
  "client_secret": "{regulator_client_secret}",
  "scope": "regulator"
}
```

---

## Endpoints

### Broadcast Advisory

```http
POST /api/v1/regulator/advisories
Authorization: Bearer {regulator_token}
```

Creates and broadcasts an advisory to all partners in the specified target scope.

**Request Body**:

```json
{
  "title": "FATF Mutual Evaluation — Enhanced Monitoring Required",
  "body": "All partners operating in jurisdictions under enhanced monitoring must implement additional transaction screening by 2026-04-01.",
  "severity": "high",
  "category": "regulatory_update",
  "target_scope": "all",
  "expires_at": "2026-04-30T23:59:59Z",
  "action_required": true,
  "action_deadline": "2026-04-01T00:00:00Z"
}
```

| Field | Type | Description |
|-------|------|-------------|
| `title` | string | Max 255 chars |
| `body` | string | Full advisory text (Markdown supported) |
| `severity` | string | `critical`, `high`, `medium`, `low`, `info` |
| `category` | string | `regulatory_update`, `threat_intelligence`, `platform_notice`, `compliance_deadline` |
| `target_scope` | string | `all`, `enterprise`, or specific `partner_uuid` |
| `expires_at` | datetime | When the advisory expires (optional) |
| `action_required` | boolean | Whether partners must acknowledge |
| `action_deadline` | datetime | Deadline for required action (optional) |

**Response**: `201 Created` with the advisory UUID.

---

### Deactivate Advisory

```http
PATCH /api/v1/regulator/advisories/{uuid}/deactivate
Authorization: Bearer {regulator_token}
```

Immediately deactivates an advisory — it disappears from all partner portals and is no longer counted in unread badges. Use when an advisory was issued in error or is superseded.

**Response**: `200 OK` with updated advisory status.

---

### Delivery Statistics

```http
GET /api/v1/regulator/advisories/{uuid}/stats
Authorization: Bearer {regulator_token}
```

Returns delivery and acknowledgement statistics for a broadcast advisory.

**Response**:

```json
{
  "data": {
    "advisory_uuid": "adv_01HZ...",
    "title": "FATF Mutual Evaluation — Enhanced Monitoring Required",
    "total_recipients": 47,
    "delivered": 47,
    "read": 38,
    "acknowledged": 29,
    "dismissed": 3,
    "pending_acknowledgement": 15,
    "action_required": true,
    "action_deadline": "2026-04-01T00:00:00Z"
  }
}
```

## Rate Limits

Regulator tokens are subject to stricter rate limits than partner tokens — advisory broadcast is a high-fan-out operation.

| Endpoint | Limit | Window |
|----------|-------|--------|
| `POST /regulator/advisories` | 10 | per hour |
| `PATCH /regulator/advisories/{uuid}/deactivate` | 30 | per hour |
| `GET /regulator/advisories/{uuid}/stats` | 120 | per hour |

Exceeding limits returns `429 Too Many Requests` with a `Retry-After` header (seconds). Advisory broadcast requests that trigger fan-out to >100 partners are queued — the response returns immediately with `202 Accepted` and the advisory UUID; delivery is async.

---

## Error Codes

| Code | HTTP | Meaning |
|------|------|---------|
| `advisory_not_found` | 404 | UUID does not exist or belongs to a different regulator |
| `advisory_already_deactivated` | 409 | Advisory is already inactive — idempotent deactivate is safe to retry |
| `advisory_expired` | 422 | `expires_at` is in the past at broadcast time |
| `invalid_target_scope` | 422 | `target_scope` is not `all`, `enterprise`, or a valid partner UUID |
| `action_deadline_before_now` | 422 | `action_deadline` is in the past |
| `action_deadline_without_flag` | 422 | `action_deadline` supplied but `action_required: false` |
| `regulator_scope_missing` | 403 | Token does not carry the `regulator` scope |
| `regulator_account_suspended` | 403 | Regulator account is inactive — contact Protegey ops |
| `broadcast_fan_out_failed` | 500 | Queue dispatch error — advisory was saved but delivery jobs were not enqueued; re-trigger via `php artisan advisories:retry-dispatch {uuid}` |

## OAuth Client Provisioning

### Creating a Regulator Account

```bash
# 1. Create the regulator user + partner record
php artisan make:regulator "{institution_name}" "{admin_email}"
# Outputs: regulator UUID, generated password (one-time — send via secure channel)

# 2. Create the OAuth2 client_credentials client
php artisan passport:client --client --name="{institution_name} Regulator Client"
# Outputs: client_id and client_secret — store in 1Password under "Regulator OAuth Clients"
# These are shown ONCE; Passport does not expose the secret again after creation

# 3. Assign the regulator scope to the client
php artisan passport:scope --client-id={client_id} --scope=regulator
# Or set manually in the database:
# UPDATE oauth_clients SET personal_access_client = 0, password_client = 0 WHERE id = {client_id};
# The scope is enforced in RegulatorMiddleware — token must have 'regulator' in scopes array
```

### Rotating Client Credentials

Client secrets cannot be rotated in-place via Passport — the client must be recreated:

```bash
# 1. Create replacement client
php artisan passport:client --client --name="{institution_name} Regulator Client v2"

# 2. Assign scope
php artisan passport:scope --client-id={new_client_id} --scope=regulator

# 3. Share new credentials with regulator (secure channel)

# 4. After regulator confirms migration, revoke old tokens
php artisan passport:purge --revoked
# Then soft-delete old OAuth client:
# UPDATE oauth_clients SET revoked = 1 WHERE id = {old_client_id};
```

**Rotation window**: Allow at least 48 hours of parallel validity. Do not revoke the old client until the regulator confirms the new client is working in production.

### Suspending a Regulator Account

```bash
# Revoke all active tokens immediately
php artisan passport:purge --revoked --client-id={client_id}

# Disable the OAuth client
# UPDATE oauth_clients SET revoked = 1 WHERE id = {client_id};

# Mark the regulator partner record inactive
php artisan partner:deactivate {regulator_uuid} --reason="Suspended per ops ticket #OP-XXXX"
```

Suspended regulators receive `403 regulator_account_suspended` on all API calls. Their previously-broadcast advisories remain visible to partners (soft-deleted only on `deactivate` endpoint, not on account suspension).

## Webhook Events

### `advisory.created`

Fired for every partner in the target scope when an advisory is broadcast. Delivered via the partner's registered webhook endpoints that subscribe to this event type.

```json
{
  "event": "advisory.created",
  "delivery_id": "del_01HZ...",
  "timestamp": "2026-03-19T08:00:00Z",
  "data": {
    "advisory_uuid": "adv_01HZ...",
    "title": "FATF Mutual Evaluation — Enhanced Monitoring Required",
    "severity": "high",
    "category": "regulatory_update",
    "action_required": true,
    "action_deadline": "2026-04-01T00:00:00Z",
    "expires_at": "2026-04-30T23:59:59Z",
    "issued_by": "Central Bank of Ghana",
    "issued_at": "2026-03-19T08:00:00Z"
  }
}
```

**Fan-out behaviour**: Webhook delivery jobs are dispatched per partner per endpoint — a `target_scope: all` advisory to 47 partners with an average of 1.8 webhook endpoints each dispatches ~85 jobs. All jobs run on the `webhooks` queue. Monitor via the queue dashboard (`/admin/queues`).

**No `advisory.deactivated` event**: Deactivation does not fire a webhook — it only removes the advisory from the partner portal UI. If partners need real-time deactivation signals, they must poll `GET /api/v1/partner/advisories` (unread count drops to reflect removal).

## Notes for Ops Team

- Regulator accounts are provisioned manually — see **OAuth Client Provisioning** section above
- `target_scope: all` sends to ALL active partners regardless of plan tier — use carefully; this triggers ~85 webhook jobs for a typical deployment
- Deactivated advisories are soft-deleted — they remain in the DB for audit purposes; accessible via admin panel at `/admin/advisories`
- Delivery stats include `sandbox` partner accounts — filter by `is_sandbox: false` if needed for compliance reporting
- Advisory `body` supports Markdown — links, bold, and lists render in the partner portal; raw Markdown is stored in DB
- Re-dispatch failed advisory broadcasts: `php artisan advisories:retry-dispatch {uuid}` — safe to run multiple times (idempotent per partner endpoint)

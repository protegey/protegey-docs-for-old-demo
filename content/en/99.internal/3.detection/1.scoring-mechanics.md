## Weighted Risk Fusion (v2.0 — Current)

As of v1.5.0, the final risk score is computed by `WeightedRiskFusionEngine` which combines four independent scoring dimensions:

| Dimension  | Weight  | Source                                                     |
| ---------- | ------- | ---------------------------------------------------------- |
| Behavioral | **35%** | NUFSS pipeline (detector chain aggregate)                  |
| Network    | **40%** | `HotGraphService::getNeighborhoodRisk()` — 1 + 2 hop       |
| Contextual | **15%** | Resolver feature contributions (geo, time, device novelty) |
| Historical | **10%** | Entity risk history (rolling 90-day window)                |

**Fused score formula:**

```
fused_score = (behavioral × 0.35) + (network × 0.40) + (contextual × 0.15) + (historical × 0.10)
```

**Graph amplification** — applied after fusion:

- If `network_score > 0.7` AND `behavioral_score > 0.5`: multiply by `1.15`
- If any 2-hop neighbor has `risk_score > 0.9`: add flat `+0.05`
- Amplified score is capped at `1.0`

The full `WeightedRiskScore` DTO is stored in `alert_lineage` with per-dimension fields: `behavioral_score`, `network_score`, `contextual_score`, `historical_score`, `fused_risk_score`.

### Network Risk (40% weight)

Computed by `HotGraphService::getNeighborhoodRisk(nodeId, hops=2)`:

```
NeighborhoodRiskResult {
    direct_neighbors: int,
    avg_risk: float,
    max_risk: float,
    high_risk_count: int,
    propagated_risk: float   ← used as networkScore
}
```

Hop decay: 1-hop neighbors contribute at `0.7` weight, 2-hop at `0.3`.

Redis adjacency cache keys: `graph:1hop:{tenantId}:{node_id}`, `graph:2hop:{tenantId}:{node_id}`. TTL: 15 minutes.

### Threshold Calibration

Fused scores are classified into severity levels by `ThresholdCalibrationService`:

- Partners have configurable thresholds stored in `partner_threshold_profiles`
- Defaults: critical ≥ 0.80, high ≥ 0.60, medium ≥ 0.40, low < 0.40
- Time multipliers: `off_hours`, `weekend`, `salary_week` — applied before classification
- Regulatory floor: cannot classify as `low` if fused score ≥ `regulatory_floor` (default 0.35)

## NUFSS Pipeline (Behavioral Component)

The **Network-Unified Fraud Severity Score** feeds the 35% behavioral dimension. Computed in `FraudScoringService`:

```
behavioral_score = base_risk × source_confidence × anomaly_factor
```

| Component           | Source                                                    | Range     |
| ------------------- | --------------------------------------------------------- | --------- |
| `base_risk`         | Taxonomy Registry lookup by `event_type` + detector boost | 0.3 – 1.0 |
| `source_confidence` | Signal `source_confidence` field                          | 0.0 – 1.0 |
| `anomaly_factor`    | `AnomalyDetectionService` multiplier                      | 1.0 – 1.5 |

### Detector Severity Boost

When fired detectors overlap with a taxonomy entry's `detectors_required`, `base_risk` receives a proportional boost (up to +0.10):

```php
$boost = min(0.10, $matchRatio * 0.10);
$baseSeverity += $boost;
// $matchRatio = count(intersection) / count(detectors_required)
```

**9 active detectors** (as of v1.16.0):

#### Single-signal detectors

| Detector ID            | Class                              | Detection                                          | Max Risk |
| ---------------------- | ---------------------------------- | -------------------------------------------------- | -------- |
| `RAPID_VELOCITY`       | `RapidVelocityDetector`            | Transaction frequency spike in short windows       | 25       |
| `LARGE_OUTLIER`        | `LargeOutlierTransactionDetector`  | Amount > 3σ from entity rolling history            | 30       |
| `SIM_SWAP_PROXIMITY`   | `SimSwapProximityDetector`         | MSISDN linked to SIM swap within 24h               | 35       |
| `NEW_DEVICE_ACCESS`    | `NewDeviceAccessDetector`          | First-time device fingerprint for actor            | 25       |
| `IMPOSSIBLE_TRAVEL`    | `ImpossibleTravelDetector`         | Geographic movement impossible in elapsed time     | 35       |
| `SESSION_ANOMALY`      | `SessionAnomalyDetector`           | Bot-speed interaction or impossible concurrent sessions | 20  |

#### Cross-signal detectors (Phase S — v1.16.0)

| Detector ID                    | Class                               | Detection                                                    | Max Risk |
| ------------------------------ | ----------------------------------- | ------------------------------------------------------------ | -------- |
| `ATTACK_CHAIN`                 | `AttackChainDetector`               | Multi-step attack sequence for same actor in time window     | 40       |
| `BENEFICIARY_CONCENTRATION`    | `BeneficiaryConcentrationDetector`  | Many distinct senders → same beneficiary (mule/scam funnel)  | 35       |
| `AGENT_CONCENTRATION`          | `AgentConcentrationDetector`        | Many distinct actors cashing out through same agent node     | 35       |

**Attack chain registry** — `AttackChainDetector` reads from `AttackChainRegistry` (OCP pattern: adding a new chain requires only registering a `ChainPattern` value object; the detector class is never modified):

| Chain ID           | Precursor            | Terminal          | Window  | Confidence | Risk |
| ------------------ | -------------------- | ----------------- | ------- | ---------- | ---- |
| `ATO_SIM_SWAP`     | `ACCOUNT_TAKEOVER`   | `PAYMENT_FRAUD`   | 60 min  | 0.92       | 40   |
| `SOCIAL_TO_PAYMENT`| `SOCIAL_ENGINEERING` | `PAYMENT_FRAUD`   | 120 min | 0.80       | 32   |

All detectors implement `canDetect(Signal)` as a strict guard — if required fields are absent, they return `notDetected` without touching the DB. The pipeline runs with `continueOnFailure: true`; a detector exception returns `DetectorResult::failure()` and does not interrupt other detectors.

## AML Rule Scoring (Enterprise — `risk_and_compliance` flag)

`TransactionMonitoringRulesService` evaluates **11 configurable AML rules** per signal and persists `AmlTransactionFlag` records. All thresholds are DB-backed via `ConfigurableRuleEngine` with 3-layer resolution: platform defaults → partner overrides → resolved value.

| Rule                          | Added   | Detection                                                                   | Risk Contribution |
| ----------------------------- | ------- | --------------------------------------------------------------------------- | ----------------- |
| `structuring_detection`       | v1.14.0 | Multiple transactions just below reporting threshold (Layering / Smurfing). Optional `young_account_multiplier` amplifies risk for accounts under `min_account_age_hours`. | High |
| `velocity_1h_limit`           | v1.14.0 | Tx count or volume exceeds AML threshold within 1-hour rolling window       | High              |
| `high_risk_corridor`          | v1.14.0 | `country_code` is FATF grey or black list                                   | High              |
| `currency_transaction_report` | v1.14.0 | Single transaction exceeds CTR-equivalent reporting threshold               | High              |
| `mobile_money_velocity`       | v1.14.0 | Mobile money channel velocity breach (separate thresholds from card)        | High              |
| `cross_border_corridor`       | v1.14.0 | Cross-border transaction to high-risk jurisdiction                          | High              |
| `dormant_account_activation`  | v1.14.0 | Long-dormant account suddenly becomes active                                | Medium            |
| `auto_str_correlation`        | v1.14.0 | `structuring` + `velocity_breach` flags co-occur on same entity in window   | High (auto-SAR)   |
| `round_number_detection`      | v1.14.0 | Amount is a suspiciously round number                                       | Medium            |
| `duplicate_identity`          | v1.14.5 | Device (`USES_DEVICE` graph edge) shared with a high-risk actor — synthetic identity signal | 0.80 |
| `device_farm_detection`       | v1.14.5 | N+ distinct new entities on the same device in a rolling window (default threshold: 10) — agent-banking device farms and bot bulk account creation | 0.90 (critical) |

Partners with `risk_and_compliance` can tune thresholds (except system rules) via `PUT /compliance/rules/{uuid}/config`. System rules (`nufss_fusion_weights`, `sanctions_blocking`, `audit_log_creation`) cannot be disabled — returns 403.

**Cache isolation note** (v1.15.5+): `ConfigurableRuleEngine` clears its parameter cache at the start of each queue job. Without this, a slow worker could carry stale partner-specific thresholds from a previous job into the next job's AML evaluation.

AML flags do not directly modify the fused score — they create `aml_transaction_flags` records and may trigger SAR creation or ESCALATE policy actions.

## Entity Risk History (Historical Component — 10% weight)

`HistoricalRiskService::getHistoricalScore(entity)`:

- Queries `fraud_entity_risk_histories` for past 90 days
- Returns rolling weighted average (0.0–1.0)
- Used as the `historical_score` dimension in weighted fusion

## Time Decay (Legacy Entity Signals)

The entity's aggregate risk score (separate from per-signal fused score) uses exponential time decay:

```
decay = e^(-0.1 × days_since_event)
```

- **Half-life**: ~7 days
- **Max age**: 90 days (effectively 0 weight)

---

## Tuning Policy

Changes to fusion weights, threshold defaults, decay constant, or taxonomy base severities require **CTO approval** and a full backtest against the `golden_dataset`.

## OSINT Confidence Layer

OSINT screening results are scored before contributing to risk decisions. The composite confidence formula:

```
confidence = (authority × 0.40) + (freshness × 0.25) + (corroboration × 0.20) + (specificity × 0.15)
```

**Authority scores** (static per source, from `config/osint.php`):
- UN Security Council Consolidated List: 1.00
- EU/OFAC: 0.95
- African Union PSC: 0.85
- INTERPOL Red Notices: 0.80
- FATF member national FIU lists: 0.75
- GIABA/ESAAMLG: 0.65
- OHADA: 0.55

**Freshness**: Exponential decay `exp(-days/365)`. Half-life ~253 days. Recomputed weekly.

**Corroboration**: `min(1.0, 0.4 + (sources - 1) × 0.2)` — single source scores 0.40, 4+ sources score 1.00.

**Specificity**: Name + DOB + nationality + identifier = 1.00 → name only = 0.40.

**Risk contribution**:
```php
$riskContribution = $match->is_exact_match
    ? 100 * $match->confidence_score   // exact: up to 100 pts
    : 50  * $match->confidence_score;  // partial: up to 50 pts
```

Threshold: confidence < 0.3 → manual review only, no auto-block contribution.

## Purpose

The Taxonomy Registry replaces hardcoded `event_type → severity` mappings in `FraudScoringService` with a database-backed, detector-aware compositional system. This enables:

- Per-domain severity tuning without code deploys
- Detector-aware severity boosting (detectors reinforce taxonomy confidence)
- Multi-label classification (a signal can belong to multiple categories)
- Auditable, explainable fraud categorization

## Schema

### `taxonomy_registry`

| Column                | Type       | Description                                                         |
| --------------------- | ---------- | ------------------------------------------------------------------- |
| `id`                  | ULID       | Primary key                                                         |
| `category_id`         | string     | Dot-notation identifier (e.g. `identity.account_takeover`)          |
| `domain`              | string     | Top-level domain (`identity`, `payment`, `social`, `device`, `geo`) |
| `name`                | string     | Human-readable name                                                 |
| `description`         | text       | Category description                                                |
| `base_severity`       | float      | Base NUFSS severity (0.0–1.0)                                       |
| `detectors_required`  | JSON array | Detector IDs that strongly indicate this category                   |
| `event_type_mappings` | JSON array | `event_type` values that map to this category                       |
| `version`             | string     | SemVer version                                                      |

### `taxonomy_assignments`

| Column              | Type    | Description                                |
| ------------------- | ------- | ------------------------------------------ |
| `id`                | ULID    | Primary key                                |
| `signal_id`         | ULID    | FK → `signals.id`                          |
| `taxonomy_id`       | ULID    | FK → `taxonomy_registry.id`                |
| `category_id`       | string  | Denormalized for fast lookup               |
| `confidence`        | float   | Assignment confidence (0.0–1.0)            |
| `is_primary`        | boolean | Whether this is the primary classification |
| `assignment_method` | string  | `event_type_mapping` or `detector_overlap` |

## Service API

### `TaxonomyRegistry::getSeverityForEventType(string $eventType): float`

Looks up the `base_severity` for a signal's `event_type`. Returns `0.5` fallback if not found. Results are cached for 5 minutes.

### `TaxonomyRegistry::getSeverityWithDetectorBoost(string $eventType, array $firedDetectorIds): float`

Returns `base_severity` plus a detector overlap boost (up to +0.10). Used by `FraudScoringService`.

### `TaxonomyRegistry::assignTaxonomy(Signal $signal, array $detectorResults): array`

Writes `taxonomy_assignments` rows for the signal:

1. **Primary assignment**: Derived from `event_type` mapping
2. **Secondary assignments**: Detector overlap entries where overlap confidence ≥ 0.5

Returns the array of created `TaxonomyAssignment` models.

## Integration Points

- **`FraudScoringService::calculateScoringBreakdown()`** — calls `getSeverityWithDetectorBoost()`
- **`CalculateSignalSeverity` listener** — calls `assignTaxonomy()` after scoring
- **`LineageTrackingService::recordAlertLineage()`** — reads `taxonomy_assignments` for lineage record
- **`TaxonomyRegistrySeeder`** — seeds 13 canonical entries; run during `db:seed`

---

## Tuning

To adjust severity for a taxonomy category, update the `base_severity` column directly in `taxonomy_registry`. Changes take effect after cache expiry (5 minutes) without code deploys.

To add new categories, create a migration or seeder that inserts into `taxonomy_registry`. Add corresponding `event_type_mappings` to ensure signals are auto-classified.

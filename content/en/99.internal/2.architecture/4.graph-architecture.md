# Graph Architecture

## Overview

The hot graph is a real-time entity relationship store implemented on PostgreSQL (`graph_nodes` + `graph_edges` tables) with a Redis adjacency cache for sub-5ms traversal. It is designed for ingestion-path performance — every signal that enters the system updates the graph synchronously within the IngestSignalAction pipeline.

---

## Data Model

### `graph_nodes`

```sql
id              bigserial PRIMARY KEY
partner_uuid    uuid NOT NULL
entity_uuid     uuid REFERENCES fraud_entities(uuid)
node_type       varchar(50)  -- ACTOR, ACCOUNT, MSISDN, DEVICE, IP, MERCHANT, AGENT, BENEFICIARY
external_id     varchar(255) -- HMAC-SHA256 of the actual identifier
risk_score      int DEFAULT 0
metadata        jsonb
created_at      timestamptz
updated_at      timestamptz

INDEX: (partner_uuid, node_type, external_id)
INDEX: (partner_uuid, risk_score DESC)
```

### `graph_edges`

```sql
id              bigserial PRIMARY KEY
partner_uuid    uuid NOT NULL
source_node_id  bigint REFERENCES graph_nodes(id)
target_node_id  bigint REFERENCES graph_nodes(id)
edge_type       varchar(50)  -- USES_DEVICE, USES_PHONE, SENT_TO, RECEIVED_FROM, CASHED_OUT_AT, SHARED_IDENTIFIER
weight          float        -- 0.0–1.0 relationship strength
metadata        jsonb
first_seen_at   timestamptz
last_seen_at    timestamptz
signal_count    int DEFAULT 1

INDEX: (partner_uuid, source_node_id)
INDEX: (partner_uuid, target_node_id)
INDEX: (partner_uuid, edge_type, weight DESC)
```

## Redis Adjacency Cache

Cache key pattern: `graph:adj:{partner_uuid}:{node_id}`

Cache value: JSON array of `[target_node_id, edge_type, weight]` tuples for all outgoing edges.

TTL: **15 minutes** (configurable via `config/graph.php`).

Cache is populated lazily on first traversal and invalidated on edge upsert. A weekly `graph:rebuild-cache` job pre-warms all partner graphs.

```php
// Cache key format
$key = "graph:adj:{$partnerUuid}:{$nodeId}";

// Read adjacency list
$adjacency = Cache::store('redis')->get($key);

// Write on cache miss
Cache::store('redis')->put($key, $adjacency, seconds: 900);
```

## BFS Traversal

The `HotGraphService::getNeighborhood()` method uses an iterative BFS with the Redis cache as the primary read path:

```php
public function getNeighborhood(string $partnerUuid, int $nodeId, int $depth = 2): array
{
    $visited = [$nodeId];
    $queue   = [[$nodeId, 0]];
    $nodes   = [];

    while (!empty($queue) && count($nodes) < 200) {
        [$current, $currentDepth] = array_shift($queue);

        if ($currentDepth >= $depth) {
            continue;
        }

        $adjacency = $this->getAdjacency($partnerUuid, $current); // Redis or DB

        foreach ($adjacency as [$targetId, $edgeType, $weight]) {
            if (!in_array($targetId, $visited) && $weight >= 0.3) {
                $visited[]  = $targetId;
                $nodes[]    = ['id' => $targetId, 'depth' => $currentDepth + 1];
                $queue[]    = [$targetId, $currentDepth + 1];
            }
        }
    }

    return ['nodes' => $nodes, 'truncated' => count($nodes) >= 200];
}
```

**Edge pruning**: Edges with weight < 0.3 are excluded from traversal. This prevents weak correlations (e.g., shared ISP at country level) from inflating the neighborhood size.

## IDOR Protection

The graph API exposes node `external_id` values (HMAC hashes of real identifiers). To prevent cross-partner entity inference, all `external_id` values are masked before returning to the API layer:

```php
protected function maskExternalId(string $externalId): string
{
    return substr($externalId, 0, 8) . '****';
}
```

This means API consumers can recognize their own entities (by comparing the first 8 chars to their local hash records) but cannot reconstruct full hashes or match entities across partner accounts.

All graph queries are gated by `partner_uuid` at the DB level — it is architecturally impossible to traverse into another partner's graph nodes.

## Risk Propagation Formula

```php
$propagatedRisk = 0;
$totalWeight    = 0;

foreach ($neighbors as $neighbor) {
    $hopDecay    = pow(0.7, $neighbor['depth']); // 0.7 per hop
    $edgeWeight  = $neighbor['weight'];
    $contribution = $neighbor['risk_score'] * $edgeWeight * $hopDecay;
    $propagatedRisk += $contribution;
    $totalWeight    += $edgeWeight * $hopDecay;
}

$propagatedRisk = $totalWeight > 0 ? $propagatedRisk / $totalWeight : 0;

// Apply amplifier if any direct neighbor is high-risk
$highRiskCount = count(array_filter($neighbors, fn($n) => $n['risk_score'] > 80 && $n['depth'] === 1));
$amplifier     = min(15, $highRiskCount * 5); // max +15 pts
$networkScore  = min(100, $propagatedRisk + $amplifier);
```

## Integration with WeightedRiskFusionEngine

The hot graph contributes the `network_score` (40% weight) to the final fused risk score:

```
fused_score = (behavioral × 0.35) + (network × 0.40) + (contextual × 0.15) + (historical × 0.10)
```

`HotGraphService` is called synchronously in the ingestion path, after `FeatureEngineeringService` and before `WeightedRiskFusionEngine`. Graph computation must complete within the 50ms explainability target.

## Operational Notes

- **Graph cache miss rate** is tracked in the `/health` endpoint under `graph_cache_hit_rate`
- **Weekly rebuild job**: `graph:rebuild-adjacency-cache` — runs Sunday 02:00 UTC, uses queue `graph`
- **Edge weight decay**: Not currently implemented — edges don't decay over time. Phase 12 will introduce time-decayed edge weights in the cold graph
- **Node deduplication**: Nodes are keyed on `(partner_uuid, node_type, external_id)` — same entity appearing via different signals does not create duplicate nodes

Multi-step scenario simulation allows you to test complex fraud patterns that unfold over time, mimicking real-world attack patterns.

## Concept

Unlike single demo signals, **scenarios** generate a sequence of related signals that represent a coordinated fraud attack:

### Example: SIM Swap Drainage

1. **Step 1** (T+0 min): Initial account login from new device → Generates `ACCOUNT_TAKEOVER` signal
2. **Step 2** (T+5 min): Phone verification failure → Generates `PHONE_VERIFICATION_FAILURE` signal
3. **Step 3** (T+10 min): SIM swap detected → Generates `SIM_SWAP` signal
4. **Step 4** (T+12 min): High-value transfer to external account → Generates `TRANSACTION` signal (critical risk)
5. **Step 5** (T+15 min): Multiple small withdrawals → Generates multiple `TRANSACTION` signals (velocity pattern)

## Key Features (Planned)

### Consistent Actor Data

All steps in a scenario share the same actor identifiers (phone number, original device, etc.), creating a coherent fraud pattern:

```json
{
  "scenario_variables": {
    "SCENARIO_PHONE": "0244123456",
    "SCENARIO_ACCOUNT_ID": "ACC-12345"
  }
}
```

These variables are resolved once at scenario start and reused across all steps.

### Time-Based Delays

Scenarios unfold over realistic timeframes:

```json
{
  "step": 3,
  "delay": 600, // 10 minutes after scenario start
  "template": "sim_swap"
}
```

**Delay Modes**:

- **Real-time**: Actual delays (for live testing)
- **Fast-forward**: Accelerated delays (1 second = 1 minute) for quick testing
- **Immediate**: No delays (for bulk testing)

### Batch Tracking

All signals from a scenario are tagged with a shared batch ID:

```json
{
  "metadata": {
    "generated_by": "centry_scenario",
    "scenario_name": "sim_swap_drainage",
    "scenario_batch_id": "scenario_1738598400_abc123",
    "scenario_step": 3,
    "scenario_total_steps": 5
  }
}
```

This allows you to:

- Filter signals by scenario
- Track scenario completion
- Visualize attack timelines
- Test case linkage logic

### Simulation Events (Planned)

Scenarios emit real-time events during execution:

```json
{
  "event": "scenario.step_completed",
  "scenario_id": "scenario_1738598400_abc123",
  "step": 3,
  "total_steps": 5,
  "signals_created": 1,
  "next_step_delay": 120
}
```

## API Endpoints (Planned)

### List Available Scenarios

```bash
GET /api/v1/partner/sandbox/scenarios
```

**Response**:

```json
{
  "scenarios": [
    {
      "name": "sim_swap_drainage",
      "title": "SIM Swap Account Drainage",
      "description": "Simulates a coordinated SIM swap attack...",
      "steps": 5,
      "estimated_duration": "30 minutes",
      "risk_indicators": ["sim_swap", "velocity", "cross_border"]
    }
  ]
}
```

### Run a Scenario

```bash
POST /api/v1/partner/sandbox/simulate
{
  "scenario": "sim_swap_drainage",
  "mode": "fast-forward",
  "overrides": {
    "SCENARIO_PHONE": "0244123456"
  }
}
```

**Response**:

```json
{
  "scenario_id": "scenario_1738598400_abc123",
  "status": "running",
  "steps_completed": 0,
  "total_steps": 5,
  "estimated_completion": "2026-02-03T15:00:00Z",
  "tracking_url": "/api/v1/partner/sandbox/simulate/scenario_1738598400_abc123"
}
```

## Use Cases

### Test Case Linkage Logic

Run scenarios to verify that your fraud detection system correctly:

- Links related signals to the same actor
- Escalates from signals to alerts to cases
- Prioritizes cases based on pattern severity

### Test Investigation Workflows

Use scenarios to train analysts on:

- Recognizing coordinated attack patterns
- Triaging alerts by timeline
- Identifying modus operandi from signal sequences

### Test Alert Escalation

Verify that alert rules fire correctly as scenarios unfold:

- **After Step 1**: Low-priority alert (device change)
- **After Step 3**: High-priority alert (SIM swap detected)
- **After Step 5**: Critical alert (high-velocity drainage pattern)

### Performance Testing

Run multiple scenarios concurrently to test system load:

```bash
POST /api/v1/partner/sandbox/simulate-batch
{
  "scenarios": [
    {"scenario": "sim_swap_drainage", "count": 10},
    {"scenario": "account_takeover_cascade", "count": 5}
  ],
  "mode": "fast-forward"
}
```

## Current Workaround

Until multi-step scenarios are available, you can simulate multi-step patterns manually:

### Manual Multi-Step Simulation

```bash
# Step 1: Account takeover
POST /api/v1/partner/sandbox/generate-demo-signals
{
  "template": "transaction/account_takeover",
  "count": 1,
  "overrides": {
    "PHONE_NUMBER": "0244123456"
  }
}

# Wait 5 minutes or continue immediately for testing

# Step 2: SIM swap
POST /api/v1/partner/sandbox/generate-demo-signals
{
  "template": "identity/phone_verification_failure",
  "count": 1,
  "overrides": {
    "PHONE_NUMBER": "0244123456"
  }
}

# Step 3: High-value transaction
POST /api/v1/partner/sandbox/generate-demo-signals
{
  "template": "transaction/stolen_financials",
  "count": 1,
  "overrides": {
    "PHONE_NUMBER": "0244123456",
    "TRANSACTION_AMOUNT": 50000
  }
}
```

::callout{type="info"}
**Pro Tip**: Use consistent `overrides` across calls to simulate the same actor. This allows you to test entity linking and pattern detection logic.
::

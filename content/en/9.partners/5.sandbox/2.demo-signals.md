If you don't have real signal data yet, you can use our **Demo Signal Generator** to populate your sandbox with realistic scenarios.

## How to Generate Signals

1. Navigate to **Sandbox > Demo Signals** in the Partner Portal.
2. Select a **Signal Template** (e.g., Account Takeover).
3. Choose a **Volume Preset** (5, 20, or 100 signals).
4. Click **Generate Signals**.

## Available Templates

| Template                       | Scenario                                                       |
| ------------------------------ | -------------------------------------------------------------- |
| **Account Takeover**           | Simulates suspicious logins and unauthorized account activity. |
| **Stolen Financials**          | Simulates transactions using compromised payment methods.      |
| **Synthetic Identity**         | Simulates onboarding with fake or manipulated identity data.   |
| **Phone Verification Failure** | Simulates repeated failures in 2FA/KYC flows.                  |
| **External Fraud Report**      | Simulates incoming reports from external partner networks.     |

## Dynamic Risk Profiling

The demo signal generator uses **dynamic risk profiling** to create realistic testing scenarios. Each signal is automatically assigned a risk profile that influences multiple variables:

### Risk Distribution

| Risk Level   | Probability | Characteristics                                                                      |
| ------------ | ----------- | ------------------------------------------------------------------------------------ |
| **Critical** | 10%         | High amounts ($15k-$50k), cross-border transactions, high confidence (0.85-0.99)     |
| **High**     | 20%         | Amounts near thresholds ($9k-$14k), cross-border, medium-high confidence (0.75-0.90) |
| **Medium**   | 30%         | Moderate amounts ($1k-$5k), local transactions, medium confidence (0.50-0.75)        |
| **Low**      | 40%         | Small amounts ($10-$500), local transactions, high confidence (0.80-0.99)            |

### How Risk Profiling Works

The system automatically overrides template variables based on the selected risk profile:

**Transaction Amounts:**

- **Critical**: $15,000 - $50,000 (triggers amount anomaly detection)
- **High**: $9,000 - $14,000 (near threshold boundaries)
- **Medium**: $1,000 - $5,000 (normal range)
- **Low**: $10 - $500 (typical small transactions)

**Geographic Indicators:**

- **Critical/High**: Cross-border transactions (country code different from your partner country)
- **Medium/Low**: Local transactions (same country as partner)

**Source Confidence:**

- **Critical**: 0.85 - 0.99 (high confidence it's fraud)
- **High**: 0.75 - 0.90 (moderately high confidence)
- **Medium**: 0.50 - 0.75 (uncertain)
- **Low**: 0.80 - 0.99 (high confidence it's legitimate)

::callout{type="info"}
**Why This Matters**: The risk profiling system ensures your sandbox has a realistic mix of fraud signals, allowing you to test alert thresholds, case prioritization, and investigation workflows under realistic conditions.
::

## Variable Overrides

While the system automatically applies risk profiling, you can override specific variables when using the API directly:

```bash
POST /api/v1/partner/sandbox/generate-demo-signals
{
  "template": "account_takeover",
  "count": 10,
  "overrides": {
    "TRANSACTION_AMOUNT": 25000,
    "PHONE_NUMBER": "+233240000000",
    "COUNTRY_CODE": "GH"
  }
}
```

## Rate Limits

To ensure system stability, demo signal generation is limited to **3 requests per hour** per partner via the HTTP endpoint. For higher volume testing, use the [API Simulator](./api-simulator) CLI tool or the [Scenario Simulation](./scenarios) feature.

## Viewing Results

Once generated, signals will appear in your **Signal Logs** with a `Simulator` source tag and `generated_by: centry_demo` metadata. You can filter the logs by environment and source to isolate demo data.

### Signal Metadata

Each demo signal includes tracking metadata:

```json
{
  "metadata": {
    "generated_by": "centry_demo",
    "demo_batch": 1738598400,
    "demo_sequence": 1,
    "demo_risk_intent": "critical"
  }
}
```

This allows you to:

- Filter demo signals from real test data
- Track signal generation batches
- Analyze risk distribution accuracy
- Debug specific scenarios

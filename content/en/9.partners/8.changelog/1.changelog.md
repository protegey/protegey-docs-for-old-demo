# Changelog

## v1.8.0 (Current)
_Released: 2026-02-18_

### AML / Compliance Engine (RCaaS) — Enterprise

The Risk & Compliance as a Service pillar is now live for Enterprise partners with the `risk_and_compliance` feature flag enabled.

- **New**: Sanctions screening — entities are screened against OSINT pipeline data (UN, EU, AU sanctions lists) on every signal ingestion
- **New**: PEP detection — Politically Exposed Person flag via fuzzy name matching (≥85% similarity) against the `pep_designations` database
- **New**: Transaction monitoring rules — 4 AML rules evaluated per signal: structuring (amounts just below reporting thresholds), velocity breach, round-number transactions, high-risk jurisdiction (FATF grey/black list)
- **New**: Geographic risk scoring — per-country FATF status lookups (black list / grey list / compliant) with 30 country profiles seeded
- **New**: SAR workflow — Suspicious Activity Report lifecycle: draft → under review → filed → archived, with auto-generated narrative
- **New**: Compliance API — 14 new endpoints under `GET/POST /api/v1/partner/compliance/*` (dashboard, sanctions screening, SARs, compliance calendar, transaction flags, geo-risk)
- **New**: Compliance portal — 6 new partner portal pages: Compliance Dashboard, Sanctions Screening, SAR list + detail, Calendar, Transaction Flags

## v1.7.0
_Released: 2026-02-18_

### Multi-Endpoint Webhook Management

The webhook system has been fully redesigned. Partners can now register multiple webhook endpoints, each with its own secret, event subscriptions, and delivery log.

- **New**: `GET/POST /api/v1/partner/webhooks` — list and create webhook endpoints
- **New**: `GET/PUT/DELETE /api/v1/partner/webhooks/{id}` — manage individual endpoints
- **New**: `GET /api/v1/partner/webhooks/{id}/deliveries` — per-endpoint delivery log
- **New**: `POST /api/v1/partner/webhooks/{id}/deliveries/{deliveryId}/retry` — retry a failed delivery
- **New**: `POST /api/v1/partner/webhooks/{id}/test` — send a test ping to verify configuration
- **New**: Per-endpoint HMAC-SHA256 secrets — each endpoint has its own secret, revealed once on creation
- **New**: Per-endpoint event subscriptions — choose which event types each endpoint receives
- **Change**: Webhook signature header is now `X-Protegey-Signature` (was `X-Centry-Signature`)
- **Change**: Endpoints are automatically disabled after **3 consecutive delivery failures** (previously undocumented)
- **New events**: `alert.created`, `alert.status_changed`, `case.status_changed`, `case.priority_changed`, `case.assigned`, `entity.risk_changed`, `signal.ingested`

## v1.6.0
_Released: 2026-02-17_

### Decision Orchestration Layer

- **New**: Policy Engine — define YAML-based fraud policies (global, regulatory, partner tier) evaluated against full `DecisionContext` in <5ms
- **New**: Per-partner threshold calibration — `critical`, `high`, `medium`, `low` thresholds are now configurable per partner (replacing hardcoded 0.8/0.6/0.4 cutoffs)
- **New**: Decision explainability — every alert now carries a 3-tier explanation: partner-readable summary, regulatory-grade detail, and internal debug trace
- **New**: Cross-partner action routing — policy decisions (BLOCK, ESCALATE, SHARE) are routed to recipient partners using trust + consent gating
- **Improvement**: Alert lineage (`GET /api/v1/partner/alerts/{id}/lineage`) now includes full weighted risk score breakdown and policy match details

## v1.5.0
_Released: 2026-02-16_

### Graph Intelligence Engine + Weighted Risk Fusion

- **New**: Hot Graph — every ingested signal now builds and maintains a typed entity graph: ACTOR, ACCOUNT, DEVICE, MSISDN nodes with USES_DEVICE, USES_PHONE, SENT_TO, RECEIVED_FROM edges
- **New**: Weighted Risk Fusion — final risk score now combines 4 dimensions: Behavioral (35%), Network/Graph (40%), Contextual (15%), Historical (10%)
- **New**: Network risk propagation — if 1–2 hop graph neighbors have elevated risk scores, the fused score is amplified (up to 1.15×)
- **Improvement**: The entity risk score visible in `GET /api/v1/partner/entities/{id}` now reflects multi-dimensional fused scoring, not just behavioral signals
- **Improvement**: Alert severity classification now uses the full fused score, reducing false negatives for network fraud (fraud rings, mule accounts)

## v1.4.0
_Released: 2026-02-14_

### Collaborative Intelligence + OSINT

- **New**: Institution-to-institution alert sharing — partners can opt in to share alerts with other institutions via bilateral agreements. Three masking levels: full, partial, or metadata-only
- **New**: `GET/PUT /api/v1/partner/intelligence-sharing/config` — configure sharing preferences
- **New**: `GET/POST /api/v1/partner/intelligence-sharing/agreements` — manage bilateral sharing agreements
- **New**: `GET /api/v1/partner/intelligence-sharing/received` — received intelligence feed (paginated)
- **New**: Regulator advisory inbox — regulators can broadcast jurisdiction-scoped advisories to all connected partners
- **New**: `GET /api/v1/partner/advisories` — advisory inbox with unread count
- **New**: `GET /api/v1/partner/advisories/{uuid}` — advisory detail (marks read on fetch)
- **New**: OSINT ingestion — UN, EU, and AU sanctions lists are ingested daily at 03:00 UTC and matched against entity profiles using fuzzy entity resolution
- **New**: SemVer enforcement — detector versions and taxonomy entries now enforce semantic versioning at registration time

## v1.3.0
_Released: 2026-02-11_

- **New Feature**: Alert lineage endpoint — `GET /api/v1/partner/alerts/{uuid}/lineage` returns the full audit chain (detectors, features, scoring breakdown) for every alert. Powers the "Explain This Alert" UI in the Partner Portal.
- **New Feature**: Taxonomy Registry — fraud categories are now database-backed and detector-aware. Severity scores reflect compositional fraud taxonomy rather than hardcoded event-type mappings.
- **New Feature**: Multi-label fraud classification — a signal can now receive multiple taxonomy labels (e.g. `identity.account_takeover` + `device.anomaly`).
- **Improvement**: Detector execution records (`detector_executions` table) enable false-positive rate analytics per detector.
- **Fix**: Analytics date filtering now returns correct results when `from`/`to` parameters are date-only strings (e.g. `2026-02-11`). Previously, date-only `to` values were treated as midnight, excluding same-day records.
- **Fix**: Sandbox reset no longer returns a 500 error when signals have dependent records in related tables.

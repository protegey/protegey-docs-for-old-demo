The Team Management API allows partners to programmatically manage their organization's team members, invite new users, and control access to the Protegey platform.

::callout{type="info"}
**Feature Gate**: Team management is available on Business and Enterprise plans. **Access Level**: Read/Write (requires admin privileges).
::

## Authentication

All team management endpoints require OAuth2 Bearer token authentication with admin privileges:

```bash
Authorization: Bearer YOUR_ACCESS_TOKEN
```

::callout{type="warning"}
**Admin Access Required**: You must be authenticated as a partner administrator to use these endpoints. Regular team members cannot access team management APIs.
::

## Rate Limits

- **List Team Members**: 60 requests per minute
- **Invite Team Member**: 20 requests per hour
- **Remove Team Member**: 20 requests per hour

---

## List Team Members

**GET** `/api/v1/partner/team`

Retrieve a list of all team members in your partner organization, including their roles, status, and activity information.

### Request Example

```bash
curl -X GET "https://api.protegey.com/api/v1/partner/team" \
  -H "Authorization: Bearer YOUR_ACCESS_TOKEN"
```

**Response Fields**:

| Field | Description |
|-------|-------------|
| `id` | User unique identifier |
| `name` | Full name (first name + last name) |
| `first_name` | First name |
| `last_name` | Last name |
| `email` | Email address |
| `role` | User role display name |
| `is_active` | Whether user account is active |
| `created_at` | When user was added to organization |
| `last_login_at` | Last login timestamp (null if never logged in) |

**Status Codes**:
- `200 OK` - Success
- `401 Unauthorized` - Invalid or missing authentication token
- `403 Forbidden` - User does not belong to a partner or insufficient permissions

## Invite Team Member

**POST** `/api/v1/partner/team`

Invite a new team member to your partner organization. An account will be created and the user will receive invitation instructions.

### Request Body

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `first_name` | string | Yes | First name (max 255 characters) |
| `last_name` | string | Yes | Last name (max 255 characters) |
| `email` | string | Yes | Email address (must be unique) |

::callout{type="info"}
**Automatic Role Assignment**: New team members are automatically assigned the "Partner Administrator" role. Role management will be available in a future update.
::

### Request Example

```bash
curl -X POST "https://api.protegey.com/api/v1/partner/team" \
  -H "Authorization: Bearer YOUR_ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "first_name": "Emma",
    "last_name": "Williams",
    "email": "emma@example.com"
  }'
```

### Response Example

**Success (201 Created)**:

```json
{
  "message": "Team member invited successfully.",
  "user": {
    "id": 45,
    "name": "Emma Williams",
    "email": "emma@example.com",
    "role": "Partner Administrator",
    "is_active": true,
    "created_at": "2026-02-03T15:45:00Z"
  }
}
```

**Status Codes**:
- `201 Created` - Team member invited successfully
- `400 Bad Request` - Invalid request body
- `401 Unauthorized` - Invalid authentication
- `403 Forbidden` - User does not belong to a partner or insufficient permissions
- `422 Unprocessable Entity` - Validation errors (e.g., email already exists)

### Validation Errors Example

```json
{
  "message": "The given data was invalid.",
  "errors": {
    "email": ["The email has already been taken."],
    "first_name": ["The first name field is required."]
  }
}
```

::callout{type="success"}
**Invitation Process**: After creating the account, Protegey sends an invitation email with setup instructions. The initial password is generated automatically and included in the invitation email (or available via password reset).
::

## Remove Team Member

**DELETE** `/api/v1/partner/team/{id}`

Remove a team member from your partner organization. This permanently deletes the user account.

::callout{type="danger"}
**Permanent Deletion**: This action is irreversible. The user will lose access to all partner data, cases, and investigations. Consider deactivating users instead if you need to preserve audit trails.
::

### Path Parameters

| Parameter | Type | Description |
|-----------|------|-------------|
| `id` | integer | User ID to remove |

### Request Example

```bash
curl -X DELETE "https://api.protegey.com/api/v1/partner/team/45" \
  -H "Authorization: Bearer YOUR_ACCESS_TOKEN"
```

### Response Example

**Success (200 OK)**:

```json
{
  "message": "Team member removed successfully."
}
```

**Status Codes**:
- `200 OK` - Team member removed successfully
- `400 Bad Request` - Cannot remove yourself
- `401 Unauthorized` - Invalid authentication
- `403 Forbidden` - User does not belong to a partner or insufficient permissions
- `404 Not Found` - User not found in your organization

### Self-Removal Prevention

```json
{
  "message": "You cannot remove yourself."
}
```

::callout{type="warning"}
**Self-Removal Protection**: You cannot remove your own account via API. To leave the organization, use the Partner Portal settings or contact another administrator.
::

## User Roles

Protegey supports role-based access control (RBAC) for team members:

| Role | Description | Permissions |
|------|-------------|-------------|
| **Partner Administrator** | Full access to partner organization | All permissions (manage team, cases, settings, billing) |
| **Fraud Analyst** | Investigation and case management | View/manage cases, alerts, entities; no admin access |
| **Read-Only Analyst** | View-only access | View cases, alerts, signals; cannot modify |
| **Member** | Basic access | Limited to assigned cases and alerts |

::callout{type="info"}
**Coming Soon**: Granular role management and custom role creation will be available in a future update. Currently, all invited users are assigned "Partner Administrator" role.
::

## Best Practices

### Team Onboarding Workflow

**Bulk Team Invitation**:
```javascript
const newMembers = [
  { first_name: 'John', last_name: 'Doe', email: 'john@example.com' },
  { first_name: 'Jane', last_name: 'Smith', email: 'jane@example.com' },
  { first_name: 'Bob', last_name: 'Johnson', email: 'bob@example.com' }
];

// Invite each member
for (const member of newMembers) {
  try {
    const result = await client.team.invite(member);
    console.log(`✅ Invited: ${result.user.email}`);
  } catch (error) {
    console.error(`❌ Failed: ${member.email} - ${error.message}`);
  }
}
```

### Team Audit and Cleanup

**Identify Inactive Users**:
```javascript
// Get all team members
const team = await client.team.list();

// Find inactive users (no login in 90 days)
const ninetyDaysAgo = new Date();
ninetyDaysAgo.setDate(ninetyDaysAgo.getDate() - 90);

const inactiveUsers = team.filter(user => {
  const lastLogin = new Date(user.last_login_at);
  return lastLogin < ninetyDaysAgo;
});

console.log(`Inactive users: ${inactiveUsers.length}`);

// Review and potentially remove
for (const user of inactiveUsers) {
  console.log(`${user.name} (${user.email}) - Last login: ${user.last_login_at}`);
  // Decide whether to remove or keep
}
```

### Access Control Management

**Enforce Security Policies**:
```javascript
// Regular team audit
const team = await client.team.list();

// Check for users who never logged in (potential security risk)
const neverLoggedIn = team.filter(user => user.last_login_at === null);

if (neverLoggedIn.length > 0) {
  console.warn(`${neverLoggedIn.length} users have never logged in`);

  // Auto-remove invitations older than 30 days
  for (const user of neverLoggedIn) {
    const invitedDaysAgo = daysSince(user.created_at);

    if (invitedDaysAgo > 30) {
      console.log(`Removing stale invitation: ${user.email}`);
      await client.team.remove(user.id);
    }
  }
}
```

## Integration Examples

### Sync with HR Systems

**Automated Team Synchronization**:
```javascript
// Fetch employees from HR system
const hrEmployees = await fetchFromHRSystem();

// Get current Protegey team
const protegeyTeam = await client.team.list();

// Find employees who should be added
const emailsInProtegey = new Set(protegeyTeam.map(u => u.email));
const toAdd = hrEmployees.filter(emp => !emailsInProtegey.has(emp.email));

// Invite new employees
for (const emp of toAdd) {
  await client.team.invite({
    first_name: emp.firstName,
    last_name: emp.lastName,
    email: emp.email
  });
  console.log(`Added: ${emp.email}`);
}

// Find employees who left (should be removed)
const emailsInHR = new Set(hrEmployees.map(emp => emp.email));
const toRemove = protegeyTeam.filter(user => !emailsInHR.has(user.email));

// Remove ex-employees
for (const user of toRemove) {
  await client.team.remove(user.id);
  console.log(`Removed: ${user.email}`);
}
```

## Error Handling

### Common Error Codes

| Status Code | Error | Cause | Solution |
|-------------|-------|-------|----------|
| `400 Bad Request` | `Cannot remove yourself` | Attempting self-removal | Have another admin remove your account |
| `403 Forbidden` | `Insufficient permissions` | Non-admin user attempting team management | Authenticate as admin |
| `404 Not Found` | `User not found` | User ID doesn't exist in organization | Verify user ID from team list |
| `422 Unprocessable Entity` | `Email already taken` | Email address already registered | Use different email address |

### Example Error Response

```json
{
  "message": "The given data was invalid.",
  "errors": {
    "email": ["The email has already been taken."]
  }
}
```

## FAQ

**Q: Can I assign specific roles when inviting users?**
A: Not yet via API. All invited users are currently assigned "Partner Administrator" role. Granular role management is planned for a future update. You can change roles manually in the Partner Portal.

**Q: What happens to cases assigned to a removed user?**
A: Cases remain in the system but become unassigned. You should reassign cases before removing team members to maintain investigation continuity.

**Q: Can I deactivate users instead of deleting them?**
A: User deactivation is not available via API currently. The `DELETE` endpoint permanently deletes users. For audit trail preservation, consider keeping inactive users and managing access via the Partner Portal.

**Q: How many team members can I have?**
A: Team size limits depend on your subscription plan:
- **Professional**: Up to 5 team members
- **Business**: Up to 20 team members
- **Enterprise**: Unlimited team members

**Q: Do removed users count against my team member limit?**
A: No, only active users count against your plan limit.

**Q: Can team members access sandbox and production environments?**
A: Yes, team members inherit the partner's environment access. Sandbox and production access is controlled at the partner level, not per user.

**Q: What happens when I invite a user who already has a Protegey account?**
A: If the email is already registered, the invitation will fail with a `422 Unprocessable Entity` error. Contact support to transfer existing accounts between organizations.

**Q: How are invitation emails sent?**
A: Protegey automatically sends invitation emails with setup instructions and initial access details. Ensure your organization's email domain is not blocking emails from `noreply@protegey.com`.

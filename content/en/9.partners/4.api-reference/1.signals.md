# Signals API

The Signals API enables partners to submit fraud indicators to the network. Signals are ingested asynchronously and processed by the Risk Engine.

::callout{icon="i-lucide-shield-alert" color="amber"}
**Production Access Required**: You must have active production keys to post live signals. Sandbox signals do not affect network scores.
::

## Endpoint

```http
POST /api/v1/signals
```

## Request Schema

### Headers

| Header | Value | Required | Description |
|--------|-------|----------|-------------|
| `Content-Type` | `application/json` | Yes | Standard JSON payload. |
| `X-Centry-Key` | `cen_live_sk_...` | Yes | Your Production Secret Key. |

### Body Parameters

The payload is structured into `actor`, `event`, and `transaction` objects.

```typescript
interface SignalRequest {
  actor: {
    hashed_id: string; // The primary entity identifier (hashed or plain)
    device_fingerprint?: string;
    region?: string;
  };
  event: {
    type: string; // The fraud signal (e.g., ACCOUNT_TAKEOVER)
    timestamp: string; // ISO 8601 (e.g., 2026-01-12T14:30:00Z)
    channel?: string; // WEB, MOBILE, API, etc.
  };
  transaction?: {
    amount?: number;
    currency?: string; // ISO 4217 (3 chars)
    geo_location?: {
      lat: number;
      lon: number;
    };
  };
  source_confidence?: number; // 0.0 to 1.0 (default: 0.5)
  metadata?: Record<string, any>;
}
```

### Validation Rules

| Field | Required | Rules |
|-------|----------|-------|
| `actor.hashed_id` | **Yes** | String. The identifier of the entity (e.g. SHA-256 hash or raw value). |
| `event.type` | **Yes** | Must match a valid code (e.g., `ACCOUNT_TAKEOVER`, `SYNTHETIC_IDENTITY`). |
| `event.timestamp` | **Yes** | ISO 8601. Cannot be in the future. |
| `transaction.currency` | No | Must be exactly 3 characters if provided. |
| `transaction.geo_location` | No | Both `lat` and `lon` required if object exists. |
| `source_confidence` | No | Float between 0.0 and 1.0. |

## Examples

### 1. Standard Submission

```bash
curl -X POST "https://api.protegey.com/v1/signals" \
  -H "Content-Type: application/json" \
  -H "X-Centry-Key: cen_live_sk_..." \
  -d '{
    "actor": {
      "hashed_id": "e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855",
      "region": "US"
    },
    "event": {
      "type": "ACCOUNT_TAKEOVER",
      "timestamp": "2026-01-12T14:30:00Z",
      "channel": "MOBILE"
    },
    "source_confidence": 0.9,
    "metadata": {
      "detection_method": "behavioral_biometrics"
    }
  }'
```

### 2. Transaction Signal

```bash
curl -X POST "https://api.protegey.com/v1/signals" \
  -H "Content-Type: application/json" \
  -H "X-Centry-Key: cen_live_..." \
  -d '{
    "actor": {
      "hashed_id": "user@example.com"
    },
    "event": {
      "type": "STOLEN_FINANCIALS",
      "timestamp": "2026-01-12T14:30:00Z"
    },
    "transaction": {
      "amount": 4500.00,
      "currency": "USD",
      "geo_location": {
        "lat": 37.7749,
        "lon": -122.4194
      }
    }
  }'
```

## Response

### Success Response (`201 Created`)

```json
{
  "success": true,
  "data": {
    "signal_id": "9df4a3b1-...",
    "status": "received",
    "event_type": "ACCOUNT_TAKEOVER",
    "timestamp": "2026-01-12T14:30:00+00:00"
  },
  "message": "Signal received and queued for processing"
}
```

### Error Response (`422 Unprocessable Content`)

```json
{
    "message": "The event.type field is required.",
    "errors": {
        "event.type": [
            "The event.type field is required."
        ]
    }
}
```

The Transaction Monitoring API provides comprehensive endpoints for reviewing fraud signals, making decisions, analyzing patterns, and tracking performance metrics. This is the primary interface for fraud analysts to manage the transaction review workflow.

::callout{icon="i-lucide-shield-check" color="blue"}
**Real-Time Monitoring**: All endpoints support real-time polling with optimized filtering and pagination for high-volume transaction streams.
::

---

## Overview

### Core Capabilities

- **Transaction Feed**: Real-time signal monitoring with extensive filtering
- **Decision Making**: Single and bulk transaction decisions
- **Analytics**: Comprehensive fraud analytics and trends
- **Performance Tracking**: Reviewer and team performance metrics
- **Risk Analysis**: Detailed risk factor breakdown and heatmaps
- **Assignment Management**: Transaction assignment and workload distribution
- **Data Export**: CSV export for reporting and compliance

### Authentication

All endpoints require OAuth2 Bearer token authentication:

```bash
Authorization: Bearer YOUR_ACCESS_TOKEN
```

## Endpoints

### List Transactions

**GET** `/api/v1/transaction-monitoring`

Retrieve paginated transaction feed with extensive filtering and search capabilities.

**Query Parameters**:

| Parameter     | Type    | Required | Default    | Description                                                    |
| ------------- | ------- | -------- | ---------- | -------------------------------------------------------------- |
| `page`        | integer | No       | 1          | Page number (starts at 1)                                      |
| `per_page`    | integer | No       | 20         | Items per page (max 100)                                       |
| `status`      | string  | No       | all        | Filter by status: `pending`, `approved`, `declined`, `flagged` |
| `risk_level`  | string  | No       | all        | Filter by risk: `low`, `medium`, `high`, `critical`            |
| `start_date`  | string  | No       | -          | Start date (ISO 8601: `2026-02-01`)                            |
| `end_date`    | string  | No       | -          | End date (ISO 8601: `2026-02-28`)                              |
| `search`      | string  | No       | -          | Search by transaction ID, entity identifier, or metadata       |
| `assigned_to` | integer | No       | -          | Filter by assigned user ID                                     |
| `unassigned`  | boolean | No       | false      | Show only unassigned transactions                              |
| `sort_by`     | string  | No       | created_at | Sort field: `created_at`, `risk_score`, `amount`               |
| `sort_order`  | string  | No       | desc       | Sort order: `asc`, `desc`                                      |
| `event_type`  | string  | No       | -          | Filter by fraud event type (e.g., `ACCOUNT_TAKEOVER`)          |
| `min_amount`  | number  | No       | -          | Minimum transaction amount                                     |
| `max_amount`  | number  | No       | -          | Maximum transaction amount                                     |

**Response (200 OK)**:

```json
{
  "data": [
    {
      "id": "sig_abc123",
      "transaction_id": "TXN-20260203-001",
      "event_type": "ACCOUNT_TAKEOVER",
      "risk_score": 87,
      "risk_level": "high",
      "status": "pending",
      "actor": {
        "hashed_id": "hash_0244567890",
        "entity_uuid": "ent_xyz789"
      },
      "transaction": {
        "amount": 15000.0,
        "currency": "GHS",
        "timestamp": "2026-02-03T14:30:00Z"
      },
      "metadata": {
        "country_code": "NG",
        "device_fingerprint": "d3v1c3-f1ng3rpr1nt"
      },
      "assigned_to": null,
      "created_at": "2026-02-03T14:30:00Z",
      "updated_at": "2026-02-03T14:30:00Z"
    }
  ],
  "meta": {
    "current_page": 1,
    "per_page": 20,
    "total": 247,
    "last_page": 13
  }
}
```

**SDK Examples**:

::code-group

```typescript [TypeScript]
import { ProtegeyClient } from "@protegey/api-client";

const client = new ProtegeyClient({ accessToken: "YOUR_TOKEN" });

// Get pending high-risk transactions
const transactions = await client.transactionMonitoring.list({
  status: "pending",
  risk_level: "high",
  per_page: 50,
  sort_by: "risk_score",
  sort_order: "desc",
});

console.log(`Found ${transactions.meta.total} high-risk transactions`);
```

```python [Python]
from protegey import ProtegeyClient

client = ProtegeyClient(access_token='YOUR_TOKEN')

```

### Make Decision

**POST** `/api/v1/transaction-monitoring/{signalId}/decide`

Make a fraud decision on a transaction signal.

**Path Parameters**:

| Parameter  | Type   | Description                    |
| ---------- | ------ | ------------------------------ |
| `signalId` | string | Signal ID (e.g., `sig_abc123`) |

**Request Body**:

```json
{
  "decision": "declined",
  "reason": "High velocity pattern detected with new device. Customer unable to verify recent activity.",
  "confidence": "high",
  "notify_customer": true
}
```

**Body Parameters**:

| Parameter         | Type    | Required | Description                                                    |
| ----------------- | ------- | -------- | -------------------------------------------------------------- |
| `decision`        | string  | Yes      | Decision: `approved`, `declined`, `flagged`, `mark_suspicious` |
| `reason`          | string  | Yes      | Decision justification (10-500 characters)                     |
| `confidence`      | string  | No       | Confidence level: `low`, `medium`, `high`                      |
| `notify_customer` | boolean | No       | Send notification to customer (default: false)                 |

**Response (200 OK)**:

```json
{
  "success": true,
  "message": "Decision recorded successfully",
  "data": {
    "id": "sig_abc123",
    "decision": "declined",
    "decided_at": "2026-02-03T15:45:00Z",
    "decided_by": {
      "id": 42,
      "name": "Sarah Johnson"
    }
  }
}
```

**Error Responses**:

**422 Unprocessable Entity** (Already decided):

```json
{
  "success": false,
  "message": "This transaction has already been decided",
  "errors": {
    "decision": [
      "Decision already made on 2026-02-03T14:30:00Z by Sarah Johnson"
    ]
  }
}
```

**SDK Examples**:

::code-group

```typescript [TypeScript]
await client.transactionMonitoring.decide("sig_abc123", {
  decision: "declined",
  reason: "Confirmed fraud pattern with stolen credentials",
  confidence: "high",
  notify_customer: true,
});
```

```python [Python]
client.transaction_monitoring.decide(
    signal_id='sig_abc123',
    decision='approved',
    reason='Verified with customer - legitimate transaction',
    confidence='high'
)
```

```php [PHP]
$client->transactionMonitoring->decide('sig_abc123', [
    'decision' => 'flagged',
    'reason' => 'Requires additional verification',
    'confidence' => 'medium'
]);
```

### Find Similar Transactions

**GET** `/api/v1/transaction-monitoring/{signalId}/similar`

Find transactions with similar patterns to help identify fraud rings.

**Path Parameters**:

| Parameter  | Type   | Description         |
| ---------- | ------ | ------------------- |
| `signalId` | string | Reference signal ID |

**Query Parameters**:

| Parameter   | Type    | Required | Default | Description                               |
| ----------- | ------- | -------- | ------- | ----------------------------------------- |
| `limit`     | integer | No       | 10      | Max similar transactions to return (1-50) |
| `threshold` | number  | No       | 0.7     | Similarity threshold (0.5-1.0)            |

**Response (200 OK)**:

```json
{
  "reference_signal": {
    "id": "sig_abc123",
    "risk_score": 87,
    "actor_hash": "hash_0244567890"
  },
  "similar_transactions": [
    {
      "id": "sig_def456",
      "similarity_score": 0.92,
      "shared_attributes": [
        "same_device_fingerprint",
        "same_actor_hash",
        "similar_amount"
      ],
      "risk_score": 85,
      "status": "declined",
      "created_at": "2026-02-03T13:15:00Z"
    },
    {
      "id": "sig_ghi789",
      "similarity_score": 0.78,
      "shared_attributes": ["same_ip_address", "similar_timestamp"],
      "risk_score": 72,
      "status": "pending",
      "created_at": "2026-02-03T14:10:00Z"
    }
  ],
  "total_found": 2
}
```

**SDK Example**:

```typescript
// Find fraud ring patterns
const similar = await client.transactionMonitoring.findSimilar("sig_abc123", {
  limit: 20,
  threshold: 0.8,
});

if (similar.total_found > 5) {
  console.log("Potential fraud ring detected!");
}
```

### Export Transactions

**POST** `/api/v1/transaction-monitoring/export`

Export transactions to CSV for reporting and compliance.

**Request Body**:

```json
{
  "filters": {
    "start_date": "2026-02-01",
    "end_date": "2026-02-28",
    "status": "declined",
    "risk_level": "high"
  },
  "fields": [
    "id",
    "transaction_id",
    "risk_score",
    "decision",
    "decided_by",
    "decided_at"
  ]
}
```

**Response (200 OK)**:

```json
{
  "success": true,
  "message": "Export initiated successfully",
  "data": {
    "export_id": "exp_abc123",
    "status": "processing",
    "estimated_rows": 1247,
    "download_url": null,
    "expires_at": null
  }
}
```

::callout{icon="i-lucide-info" color="blue"}
**Async Processing**: Large exports are processed asynchronously. Poll the export status endpoint or wait for a webhook notification.
::

**Available Fields**:

- `id` - Signal ID
- `transaction_id` - External transaction ID
- `event_type` - Fraud event type
- `risk_score` - Risk score (0-100)
- `risk_level` - Risk level category
- `status` - Current status
- `decision` - Final decision
- `decided_by` - Reviewer name
- `decided_at` - Decision timestamp
- `actor_hash` - Actor identifier hash
- `amount` - Transaction amount
- `currency` - Transaction currency
- `country_code` - Country code
- `created_at` - Signal creation time

## Best Practices

### Real-Time Monitoring

Implement efficient polling for real-time transaction feed:

```typescript
class TransactionMonitor {
  private lastPollTime: Date;

  async pollNewTransactions() {
    const transactions = await client.transactionMonitoring.list({
      status: "pending",
      start_date: this.lastPollTime.toISOString(),
      sort_by: "created_at",
      sort_order: "desc",
      per_page: 50,
    });

    this.lastPollTime = new Date();

    // Process new transactions
    for (const tx of transactions.data) {
      await this.processTransaction(tx);
    }
  }

  startPolling(intervalMs = 5000) {
    setInterval(() => this.pollNewTransactions(), intervalMs);
  }
}
```

### Decision Workflow

Implement a structured decision workflow:

```typescript
async function reviewTransaction(signalId: string) {
  // 1. Get transaction details
  const transaction = await client.transactionMonitoring.get(signalId);

  // 2. Get risk breakdown
  const breakdown = await client.transactionMonitoring.riskBreakdown(signalId);

  // 3. Find similar transactions for pattern analysis
  const similar = await client.transactionMonitoring.findSimilar(signalId, {
    threshold: 0.8,
    limit: 10,
  });

  // 4. Analyze and make decision
  const decision = analyzeRisk(transaction, breakdown, similar);

  // 5. Record decision
  await client.transactionMonitoring.decide(signalId, {
    decision: decision.type,
    reason: decision.reason,
    confidence: decision.confidence,
  });
}
```

### Retry Strategy

```typescript
async function makeDecisionWithRetry(
  signalId: string,
  decision: any,
  maxRetries = 3,
) {
  for (let i = 0; i < maxRetries; i++) {
    try {
      return await client.transactionMonitoring.decide(signalId, decision);
    } catch (error) {
      if (error.status === 429) {
        const retryAfter = error.headers["retry-after"] || 60;
        await sleep(retryAfter * 1000);
        continue;
      }

      if (error.status >= 500 && i < maxRetries - 1) {
        await sleep(Math.pow(2, i) * 1000); // Exponential backoff
        continue;
      }

      throw error; // Don't retry client errors
    }
  }
}
```

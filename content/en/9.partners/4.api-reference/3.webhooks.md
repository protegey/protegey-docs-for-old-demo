Webhooks allow Protegey to push intelligence to your systems in real-time. This is useful for async workflows or monitoring entity status changes.

## Event Taxonomy

We support several event types that you can subscribe to in the Partner Portal.

### Core Events

| Event Type | Description | Payload Key |
|------------|-------------|-------------|
| `signal.created` | A new signal was added to the network for an entity you actively monitor. | `signal` |
| `risk_score.changed` | The score for a monitored entity crossed a defined threshold (e.g., became HIGH). | `risk_change` |
| `trust_score.updated` | Your own Partner Trust Score has changed (e.g., dropped due to false positives). | `trust_score` |
| `list.match` | An entity matched a specific Watchlist or Blocklist. | `match` |

### Case Management Events

| Event Type | Description | Payload Key |
|------------|-------------|-------------|
| `case.created` | New fraud case created | `case` |
| `case.updated` | Case status, priority, or assignment changed | `case` |
| `case.note_added` | Note added to case | `case`, `note` |
| `case.evidence_attached` | Evidence uploaded to case | `case`, `evidence` |
| `case.resolved` | Case marked as resolved | `case` |
| `case.closed` | Case closed | `case` |

### Alert Management Events

| Event Type | Description | Payload Key |
|------------|-------------|-------------|
| `alert.triggered` | New alert generated | `alert` |
| `alert.acknowledged` | Alert acknowledged by user | `alert` |
| `alert.resolved` | Alert marked as resolved | `alert` |
| `alert.false_positive` | Alert marked as false positive | `alert` |

### Entity Management Events

| Event Type | Description | Payload Key |
|------------|-------------|-------------|
| `entity.created` | New fraud entity profile created | `entity` |
| `entity.status_updated` | Entity status changed | `entity` |
| `entity.risk_escalated` | Entity risk score exceeded threshold | `entity` |

## Payload Schema

All webhooks share a standardized envelope.

```typescript
interface WebhookPayload {
  id: string; // Unique event ID (evt_...)
  type: EventType;
  created_at: string; // ISO 8601
  data: Record<string, any>; // Event-specific data
}
```

### Example: Risk Score Changed

```json
{
  "id": "evt_abc123",
  "type": "risk_score.changed",
  "created_at": "2026-01-12T15:00:00Z",

    "entity_value": "user@example.com",
    "old_score": 40,
    "new_score": 85,
    "trigger": "new_signal_received",
    "source_signal_id": "sig_8x9s7..."
  }
}
```

## Security: Signature Verification

Protegey signs every webhook request to verify its authenticity.

### Verification Headers

| Header | Description |
|--------|-------------|
| `X-Centry-Signature` | The HMAC-SHA256 signature of the request body. |
| `X-Centry-Event` | The event type (e.g., `fraud_case.created`). |
| `X-Centry-Delivery-ID` | Unique UUID for the delivery attempt. |
| `X-Centry-Timestamp` | Unix timestamp of when the webhook was sent. |

### Verifying Signatures

To verify a webhook, compute the HMAC-SHA256 signature of the raw request body using your **Webhook Secret** (available in the Partner Portal).

**Typescript Example:**

```typescript
import crypto from 'crypto';

const webhookSecret = 'whsec_...'; 

function verifyWebhook(body: string, signature: string) {
  // 1. Compute expected signature
  const computedSignature = crypto
    .createHmac('sha256', webhookSecret)
    .update(body) // Raw request body string
    .digest('hex');

  // 2. Compare with secure timing check
  if (computedSignature !== signature) {
    throw new Error('Invalid signature');
  }
  
  return true;
}
```

## IP Whitelisting

Webhooks will always originate from one of the following static IP addresses. We recommend allowing only these IPs on your webhook ingress.

- `34.11.23.45`
- `34.11.23.46`
- `35.22.11.99`

## Retry Policy

Protegey uses an exponential backoff strategy for failed webhook deliveries.

| Attempt | Delay |
|---------|-------|
| 1 | Immediate |
| 2 | 1 minute |
| 3 | 5 minutes |
| 4 | 30 minutes |
| 5 | 1 hour |
| 6 | 6 hours |

**Note**: If the endpoint fails consistently for 24 hours, the webhook subscription will be automatically disabled.

## Configuration

### Setting Up Webhooks

Configure webhooks in the Partner Portal under **Settings > Integrations > Webhooks**:

1. **Endpoint URL**: Your HTTPS endpoint that will receive webhooks
2. **Events**: Select which event types to subscribe to
3. **Secret**: Copy your webhook secret for signature verification
4. **Test**: Send a test webhook to verify configuration

### Best Practices

**Idempotency**:
```javascript
const processedEvents = new Set();

app.post('/webhooks/protegey', (req, res) => {
  const eventId = req.body.id;

  // Check if already processed
  if (processedEvents.has(eventId)) {
    return res.status(200).send('OK'); // Acknowledge duplicate
  }

  // Process event
  processEvent(req.body);

  // Mark as processed
  processedEvents.add(eventId);

  res.status(200).send('OK');
});
```

**Async Processing**:
```javascript
// Respond quickly, process asynchronously
app.post('/webhooks/protegey', async (req, res) => {
  // 1. Verify signature
  if (!verifyWebhook(req.rawBody, req.headers['x-centry-signature'])) {
    return res.status(401).send('Invalid signature');
  }

  // 2. Acknowledge immediately
  res.status(200).send('OK');

  // 3. Process asynchronously (don't await)
  processWebhookAsync(req.body).catch(err => {
    console.error('Webhook processing failed:', err);
  });
});
```

**Error Handling**:
```javascript
app.post('/webhooks/protegey', async (req, res) => {
  try {
    // Verify and process
    verifyWebhook(req.rawBody, req.headers['x-centry-signature']);
    await processEvent(req.body);

    res.status(200).send('OK');
  } catch (error) {
    console.error('Webhook error:', error);

    // Respond with error status for retry
    res.status(500).send('Processing failed');
  }
});
```

## Integration Examples

### Route by Event Type

```javascript
async function processEvent(webhook) {
  switch (webhook.type) {
    case 'case.created':
      await notifyFraudTeam(webhook.data.case);
      break;

    case 'alert.triggered':
      if (webhook.data.alert.severity_level === 'critical') {
        await sendPagerDutyAlert(webhook.data.alert);
      }
      break;

    case 'entity.risk_escalated':
      await blockUserTransactions(webhook.data.entity.identifier);
      break;

    case 'signal.created':
      await enrichSignalData(webhook.data.signal);
      break;

    default:
      console.log('Unhandled event type:', webhook.type);
  }
}
```

### Automated Response Workflow

```javascript
// Auto-create Jira tickets for high-priority cases
app.post('/webhooks/protegey', async (req, res) => {
  const webhook = req.body;

  if (webhook.type === 'case.created') {
    const { case: fraudCase } = webhook.data;

    if (fraudCase.priority === 'critical') {
      await jira.createIssue({
        project: 'FRAUD',
        summary: fraudCase.title,
        description: fraudCase.description,
        priority: 'Highest',
        labels: ['protegey', 'fraud-investigation']
      });
    }
  }

  res.status(200).send('OK');
});
```

## Troubleshooting

### Common Issues

| Issue | Cause | Solution |
|-------|-------|----------|
| Webhooks not received | Firewall blocking Protegey IPs | Whitelist IPs: 34.11.23.45-46, 35.22.11.99 |
| Signature verification fails | Using wrong secret | Verify webhook secret in Partner Portal |
| Duplicate events | Not implementing idempotency | Track processed event IDs |
| Auto-disabled after 24h | Endpoint returning errors | Check logs, fix endpoint, re-enable |

### Debugging

**Log Webhook Deliveries**:
```javascript
app.post('/webhooks/protegey', (req, res) => {
```

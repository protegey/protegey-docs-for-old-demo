The Risk Assessment API allows you to retrieve a real-time risk decision for an entity. This endpoint is designed to be called synchronously during your user flows (e.g., signup, checkout).

## Endpoint

```http
POST /api/v1/risk/assess
```

## Request Schema

### Headers

| Header         | Value              | Required | Description                 |
| -------------- | ------------------ | -------- | --------------------------- |
| `Content-Type` | `application/json` | Yes      | Standard JSON payload.      |
| `X-Centry-Key` | `cen_live_sk_...`  | Yes      | Your Production Secret Key. |

### Body Parameters

```typescript
interface RiskAssessmentRequest {
  entity_type: "email" | "phone" | "ip" | "device_id" | "crypto_address";
  identifier: string; // The value to assess (e.g., email address)
}
```

### Example Request

```bash
curl -X POST "https://api.protegey.com/v1/risk/assess" \
  -H "Content-Type: application/json" \
  -H "X-Centry-Key: cen_live_sk_..." \
  -d '{
    "entity_type": "email",
    "identifier": "fraudster@example.com"
  }'
```

## Response Schema

```typescript
interface RiskAssessmentResponse {
  decision: "ALLOW" | "REVIEW" | "BLOCK";
  risk_score: number; // 0-100
  reasons: string[]; // List of contributing factors
}
```

### Decision Logic

| Decision | Risk Score | Meaning             | Suggested Action                             |
| -------- | ---------- | ------------------- | -------------------------------------------- |
| `ALLOW`  | < 50       | Low risk.           | Proceed with transaction.                    |
| `REVIEW` | 50 - 79    | Medium risk.        | Trigger step-up auth (2FA) or manual review. |
| `BLOCK`  | >= 80      | High/Critical risk. | Deny the transaction/signup.                 |

### Example Response

```json
{
  "decision": "BLOCK",
  "risk_score": 85,
  "reasons": ["VELOCITY_HIGH", "NETWORK_BLOCKLIST_MATCH"]
}
```

### Error Responses

**400 Bad Request**

```json
{
  "message": "The entity type must be one of: email, phone, ip, device_id, crypto_address."
}
```

**401 Unauthorized**

```json
{
  "message": "Partner authentication required"
}
```

## Risk Scoring Methodology

### Scoring Factors

Protegey's risk assessment considers multiple fraud indicators:

| Factor                  | Weight | Description                                             |
| ----------------------- | ------ | ------------------------------------------------------- |
| **Velocity**            | High   | Transaction frequency within time windows (1h, 24h, 7d) |
| **Network Analysis**    | High   | Links to known fraudsters or suspicious entities        |
| **Anomaly Detection**   | Medium | Deviation from historical behavior patterns             |
| **Geographic Signals**  | Medium | Impossible travel, cross-border patterns                |
| **Device Signals**      | Medium | New devices, fingerprint mismatches                     |
| **Historical Behavior** | Low    | Past fraud involvement, account age                     |

### Risk Score Ranges

| Score      | Level    | Action Recommendation                 |
| ---------- | -------- | ------------------------------------- |
| **0-39**   | Low      | Approve automatically                 |
| **40-59**  | Medium   | Step-up authentication (2FA, SMS OTP) |
| **60-79**  | High     | Manual review required                |
| **80-100** | Critical | Block transaction, flag entity        |

### Reason Codes

The `reasons` array contains specific fraud indicators detected:

| Reason Code                | Description                                         |
| -------------------------- | --------------------------------------------------- |
| `VELOCITY_HIGH`            | Excessive transaction frequency detected            |
| `AMOUNT_ANOMALY`           | Transaction amount exceeds normal patterns          |
| `IMPOSSIBLE_TRAVEL`        | Geographic inconsistency detected                   |
| `DEVICE_NEW`               | First transaction from this device                  |
| `DEVICE_MISMATCH`          | Device fingerprint doesn't match historical pattern |
| `CROSS_BORDER`             | International transaction from high-risk country    |
| `NETWORK_BLOCKLIST_MATCH`  | Entity linked to known fraudster                    |
| `NETWORK_FRAUD_RING`       | Part of suspected fraud network                     |
| `MULTIPLE_FAILED_ATTEMPTS` | Recent authentication failures                      |
| `STOLEN_CREDENTIALS`       | Credentials match breach database                   |

## Best Practices

### Integration Patterns

**Synchronous Assessment (Recommended)**:

```javascript
// During checkout/signup flow
async function processTransaction(user, transaction) {
  // 1. Assess risk in real-time
  const assessment = await protegey.riskAssess({
    entity_type: "email",
    identifier: user.email,
  });

  // 2. Make decision based on risk
  if (assessment.decision === "BLOCK") {
    return { success: false, reason: "Transaction declined for security" };
  }

  if (assessment.decision === "REVIEW") {
    // Trigger step-up authentication
    await sendTwoFactorCode(user.phone);
    return { success: false, reason: "Additional verification required" };
  }

  // 3. Proceed with transaction
  return processPayment(transaction);
}
```

**Batch Assessment**:

```javascript
// For existing user base screening
async function screenExistingUsers(users) {
  const results = [];

  for (const user of users) {
    const assessment = await protegey.riskAssess({
      entity_type: "email",
      identifier: user.email,
    });

    if (assessment.risk_score >= 80) {
      results.push({
        user_id: user.id,
        email: user.email,
        risk_score: assessment.risk_score,
        reasons: assessment.reasons,
      });
    }
  }

  return results; // High-risk users for review
}
```

### Caching Strategy

Risk assessments are computationally expensive. Implement caching for repeated queries:

```javascript
const cache = new Map();
const CACHE_TTL = 300000; // 5 minutes

async function cachedRiskAssess(entity_type, identifier) {
  const cacheKey = `${entity_type}:${identifier}`;
  const cached = cache.get(cacheKey);

  if (cached && Date.now() - cached.timestamp < CACHE_TTL) {
    return cached.result;
  }

  const result = await protegey.riskAssess({ entity_type, identifier });

  cache.set(cacheKey, {
    result,
    timestamp: Date.now(),
  });

  return result;
}
```

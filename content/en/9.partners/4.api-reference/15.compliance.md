The Risk & Compliance as a Service (RCaaS) API provides AML compliance tooling integrated directly into the Protegey signal pipeline. Every signal is automatically evaluated against sanctions lists, PEP databases, geographic risk profiles, and AML transaction monitoring rules.

```http
Authorization: Bearer {token}
```

```json
  "screened_entities": 1240,
  "sanctions_matches": 2,
  "high_risk_jurisdictions_flagged": 8,
```

## Suspicious Activity Reports (SARs)

### List SARs

```http
GET /api/v1/partner/compliance/sars
Authorization: Bearer {token}
```

Query parameters: `status` (`draft`, `under_review`, `filed`, `archived`), `per_page`

```json
{
  "data": [
    {
      "id": "sar_abc123",
      "reference_number": "SAR-20260218-00042",
      "status": "under_review",
      "entity_id": 42,
      "narrative": "Entity exhibited structuring behaviour across 3 accounts...",
      "transaction_total": 45000.0,
      "currency": "NGN",
      "created_at": "2026-02-15T10:00:00Z",
      "filed_at": null
    }
  ]
}
```

### Create a SAR (Draft)

```http
POST /api/v1/partner/compliance/sars
Authorization: Bearer {token}
Content-Type: application/json
```

```json
{
  "entity_id": 42,
  "reason": "Structuring detected: 12 transactions just below ₦500,000 threshold",
  "case_id": "case_uuid_optional"
}
```

A narrative is auto-generated from the entity's `AmlTransactionFlag` records. You can edit it before filing.

```json
{
  "id": "sar_abc123",
  "reference_number": "SAR-20260218-00043",
  "status": "draft",
  "narrative": "Entity [REF-42] triggered structuring rule on 2026-02-15...",
  "created_at": "2026-02-18T10:00:00Z"
}
```

### Get SAR Detail

```http
GET /api/v1/partner/compliance/sars/{sarId}
Authorization: Bearer {token}
```

### Update SAR Narrative

```http
PUT /api/v1/partner/compliance/sars/{sarId}
Authorization: Bearer {token}
Content-Type: application/json
```

```json
{
  "narrative": "Updated investigation narrative..."

```

### Move to Under Review

```http
POST /api/v1/partner/compliance/sars/{sarId}/review
Authorization: Bearer {token}
```

### File a SAR

Requires `analyst` role or above.

```http
POST /api/v1/partner/compliance/sars/{sarId}/file
Authorization: Bearer {token}
```

```json
{
  "status": "filed",
  "reference_number": "SAR-20260218-00043",
  "filed_at": "2026-02-18T11:30:00Z",
  "filed_by": 42
}
```

SAR lifecycle: `draft` → `under_review` → `filed` → `archived`

### SAR Lifecycle

SARs follow a strict state machine. Each transition has a dedicated endpoint:

```
draft → under_review → filed
      ↘              ↘ closed
```

| Step | Endpoint | Description |
|------|----------|-------------|
| 1. Create | `POST /compliance/sars` | Auto-computes transaction totals from entity's recent AML flags |
| 2. Narrative | `POST /compliance/sars/{id}/narrative` | Generates narrative from 10 most recent AML flag events |
| 3. Review | `POST /compliance/sars/{id}/review` | Moves `draft` → `under_review` |
| 4. File | `POST /compliance/sars/{id}/file` | Moves `under_review` → `filed`, generates regulator payload + audit trail |
| 5. Evidence | `GET /compliance/sars/{id}/evidence` | Exports risk indicators + AML flags (PII-safe) |

#### Create SAR

```http
POST /api/v1/partner/compliance/sars
Authorization: Bearer {token}
Content-Type: application/json
```

```json
{
  "entity_uuid": "ent_01HZ...",
  "sar_type": "suspicious_transaction",
  "notes": "Entity has exhibited structuring behavior across 6 transactions"
}
```

The response includes `auto_computed_totals` (transaction count, aggregate amount, currency, date range).

#### Generate Narrative

```http
POST /api/v1/partner/compliance/sars/{uuid}/narrative
```

Generates a narrative from the entity's 10 most recent AML flags. The narrative is editable — this is a starting point, not a final draft.

#### File SAR

```http
POST /api/v1/partner/compliance/sars/{uuid}/file
```

Generates the regulator payload and marks the SAR as `filed`. This action is **irreversible**. Ensure the narrative and evidence are complete before filing.

#### Export Evidence

```http
GET /api/v1/partner/compliance/sars/{uuid}/evidence
```

Returns a JSON evidence package containing:
- Risk indicators (detector results, AML flags, risk scores)
- Contributing signal UUIDs
- Entity hash (HMAC-SHA256 — **not** plaintext PII)

::callout{type="warning"}
**PII Notice**: The evidence package uses HMAC-hashed entity identifiers, not plaintext names or account numbers. You must substitute hashes with real identities from your KYC records before submitting to your Financial Intelligence Unit (FIU).
::

### Auto-STR Trigger

When both `structuring` and `velocity_breach` AML flags fire within **72 hours** on the same entity, a SAR is automatically created in `draft` status:

1. Your team receives a `compliance.sar.auto_drafted` webhook event
2. The SAR appears under **Compliance → SARs → Review Required**
3. Pre-computed transaction totals and a preliminary narrative are included
4. A compliance officer must review, edit if needed, and explicitly file

Auto-drafted SARs are never automatically filed. The 72-hour window and 7-day dedup period are configurable via your compliance settings.

## Transaction Flags

AML transaction flags are created automatically by `TransactionMonitoringRulesService` for every signal passing through the pipeline.

### List Transaction Flags

```http
GET /api/v1/partner/compliance/transaction-flags
Authorization: Bearer {token}
```

Query parameters: `rule_key`, `entity_id`, `from`, `to`, `per_page`

```json
{
  "data": [
    {
      "id": "flag_abc123",
      "signal_id": "sig_xyz789",
      "entity_id": 42,
      "rule_key": "structuring",
      "rule_description": "Multiple transactions just below reporting threshold",
      "risk_contribution": 0.85,
      "flagged_at": "2026-02-18T10:00:00Z",
      "metadata": {
        "transaction_count": 8,
        "window_hours": 24,
        "threshold": 500000
      }
    },
    {
      "id": "flag_abc124",
      "signal_id": "sig_xyz790",
      "entity_id": 42,
      "rule_key": "high_risk_jurisdiction",
      "rule_description": "Transaction originates from FATF grey-list country",
      "risk_contribution": 0.7,
      "flagged_at": "2026-02-18T10:05:00Z",
      "metadata": {
        "country_code": "MM",
        "fatf_status": "grey_list"
      }
    }
  ]
}
```

**Rule keys:** `structuring`, `velocity_breach`, `round_number`, `high_risk_jurisdiction`, `currency_transaction_report`, `mobile_money_velocity`, `cross_border_corridor`, `dormant_account_activation`

## Geographic Risk

### Get Country Risk Profile

```http
GET /api/v1/partner/compliance/geo-risk/{countryCode}
Authorization: Bearer {token}
```

```http
GET /api/v1/partner/compliance/geo-risk/NG
```

```json
{
  "country_code": "NG",
  "country_name": "Nigeria",
  "fatf_status": "compliant",
  "risk_score": 0.45,
  "last_assessed_at": "2025-06-15"
}
```

**FATF statuses:** `compliant`, `grey_list`, `black_list`, `not_assessed`

Risk scores range from `0.0` (lowest risk) to `1.0` (highest risk). Scores are applied to the `high_risk_jurisdiction` AML rule and contribute to the contextual dimension of the Weighted Risk Fusion score.

## Compliance Rule Configuration

Protegey ships a set of AML transaction monitoring rules. Enterprise partners can view, enable/disable, and tune each rule's parameters without a code deploy.

::callout{icon="i-lucide-settings" color="blue"}
**Feature**: `risk_and_compliance` — Enterprise plan only.
::

### List Rules

```http
GET /api/v1/partner/compliance/rules
Authorization: Bearer {token}
```

Query parameters: `category` (`transaction_monitoring`, `behavioral`, `risk_scoring`, `compliance_policy`)

```json
{
  "success": true,
  "data": [
    {
      "uuid": "rule_abc123",
      "name": "structuring_detection",
      "display_name": "Structuring Detection",
      "category": "transaction_monitoring",
      "severity": "high",
      "is_system": false,
      "is_enabled": true,
      "has_override": false,
      "resolved_parameters": { "threshold": 10000 },
      "parameter_schema": {
        "threshold": {
          "label": "Reporting Threshold",
          "description": "Flag transactions between 80–99% of this value",
          "type": "number",
          "unit": "currency"
        }
      }
    }
  ]
}
```

### Get Rule Detail

```http
GET /api/v1/partner/compliance/rules/{uuid}
Authorization: Bearer {token}
```

Returns `default_parameters`, `parameter_overrides`, `resolved_parameters`, and `parameter_schema` in full.

### Configure a Rule

```http
PUT /api/v1/partner/compliance/rules/{uuid}/config
Authorization: Bearer {token}
Content-Type: application/json
```

```json
{
  "is_enabled": true,
  "parameter_overrides": {
    "threshold": 25000
  },
  "override_reason": "Approved by CISO — higher threshold for this market"
}
```

All fields are optional. `parameter_overrides` is merged on top of `default_parameters` — you only need to supply the keys you want to change.

```json
{
  "success": true,
  "data": {
    "uuid": "rule_abc123",
    "is_enabled": true,
    "has_override": true,
    "resolved_parameters": { "threshold": 25000 }
  }
}
```

::callout{type="warning"}
**System rules** (`is_system: true`) cannot be disabled. Attempting to set `is_enabled: false` on a system rule returns `403`.
::

### Reset to Defaults

Removes all partner overrides and reverts to global defaults:

```http
DELETE /api/v1/partner/compliance/rules/{uuid}/config
Authorization: Bearer {token}
```

Idempotent — returns `200` even when no override exists.

---

### Available Rules

| Rule key | Category | Description |
|----------|----------|-------------|
| `structuring_detection` | transaction_monitoring | Flags transactions between 80–99% of reporting threshold (smurfing pattern) |
| `velocity_1h_limit` | transaction_monitoring | 7-day aggregate volume breach |
| `currency_transaction_report` | transaction_monitoring | Single transaction at or above CTR threshold |
| `mobile_money_velocity` | transaction_monitoring | High-frequency small-value transactions within a rolling window |
| `cross_border_corridor` | transaction_monitoring | Transaction crosses a configured high-risk country pair |
| `dormant_account_activation` | transaction_monitoring | Dormant account reactivated with anomalous volume spike |
| `high_risk_corridor` | transaction_monitoring | Transaction linked to a high-risk FATF jurisdiction |
| `auto_str_correlation` | compliance_policy | Auto-drafts a SAR when structuring + velocity flags fire within 72 hours |

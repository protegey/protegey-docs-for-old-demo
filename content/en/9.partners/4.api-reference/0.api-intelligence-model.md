Protegey exposes three endpoints for different stages of the fraud intelligence lifecycle. Understanding which to use — and why — is the foundation of a well-integrated implementation.

## Two Intelligence Layers

The API is organized around two distinct intelligence layers:

### Evaluation (Stateless)

Real-time scoring of raw or unlinked data. No entity is created or updated. Safe to call on every request without side effects.

- Input: raw identifiers (email, phone, device, account, composite)
- Output: `risk_score`, `risk_level`, `confidence`, `explanations[]`, `recommendation`
- Latency target: **< 100ms**
- Use when: pre-screening new users, scoring before onboarding, real-time checkout decisions

### Assessment (Stateful)

Deep intelligence on a known entity in the graph. Requires the entity to already exist (from prior signal ingestion or entity resolution). Returns a full intelligence package including behavioral history, network neighborhood, and compliance context.

- Input: entity UUID or linked identifier
- Output: full scoring contract + `profile`, `network`, `history`
- Latency target: **< 500ms**
- Use when: investigating a flagged user, enriching a case, high-value transaction review

---

## Three Endpoints Overview

| Endpoint | Type | Purpose | Latency |
|---|---|---|---|
| `POST /api/v1/signals` | Stateful | Ingest events into the entity graph | Async-safe |
| `POST /api/v1/evaluate` | Stateless | Score raw/unlinked data in real time | < 100ms |
| `POST /api/v1/risk/assess` | Stateful | Deep entity intelligence package | < 500ms |

---

## The Entity Graph Model

Signals are the raw material. Entities are the persistent intelligence.

When a signal arrives, Protegey:

1. **Validates** the event against the UFES v2 schema
2. **Resolves** identifiers to existing entities (or creates new ones)
3. **Runs detectors** (velocity, outlier, SIM swap, device, travel)
4. **Fuses scores** across behavioral, network, contextual, and historical dimensions
5. **Updates** the entity's risk profile and graph edges

Over time, each entity accumulates a behavioral history, network neighborhood, and compliance record — making `/risk/assess` progressively richer.

---

## Progressive Intelligence Flow

```
Raw Input → POST /evaluate → (resolve_entity: true) → Entity → POST /risk/assess
                ↓ stateless                                          ↓ stateful
           Immediate verdict                               Full intelligence package
```

The `resolve_entity: true` option in `/evaluate` instructs Protegey to link the evaluated input to an existing entity if a match is found. The resolved entity UUID is returned and can immediately be used with `/risk/assess` for a deeper assessment.

---

## When to Use Which Endpoint

### Use `/signals` when:
- Reporting a confirmed fraud event or chargeback
- Feeding the graph with behavioral context over time
- Submitting signals for network-level intelligence sharing
- You don't need a synchronous verdict (fire-and-forget with idempotency)

### Use `/evaluate` when:
- Scoring an email, phone, or device at account creation
- Pre-screening a user before they appear in your system
- Real-time checkout or payment decisions
- You want a verdict without creating a persistent entity

### Use `/risk/assess` when:
- Reviewing a flagged entity from your alert queue
- Enriching an open fraud case with full context
- Building an investigation workflow that needs behavioral history
- High-value transactions where you need the full intelligence package

## SDK Abstraction Preview

The forthcoming Protegey SDK will expose composite methods that map to this model:

```typescript
// Stateless — wraps POST /evaluate
await protegey.evaluateEmail("user@example.com");
await protegey.evaluatePhone("+233244123456");
await protegey.evaluateDevice({ fingerprint: "fp_abc123" });

// Stateful — wraps POST /risk/assess
await protegey.assessEntity("ent_uuid_here");

// Composite — evaluate + resolve + assess in one call
await protegey.assessByEmail("user@example.com");
// → evaluate → resolve_entity: true → assess
```

Composite methods handle the evaluate → resolve → assess chain automatically, returning the full intelligence package even for previously unseen entities.

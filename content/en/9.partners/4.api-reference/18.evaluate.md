The Evaluate API provides real-time risk scoring on raw or unlinked data. It is **stateless** — no entity is created or updated. Safe to call on every request, with no side effects on your entity graph.

::callout{icon="i-lucide-zap" color="primary"}
**Real-time use case**: `/evaluate` is optimized for < 100ms response times. Use it for account creation screening, payment pre-authorization, and onboarding flows.
::

> **Looking for something else?**
> - Real-time scoring without persistence → [Evaluate API](/partners/api-reference/evaluate)
> - Deep entity intelligence → [Assess API](/partners/api-reference/entities#assess)

## Endpoint

```http
POST /api/v1/evaluate
```

### Authentication

```http
X-Centry-Key: cen_live_sk_...
```

### Rate Limits

- 300 requests per minute (Standard)
- 1,000 requests per minute (Enterprise)

---

## Request Schema

```typescript
interface EvaluateRequest {
  // ── What you're evaluating (choose one or provide multiple for composite) ──
  email?: string;        // plaintext — hashed internally before scoring
  phone?: string;        // E.164 format (e.g. "+233244123456")
  device?: {
    fingerprint: string;      // device fingerprint string
    user_agent?: string;      // raw UA string
    ip_address?: string;      // submitting IP for geo enrichment
  };
  account?: {
    account_id: string;       // your internal account identifier
    account_type?: "individual" | "business" | "wallet";
  };
  composite?: {
    // Evaluate multiple identifiers together — higher confidence result
    email?: string;
    phone?: string;
    device_fingerprint?: string;
    account_id?: string;
  };

  // ── Options ──────────────────────────────────────────────────────────────
  options?: {
    resolve_entity?: boolean;      // default: false — link to existing entity if found
    detect_duplicates?: boolean;   // default: false — check for synthetic ID patterns
    include_explanations?: boolean; // default: true — include explanations[] in response
  };

  // ── Evaluation context (optional, improves accuracy) ─────────────────────
  context?: {
    event_type?: string;           // e.g. "ACCOUNT_CREATION", "PAYMENT"
    amount?: number;               // transaction amount if relevant
    currency?: string;             // ISO 4217
    ip_address?: string;           // end-user IP (if not in device block)
    region?: string;               // ISO 3166-1 alpha-2
  };
}
```

### Evaluation Types

| Type | Required Field(s) | Billed As |
|---|---|---|
| `email` | `email` | `fraud_account_check` |
| `phone` | `phone` | `fraud_account_check` |
| `account` | `account.account_id` | `fraud_account_check` |
| `device` | `device.fingerprint` | `device_behavioral_signals` |
| `composite` | `composite.*` (at least 2) | `fraud_account_check` |
| `identity_verification` | _(planned)_ | _(Phase 11)_ |

::callout{icon="i-lucide-info" color="blue"}
**Identity Verification**: The `identity_verification` type (document + biometric) is planned for Phase 11. It will follow the same request/response contract with additional fields. Existing integrations will not be affected.
::

## Request Examples

### Email Evaluation

```bash
curl -X POST "https://api.protegey.com/api/v1/evaluate" \
  -H "Content-Type: application/json" \
  -H "X-Centry-Key: cen_live_sk_..." \
  -d '{
    "email": "user@example.com",
    "options": {
      "include_explanations": true
    }
  }'
```

```bash
        }
```

```bash
    }
```


### Response Fields

| Field | Type | Description |
|---|---|---|
| `risk_score` | float | 0.0–1.0 risk score |
| `risk_level` | string | `low`, `medium`, `high`, or `critical` |
| `confidence` | float | 0.0–1.0 confidence in the score |
| `entity` | object\|null | Resolved entity (only if `resolve_entity: true` and a match is found) |
| `entity.uuid` | string | Entity UUID — use with `/risk/assess` for full intelligence |
| `duplicate` | object\|null | Duplicate detection result (only if `detect_duplicates: true`) |
| `signals_summary` | object | Aggregate signal context for the evaluated identifier |
| `explanations` | array | Ordered list of scored reasons (highest severity first) |
| `recommendation` | object | Suggested action and priority |

---

## Risk Level Reference

| `risk_level` | `risk_score` | Suggested Response |
|---|---|---|
| `low` | 0.00 – 0.20 | Allow — no significant signals |
| `medium` | 0.21 – 0.50 | Step-up authentication or soft decline |
| `high` | 0.51 – 0.80 | Manual review or challenge flow |
| `critical` | 0.81 – 1.00 | Block and investigate |

## Progressive Intelligence Pattern

When `resolve_entity: true` is set and an entity is resolved, use the returned `entity.uuid` to immediately retrieve the full assessment:

```javascript
const evalResult = await fetch("/api/v1/evaluate", {
  method: "POST",
  body: JSON.stringify({
    phone: "+233244123456",
    options: { resolve_entity: true }
  })
});

const { data } = await evalResult.json();

if (data.entity?.uuid && data.risk_level !== "low") {
  // Escalate to full assessment
  const assessResult = await fetch(`/api/v1/risk/assess`, {
    method: "POST",
    body: JSON.stringify({ entity_uuid: data.entity.uuid })
  });
}
```

## Error Responses

### Validation Error (`422`)

```json
{
  "message": "At least one evaluation input is required.",
  "errors": {
    "input": ["Provide one of: email, phone, device, account, or composite."]
  }
}
```

### Common Errors

| Error | Cause |
|---|---|
| `At least one evaluation input is required` | No input field provided |
| `composite requires at least 2 identifiers` | Only one field set in `composite` block |
| `phone must be in E.164 format` | Phone not prefixed with `+` and country code |
| `device.fingerprint is required when using device evaluation` | Missing fingerprint in device block |

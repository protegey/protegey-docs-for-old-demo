The Integration Health dashboard (`/integration` in the Partner Portal) gives you a real-time, graded view of whether your integration is sending the right signals for Protegey to detect fraud effectively.

::callout{icon="i-lucide-gauge" color="blue"}
**Score range**: 0–100. Graded A (≥90), B (≥75), C (≥60), D (≥45), F (<45). Score is computed on demand and cached for 1 hour.
::

---

## How the Score is Calculated

Your total score (0–100) is the sum of four dimensions:

| Dimension            | Max Points | What it Measures                                                        |
| -------------------- | ---------- | ----------------------------------------------------------------------- |
| Signal Coverage      | 40 pts     | Which critical and important signal types you are sending               |
| Field Completeness   | 40 pts     | How many enrichment fields your signals include                         |
| Signal Breadth       | 15 pts     | Diversity across event categories (auth, transaction, KYC, fraud_signal)|
| Detector Readiness   | 5 pts      | Fraction of the 9 detectors that have sufficient data to fire           |

**Hard cap rule**: An A or B grade is impossible if any critical signal type has never been sent in the active window (30 days). Missing a critical type locks the Signal Coverage score at a maximum of 50%, regardless of other dimensions.

---

## Signal Priorities

| Priority      | Meaning                                                                          |
| ------------- | -------------------------------------------------------------------------------- |
| **Critical**  | Required for real-time fraud interception. Missing = hard cap applied.            |
| **Important** | Significant detection capability loss if absent. Contributes heavily to score.    |
| **Valuable**  | Enriches detection but not blocking. Lower score impact.                          |
| **Feedback only** | Useful for historical analysis. Minimal score impact.                        |

The canonical list of signal types and their priorities is maintained in `IntegrationHealthService` and is the single source of truth used by both the dashboard and the proactive degradation alerting system.

## Reading the Dashboard

### Score Card

The letter grade and numeric score give you an at-a-glance health indicator. The score reflects signal activity in the **last 30 days**.

### Signal Coverage

Shows how many critical signal types you have sent in the last 30 days. The count reads `sent / total`. Any missing critical types are shown as red badges — each one is a gap in real-time detection.

### Detector Readiness

Shows how many of the 9 detectors are currently operational. A detector is "ready" when its required signal types and fields are present in sufficient volume. The percentage next to each detector is its coverage score; a `blocker` message explains what's missing.

The 9 detectors and what they need:

| Detector                  | Needs                                                  |
| ------------------------- | ------------------------------------------------------ |
| Rapid Velocity            | Transaction signals with `actor_hashed_id`             |
| Large Outlier             | Transaction signals with `transaction_amount`          |
| SIM Swap Proximity        | Signals with `sim_changed_at` populated                |
| New Device Access         | Signals with `actor_device_fingerprint`                |
| Impossible Travel         | Signals with `actor_ip_address` or geo coordinates     |
| Session Anomaly           | Auth signals with session metadata                     |
| Attack Chain              | Sequence: account takeover → payment fraud, same actor |
| Beneficiary Concentration | Transaction signals with `metadata.transaction.recipient_id` |
| Agent Concentration       | Mobile/USSD signals with `related_entities[type=AGENT]`|

### Field Completeness

Shows fill rate for the enrichment fields that detectors depend on, across your last 30 days of transaction signals. The progress bar turns amber below 50% and red below 30%.

### Recommendations

Auto-generated based on your score. Recommendations are sorted by priority — address critical items first, as they block the largest score improvements.

## Improving Your Score

### Fast wins (Signal Coverage)

1. **Add missing critical signal types** — each critical type you add contributes proportionally to Signal Coverage (40 pts total).
2. **Send all event categories** — if you are only sending transaction signals, start sending auth events (`LOGIN_SUCCESS`, `LOGIN_FAILURE`) to unlock the Signal Breadth dimension.

### Detector enablement (Field Completeness + Readiness)

3. **Populate `actor_ip_address`** — enables Impossible Travel detection.
4. **Populate `actor_device_fingerprint`** — enables New Device Access detection.
5. **Populate `sim_changed_at`** — enables SIM Swap Proximity detection.
6. **Populate `metadata.transaction.recipient_id`** — enables Beneficiary Concentration detection (investment scam funnel patterns).
7. **Populate `related_entities` with `entity_type: AGENT`** — enables Agent Concentration detection (mobile money agent collusion).

### UFES v2 field reference

All enrichment fields live in the UFES v2 envelope. See [API Reference → Signals](../api-reference/signals) for the full schema. The `ingestion_quality` block in every ingestion response links missing fields directly to the detector they enable:

```json
{
  "ingestion_quality": {
    "completeness_score": 0.41,
    "missing_fields": [
      {
        "field": "actor_ip_address",
        "required_for": ["IMPOSSIBLE_TRAVEL"]
      }
    ]
  }
}
```

## Proactive Degradation Alerts

If a critical signal type that you were previously sending (active in the last 30 days) goes silent for **48 consecutive hours**, Protegey will send an email to your integration contact address.

- Alerts have a **72-hour cooldown** per signal type to prevent noise on sustained gaps.
- The email includes the affected signal types and a link back to this dashboard.
- If you receive a degradation alert and your pipeline appears healthy, check that your API key is active and your endpoint is correctly configured.

To verify or update your integration contact email, go to **Settings → Organization Details**.

# Compliance Rules & AML Thresholds

The Protegey AML/CFT engine applies a layered rule set derived from FATF Recommendation 16 (wire transfers), Recommendation 7 (sanctions), and national threshold guidance for 31 African and major currencies. This page explains how those rules apply to your signals and how to interpret compliance flags.

::callout{type="info"}
AML/RCaaS features require the **Enterprise** plan. The compliance dashboard is available at `/compliance` in the partner portal.
::

---

## Multi-Currency FATF Thresholds

Each currency has an independent threshold calibrated to the FATF-equivalent local value. Thresholds apply to:

1. **Single transaction** reporting trigger (CTR-equivalent)
2. **Structuring detection** window (24h aggregated)
3. **Velocity breach** window (1h rapid movement)

## FATF Tier Classification

| Tier | Description | Regulatory Posture |
|------|-------------|-------------------|
| **Tier 1** | FATF member states — full mutual evaluation | Highest threshold confidence |
| **Tier 2** | FATF-style regional bodies (GIABA, ESAAMLG) | Calibrated to regional guidance |
| **Tier 3** | Jurisdictions under enhanced monitoring | Lower thresholds, elevated scrutiny |
| **Blacklist** | FATF high-risk jurisdictions | All transactions flagged regardless of amount |

Blacklisted jurisdictions trigger an automatic `high_risk_jurisdiction` AML flag and route to SAR consideration regardless of transaction amount.

## Structuring Detection

Structuring (Smurfing) occurs when a customer breaks a reportable transaction into smaller amounts to evade threshold reporting.

**Detection logic**:
- The engine aggregates all transactions for the same `entity_id` within a rolling 24-hour window
- If the aggregate exceeds the `structuring` threshold (95% of the single-transaction limit) across 3+ transactions, a `structuring` flag is raised
- The window is entity-scoped — cross-entity coordination is detected via the graph engine, not structuring rules

**Flag fields**:
```json
{
  "flag_type": "structuring",
  "evidence": {
    "transaction_count": 4,
    "aggregate_amount": 9700.00,
    "currency": "USD",
    "window_hours": 24,
    "threshold": 9500.00
  }
}
```

## Configuring Per-Currency Thresholds

Enterprise partners can override AML thresholds per currency directly from the portal or API — no code deploy required.

### From the Portal

Navigate to **Compliance → Rules**, find the rule (e.g. `Structuring / Smurfing Detection`), and click **Configure**. Rules with a `currency_overrides` parameter show a currency map editor:

1. Click **Currency…** to select a currency from the dropdown (31 supported)
2. Enter the threshold amount in the currency's base unit
3. Click **Add** — the override takes effect immediately for new signals
4. Leave the field empty to fall back to the platform default for that currency

::callout{type="info"}
Entering no override for a currency means the platform default from the global threshold table applies. You only need to override currencies where your regulatory threshold differs from the platform default.
::

### Via API

```http
PUT /api/v1/partner/compliance/rules/{uuid}/config
Authorization: Bearer {token}
Content-Type: application/json
```

```json
{
  "parameter_overrides": {
    "currency_overrides": {
      "GNF": 100000000,
      "NGN": 5000000,
      "XOF": 6000000
    }
  },
  "override_reason": "Deployed to Guinea — BCRG threshold GNF 100M per BCRG/AML/2023-4"
}
```

For round number detection, values are arrays of suspicious amounts:

```json
{
  "parameter_overrides": {
    "currency_overrides": {
      "GNF": [500000, 1000000, 5000000, 10000000, 50000000, 100000000]
    }
  }
}
```

## Auto-STR Correlation

When **both** `structuring` and `velocity_breach` AML flags fire within 72 hours on the same entity, the engine automatically drafts a Suspicious Transaction Report (SAR/STR):

1. A SAR is created in `draft` status
2. Transaction totals are pre-computed from the flagged signals
3. Your team receives a webhook notification (`compliance.sar.auto_drafted`)
4. The SAR appears in the compliance dashboard under **SARs → Review Required**

Your team reviews and edits the narrative before filing. See the [Compliance API](/partners/api-reference/compliance) for the full SAR lifecycle.

::callout{type="warning"}
Auto-drafted SARs are not automatically filed with regulators. A compliance officer must review and explicitly trigger filing via `POST /compliance/sars/{id}/file` or the dashboard.
::

## Round Number Detection

The `round_number` rule flags transactions that are exact round amounts (e.g., $5,000, $10,000) combined with a high-risk geography or first-seen device. Round amounts are disproportionately associated with structuring and money mule activity.

This rule has a lower confidence score than structuring (0.45 vs 0.75) and does not by itself trigger an auto-STR.

## Velocity Breach

A velocity breach flag fires when an entity moves more than the 1-hour threshold within a 60-minute window. This is distinct from the `RAPID_TRANSACTION_VELOCITY` detector:

| Component | Threshold Type | Scope |
|-----------|----------------|-------|
| `velocity_breach` AML flag | Currency-denominated amount | Compliance pipeline |
| `RAPID_TRANSACTION_VELOCITY` detector | Transaction count (≥10/hr) | Fraud detection pipeline |

Both can fire on the same signal and contribute independently to the risk score and SAR consideration.

## Identity-Graph Rules

Two AML rules operate on device graph patterns rather than transaction amounts. They do not use currency thresholds and are not affected by the per-currency override system.

**`duplicate_identity`** — fires when a single device fingerprint is associated with more than `max_actors_per_device` distinct actor IDs within a 7-day rolling window. Default threshold: 3 actors. Indicates device sharing across unrelated identities — common pattern in synthetic identity fraud and mule account farms.

**`device_farm_detection`** — fires when a device fingerprint accumulates signals from distinct actors at a rate that exceeds a configurable burst threshold within a short window. Distinguishes legitimate shared devices (family plan, internet café) from adversarial reuse by evaluating signal velocity alongside actor count.

Both rules are configurable via the Rules API and portal (`/compliance/rules`). Neither can auto-trigger a SAR independently, but co-occurrence with `structuring` or `velocity_breach` within the correlation window will.

## Reviewing Compliance Flags

Navigate to **Compliance → Transaction Flags** to review all AML flags. Each flag shows:
- Flag type and confidence score
- Evidence (amounts, counts, window)
- Linked signals
- Auto-STR status (if applicable)

Use `GET /api/v1/partner/compliance/transaction-flags` to retrieve flags programmatically. See the [Compliance API](/partners/api-reference/compliance) for filter options and response schema.

# Getting Support

Protegey's in-platform support gateway lets you raise issues, ask questions, and track resolution without leaving the portal. All communication is linked to your partner account — your team and Protegey support agents share a single thread inbox.

---

## Opening a Thread

Navigate to **Settings → Support** in the partner portal, then click **New Thread**.

Choose the subject category that best matches your issue:

| Subject | When to Use |
|---------|-------------|
| **Technical Issue** | API errors, 4xx/5xx responses, unexpected behaviour, SDK problems |
| **Signal Question** | Why a signal scored the way it did, detector reasoning |
| **Integration Support** | Webhook setup, UFES schema questions, onboarding help |
| **Billing** | Invoice queries, plan upgrades, overage questions |
| **Other** | Anything not covered above |

---

## Attaching Context

### Linking to a Case or Alert

When raising a technical issue related to a specific case or alert, use the **Get Help** button on the case or alert detail page. This pre-fills the thread with `context_type` and `context_id` so the support team sees the exact resource you are referring to.

This is strongly preferred over manually describing the case — it gives support agents direct read access to the relevant data.

### Attaching Files

Each message supports up to **5 attachments** (max 10 MB each). Supported formats: `jpg`, `png`, `gif`, `webp`, `pdf`, `txt`.

For API integration issues, attach:
- The raw request payload (sanitise any real PII before attaching — use HMAC hashes or synthetic identifiers)
- The full API response body including headers
- Any relevant log lines

## Priority Levels

| Priority | SLA (First Response) | Use For |
|----------|---------------------|---------|
| `low` | 48 hours | General questions, feature requests |
| `normal` | 24 hours | Non-blocking integration questions |
| `high` | 4 hours | Blocked integration, production signal errors |
| `urgent` | 1 hour | Production outage, compliance deadline |

::callout{type="warning"}
Urgent priority is intended for genuine production-impacting issues. Threads marked urgent for non-critical questions may be reclassified by the support team.
::

## Thread Lifecycle

```
open → pending (awaiting your reply) → open (you replied) → closed (resolved)
```

Sending a new message on a `closed` thread automatically re-opens it. You do not need to create a new thread for follow-up questions on the same issue.

---

## Real-Time Notifications

The partner portal subscribes to the thread's WebSocket channel automatically. New support replies appear instantly without refreshing the page. You can also configure a webhook notification for new support messages under **Settings → Webhooks → Event Types → `support.message.created`**.

---

## API Access

If you prefer to manage threads programmatically, use the [Support Threads API](/partners/api-reference/support). This is useful for:

- Embedding support escalation in your own internal tooling
- Automating thread creation from your alerting pipeline
- Exporting thread history for compliance records

---

## Privacy and Data Handling

- All thread content and attachments are encrypted at rest using AES-256-CBC
- Support agents access only threads belonging to your partner account
- Attachments are automatically purged after **180 days**
- Thread metadata is retained for audit purposes per your data retention configuration

Do not include plaintext PII (names, phone numbers, account numbers) in support messages or attachments. Use HMAC-hashed identifiers or synthetic values instead.

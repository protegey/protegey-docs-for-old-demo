We use a standard severity matrix to classify incidents. This ensures a predictable response.

## Severity Levels

| Level     | Severity | Description                                                                                          | Response Time (SLA) |
| --------- | -------- | ---------------------------------------------------------------------------------------------------- | ------------------- |
| **SEV-1** | Critical | **System Down** or **Data Breach**. The platform is unusable or critical data is at immediate risk.  | < 15 mins           |
| **SEV-2** | High     | **Degraded Service**. Platform is usable but significant features (e.g., query latency) are failing. | < 1 hour            |
| **SEV-3** | Medium   | **Functional Issue**. Specific edge case failure or bug that allows workaround.                      | < 4 hours           |
| **SEV-4** | Low      | **Minor Bug**. Cosmetic issues or documentation errors.                                              | < 24 hours          |

## Security vs Operational

### Operational Incidents

- API timeouts
- Incorrect 4xx/5xx responses
- Webhook delivery failures

### Security Incidents

- Suspected key compromise
- Suspected adversary probe
- Detected anomaly in risk scores
- Unauthorized access attempt

::callout{icon="i-lucide-alert-octagon" color="red"}
**Security First**: Any potential security issue is treated as SEV-1 until proven otherwise.
::

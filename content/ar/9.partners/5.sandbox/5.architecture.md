تنفِّذ Protegey **عزلًا حقيقيًا على مستوى قاعدة البيانات** لبيئات الاختبار، مما يضمن فصلًا كاملًا بين بيانات الاختبار وبيانات الإنتاج على مستوى مخطط PostgreSQL.

## عزل مخطط PostgreSQL

### الفصل الفيزيائي

على خلاف الفصل المنطقي (مثلاً `WHERE environment = 'sandbox'`)، تستخدم Protegey **الفصل الفيزيائي للمخططات**:

```
protegey_database
├── public schema (production)
│   ├── signals
│   ├── fraud_cases
│   ├── fraud_entities
│   ├── fraud_alerts
│   └── ... (all partner-scoped tables)
│
├── sandbox schema (sandbox)
│   ├── signals
│   ├── fraud_cases
│   ├── fraud_entities
│   ├── fraud_alerts
│   └── ... (duplicated partner-scoped tables)
│
└── shared tables (public only)
    ├── users
    ├── partners
    ├── subscriptions
    ├── plans
    └── invoices
```

### فوائد عزل المخطط

| الفائدة                          | الوصف                                                             |
| -------------------------------- | ----------------------------------------------------------------- |
| **صفر تلوث للتحليلات**           | إشارات الاختبار لا تؤثر أبدًا على مقاييس الإنتاج أو تسجيل المخاطر |
| **سهولة إعادة التعيين**          | `TRUNCATE sandbox.signals` يمسح جميع بيانات الاختبار فورًا        |
| **عزل الأداء**                   | استعلامات الاختبار لا تتنافس مع فهارس الإنتاج                     |
| **جاهز للامتثال**                | فصل فيزيائي لمتطلبات الفصل التنظيمي للبيانات                      |
| **استراتيجية نسخ احتياطي بسيطة** | النسخ الاحتياطي لمخطط `public` دون بيانات الاختبار                |

### كيفية عمل إنفاذ المخطط

يُعيَّن `search_path` في PostgreSQL تلقائيًا لكل طلب:

```sql
-- Sandbox request
SET search_path TO sandbox, public;

-- Production request
SET search_path TO public, public;
```

يعني ذلك:

1. تستخدم جميع الاستعلامات المخطط الصحيح تلقائيًا
2. لا حاجة لإضافة بادئة اسم المخطط لأسماء الجداول (مثلاً `sandbox.signals`)
3. الجداول المشتركة (users وpartners) موجودة دائمًا في `public`، وتعمل بسلاسة

::callout{type="info"}
**تفاصيل تقنية**: يعمل وسيط `EnforceSchemaIsolation` بعد المصادقة ويُعيِّن المخطط بناءً على `CentryContext` المحلول. هذه العملية آمنة من التكرار ويمكن تنفيذها مرات متعددة دون مشاكل.
::

## CentryContext: سياق التنفيذ غير القابل للتغيير

`CentryContext` هو كائن غير قابل للتغيير يتضمن جميع حالات البيئة لطلب أو وظيفة ما.

### بنية السياق

```php
CentryContext {
  environment: 'sandbox' | 'production'
  partnerUuid: string | null
  requestId: string | null
  metadata: array
}
```

### إنشاء السياق

```php
// Create sandbox context
$context = CentryContext::sandbox($partnerUuid);

// Create production context
$context = CentryContext::production($partnerUuid);

// Detect from HTTP request
$context = CentryContext::fromRequest($request);

// With metadata
$context = CentryContext::sandbox($partnerUuid)
    ->withMetadata(['user_id' => $userId]);
```

### توابع السياق

| التابع           | يُعيد          | الوصف                                                      |
| ---------------- | -------------- | ---------------------------------------------------------- |
| `environment()`  | `string`       | الحصول على اسم البيئة                                      |
| `partnerUuid()`  | `string\|null` | الحصول على UUID الشريك                                     |
| `requestId()`    | `string\|null` | الحصول على معرف تتبع الطلب                                 |
| `metadata()`     | `array`        | الحصول على البيانات الوصفية الإضافية                       |
| `isSandbox()`    | `bool`         | التحقق من بيئة الاختبار                                    |
| `isProduction()` | `bool`         | التحقق من بيئة الإنتاج                                     |
| `schema()`       | `string`       | الحصول على اسم مخطط قاعدة البيانات (`sandbox` أو `public`) |

## أولوية اكتشاف البيئة

عند معالجة طلب ما، يحل النظام البيئة وفق هذا الترتيب:

1. **معامل الاستعلام**: `?environment=sandbox`

   ```bash
   https://api.protegey.com/api/v1/signals?environment=sandbox
   ```

2. **تجاوز الجلسة أو ملف تعريف الارتباط**: ملف تعريف الارتباط `centry_env_override`

   ```javascript
   // Set in browser console for persistent switching
   document.cookie = "centry_env_override=sandbox; path=/";
   ```

3. **رأس الطلب**: رأس `X-Centry-Environment`

   ```bash
   curl -H "X-Centry-Environment: sandbox" \
     https://api.protegey.com/api/v1/signals
   ```

4. **اكتشاف النطاق**: النطاق الفرعي `sandbox.*`

   ```
   https://sandbox.api.protegey.com/api/v1/signals
   ```

5. **رأس Referer**: لطلبات API عبر الأصول من بوابة الشريك

   ```
   Referer: https://sandbox.partner.protegey.com/...
   ```

6. **المستخدم المصادق عليه**: حالة بيئة الشريك

   ```php
   if ($user->partner->is_sandbox) {
       $environment = 'sandbox';
   }
   ```

7. **الافتراضي**: `production` (آمن عند الفشل)

::callout{type="warning"}
**ملاحظة أمنية**: يُتحقق دائمًا من اكتشاف البيئة مقابل البيئات المسموح بها للشريك المصادق عليه. لا يمكنك الوصول إلى بيانات الإنتاج أثناء المصادقة على شريك مخصص للاختبار فقط.
::

## التنفيذ الواعي بالسياق

### طلبات HTTP

```
HTTP Request
    ↓
[ResolveCentryContext Middleware]
    ↓
[EnforceSchemaIsolation Middleware]
    ↓
Controller → Model Query
    ↓
PostgreSQL (correct schema)
```

**مكدس الوسيط**:

```php
Route::middleware([
    'auth:api',
    'resolve.context',      // Creates CentryContext
    'enforce.schema',       // Sets search_path
])->group(function () {
    // All routes here have correct schema
});
```

### وظائف قائمة الانتظار

للمعالجة غير المتزامنة، يجب الحفاظ على السياق عبر حدود قائمة الانتظار.

**الفئة الأساسية ContextAwareJob**:

```php
use App\Jobs\ContextAwareJob;

class ProcessFraudSignal extends ContextAwareJob
{
    public function __construct(private string $signalId) {
        parent::__construct(); // Captures current context
    }

    protected function perform(): void {
        // Context already restored
        // All queries use correct schema
        $signal = Signal::find($this->signalId);
        // ... fraud scoring logic
    }
}
```

**آلية العمل**:

1. **وقت الإرسال**: يلتقط المُنشئ `CentryContext` الحالي من حاوية الخدمة
2. **التسلسل**: يُسلسَل السياق ويُخزَّن مع حمولة الوظيفة
3. **تنفيذ العامل**: يُستعاد السياق قبل تنفيذ `perform()`
4. **إنفاذ المخطط**: يُعيَّن `search_path` تلقائيًا

::callout{type="danger"}
**حرج**: يجب على جميع وظائف قائمة الانتظار أن تمتد من `ContextAwareJob` لضمان عزل المخطط الصحيح. الوظائف التي لا تمتد من هذه الفئة الأساسية ستفشل بخطأ `MissingContextException` إذا حاولت الإرسال دون سياق مرتبط.
::

### أوامر CLI

لأوامر Artisan التي ترسل وظائف، يجب ربط السياق صراحةً:

```php
use App\Context\CentryContext;

class GenerateDemoSignalsCommand extends Command
{
    public function handle()
    {
        $partnerUuid = $this->argument('partner');

        // Bind sandbox context
        app()->instance(
            CentryContext::class,
            CentryContext::sandbox($partnerUuid)
        );

        // Now jobs dispatched from this command inherit context
        ProcessFraudSignal::dispatch($signalId);
    }
}
```

## ضمانات عزل البيانات

### ما الذي يُعزل

✅ **الجداول ذات النطاق الشريكي** (مكررة في مخطط `sandbox`):

- `signals`
- `fraud_cases`
- `fraud_entities`
- `fraud_alerts`
- `case_notes`
- `case_evidence`
- جميع البيانات التشغيلية الخاصة بالشريك

### ما الذي يُشارَك

🔗 **الجداول المشتركة** (في مخطط `public` فقط):

- `users` - حسابات المستخدمين
- `partners` - منظمات الشركاء
- `subscriptions` - اشتراكات الفوترة
- `plans` - خطط الاشتراك
- `invoices` - فواتير الفوترة
- `partner_api_keys` - مفاتيح API (مع علامة البيئة)
- جداول تهيئة النظام

::callout{type="info"}
**لماذا مشاركة هذه الجداول؟**: الفوترة وإدارة المستخدمين وتهيئة النظام عالمية لمنظمة الشريك. يرتبط سجل الشريك في بيئة الاختبار بالأصل في الإنتاج عبر `production_parent_uuid`.
::

## أفضل ممارسات الاختبار

### اختبار عزل المخطط

```php
// In tests, explicitly set context
public function test_sandbox_signal_creation()
{
    $this->actingAs($user);

    app()->instance(
        CentryContext::class,
        CentryContext::sandbox($partner->uuid)
    );

    $response = $this->postJson('/api/v1/signals', $payload);

    // Signal should exist in sandbox schema only
    $this->assertDatabaseHas('sandbox.signals', [
        'partner_uuid' => $partner->uuid,
    ]);

    $this->assertDatabaseMissing('public.signals', [
        'partner_uuid' => $partner->uuid,
    ]);
}
```

### التحقق من الحفاظ على السياق في الوظائف

```php
public function test_job_preserves_context()
{
    app()->instance(
        CentryContext::class,
        CentryContext::sandbox($partner->uuid)
    );

    ProcessFraudSignal::dispatch($signalId);

    // After job runs, signal should be scored in sandbox
    $signal = Signal::find($signalId); // Queries sandbox schema
    $this->assertEquals('sandbox', $signal->environment);
}
```

## موضوعات متقدمة

### أسماء مخططات مخصصة

رغم عدم التوصية بذلك، يمكنك توسيع النظام لدعم أسماء مخططات مخصصة:

```php
// In CentryContext
public function schema(): string
{
    return match($this->environment) {
        'sandbox' => 'sandbox',
        'staging' => 'staging',
        'production' => 'public',
        default => 'public',
    };
}
```

### عزل المخطط متعدد المناطق

بالنسبة للنشر متعدد المناطق، يمكن دمج عزل المخطط مع الفصل على مستوى قاعدة البيانات:

```
Region: West Africa (WA)
└── protegey_wa
    ├── public (production)
    └── sandbox (sandbox)

Region: East Africa (EA)
└── protegey_ea
    ├── public (production)
    └── sandbox (sandbox)
```

### اعتبارات الأداء

**الفهارس**: تحتفظ كل مخطط بفهارسه الخاصة، لذا:

- اختبار بيئة الاختبار لا يؤثر على إحصاءات فهارس الإنتاج
- يمكن إسقاط/إعادة إنشاء فهارس الاختبار دون توقف

**Vacuum**: يمكن تنفيذ Vacuum لمخططي الاختبار والإنتاج باستقلالية:

```sql
VACUUM ANALYZE sandbox.signals;
```

**الاتصالات**: يستخدم عزل المخطط نفس مجموعة الاتصالات، دون أي تكلفة إضافية للاتصال.

## استكشاف الأخطاء وإصلاحها

### أخطاء "الجدول غير موجود"

**الأعراض**: `ERROR: relation "signals" does not exist`

**السبب**: عدم ضبط المخطط بشكل صحيح

**الحل**: التحقق من ترتيب الوسيط:

```php
// ResolveCentryContext MUST come before EnforceSchemaIsolation
Route::middleware([
    'resolve.context',
    'enforce.schema',
])->group(...);
```

### الوظائف تكتب في المخطط الخاطئ

**الأعراض**: وظائف الاختبار تنشئ سجلات في الإنتاج

**السبب**: الوظيفة لا تمتد من `ContextAwareJob`

**الحل**:

```php
// ❌ Wrong
class MyJob extends Job { ... }

// ✅ Correct
class MyJob extends ContextAwareJob { ... }
```

### السياق غير موجود في CLI

**الأعراض**: `MissingContextException` عند تشغيل أمر Artisan

**السبب**: السياق غير مرتبط في بيئة CLI

**الحل**:

```php
// Bind context before dispatching jobs
app()->instance(
    CentryContext::class,
    CentryContext::sandbox($partnerUuid)
);
```

## اعتبارات الأمان

### التحقق من البيئة

يتحقق النظام من وصول البيئة بناءً على أذونات الشريك:

```php
// Partner can only access sandbox if explicitly allowed
if ($requestedEnvironment === 'sandbox' && !$partner->has_sandbox_access) {
    abort(403, 'Sandbox access not enabled for this partner');
}
```

### تحديد نطاق مفتاح API للبيئة

مفاتيح API محدودة النطاق حسب البيئة:

- **مفاتيح الإنتاج**: `cen_live_sk_*` ← يمكنها الوصول إلى الإنتاج فقط
- **مفاتيح الاختبار**: `cen_test_sk_*` ← يمكنها الوصول إلى الاختبار فقط

### منع تسرب البيانات عبر البيئات

1. **عزل المخطط**: فصل فيزيائي لقاعدة البيانات
2. **التحقق من السياق**: الوسيط يُنفِّذ حدود البيئة
3. **تحديد نطاق مفتاح API**: المفاتيح لا يمكنها تجاوز البيئات
4. **التقاط سياق الوظيفة**: الوظائف غير المتزامنة تحتفظ بالبيئة

**النتيجة**: صفر مخاطر من تلوث بيانات الاختبار لمقاييس الإنتاج أو العكس.

بيئة اختبار Centry هي بيئة معزولة تمامًا تتيح لك اختبار تكاملك دون التأثير على بيانات الإنتاج أو تكبُّد أي تكاليف.

## لماذا تستخدم بيئة الاختبار؟

- **صفر مخاطر**: اختبر سيناريوهات الاحتيال دون التأثير على مقاييس الإنتاج الخاصة بك.
- **أمانة عالية**: تستخدم بيئة الاختبار نقاط النهاية ذاتها وقواعد التحقق ومنطق المعالجة كما في الإنتاج.
- **بيانات معزولة**: تُخزَّن جميع الإشارات والكيانات والتنبيهات في مخطط منفصل (`sandbox`).
- **أدوات تجريبية**: استخدم المحاكي المدمج لتوليد بيانات احتيال واقعية على الفور.

## التبديل بين البيئات

يمكنك التبديل بين بيئة **الاختبار** وبيئة **الإنتاج** بعدة طرق:

### من خلال بوابة الشريك

قم بالتبديل بين البيئات باستخدام مفتاح التبديل في الشريط العلوي.

### عبر رؤوس API

أدرج البيئة في طلبات API الخاصة بك:

```bash
curl -X GET https://api.protegey.com/api/v1/signals \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -H "X-Centry-Environment: sandbox"
```

### عبر معاملات الاستعلام

أضف `?environment=sandbox` إلى أي نقطة نهاية API:

```bash
https://api.protegey.com/api/v1/signals?environment=sandbox
```

### عبر تجاوز الجلسة أو ملف تعريف الارتباط

عيِّن ملف تعريف ارتباط للجلسة `centry_env_override=sandbox` للتبديل الدائم.

### أولوية اكتشاف البيئة

يحدد النظام البيئة وفق الترتيب التالي:

1. معامل الاستعلام (`?environment=sandbox`)
2. تجاوز الجلسة أو ملف تعريف الارتباط (`centry_env_override`)
3. رأس الطلب (`X-Centry-Environment`)
4. اكتشاف النطاق الفرعي (`sandbox.*`)
5. رأس Referer (لطلبات API عبر الأصول المختلفة)
6. حالة بيئة شريك المستخدم المصادق عليه
7. **الافتراضي**: `production`

::callout{type="warning"}
**تنبيه**: لكل بيئة مجموعتها الخاصة من مفاتيح API. تأكد من استخدام المفتاح الصحيح للبيئة التي تستهدفها.
::

## عزل مخطط قاعدة البيانات

تنفِّذ Protegey **عزلًا حقيقيًا على مستوى قاعدة البيانات** باستخدام مخططات PostgreSQL:

- **بيانات الإنتاج**: مخزَّنة في مخطط `public`
- **بيانات الاختبار**: مخزَّنة في مخطط `sandbox`
- **الجداول المشتركة**: يبقى المستخدمون والشركاء والاشتراكات في مخطط `public` فقط

توفر هذه البنية:

- **صفر مخاطر** من تلوث بيانات الاختبار لتحليلات الإنتاج
- **سهولة إعادة تعيين البيانات** (بتر مخطط الاختبار)
- **عزل الأداء** بين البيئات
- **فصل البيانات** الجاهز للامتثال

## التنفيذ الواعي بالسياق

تحتفظ جميع الطلبات والوظائف الخلفية بكائن **CentryContext** غير قابل للتغيير يتضمن:

- حالة البيئة (sandbox/production)
- هوية الشريك (UUID)
- معرف تتبع الطلب
- حل المخطط

يضمن ذلك أن جميع استعلامات قاعدة البيانات ووظائف قائمة الانتظار وأحداث webhook تستخدم المخطط الصحيح تلقائيًا.

## استمرارية البيانات

تستمر بيانات الاختبار حتى تختار إعادة تعيينها. يمكنك إجراء إعادة التعيين بنطاقات مختلفة:

| نطاق إعادة التعيين    | ما يُحذف                    | حالة الاستخدام                           |
| --------------------- | --------------------------- | ---------------------------------------- |
| **إعادة تعيين كاملة** | جميع بيانات الاختبار للشريك | البدء من جديد بصفحة نظيفة                |
| **الإشارات فقط**      | سجلات الإشارات فحسب         | مسح إشارات الاختبار مع الاحتفاظ بالحالات |
| **الحالات فقط**       | سجلات الحالات فحسب          | إعادة تعيين التحقيقات                    |
| **الكيانات فقط**      | ملفات تعريف الكيانات فحسب   | مسح ذكاء الجهة الفاعلة                   |

يمكنك الوصول إلى وظيفة إعادة التعيين عبر **الاختبار > إعادة التعيين** في بوابة الشريك أو باستخدام نقطة النهاية: `POST /api/v1/partner/sandbox/reset`

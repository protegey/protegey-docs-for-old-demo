تتيح محاكاة السيناريوهات متعددة الخطوات اختبار أنماط احتيال معقدة تتكشف مع الوقت، محاكيةً أنماط الهجمات الواقعية.

## المفهوم

على خلاف الإشارات التجريبية الفردية، تُولِّد **السيناريوهات** سلسلة من الإشارات المترابطة التي تمثل هجوم احتيال منسقًا:

### مثال: تصفية حساب باستبدال SIM

1. **الخطوة 1** (T+0 دقيقة): تسجيل دخول أولي من جهاز جديد ← تُولِّد إشارة `ACCOUNT_TAKEOVER`
2. **الخطوة 2** (T+5 دقائق): فشل التحقق من رقم الهاتف ← تُولِّد إشارة `PHONE_VERIFICATION_FAILURE`
3. **الخطوة 3** (T+10 دقائق): اكتشاف استبدال SIM ← تُولِّد إشارة `SIM_SWAP`
4. **الخطوة 4** (T+12 دقيقة): تحويل ذو قيمة عالية إلى حساب خارجي ← تُولِّد إشارة `TRANSACTION` (مخاطر حرجة)
5. **الخطوة 5** (T+15 دقيقة): سحوبات صغيرة متعددة ← تُولِّد إشارات `TRANSACTION` متعددة (نمط سرعة)

## الميزات الرئيسية (مخططة)

### بيانات الجهة الفاعلة المتسقة

تشترك جميع خطوات السيناريو في نفس معرفات الجهة الفاعلة (رقم الهاتف والجهاز الأصلي وغير ذلك)، مما يُنشئ نمط احتيال متماسكًا:

```json
{
  "scenario_variables": {
    "SCENARIO_PHONE": "0244123456",
    "SCENARIO_ACCOUNT_ID": "ACC-12345"
  }
}
```

تُحلَّل هذه المتغيرات مرة واحدة عند بدء السيناريو وتُعاد عبر جميع الخطوات.

### التأخيرات الزمنية

تتكشف السيناريوهات خلال أطر زمنية واقعية:

```json
{
  "step": 3,
  "delay": 600, // 10 minutes after scenario start
  "template": "sim_swap"
}
```

**أوضاع التأخير**:

- **الوقت الفعلي**: تأخيرات حقيقية (للاختبار الحي)
- **التقديم السريع**: تأخيرات متسارعة (ثانية واحدة = دقيقة واحدة) للاختبار السريع
- **الفوري**: بدون تأخيرات (للاختبار الجماعي)

### تتبع الدفعات

تُوسَم جميع إشارات السيناريو بمعرف دفعة مشترك:

```json
{
  "metadata": {
    "generated_by": "centry_scenario",
    "scenario_name": "sim_swap_drainage",
    "scenario_batch_id": "scenario_1738598400_abc123",
    "scenario_step": 3,
    "scenario_total_steps": 5
  }
}
```

يتيح لك ذلك:

- تصفية الإشارات حسب السيناريو
- تتبع اكتمال السيناريو
- تصوير جداول زمنية للهجمات
- اختبار منطق ربط الحالات

### أحداث المحاكاة (مخططة)

تُصدر السيناريوهات أحداثًا فورية أثناء التنفيذ:

```json
{
  "event": "scenario.step_completed",
  "scenario_id": "scenario_1738598400_abc123",
  "step": 3,
  "total_steps": 5,
  "signals_created": 1,
  "next_step_delay": 120
}
```

## نقاط نهاية API (مخططة)

```bash
GET /api/v1/partner/sandbox/scenarios
```

**الاستجابة**:

```json
{
  "scenarios": [
```

## حالات الاستخدام

### اختبار منطق ربط الحالات

شغِّل السيناريوهات للتحقق من أن نظام الكشف عن الاحتيال يقوم بما يلي بشكل صحيح:

- ربط الإشارات ذات الصلة بنفس الجهة الفاعلة
- التصعيد من الإشارات إلى التنبيهات إلى الحالات
- تحديد أولوية الحالات بناءً على خطورة النمط

### اختبار سير عمل التحقيق

استخدم السيناريوهات لتدريب المحللين على:

- التعرف على أنماط الهجمات المنسقة
- ترتيب أولوية التنبيهات حسب الجدول الزمني
- تحديد مودوس أوبراندي من تسلسلات الإشارات

### اختبار تصعيد التنبيهات

تحقق من صحة إطلاق قواعد التنبيه مع تكشف السيناريوهات:

- **بعد الخطوة 1**: تنبيه منخفض الأولوية (تغيير الجهاز)
- **بعد الخطوة 3**: تنبيه عالي الأولوية (اكتشاف استبدال SIM)
- **بعد الخطوة 5**: تنبيه حرج (نمط تصفية عالية السرعة)

### اختبار الأداء

شغِّل سيناريوهات متعددة بالتزامن لاختبار حمل النظام:

```bash
POST /api/v1/partner/sandbox/simulate-batch
{
  "scenarios": [
    {"scenario": "sim_swap_drainage", "count": 10},
    {"scenario": "account_takeover_cascade", "count": 5}
  ],
  "mode": "fast-forward"
}
```

## الحل البديل الحالي

حتى تتوفر السيناريوهات متعددة الخطوات، يمكنك محاكاة الأنماط متعددة الخطوات يدويًا:

### المحاكاة اليدوية متعددة الخطوات

```bash
# Step 1: Account takeover
POST /api/v1/partner/sandbox/generate-demo-signals
{
  "template": "transaction/account_takeover",
  "count": 1,
  "overrides": {
    "PHONE_NUMBER": "0244123456"
  }
}

# Wait 5 minutes or continue immediately for testing

# Step 2: SIM swap
POST /api/v1/partner/sandbox/generate-demo-signals
{
  "template": "identity/phone_verification_failure",
  "count": 1,
  "overrides": {
    "PHONE_NUMBER": "0244123456"
  }
}

# Step 3: High-value transaction
POST /api/v1/partner/sandbox/generate-demo-signals
{
  "template": "transaction/stolen_financials",
  "count": 1,
  "overrides": {
    "PHONE_NUMBER": "0244123456",
    "TRANSACTION_AMOUNT": 50000
  }
}
```

::callout{type="info"}
**نصيحة احترافية**: استخدم `overrides` متسقة عبر الطلبات لمحاكاة نفس الجهة الفاعلة. يتيح ذلك اختبار منطق ربط الكيانات والكشف عن الأنماط.
::

## سيناريوهات موجهة لكواشف محددة

صُممت السيناريوهات التالية لتشغيل كواشف احتيال محددة بشكل موثوق. استخدمها لاختبار خط أنابيب معالجة التنبيهات لديك والتحقق من أن تكاملك يعالج كل نوع كاشف بصورة صحيحة.

### 1. انفجار سرعة — `RAPID_TRANSACTION_VELOCITY`

أرسل **12 إشارة** لنفس `entity_id` خلال نافذة 45 دقيقة. يجب أن تحمل كل إشارة `event_type: PAYMENT_FRAUD` ومبلغًا متواضعًا (أقل من حد التهيكل). ستُشغِّل الإشارة العاشرة `RAPID_TRANSACTION_VELOCITY`.

```bash
# Loop 12 times with the same entity_id
for i in $(seq 1 12); do
  curl -X POST https://api.protegey.com/api/v1/signals \
    -H "X-API-Key: $SANDBOX_KEY" \
    -d '{"event_type":"PAYMENT_FRAUD","primary_actor":{"entity_id":"test-entity-burst-001"},"event_payload":{"amount":150,"currency":"USD"}}'
  sleep 3
done
```

**المتوقع**: تنبيه بـ `detectors_triggered: ["RAPID_TRANSACTION_VELOCITY"]`، risk_level `high`.

::callout{icon="i-lucide-info" color="blue"}
**حد التنبيه**: تُولَّد التنبيهات عندما تتجاوز درجة مخاطر الكيان **0.40** (medium). تنمو درجات المخاطر مع حجم الإشارات — إرسال أكثر من 100 إشارة لنفس الجهة الفاعلة خلال جلسة واحدة سيتجاوز هذا الحد بشكل موثوق. يمكنك التحقق من الدرجة الحالية في أي وقت عبر `POST /api/v1/evaluate` بمعرّف الجهة الفاعلة.
::

---

### 2. شذوذ كبير في المبلغ — `LARGE_OUTLIER_TRANSACTION`

أولًا، أنشئ خط أساسًا بإرسال **10 إشارات** لنفس الكيان بمبالغ بين 50–200 دولار. ثم أرسل إشارة واحدة بـ `amount: 2500`. سيتجاوز Z-score 3.0 ويُشغِّل `LARGE_OUTLIER_TRANSACTION`.

**المتوقع**: تنبيه بـ `detectors_triggered: ["LARGE_OUTLIER_TRANSACTION"]`، `fusion.behavioral_score > 0.7`.

---

### 3. هجوم استبدال SIM — `SIM_SWAP_PROXIMITY`

أرسل إشارة تتضمن `sim_changed_at` مضبوطًا على **90 دقيقة مضت** مقترنًا ببصمة جهاز جديدة (تُرى لأول مرة). يحاكي ذلك الاستيلاء على حساب عقب استبدال SIM.

```json
{
  "event_type": "ACCOUNT_TAKEOVER",
  "primary_actor": {
    "entity_id": "test-entity-simswap-001",
    "identifiers": {
      "msisdn": "hash:msisdn",
      "sim_changed_at": "{{ now | minus: 90 | iso8601 }}"
    },
    "device": {
      "fingerprint": "{{ uuid }}",
      "is_first_seen": true
    }
  }
}
```

**المتوقع**: تنبيه بـ `detectors_triggered: ["SIM_SWAP_PROXIMITY"]`.

---

### 4. جهاز جديد + جغرافيا عالية المخاطر — `NEW_DEVICE_ACCESS`

أرسل إشارة ببصمة جهاز تُرى لأول مرة وعنوان IP مصدري يُحلَّل إلى ولاية قضائية عالية المخاطر (مثلًا: نيجيريا عبر GeoResolver).

```json
{
  "event_type": "ACCOUNT_TAKEOVER",
  "primary_actor": {
    "entity_id": "test-entity-newdevice-001",
    "device": {
      "fingerprint": "{{ uuid }}"
    }
  },
  "source": {
    "ip_address": "197.210.0.1"
  }
}
```

**المتوقع**: تنبيه بـ `detectors_triggered: ["NEW_DEVICE_ACCESS"]`.

---

### 5. سفر مستحيل — `IMPOSSIBLE_TRAVEL`

أرسل إشارتين لنفس الكيان خلال **90 دقيقة** — واحدة بعنوان IP غاني وأخرى بعنوان IP فرنسي. سيحتسب GeoResolver المسافة ويُشغِّل كاشف السفر المستحيل.

**الإشارة 1** — IP يُحلَّل إلى أكرا، غانا: `source.ip_address: "154.160.0.1"`
**الإشارة 2** (بعد 90 دقيقة) — IP يُحلَّل إلى باريس، فرنسا: `source.ip_address: "2.2.0.1"`

**المتوقع**: تُشغِّل الإشارة الثانية تنبيهًا بـ `detectors_triggered: ["IMPOSSIBLE_TRAVEL"]`.

---

### 6. حلقة احتيال — شبكة بيانية — تصوير الرسم البياني

أنشئ **3 كيانات** تشترك في نفس `device.fingerprint`. أرسل 2–3 إشارات لكل كيان. بعد الاستيعاب، استدعِ `GET /entities/{uuid}/graph-visualization` على أي من الكيانات الثلاثة.

**المتوقع**: تُظهر استجابة الرسم البياني الكيانات الثلاثة مرتبطةً عبر حواف `shared_device` بوزن ≥ 0.9. سيعكس `propagated_risk` على كل كيان مخاطر الشبكة الإجمالية.

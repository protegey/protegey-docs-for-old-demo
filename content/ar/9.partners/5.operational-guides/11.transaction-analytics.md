# تحليلات المعاملات

تمنح مجموعة تحليلات المعاملات فرق الامتثال والعمليات رؤيةً كميةً في أحجام الإشارات، وتوزيعات المخاطر، وإنتاجية اتخاذ القرار، وأداء المحللين. جميع نقاط نهاية التحليلات مقيّدة بنطاق الشريك وتحترم سياق بيئتك (sandbox أو الإنتاج).

---

## نظرة عامة

تتضمن مجموعة التحليلات 14 نقطة نهاية موزعةً في أربع فئات:

| الفئة | نقاط النهاية | حالة الاستخدام |
|----------|-----------|----------|
| **الحجم والاتجاهات** | السلاسل الزمنية، المقارنة | تتبع حجم الإشارات بمرور الوقت، التغييرات أسبوعًا بعد أسبوع |
| **التوزيع** | توزيع المخاطر، وقت اتخاذ القرار | فهم توزع درجات المخاطر وزمن الاستجابة |
| **الأنماط السلوكية** | الخريطة الحرارية، عوامل المخاطر | تحديد أنماط التوقيت وأبرز فئات الاحتيال |
| **أداء الفريق** | أداء المراجعين، إحصاءات قائمة الانتظار | مراقبة إنتاجية المحللين وجودة القرارات |

تقبل جميع نقاط النهاية معلمتَي التاريخ `from` و`to` بصيغة ISO 8601. النطاق الافتراضي هو آخر 30 يومًا.

---

## الحجم والاتجاهات

### السلاسل الزمنية للحجم

```http
GET /api/v1/transaction-monitoring/analytics/time-series
```

يُعيد الأعداد اليومية أو بالساعة ومتوسطات درجات المخاطر خلال الفترة المطلوبة.

**المعلمات**:

| المعلمة | النوع | الوصف |
|-----------|------|-------------|
| `from` | date | تاريخ البداية (ISO 8601) |
| `to` | date | تاريخ النهاية (ISO 8601) |
| `granularity` | string | `hour`، `day`، `week` — الافتراضي `day` |
| `risk_level` | string | التصفية حسب `low`، `medium`، `high`، `critical` |

**الاستجابة**:
```json
{
  "data": [
    {
      "date": "2026-03-01",
      "total_transactions": 1247,
      "flagged": 89,
      "avg_risk_score": 34.2,
      "risk_levels": {
        "low": 1045,
        "medium": 123,
        "high": 65,
        "critical": 14
      }
    }
  ],
  "summary": {
    "total_transactions": 38257,
    "total_flagged": 2741,
    "flag_rate": 7.16
  }
}
```

### مقارنة الفترات

```http
GET /api/v1/transaction-monitoring/analytics/comparison
```

تقارن فترتين زمنيتين (الحالية مقابل السابقة) من حيث الحجم ومعدل العلامات ومتوسط درجة المخاطر. مفيد للكشف عن الشذوذات أسبوعًا بعد أسبوع في نشاط الاحتيال.

**المعلمات**: `current_from`، `current_to`، `prior_from`، `prior_to`

## تحليل التوزيع

### توزيع درجات المخاطر

```http
GET /api/v1/transaction-monitoring/analytics/distribution
```

يُعيد مدرجًا تكراريًا لدرجات المخاطر خلال الفترة المختارة. استخدمه لمعايرة إعدادات الحدود وفهم توزيع الدرجات لديك.

**الاستجابة**:
```json
{
  "data": {
    "buckets": [
      { "range": "0-9", "count": 8420 },
      { "range": "10-19", "count": 6215 },
      { "range": "20-29", "count": 4830 },
      { "range": "30-39", "count": 3120 },
      { "range": "40-49", "count": 2890 },
      { "range": "50-59", "count": 2410 },
      { "range": "60-69", "count": 1870 },
      { "range": "70-79", "count": 1340 },
      { "range": "80-89", "count": 920 },
      { "range": "90-100", "count": 622 }
    ],
    "mean": 31.4,
    "median": 24.0,
    "p95": 78.0,
    "p99": 91.0
  }
}
```

### توزيع وقت اتخاذ القرار

```http
GET /api/v1/transaction-monitoring/analytics/decision-time
```

يعرض توزيع وقت اتخاذ القرار عبر جميع المعاملات المراجعة. مفيد لمراقبة اتفاقية مستوى الخدمة وتحديد الاختناقات في قائمة انتظار المراجعة.

**تتضمن الاستجابة**: `p50_seconds`، `p90_seconds`، `p99_seconds`، `mean_seconds`، `reviewed_count`

## الأنماط السلوكية

### الخريطة الحرارية للنشاط

```http
GET /api/v1/transaction-monitoring/analytics/heatmap
```

يُعيد مصفوفة 7×24 (يوم الأسبوع × ساعة اليوم) لحجم المعاملات ومتوسطات درجات المخاطر. يساعد على تحديد نوافذ الوقت عالية المخاطر (مثلًا: انفجارات ليلية، ارتفاعات في عطلات نهاية الأسبوع).

**الاستجابة**:
```json
{
  "data": {
    "matrix": [
      {
        "day": "monday",
        "hours": [
          { "hour": 0, "count": 12, "avg_risk": 71.2 },
          { "hour": 1, "count": 8, "avg_risk": 68.5 }
        ]
      }
    ],
    "peak_hour": { "day": "friday", "hour": 23, "avg_risk": 82.1 }
  }
}
```

### تصنيف عوامل المخاطر

```http
GET /api/v1/transaction-monitoring/analytics/risk-factors
```

يجمع الكواشف الأكثر تشغيلًا وعلامات AML وفئات التصنيف خلال الفترة المختارة.

**الاستجابة**:
```json
{
  "data": {
    "top_detectors": [
      { "detector": "RAPID_TRANSACTION_VELOCITY", "trigger_count": 892, "pct": 32.5 },
      { "detector": "LARGE_OUTLIER_TRANSACTION", "trigger_count": 741, "pct": 27.0 }
    ],
    "top_taxonomy": [
      { "category": "payment.structuring", "count": 654, "pct": 23.8 }
    ],
    "top_aml_flags": [
      { "flag_type": "velocity_breach", "count": 1102, "pct": 40.2 }
    ]
  }
}
```

## أداء الفريق

### أداء المراجعين

```http
GET /api/v1/transaction-monitoring/analytics/reviewer-performance
```

مؤشرات لكل محلل: القرارات المتخذة، متوسط وقت المراجعة، معدل الإيجابيات الكاذبة، والدقة (حيثما توفرت نتائج الحالة الحقيقية).

::callout{type="info"}
يتطلب خطة **Business** أو **Enterprise**. هوية المراجع مرتبطة بحسابات مستخدمي OAuth2.
::

**الاستجابة**:
```json
{
  "data": [
    {
      "reviewer_uuid": "usr_01HZ...",
      "reviewer_name": "Kofi Mensah",
      "decisions_made": 342,
      "avg_review_seconds": 147,
      "approve_rate": 0.61,
      "reject_rate": 0.39,
      "escalation_rate": 0.08
    }
  ]
}
```

### مؤشرات الأداء (إحصاءات قائمة الانتظار)

```http
GET /api/v1/transaction-monitoring/analytics/performance
```

مؤشرات قائمة الانتظار الإجمالية: عدد المعاملات في انتظار المراجعة، متوسط عمر القائمة، معدل خرق اتفاقية مستوى الخدمة، والإنتاجية.

## استخدام التحليلات لمعايرة الحدود

تبرز قيمة نقطة نهاية التوزيع بشكل خاص عند معايرة حدود درجات المخاطر:

1. شغِّل `GET /analytics/distribution` على 30 يومًا من بيانات الإنتاج
2. حدد درجة `p95` — هذا الحد الطبيعي لمستوى المخاطر `high`
3. عيِّن حد سياسة `BLOCK` عند `p99` لتقليل الإيجابيات الكاذبة
4. راجع `risk-factors` لتحديد الكواشف التي تولّد ضوضاء مقابل إشارات حقيقية

تغييرات الحدود تسري فورًا عبر محرك سياسة القرار ولا تتطلب عمليات نشر جديدة للكود.

## القرارات الجماعية على المعاملات

::callout{icon="i-lucide-lock" color="orange"}
متاح لخطط **Enterprise** مع تفعيل ميزة `bulk_decisioning`.
::

للعمليات ذات الحجم الكبير — عواصف التنبيهات، طوابير المراجعة في نهاية اليوم، استجابات الاحتيال المنسق — يتيح لك endpoint القرار الجماعي الموافقة على معاملات متعددة أو حظرها في استدعاء API واحد:

```http
POST /api/v1/transaction-monitoring/bulk-decide
```

**جسم الطلب:**

```json
{
  "transaction_ids": ["TXN-001", "TXN-002", "TXN-003"],
  "decision": "block",
  "reason": "هجوم سرعة منسق — تم حظر الجهة الفاعلة عبر جميع المعاملات المعلقة",
  "decision_type": "automated"
}
```

| الحقل | النوع | القيم |
|-------|-------|-------|
| `transaction_ids` | string[] | حتى 100 لكل استدعاء |
| `decision` | string | `approve` · `block` · `review` |
| `reason` | string | ملاحظة التدقيق — مطلوبة لقرارات `block` |
| `decision_type` | string | `manual` · `automated` · `hybrid` |

يؤثر `decision_type` على وزن تدريب النموذج. ميّز القرارات الآلية (`automated`) عن تلك التي راجعها المحللون حتى يتمكن خط أنابيب التدريب من إعطاء وزن أعلى للتسميات المتحقق منها بشريًا.

**أنماط الحجم الكبير:**

- **استجابة عاصفة التنبيهات** — عندما يُظهر `GET /analytics/time-series` ارتفاعًا، اسحب المعاملات `pending` المتأثرة وحظرها على دفعات من 100
- **إفراغ الطابور في نهاية اليوم** — عالج طابور المخاطر المنخفضة في نهاية اليوم بالموافقة الجماعية على المعاملات دون عتبة `p50`
- **تنظيف ما بعد الحادث** — بعد إغلاق حالة احتيال منسق، حظر جميع المعاملات المرتبطة بنفس hash الجهة الفاعلة جماعيًا

## التصدير

يمكن تصدير جميع بيانات التحليلات إلى CSV عبر:

```http
POST /api/v1/transaction-monitoring/export
```

يُعيد هذا الطلب رابط تنزيل موقعًا لتحميل مجموعة بيانات المعاملات الكاملة للفترة المختارة، مناسبًا للتحليل دون اتصال في Excel أو Python.

توفر إدارة الحالات في Protegey سير عمل منظمًا للتحقيق في إشارات الاحتيال والتعاون مع فريقك والحفاظ على مسار تدقيق كامل لجميع أنشطة التحقيق.

::callout{icon="i-lucide-folder-open" color="blue"}
**تحقيقات الاحتيال بسهولة**: حوِّل الإشارات عالية المخاطر إلى حالات، أضف ملاحظات التحقيق، أرفق الأدلة، وتتبع الحالة حتى الحل.
::

## نظرة عامة

### ما هي الحالة؟

**حالة الاحتيال** هي سجل تحقيق منظم يقوم بما يلي:
- الارتباط بإشارة احتيال واحدة أو أكثر
- احتواء ملاحظات التحقيق والنتائج
- تتبع الأدلة (لقطات الشاشة، الوثائق، السجلات)
- الحفاظ على الحالة والأولوية
- تسجيل جدول زمني كامل لجميع الأنشطة
- دعم التعاون الجماعي والتعيين

### متى تُنشئ حالة

أنشئ حالات للإشارات التي تتطلب:
- **تحقيقًا يدويًا**: الإشارات عالية المخاطر (درجة ≥ 80) التي تحتاج إلى مراجعة المحلل
- **نمط متعدد الإشارات**: إشارات متعددة ذات صلة تشير إلى حلقة احتيال
- **نزاع العميل**: يدّعي المستخدم أن نشاطًا مشروعًا تم تصنيفه كاحتيال
- **توثيق**: احتيال معقد يتطلب جمع أدلة مفصلة
- **تصعيد**: إشارات تتطلب تدخل محلل أقدم أو جهات إنفاذ القانون

## دورة حياة الحالة

### تدفق الحالة

```
open → in_progress → resolved → closed
         ↓
      on_hold
```

| الحالة | الوصف | الإجراءات المتاحة |
|--------|-------|------------------|
| **open** | حالة جديدة في انتظار التعيين | التعيين، إضافة ملاحظات، بدء التحقيق |
| **in_progress** | يجري التحقيق فيها بنشاط | إضافة أدلة، تحديث النتائج، الحل |
| **on_hold** | موقوفة (في انتظار معلومات) | الاستئناف، إضافة ملاحظات، الإغلاق |
| **resolved** | اكتمل التحقيق | إضافة ملاحظات الحل، الإغلاق |
| **closed** | الحالة مؤرشفة | عرض فقط (للقراءة فقط) |

### مستويات الأولوية

| الأولوية | الوصف | SLA الاستجابة | متى تستخدم |
|----------|-------|--------------|-----------|
| **low** | تحقيق غير عاجل | 72 ساعة | أنماط منخفضة المخاطر، مراقبة استباقية |
| **medium** | تحقيق معياري | 24 ساعة | إشارات متوسطة المخاطر، جهات فاعلة متكررة |
| **high** | مراجعة عاجلة | 4 ساعات | إشارات عالية المخاطر، تأثير على العميل |
| **critical** | إجراء فوري مطلوب | ساعة واحدة | احتيال مؤكد، هجوم نشط، مبالغ كبيرة |

## إنشاء الحالات

### الطريقة الأولى: من إشارة (موصى بها)

إنشاء حالة مباشرةً من إشارة عالية المخاطر:

**بوابة الشريك**:
1. انتقل إلى مراقبة المعاملات
2. انقر فوق إشارة عالية المخاطر
3. انقر فوق زر "إنشاء حالة"
4. تُملأ الحالة مسبقًا ببيانات الإشارة

**API**:
```typescript
const fraudCase = await client.cases.createFromSignal('sig_abc123', {
  description: 'High-value cross-border transfer requires investigation',
  priority: 'high',
  category: 'ACCOUNT_TAKEOVER'
});

console.log(`Case created: ${fraudCase.uuid}`);
```

**البيانات المنسوخة من الإشارة**:
- معرف المعاملة
- درجة المخاطر ومستواها
- تجزئة الجهة الفاعلة
- مبلغ المعاملة وعملتها
- البيانات الوصفية (الجهاز، IP، الدولة)
- عوامل المخاطر التي أطلقت الكشف

---

### الطريقة الثانية: الإنشاء اليدوي

إنشاء حالة دون إشارة مرتبطة:

**بوابة الشريك**:
1. انتقل إلى الحالات
2. انقر فوق زر "حالة جديدة"
3. أدخل تفاصيل الحالة
4. عيِّن إلى محلل (اختياري)

**API**:
```typescript
const fraudCase = await client.cases.create({
  title: 'Investigation: Account Takeover - 2026-02-03',
  description: 'Customer reported unauthorized transactions on account ending in 4532. Investigating access pattern and transaction history.',
  priority: 'high',
  category: 'ACCOUNT_TAKEOVER',
  assigned_user_id: 42 // Optional
});
```

- **القائم على المهارة**: التوجيه حسب خبرة تصنيف الاحتيال
- **القائم على العبء**: التعيين للمحلل الذي لديه أقل حالات مفتوحة
- **القائم على الأولوية**: الحالات الحرجة تذهب إلى المحللين الأقدم

### الخطوة الثانية: التحقيق وتدوين الملاحظات

إضافة ملاحظات التحقيق أثناء العمل:

**API**:
```typescript
await client.cases.addNote(caseUuid, {
  content: `## Initial Findings

- Reviewed account activity for last 30 days
- Login from new device (iPhone 14) in Lagos, Nigeria
- Previous logins always from Accra, Ghana

- Customer phone number unreachable (possible SIM swap)
```

**أنواع الملاحظات**:
- **ملاحظات التحقيق**: النتائج، التحليل، الخطوات التالية
- **التواصل مع العميل**: سجلات التواصل مع العميل
- **مرجع خارجي**: روابط إلى أنظمة خارجية (CRM، نظام التذاكر)
- **ملخص الأدلة**: وصف الأدلة المرفقة

**أفضل الممارسات**:
- استخدام Markdown للتنسيق
- تضمين الطوابع الزمنية للأحداث الرئيسية
- الإشارة إلى الأدلة باسم الملف
- توثيق مبررات القرار
- تحديث الملاحظات بعد كل جلسة تحقيق

### الخطوة الثالثة: جمع الأدلة

إرفاق أدلة داعمة بالحالات:

**أنواع الأدلة المدعومة**:
- لقطات الشاشة (PNG، JPG)
- سجلات المعاملات (CSV، JSON)
- سجلات التواصل (TXT، PDF)
- وثائق الهوية (PDF، JPG - احذف البيانات الحساسة!)
- سجلات النظام (TXT، LOG)
- تسجيلات الفيديو (MP4 - دليل محاكاة الاحتيال)

**API**:
```typescript
// Upload evidence
const evidence = await client.cases.attachEvidence(caseUuid, {
  file: await fs.readFile('screenshot_fraudulent_transaction.png'),
  filename: 'screenshot_fraudulent_transaction.png',
  description: 'Screenshot showing unauthorized transfer of GHS 15,000',
  type: 'screenshot'
});

// List all evidence
const allEvidence = await client.cases.listEvidence(caseUuid);
```

**أفضل ممارسات الأدلة**:
- **حذف PII**: إزالة بيانات العميل الحساسة قبل الرفع
- **تسمية واضحة**: استخدام أسماء ملفات وصفية (مثلاً: `2026-02-03_login_logs.csv`)
- **السياق**: إضافة وصف يشرح صلة الأدلة بالقضية
- **سلسلة الحيازة**: توثيق من جمع الأدلة ومتى
- **حدود الحجم**: الحد الأقصى 10MB لكل ملف، و50MB إجمالاً لكل حالة

### الخطوة الرابعة: تحديثات الحالة

تحديث حالة القضية مع تقدم التحقيق:

**انتقالات الحالة الشائعة**:

```typescript
// Start investigation
await client.cases.update(caseUuid, {
  status: 'in_progress'
});

// Pause for customer response
await client.cases.update(caseUuid, {
  status: 'on_hold',
  notes: 'Awaiting customer response to verification email'
});

// Resume investigation
await client.cases.update(caseUuid, {
  status: 'in_progress',
  notes: 'Customer confirmed unauthorized activity'
});

// Resolve case
await client.cases.update(caseUuid, {
  status: 'resolved',
  resolution: 'Confirmed fraud. Account secured, funds recovered, law enforcement notified.'
});

// Archive case
await client.cases.update(caseUuid, {
  status: 'closed'
});
```

### الخطوة الخامسة: الحل والإغلاق

**أنواع الحل**:

| الحل | الوصف | الإجراءات المتخذة |
|------|-------|------------------|
| **Confirmed Fraud** | تم التحقق من الاحتيال | حجب الجهة الفاعلة، عكس المعاملات، إخطار الجهات المختصة |
| **False Positive** | نشاط مشروع | إدراج الجهة الفاعلة في القائمة البيضاء، ضبط عتبات المخاطر |
| **Insufficient Evidence** | لا يمكن التحديد | لا إجراء، الاستمرار في المراقبة |
| **Customer Dispute** | يدّعي العميل الشرعية | التحقيق في تاريخ العميل، التحقق من الهوية |
| **Technical Error** | خطأ في النظام تسبب في العلامة | إصلاح الخطأ، إعادة معالجة الإشارة |

**توثيق الحل**:
```typescript
await client.cases.update(caseUuid, {
  status: 'resolved',
  resolution: `## Investigation Summary
Confirmed account takeover via SIM swap fraud.

## Evidence
- Customer confirmed unauthorized SIM replacement on 2026-02-02
- Device fingerprint changed from known iPhone to new Android device
- IP geolocation changed from Accra (normal) to Lagos (unusual)
- Transaction velocity (5 transfers in 2 hours) highly anomalous

## Actions Taken
- Account access disabled pending customer verification
- Transactions reversed (GHS 45,000 total)
- Customer contacted via email - account reset link sent
- Mobile carrier notified of fraudulent SIM swap
- Actor phone number (0244xxxxxx) added to blocklist
- Law enforcement notified (case #NG-2026-0203-001)

## Prevention
- Enabled 2FA requirement for account changes
- Added SIM swap detection rule
- Updated velocity thresholds for Nigeria-origin transactions
- Customer education sent regarding SIM security

## Resolution
Confirmed fraud. All funds recovered. Account secured.`,
  priority: 'low' // Downgrade priority after resolution
});
```

## أفضل الممارسات

### 1. إنشاء الحالات على الفور

**لا تؤجل التحقيق**:
```typescript
// ✅ GOOD: Create case immediately for high-risk signals
if (signal.risk_score >= 80) {
  await client.cases.createFromSignal(signal.id, {
    priority: 'high',
    category: 'ACCOUNT_TAKEOVER'
  });
}

// ❌ BAD: Waiting days before creating case
// Evidence may be lost, actors may continue fraud
```

### 3. استخدام الأولوية بشكل صحيح

**إرشادات الأولوية**:
- **حرجة**: احتيال نشط، تعذُّر وصول العميل إلى حسابه، مبالغ كبيرة (>$10k)، مخاطر سمعة
- **عالية**: احتيال حديث (<24 ساعة)، مبالغ متوسطة ($1k-$10k)، جهة فاعلة متكررة
- **متوسطة**: إشارات أقدم، مبالغ منخفضة (<$1k)، مخالفة أولى
- **منخفضة**: مراقبة استباقية، حالات تعليمية، تحليل الاتجاهات

### 4. الاستفادة من التصنيفات

**يُتيح التصنيف الدقيق**:
- توجيه متخصص للمحللين
- تحليلات خاصة بكل تصنيف
- تحديد اتجاهات الاحتيال
- إعداد التقارير التنظيمية

---

### 5. التحديث المنتظم للحالة

**الحفاظ على حالة محدَّثة**:
- التحديث خلال ساعة من بدء التحقيق
- التغيير إلى `on_hold` إن كنت بانتظار معلومات (لا تتركها على `in_progress`)
- الحل الفوري عند اكتمال التحقيق
- الإغلاق بعد 30 يومًا من عدم النشاط (بعد الحل)

---

### 6. التعاون الفعّال

**استخدام التعيينات من أجل**:
- وضوح الملكية
- ظهور العبء
- المساءلة
- تتبع التصعيد

**استخدام الملاحظات من أجل**:
- معلومات التسليم
- تحديثات المناوبة
- طرح الأسئلة على الفريق
- توثيق المناقشات

- حذف PII الحساسة قبل الرفع
- تضمين سياق لكل قطعة دليل
- الحفاظ على الترتيب الزمني

## السيناريوهات الشائعة

### السيناريو الأول: فرز إشارة عالية المخاطر

```typescript
async function triageHighRiskSignal(signal) {
  // 1. Create case from signal
  const fraudCase = await client.cases.createFromSignal(signal.id, {
    priority: signal.risk_score >= 90 ? 'critical' : 'high',
    category: signal.event_type
  });

  // 2. Add initial triage note
  await client.cases.addNote(fraudCase.uuid, {
    content: `## Triage Assessment
Risk Score: ${signal.risk_score}/100
Risk Level: ${signal.risk_level}

## Key Risk Factors:
${signal.risk_factors.map(f => `- ${f.factor}: ${f.description}`).join('\n')}

## Next Steps:
- Review actor history
- Check similar transactions
- Contact customer if needed`
  });

  // 3. Assign based on expertise
  const analyst = await findAnalystForCategory(signal.event_type);
  await client.cases.update(fraudCase.uuid, {
    assigned_user_id: analyst.id
  });

  return fraudCase;
}
```

### السيناريو الثاني: حلقة احتيال متعددة الإشارات

```typescript
async function investigateFraudRing(signals) {
  // 1. Create master case
  const masterCase = await client.cases.create({
    title: `Fraud Ring Investigation - ${signals.length} Related Signals`,
    description: `Investigating coordinated fraud pattern across ${signals.length} signals sharing device fingerprints and IP addresses.`,
    priority: 'critical',
    category: 'ACCOUNT_TAKEOVER'
  });

  // 2. Document pattern
  await client.cases.addNote(masterCase.uuid, {
    content: `## Pattern Identified
- ${signals.length} signals within 24 hours
- Shared device fingerprint: ${signals[0].metadata.device_fingerprint}
- Same IP range: 41.XX.XX.XX
- Total exposure: GHS ${signals.reduce((sum, s) => sum + s.transaction.amount, 0).toLocaleString()}

## Affected Accounts
${signals.map(s => `- ${s.actor.hashed_id} - GHS ${s.transaction.amount}`).join('\n')}`
  });

  // 3. Link all signals to case (via notes)
  for (const signal of signals) {
    await client.cases.addNote(masterCase.uuid, {
      content: `Related signal: ${signal.id} - Risk Score: ${signal.risk_score}`
    });
  }

  return masterCase;
}
```

```typescript
async function handleCustomerDispute(signal, customerMessage) {
  // 1. Create case for investigation
  const disputeCase = await client.cases.createFromSignal(signal.id, {
    priority: 'high',
    category: 'CUSTOMER_DISPUTE',
    description: `Customer disputes fraud flag. Claims legitimate activity.`
  });

  // 2. Document customer claim
  await client.cases.addNote(disputeCase.uuid, {
    content: `## Customer Claim
"${customerMessage}"

## Signal Details
- Risk Score: ${signal.risk_score}
- Risk Factors: ${signal.risk_factors.map(f => f.factor).join(', ')}

## Investigation Plan
1. Review customer account history (last 6 months)
2. Verify device fingerprint matches known devices
3. Check IP geolocation against customer address
4. Review similar patterns in account
5. Contact customer for additional verification if needed`
  });

  // 3. Assign to senior analyst
  await client.cases.update(disputeCase.uuid, {
    assigned_user_id: await getSeniorAnalyst(),
    priority: 'high'
  });

  return disputeCase;
}
```

### مقاييس الحالات الرئيسية

**تتبع الأداء**:
- **إجمالي الحالات**: حجم الحالات الكلي
- **الحالات المفتوحة**: العبء الحالي
- **متوسط وقت الحل**: مقياس الكفاءة
- **الحالات حسب الأولوية**: توزيع الإلحاحية
- **الحالات حسب التصنيف**: تفصيل نوع الاحتيال
- **معدل الإغلاق**: نسبة المحلولة مقابل المُنشأة
- **أداء المحلل**: الحالات لكل محلل، متوسط وقت الحل

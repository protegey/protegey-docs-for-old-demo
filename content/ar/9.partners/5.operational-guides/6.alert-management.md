توفر إدارة التنبيهات في Protegey كشفًا آليًا للاحتيال مع عتبات قابلة للتخصيص، مما يُمكِّن فريقك من التركيز على التهديدات ذات الأولوية العالية مع الحفاظ على الرؤية الشاملة لجميع إشارات المخاطر.

::callout{icon="i-lucide-bell" color="amber"}
**الكشف الآلي**: تُولَّد التنبيهات تلقائيًا عندما تتجاوز الإشارات عتبات المخاطر المُهيَّأة، مما يُتيح الاستجابة السريعة لأنماط الاحتيال الناشئة.
::

## نظرة عامة

### ما هو التنبيه؟

**التنبيه** هو إشعار آلي يُولَّد عندما:

- تتجاوز إشارة الاحتيال عتبة المخاطر المُهيَّأة
- تُخترق حدود السرعة (تكرار المعاملات)
- تُكشف أنماط احتيال معروفة
- يحدث تطابق مع قائمة حجب
- يُشغِّل كاشف الشذوذ مستوى ثقة عالٍ

### التنبيهات مقابل الإشارات مقابل الحالات

| الكيان    | الوصف          | الإنشاء         | الغرض          |
| --------- | -------------- | --------------- | -------------- |
| **إشارة** | حدث احتيال خام | استيعاب API     | إدخال البيانات |
| **تنبيه** | إشعار آلي      | يُولِّده النظام | الكشف          |
| **حالة**  | سجل تحقيق      | يدوي/من تنبيه   | التحقيق        |

**التدفق**:

```
Signal Ingested → Risk Scored → Alert Generated (if threshold met) → Case Created (if needed)
```

---

## دورة حياة التنبيه

### تدفق الحالة

```
pending → acknowledged → resolved
                ↓
          false_positive
```

| الحالة             | الوصف                       | الإجراءات المتاحة                      |
| ------------------ | --------------------------- | -------------------------------------- |
| **pending**        | تنبيه جديد في انتظار الفرز  | الاعتراف، الحل، وضع علامة خطأ إيجابي   |
| **acknowledged**   | المحلل مُطَّلع، يراجع       | الحل، وضع علامة خطأ إيجابي، إنشاء حالة |
| **resolved**       | احتيال مؤكد، تم اتخاذ إجراء | عرض فقط (للقراءة فقط)                  |
| **false_positive** | ليس احتيالًا في الواقع      | عرض فقط، ضبط العتبات                   |

### مستويات الخطورة

| الخطورة      | نطاق درجة المخاطر | الوصف              | وقت الاستجابة       |
| ------------ | ----------------- | ------------------ | ------------------- |
| **low**      | 40-59             | مؤشرات مخاطر طفيفة | مراجعة خلال 24 ساعة |
| **medium**   | 60-74             | عوامل مخاطر متعددة | مراجعة خلال 4 ساعات |
| **high**     | 75-89             | مؤشرات احتيال قوية | مراجعة خلال ساعة    |
| **critical** | 90-100            | نمط احتيال مؤكد    | مراجعة فورية        |

## أنواع التنبيهات

### 1. تنبيهات السرعة

تُشغَّل عندما يتجاوز تكرار المعاملات الأنماط الطبيعية.

**مثال**:

```json
{
  "alert_type": "velocity_check",
  "severity_level": "high",
  "message": "Unusual transaction velocity detected: 5 transactions in 10 minutes",
  "metadata": {
    "window": "10_minutes",
    "count": 5,
    "threshold": 3,
    "actor_hash": "hash_0244567890"
  }
}
```

**الأنماط الشائعة**:

- اختبار البطاقات: معاملات صغيرة كثيرة بسرعة
- استيلاء على الحساب: نشاط مكثف بعد فترة طويلة من الخمول
- بغل المال: تحويلات متسارعة داخلاً وخارجاً

---

### 2. تنبيهات الشذوذ

تُشغَّل بسبب الانحرافات عن أنماط السلوك المُرسَّخة.

**مثال**:

```json
{
  "alert_type": "anomaly_detection",
  "severity_level": "high",
  "message": "Transaction amount 10x above user's normal pattern",
  "metadata": {
    "amount": 50000,
    "normal_avg": 4500,
    "deviation": "10.2x"
  }
}
```

**أنواع الشذوذ**:

- شذوذ المبلغ (حجم المعاملة)
- شذوذ الوقت (ساعة/يوم غير معتاد)
- شذوذ جغرافي (موقع جديد)
- شذوذ الجهاز (جهاز جديد أو مُغيَّر)

---

### 3. تنبيهات الشبكة

تُشغَّل بسبب الارتباط بجهات فاعلة أو شبكات احتيال معروفة.

**مثال**:

```json
{
  "alert_type": "network_link",
  "severity_level": "critical",
  "message": "Actor linked to 3 confirmed fraudsters in the network",
  "metadata": {
    "linked_entities": 3,
    "link_strength": 0.94,
    "shared_attributes": ["device_fingerprint", "ip_address"]
  }
}
```

---

### 4. تنبيهات قائمة الحجب

تُشغَّل بسبب التطابق مع قوائم الحجب العالمية أو الخاصة بالشريك.

**مثال**:

```json
{
  "alert_type": "blocklist_match",
  "severity_level": "critical",
  "message": "Actor matches global fraud blocklist",
  "metadata": {
    "list_name": "global_fraudsters",
    "match_confidence": 0.98,
    "previous_incidents": 7
  }
}
```

---

### 5. تنبيهات السفر المستحيل

تُشغَّل عندما تشير المواقع الجغرافية إلى سفر مستحيل جسديًا.

**مثال**:

```json
{
  "alert_type": "impossible_travel",
  "severity_level": "high",
  "message": "Login from Lagos 30 minutes after login from Accra (420km apart)",
  "metadata": {
    "location_1": "Accra, GH",
    "location_2": "Lagos, NG",
    "distance_km": 420,
    "time_elapsed_minutes": 30,
    "required_speed_kmh": 840
  }
}
```

## سير عمل فرز التنبيهات

### الخطوة الأولى: مراجعة التنبيه

**عرض التنبيهات الجديدة**:

```typescript
const pendingAlerts = await client.alerts.list({
  status: "pending",
  sort_by: "severity_level",
  sort_order: "desc", // Critical first
});

for (const alert of pendingAlerts.data) {
  console.log(`${alert.severity_level} - ${alert.message}`);
}
```

**التقييم السريع**:

1. مراجعة مستوى الخطورة
2. قراءة رسالة التنبيه
3. فحص تفاصيل الإشارة المرتبطة
4. تحديد نوع التنبيه
5. تقييم المخاطر الفورية

---

### الخطوة الثانية: الاعتراف بالتنبيه

الإشارة إلى الوعي والبدء في التحقيق:

```typescript
await client.alerts.update(alertUuid, {
  status: "acknowledged",
  acknowledged_by: userId,
  notes: "Reviewing actor history and linked transactions",
});
```

**متى تعترف**:

- التنبيهات العالية/الحرجة فورًا ✅
- عند بدء التحقيق ✅
- لمنع ازدواجية العمل (يُظهر للآخرين أنك تتولى الأمر) ✅

**أهداف SLA**:

- حرجة: < 5 دقائق
- عالية: < 15 دقيقة
- متوسطة: < ساعة
- منخفضة: < 4 ساعات

---

### الخطوة الثالثة: التحقيق

**مراجعة الإشارة المرتبطة**:

```typescript
const alert = await client.alerts.get(alertUuid);
const signal = await client.signals.get(alert.signal_id);

// Check risk breakdown
const riskBreakdown = await client.transactionMonitoring.riskBreakdown(
  signal.id,
);

// Find similar transactions
const similar = await client.transactionMonitoring.findSimilar(signal.id, {
  threshold: 0.8,
});
```

**قائمة تدقيق التحقيق**:

- [ ] مراجعة درجة المخاطر وعواملها
- [ ] فحص تاريخ الجهة الفاعلة (المعاملات السابقة)
- [ ] البحث عن أنماط مشابهة (حلقة احتيال؟)
- [ ] التحقق من اتساق الجغرافيا/الجهاز
- [ ] الفحص مقابل قوائم الحجب
- [ ] مراجعة صحة حساب العميل

### الخطوة الرابعة: الحل

اختيار الحل المناسب بناءً على النتائج:

#### الحل: احتيال مؤكد

```typescript
await client.alerts.update(alertUuid, {
  status: "resolved",
  resolution_type: "confirmed_fraud",
  resolution_notes:
    "Confirmed account takeover. Actor blocked, customer notified.",
  actions_taken: [
    "blocked_actor",
    "reversed_transaction",
    "notified_customer",
    "created_case",
  ],
});

// Optionally create case for detailed investigation
if (alert.severity_level === "critical") {
  await client.cases.createFromSignal(alert.signal_id, {
    priority: "high",
    category: alert.alert_type,
  });
}
```

#### الحل: خطأ إيجابي

```typescript
await client.alerts.update(alertUuid, {
  status: "false_positive",
  resolution_notes:
    "Verified with customer - legitimate high-value purchase. Customer traveling internationally.",
  tuning_notes:
    "Consider increasing threshold for verified customers with international travel history.",
});

// Update thresholds if pattern identified
if (shouldAdjustThreshold(alert)) {
  await client.settings.updateAlertThresholds({
    velocity_check: { threshold: 5 }, // Increase from 3
  });
}
```

## تهيئة التنبيهات

### قواعد التنبيه لكل فئة

يُصنَّف كل إشارة في إحدى الفئات التصنيفية الـ13 (مثل `payment.mobile_money` و`geo.impossible_travel` و`identity.synthetic`). لكل فئة قاعدة خاصة بها تتحكم في ما إذا كان التنبيه يُطلق وعند أي مستوى ثقة.

انتقل إلى **التنبيهات ← قواعد التنبيه** في بوابة الشريك للتهيئة.

#### دقة القواعد

| الطبقة | المصدر | الأولوية |
|---|---|---|
| تجاوز الشريك | تهيئتك المحفوظة | الأعلى |
| الإعداد الافتراضي للنظام | مشتق من الخطورة الأساسية للتصنيف | متوسط |
| العتبة الاحتياطية العالمية | 0.40 (العتبة المتوسطة) | الأدنى |

يعمل المحرك دائماً بنهج **fail-open** — لا يُكبَح التنبيه أبداً بسبب غياب قاعدة.

#### مفتاح التبديل

يُفعِّل أو يُعطِّل جميع التنبيهات لفئة احتيال بأكملها بصرف النظر عن درجة المخاطرة. إشارة بدرجة 0.99 في فئة معطَّلة لا تُنتج أي تنبيه.

::callout{icon="i-lucide-lock" color="red"}
**قواعد النظام** (`identity.sim_swap` و`identity.account_takeover` و`payment.agent_collusion`) نشطة دائماً لأسباب تنظيمية. يُرجع تعطيلها عبر API خطأ HTTP 403.
::

#### شريط الحد الأدنى لدرجة المخاطرة

يحدد عتبة الثقة (0.10–0.99) التي يجب أن يبلغها المحرك قبل إطلاق التنبيه.

| النطاق | المؤشر | التفسير |
|---|---|---|
| 85–99% | وردي | ثقة عالية جداً — تنبيهات قليلة ودقيقة |
| 70–84% | برتقالي | ثقة عالية — نقطة البداية الموصى بها |
| 55–69% | عنبري | ثقة متوسطة — تغطية أوسع وحجم مراجعة أكبر |
| 10–54% | أزرق | عتبة منخفضة — يلتقط إشارات ضعيفة مع مزيد من الإيجابيات الكاذبة |

#### سير عمل الحفظ

تُحفظ التغييرات كمسودات محلية حتى النقر على **حفظ**. تُشير نقطة برتقالية إلى الصفوف غير المحفوظة. زر **إعادة التعيين** (↺) يحذف التجاوز ويعود إلى الإعداد الافتراضي للنظام.

### API

```typescript
// قائمة الفئات الـ13 مع تهيئتك الفعّالة
GET /api/v1/partner/alert-rules

// تعطيل فئة
PUT /api/v1/partner/alert-rules/geo.impossible_travel
{ "is_enabled": false, "override_reason": "قاعدة عملاء عابرة للحدود" }

// رفع العتبة دون تعطيل
PUT /api/v1/partner/alert-rules/device.anomaly
{ "min_severity_score": 0.80 }

// إعادة التعيين إلى الإعداد الافتراضي للنظام
DELETE /api/v1/partner/alert-rules/device.anomaly
```

---

### ربط الخطورة

**درجة المخاطرة → مستوى الخطورة** (التصنيف بعد إطلاق التنبيه):

| درجة المخاطرة | الخطورة الافتراضية | الهدف الزمني |
| ------------- | ------------------ | ------------ |
| 90–100        | حرج (Critical)     | فوري         |
| 75–89         | مرتفع (High)       | < ساعة       |
| 60–74         | متوسط (Medium)     | < 4 ساعات    |
| 40–59         | منخفض (Low)        | < 24 ساعة    |
| أقل من العتبة | لا يوجد تنبيه      | —            |

يتحكم الحد الأدنى لدرجة المخاطرة في قاعدة التنبيه في ما إذا كان التنبيه يُطلق أصلاً؛ يأتي التصنيف أعلاه بعد إنشائه.

## قنوات إشعارات التنبيهات

### إشعارات Webhook

استقبال التنبيهات الفورية عبر webhooks:

**التهيئة في بوابة الشريك**:

- الإعدادات > التكاملات > Webhooks
- الاشتراك في حدث `alert.triggered`

**حمولة Webhook**:

```json
{
  "id": "evt_alert_001",
  "type": "alert.triggered",
  "created_at": "2026-02-03T14:30:00Z",
  "data": {
    "alert": {
      "uuid": "alert_550e8400",
      "alert_type": "velocity_check",
      "severity_level": "high",
      "status": "pending",
      "message": "Unusual transaction velocity: 5 in 10 minutes",
      "triggered_at": "2026-02-03T14:30:00Z"
    },
    "signal": {
      "id": "sig_abc123",
      "risk_score": 87,
      "risk_level": "high"
    }
  }
}
```

**مثال على المعالج**:

```typescript
app.post("/webhooks/protegey", async (req, res) => {
  const { type, data } = req.body;

  if (type === "alert.triggered") {
    const { alert, signal } = data;

    // Critical alerts → immediate notification
    if (alert.severity_level === "critical") {
      await sendPagerDutyAlert({
        title: alert.message,
        severity: "critical",
        details: { alert_id: alert.uuid, signal_id: signal.id },
      });
    }

    // High alerts → Slack notification
    else if (alert.severity_level === "high") {
      await sendSlackMessage("#fraud-alerts", {
        text: `🚨 High Priority Alert: ${alert.message}`,
        link: `https://partner.protegey.com/alerts/${alert.uuid}`,
      });
    }
  }

  res.status(200).send("OK");
});
```

## إحصاءات التنبيهات

### عرض مقاييس التنبيهات

```typescript
const stats = await client.alerts.statistics({
  start_date: "2026-02-01",
  end_date: "2026-02-03",
});

console.log(`Total Alerts: ${stats.total}`);
console.log(`Pending: ${stats.by_status.pending}`);
console.log(`False Positive Rate: ${stats.false_positive_rate}%`);
console.log(`Avg Resolution Time: ${stats.avg_resolution_minutes} minutes`);
```

**المقاييس الرئيسية**:

- **إجمالي التنبيهات**: حجم التنبيهات
- **حسب الخطورة**: توزيع أولويات التنبيهات
- **حسب الحالة**: معلقة، معترف بها، محلولة، خطأ إيجابي
- **حسب النوع**: سرعة، شذوذ، شبكة، قائمة حجب، سفر مستحيل
- **وقت الحل**: متوسط الوقت من الإطلاق إلى الحل
- **معدل الخطأ الإيجابي**: نسبة التنبيهات الموسومة كخطأ إيجابي
- **معدل التصعيد**: نسبة التنبيهات المُصعَّدة إلى حالات

### 2. ضبط العتبات بانتظام

**مراجعة معدل الخطأ الإيجابي شهريًا**:

```typescript
const stats = await client.alerts.statistics({
  start_date: oneMonthAgo,
  end_date: today,
});

// High false positive rate? Adjust thresholds
if (stats.false_positive_rate > 20) {
  console.warn("High false positive rate - consider tuning thresholds");

  // Identify worst performing alert type
  const worstType = stats.by_type.sort(
    (a, b) => b.false_positive_rate - a.false_positive_rate,
  )[0];

  console.log(`Adjust ${worstType.type} threshold`);
}
```

### 4. التصعيد إلى حالات عند الحاجة

**إنشاء حالات من أجل**:

- تنبيهات حرجة تتطلب تحقيقًا
- أنماط تشير إلى حلقات احتيال
- تنبيهات تتطلب التواصل مع العميل
- حوادث تتطلب جمع الأدلة

```typescript
if (alert.severity_level === "critical" || needsInvestigation(alert)) {
  const fraudCase = await client.cases.createFromSignal(alert.signal_id, {
    priority: "high",
    category: alert.alert_type,
    description: `Escalated from alert: ${alert.message}`,
  });

  await client.alerts.update(alertUuid, {
    status: "resolved",
    resolution_notes: `Escalated to case ${fraudCase.uuid} for investigation`,
  });
}
```

```typescript
// Weekly alert volume trend
const weeklyStats = await client.alerts.statistics({

const thisWeek = weeklyStats[weeklyStats.length - 1];
```

### 6. استخدام الأتمتة للتنبيهات منخفضة المخاطر

**الحل التلقائي لأنماط الخطأ الإيجابي المنخفض**:

```typescript
// Example: Auto-resolve low alerts for verified customers
const lowAlerts = await client.alerts.list({
  status: "pending",
  severity_level: "low",
});

for (const alert of lowAlerts.data) {
  const signal = await client.signals.get(alert.signal_id);

  // Check if customer is verified
  if (await isVerifiedCustomer(signal.actor.hashed_id)) {
    await client.alerts.update(alert.uuid, {
      status: "false_positive",
      resolution_notes: "Auto-resolved: Verified customer, low risk",
    });
  }
}
```

## السيناريوهات الشائعة

### السيناريو الأول: فرز تنبيه حرج

```typescript
async function triageCriticalAlert(alert) {
  // 1. Acknowledge immediately
  await client.alerts.update(alert.uuid, {
    status: "acknowledged",
  });

  // 2. Get signal details
  const signal = await client.signals.get(alert.signal_id);

  // 3. Check actor history
  const actorHistory = await client.actors.history(signal.actor.hashed_id);

  // 4. Find similar signals
  const similar = await client.transactionMonitoring.findSimilar(signal.id);

  // 5. Decide action
  if (actorHistory.fraud_count > 0 || similar.length > 3) {
    // Confirmed fraud - block immediately
    await blockActor(signal.actor.hashed_id);

    await client.alerts.update(alert.uuid, {
      status: "resolved",
      resolution_type: "confirmed_fraud",
      resolution_notes: `Immediate block - repeat fraudster (${actorHistory.fraud_count} previous incidents)`,
    });

    // Create case for investigation
    await client.cases.createFromSignal(signal.id, {
      priority: "critical",
      category: alert.alert_type,
    });
  } else {
    // Unclear - escalate for manual review
    await client.cases.createFromSignal(signal.id, {
      priority: "high",
      category: alert.alert_type,
      assigned_user_id: await getSeniorAnalyst(),
    });
  }
}
```

### السيناريو الثالث: التعامل مع عاصفة التنبيهات

```typescript
async function handleAlertStorm() {
  // Detect alert storm (>100 alerts in 1 hour)
  const recentAlerts = await client.alerts.list({
    created_after: oneHourAgo,
  });

  if (recentAlerts.meta.total > 100) {
    console.warn("Alert storm detected!");

    // Group by actor to identify coordinated attack
    const byActor = groupBy(recentAlerts.data, "signal.actor.hashed_id");

    // Focus on high-volume actors first
    const topActors = Object.entries(byActor)
      .sort((a, b) => b[1].length - a[1].length)
      .slice(0, 10);

    // Investigate top actors
    for (const [actorHash, alerts] of topActors) {
      console.log(`Actor ${actorHash}: ${alerts.length} alerts`);

      // Auto-block if clear pattern
      if (
        alerts.length > 10 &&
        alerts.every((a) => a.severity_level === "high")
      ) {
        await blockActor(actorHash);

        // Bulk resolve alerts
        for (const alert of alerts) {
          await client.alerts.update(alert.uuid, {
            status: "resolved",
            resolution_type: "confirmed_fraud",
            resolution_notes: "Part of coordinated attack - actor blocked",
          });
        }
      }
    }
  }
}
```

صُمِّمت بيئة الاختبار (Sandbox) لمساعدتك على التكامل بسرعة وأمان. تتصرَّف تمامًا كالإنتاج، لكنها تستخدم **بيانات معزولة فعليًا** مع فصل كامل للمخططات على مستوى قاعدة البيانات.

::callout{icon="i-lucide-database" color="blue"}
**عزل حقيقي**: تُطبِّق Protegey فصلًا فيزيائيًا لمخططات قاعدة البيانات باستخدام مخططات PostgreSQL. تعيش بيانات Sandbox في مخطط `sandbox` منفصل، مما يضمن عدم تلوث تحليلات الإنتاج.
::

---

## نظرة عامة على البنية

### عزل مخطط قاعدة البيانات

تستخدم Protegey **فصل مخططات PostgreSQL** لضمان عزل البيانات الكاملة بين بيئتَي الاختبار والإنتاج:

**هيكل المخطط**:
```
PostgreSQL Database
├── public schema (الإنتاج + الجداول المشتركة)
│   ├── signals (بيانات الإنتاج)
│   ├── fraud_entities (بيانات الإنتاج)
│   ├── fraud_cases (بيانات الإنتاج)
│   ├── users (مشتركة عبر جميع البيئات)
│   ├── partners (مشتركة عبر جميع البيئات)
│   └── subscriptions (مشتركة عبر جميع البيئات)
│
└── sandbox schema (بيانات Sandbox)
    ├── signals (بيانات Sandbox)
    ├── fraud_entities (بيانات Sandbox)
    ├── fraud_cases (بيانات Sandbox)
    └── [جميع الجداول ذات النطاق الشريكي مكرَّرة]
```

**الفوائد الرئيسية**:
- **صفر تلوث متبادل**: إشارات Sandbox لا تؤثر أبدًا على درجات مخاطر الإنتاج
- **إعادة ضبط سهلة**: اقطع مخطط Sandbox دون المساس بالإنتاج
- **عزل الأداء**: استعلامات Sandbox لا تؤثر على أداء الإنتاج
- **جاهزية للامتثال**: أثر تدقيق واضح يُظهر فصل البيانات

### آلية العمل

عند إجراء طلب API أو تسجيل الدخول إلى بوابة الشريك:

1. **اكتشاف البيئة**: يكتشف النظام البيئة من معاملات الاستعلام، والكوكيز، والرؤوس، أو النطاق
2. **ربط السياق**: ينشئ كائن `CentryContext` بحالة البيئة
3. **تطبيق المخطط**: يضبط `search_path` لـ PostgreSQL على المخطط الصحيح
4. **تنفيذ الاستعلام**: تستخدم جميع استعلامات قاعدة البيانات تلقائيًا المخطط الصحيح

**مثال**:
```sql
-- طلب Sandbox يضبط search_path
SET search_path TO sandbox, public;

-- الاستعلامات تستخدم تلقائيًا مخطط sandbox
SELECT * FROM signals WHERE partner_uuid = 'your-uuid';
-- تقرأ من: sandbox.signals

-- الجداول المشتركة لا تزال تستخدم المخطط العام
SELECT * FROM users WHERE id = 42;
-- تقرأ من: public.users (مشترك)
```

**انظر أيضًا**: [التنفيذ ذو الوعي بالسياق](./context-resolution) للتعمق التقني.

## ضمانات فصل البيانات

### ما يُعزَل

**البيانات الخاصة بكل بيئة** (مكرَّرة عبر المخططات):
- ✅ إشارات الاحتيال
- ✅ كيانات الاحتيال
- ✅ قضايا الاحتيال
- ✅ تنبيهات الاحتيال
- ✅ المعاملات
- ✅ بيانات التحليلات
- ✅ سجل القرارات

**البيانات المشتركة** (نفسها عبر البيئات):
- ✅ المستخدمون (أعضاء فريقك)
- ✅ إعدادات المنظمة الشريكة
- ✅ الاشتراكات والفوترة
- ✅ الأدوار والأذونات
- ✅ مفاتيح API

### تطبيق العزل

**الاختيار التلقائي للمخطط**:
```typescript
// استدعاء API على Sandbox
const client = new ProtegeyClient({
  accessToken: 'YOUR_TOKEN',
  environment: 'sandbox'
});

// جميع الاستعلامات تستخدم مخطط sandbox تلقائيًا
const signals = await client.signals.list();
// تقرأ من: sandbox.signals
```

**التطبيق على مستوى الاستعلام**:
- كل طلب HTTP يحلِّل سياق البيئة
- الوسيط (Middleware) يضبط `search_path` لـ PostgreSQL قبل أي استعلامات
- لا يلزم إضافة بادئة المخطط يدويًا في كود التطبيق
- يستحيل الاستعلام عن مخطط خاطئ بالصدفة

**أثر التدقيق**:
- جميع عمليات Sandbox مسجَّلة بـ `environment: 'sandbox'`
- تتبُّع معرِّف الطلب عبر HTTP ووظائف قوائم الانتظار
- تسجيل تطبيق المخطط لأغراض التصحيح

## التبديل بين البيئات

### الطريقة الأولى: معامل الاستعلام

**بوابة الشريك**:
```
https://partner.protegey.com/dashboard?environment=sandbox
```

**طلب API**:
```bash
curl "https://api.protegey.com/v1/signals?environment=sandbox" \
  -H "Authorization: Bearer YOUR_TOKEN"
```

### الطريقة الثانية: رأس HTTP

```bash
curl "https://api.protegey.com/v1/signals" \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -H "X-Centry-Environment: sandbox"
```

### الطريقة الثالثة: الكوكي (دائم)

```javascript
// التبديل إلى sandbox (يستمر عبر الطلبات)
document.cookie = 'centry_env_override=sandbox; path=/; max-age=86400';

// العودة إلى الإنتاج
document.cookie = 'centry_env_override=production; path=/; max-age=86400';
```

**انظر أيضًا**: [التنفيذ ذو الوعي بالسياق - تبديل البيئات](./context-resolution#switching-environments) لجميع الطرق.

## وظيفة إعادة الضبط

### خيارات الإعادة التفصيلية

أعِد ضبط أنواع بيانات محددة في Sandbox دون التأثير على غيرها:

| خيار الإعادة | الوصف | نقطة نهاية API |
|--------------|-------|----------------|
| **إعادة الضبط الكاملة** | مسح جميع بيانات Sandbox | `POST /api/v1/partner/sandbox/reset` |
| **الإشارات فقط** | مسح الإشارات، الاحتفاظ بالكيانات والقضايا | `POST /api/v1/partner/sandbox/reset?scope=signals` |
| **الكيانات فقط** | مسح الكيانات، الاحتفاظ بالإشارات والقضايا | `POST /api/v1/partner/sandbox/reset?scope=entities` |
| **القضايا فقط** | مسح القضايا، الاحتفاظ بالإشارات والكيانات | `POST /api/v1/partner/sandbox/reset?scope=cases` |
| **التنبيهات فقط** | مسح التنبيهات | `POST /api/v1/partner/sandbox/reset?scope=alerts` |
| **العلاقات** | مسح علاقات الكيانات | `POST /api/v1/partner/sandbox/reset?scope=relationships` |

**مثال على الإعادة الكاملة**:
```bash
curl -X POST "https://api.protegey.com/v1/partner/sandbox/reset" \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -H "X-Centry-Environment: sandbox"
```

**مثال على الإعادة الانتقائية**:
```typescript
// مسح الإشارات فقط، مع الإبقاء على ملفات الكيانات
await client.sandbox.reset({ scope: 'signals' });
```

### ما يحدث أثناء إعادة الضبط

**الإعادة الكاملة**:
1. حذف جميع إشارات Sandbox (`sandbox.signals`)
2. حذف جميع كيانات Sandbox (`sandbox.fraud_entities`)
3. حذف جميع قضايا Sandbox (`sandbox.fraud_cases`)
4. حذف جميع تنبيهات Sandbox (`sandbox.fraud_alerts`)
5. مسح علاقات الكيانات
6. إعادة حساب التحليلات

**البيانات المحفوظة**:
- حسابات المستخدمين (مشتركة)
- إعدادات الشريك (مشتركة)
- مفاتيح API (مشتركة)
- حالة الاشتراك (مشتركة)

**الحالة بعد الإعادة**:
- بيئة Sandbox نظيفة
- جاهزة للاختبار من جديد
- لا يوجد أي نقل للبيانات من الاختبارات السابقة

### تكرار الإعادة

**الإعادة اليدوية**: متاحة عند الطلب عبر API
**الإعادة التلقائية**: أسبوعيًا كل يوم أحد عند 00:00 UTC (قابلة للتكوين لكل شريك)

::callout{icon="i-lucide-alert-circle" color="amber"}
**مهم**: إعادة الضبط لا يمكن التراجع عنها. تأكَّد من تصدير أي بيانات تحتاجها قبل الإعادة.
::

## أفضل ممارسات الاختبار

### 1. استخدم Sandbox لجميع مراحل التطوير

طوِّر واختبر كود التكامل دائمًا في Sandbox قبل الانتقال إلى الإنتاج:

```typescript
// ✅ صحيح: التطوير في sandbox
const devClient = new ProtegeyClient({
  accessToken: process.env.SANDBOX_TOKEN,
  environment: 'sandbox'
});

// اختبر تكاملك
await devClient.signals.create({...});

// ❌ خطأ: التطوير في الإنتاج
const prodClient = new ProtegeyClient({
  accessToken: process.env.PROD_TOKEN,
  environment: 'production' // لا تستخدمه للاختبار!
});
```

### 2. توليد إشارات تجريبية للاختبار

استخدم API توليد الإشارات التجريبية لإنشاء بيانات اختبار واقعية:

```bash
# توليد 20 إشارة تجريبية بملفات مخاطر متنوعة
curl -X POST "https://api.protegey.com/v1/partner/sandbox/generate-demo-signals" \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -H "X-Centry-Environment: sandbox" \
  -d '{
    "template": "transaction/account_takeover",
    "count": 20
  }'
```

**توزيع ملف المخاطر**:
- 10% مخاطر حرجة (درجات 80-100)
- 20% مخاطر عالية (درجات 60-79)
- 30% مخاطر متوسطة (درجات 40-59)
- 40% مخاطر منخفضة (درجات 0-39)

**انظر أيضًا**: [دليل الإشارات التجريبية](../sandbox/demo-signals) لخيارات القوالب.

### 3. اختبار الحالات الحدِّية

**سيناريوهات عالية المخاطر**:
```typescript
// اختبار المعاملات المرفوضة
await client.signals.create({
  transaction_id: 'TXN-TEST-DECLINE-001',
  event_type: 'ACCOUNT_TAKEOVER',
  transaction: {
    amount: 50000, // مبلغ عالٍ يشغِّل الشذوذ
    currency: 'USD'
  },
  actor: {
    hashed_id: 'hash_new_device_001'
  },
  metadata: {
    device_fingerprint: 'new_device',
    country_code: 'NG' // عابر للحدود إذا كان الشريك في GH
  }
});
```

**سيناريوهات منخفضة المخاطر**:
```typescript
// اختبار المعاملات الموافق عليها
await client.signals.create({
  transaction_id: 'TXN-TEST-APPROVE-001',
  event_type: 'LOGIN',
  transaction: {
    amount: 100, // مبلغ منخفض
    currency: 'GHS'
  },
  actor: {
    hashed_id: 'hash_returning_user_001'
  },
  metadata: {
    device_fingerprint: 'known_device',
    country_code: 'GH' // نفس الدولة
  }
});
```

### 4. اختبار معالجة الأخطاء

استخدم القيم السحرية لإجبار الأخطاء (انظر القسم أدناه):

```typescript
try {
  // إجبار خطأ حد المعدل
  await client.signals.create({
    ...signalData,
    headers: { 'X-Force-Error': 'rate_limit' }
  });
} catch (error) {
  if (error.status === 429) {
    console.log('Correctly handled rate limit');
  }
}
```

### 5. الإعادة بين جولات الاختبار

أعِد ضبط بيانات Sandbox بين مجموعات الاختبار للاتساق:

```typescript
// قبل كل مجموعة اختبار
beforeAll(async () => {
  await client.sandbox.reset({ scope: 'signals' });
});

// تشغيل الاختبارات بحالة نظيفة
test('signal ingestion', async () => {
  const signal = await client.signals.create({...});
  expect(signal.id).toBeDefined();
});
```

### 6. التحقق من عزل البيانات

تحقَّق من أن بيانات Sandbox لا تتسرَّب إلى الإنتاج:

```typescript
// إنشاء إشارة في sandbox
const sandboxClient = new ProtegeyClient({
  environment: 'sandbox',
  accessToken: YOUR_TOKEN
});

await sandboxClient.signals.create({ transaction_id: 'SANDBOX-001' });

// التبديل إلى الإنتاج والتحقق من عدم وجود الإشارة
const prodClient = new ProtegeyClient({
  environment: 'production',
  accessToken: YOUR_TOKEN
});

const prodSignals = await prodClient.signals.list({
  search: 'SANDBOX-001'
});

expect(prodSignals.data.length).toBe(0); // يجب ألا توجد في الإنتاج
```

### 7. اختبار تسليم Webhook

اضبط نقطة نهاية Webhook تجريبية للتحقق من تسليم الأحداث:

```typescript
// اضبط رابط Webhook لـ sandbox في بوابة الشريك
// الإعدادات > التكاملات > Webhooks
// الرابط: https://your-test-server.com/webhooks/sandbox

// أنشئ إشارة وانتظر Webhook
await client.signals.create({...});

// نقطة نهاية Webhook تتلقَّى:
// POST https://your-test-server.com/webhooks/sandbox
// X-Centry-Event: signal.ingested
// {
//   "signal_id": "...",
//   "risk_score": 0.78,
//   "risk_level": "high",
//   "detectors_triggered": [...]
// }
```

### 8. اختبار الأداء

اختبر بأحجام واقعية لفهم سلوك النظام:

```bash
# توليد 100 إشارة لاختبار الإنتاجية
for i in {1..100}; do
  curl -X POST "https://api.protegey.com/v1/partner/sandbox/generate-demo-signals" \
    -H "Authorization: Bearer $TOKEN" \
    -H "X-Centry-Environment: sandbox" \
    -d '{"template": "transaction/account_takeover", "count": 10}' &
done
wait
```

### 9. مراقبة حدود المعدل

راقب رؤوس حد المعدل لفهم استخدامك:

```typescript
const response = await client.signals.list();

console.log('Rate Limit:', response.headers['x-ratelimit-limit']);
console.log('Remaining:', response.headers['x-ratelimit-remaining']);
console.log('Reset:', new Date(response.headers['x-ratelimit-reset'] * 1000));
```

### 10. توثيق سيناريوهات الاختبار

احتفظ بقائمة مراجعة لسيناريوهات الاختبار:

```markdown
## قائمة مراجعة اختبار Sandbox

- [ ] استيعاب إشارة عالية المخاطر
- [ ] استيعاب إشارة منخفضة المخاطر
- [ ] استيعاب إشارات دُفعية (100+ إشارة)
- [ ] إنشاء قضية من إشارة
- [ ] الإقرار بتنبيه
- [ ] تحديث حالة كيان
- [ ] التحقق من تسليم Webhook
- [ ] معالجة الأخطاء (429, 500, 503)
- [ ] معالجة حد المعدل
- [ ] التحقق من عزل البيانات
```

## القيم السحرية

تدعم بيئة Sandbox "القيم السحرية" لإجبار استجابات محددة. يتيح لك ذلك اختبار منطقك لسيناريوهات مخاطر مختلفة دون الحاجة إلى إنشاء إشارات معقدة.

### إجبار درجات المخاطر

عند الاستعلام عن كيان (مثلًا عنوان بريد إلكتروني)، استخدم هذه البادئات لتشغيل درجات محددة:

| نمط البريد الإلكتروني | الدرجة الناتجة | التوصية |
|----------------------|----------------|---------|
| `low_risk_user@example.com` | `10` | APPROVE |
| `med_risk_user@example.com` | `45` | REVIEW |
| `high_risk_user@example.com` | `85` | DECLINE |
| `critical_user@example.com` | `99` | DECLINE |

### إجبار الأخطاء

لاختبار معالجة الأخطاء، مرِّر هذه القيم في رأس `X-Force-Error` (في Sandbox فقط):

| قيمة الرأس | استجابة HTTP | السيناريو |
|-----------|-------------|-----------|
| `timeout` | `504 Gateway Timeout` | محاكاة تأخر الشبكة |
| `rate_limit` | `429 Too Many Requests` | محاكاة استنفاد الحصة |
| `server_error` | `500 Internal Server Error` | محاكاة انقطاع المنصة |

```bash
# مثال: إجبار خطأ 429
curl -X GET https://sandbox-api.protegey.com/v1/queries/user \
  -H "X-Centry-Key: cen_test_sk_..." \
  -H "X-Force-Error: rate_limit"
```

## هويات الاختبار

نوفِّر مجموعة من هويات الاختبار الثابتة المُعبَّأة مسبقًا بسجل إشارات.

### "المحتال"
- **معرِّف الكيان**: `user_fraud_001`
- **السجل**: 50 إشارة ATO حديثة عبر 10 شركاء.
- **الدرجة المتوقعة**: عالية (80+)

### "المستخدم الجيد"
- **معرِّف الكيان**: `user_good_001`
- **السجل**: 5 سنوات من السجل النظيف.
- **الدرجة المتوقعة**: منخفضة (0-10)

::callout{icon="i-lucide-info" color="blue"}
**إعادة الضبط**: تُعاد ضبط بيانات Sandbox كل يوم أحد عند 00:00 UTC. ستبقى أي إشارات تنشئها خلال الأسبوع حتى ذلك الحين.
::

# واجهة برمجة تطبيقات الإشارات (Signals API)

تسمح واجهة برمجة تطبيقات الإشارات (Signals API) للشركاء بإرسال مؤشرات الاحتيال إلى الشبكة. يتم استيعاب الإشارات بشكل غير متزامن ومعالجتها بواسطة محرك المخاطر (Risk Engine).

::callout{icon="i-lucide-shield-alert" color="amber"}
**الوصول إلى الإنتاج مطلوب**: يجب أن يكون لديك مفاتيح إنتاج نشطة لنشر الإشارات الحية. إشارات البيئة التجريبية (Sandbox) لا تؤثر على نتائج الشبكة.
::

## نقطة النهاية (Endpoint)

```http
POST /api/v1/signals
```

## مخطط الطلب (Request Schema)

### الرؤوس (Headers)

| الرأس | القيمة | مطلوب | الوصف |
|--------|-------|----------|-------------|
| `Content-Type` | `application/json` | نعم | حمولة JSON قياسية. |
| `X-Centry-Key` | `cen_live_sk_...` | نعم | مفتاح الإنتاج السري الخاص بك. |

### معلمات الجسم (Body Parameters)

يتم هيكلة الحمولة في كائنات `actor` (الفاعل)، و`event` (الحدث)، و`transaction` (المعاملة).

```typescript
interface SignalRequest {
  actor: {
    hashed_id: string; // المعرف الأساسي للكيان (مُعمّى أو خام)
    device_fingerprint?: string;
    region?: string;
  };
  event: {
    type: string; // إشارة الاحتيال (مثلاً: ACCOUNT_TAKEOVER)
    timestamp: string; // ISO 8601 (مثلاً: 2026-01-12T14:30:00Z)
    channel?: string; // WEB, MOBILE, API، إلخ.
  };
  transaction?: {
    amount?: number;
    currency?: string; // ISO 4217 (3 أحرف)
    geo_location?: {
      lat: number;
      lon: number;
    };
  };
  source_confidence?: number; // 0.0 إلى 1.0 (الافتراضي: 0.5)
  metadata?: Record<string, any>;
}
```

### قواعد التحقق (Validation Rules)

| الحقل | مطلوب | القواعد |
|-------|----------|-------|
| `actor.hashed_id` | **نعم** | سلسلة نصية. معرف الكيان (مثلاً هاش SHA-256 أو القيمة الخام). |
| `event.type` | **نعم** | يجب أن يطابق كوداً صالحاً (مثلاً: `ACCOUNT_TAKEOVER`, `SYNTHETIC_IDENTITY`). |
| `event.timestamp` | **نعم** | ISO 8601. لا يمكن أن يكون في المستقبل. |
| `transaction.currency` | لا | يجب أن يكون 3 أحرف تماماً إذا تم توفيره. |
| `transaction.geo_location` | لا | كلاً من `lat` و `lon` مطلوبان إذا وجد الكائن. |
| `source_confidence` | لا | رقم عشري بين 0.0 و 1.0. |

## توحيد أرقام الهاتف (Phone Normalization)

تستخدم Protegey **استراتيجية توحيد متعددة المستويات** لضمان جودة بيانات عالية للكيانات القائمة على أرقام الهاتف. عندما ترسل إشارة تحتوي على `actor_hashed_id` أو بيانات وصفية (metadata) تتضمن رقم هاتف، يقوم النظام تلقائياً بتحويله إلى تنسيق E.164 القياسي.

### الأسواق المدعومة (الأسواق الأفريقية الأساسية)

يوفر النظام توحيداً صارماً بالتنسيق المحلي للدول التالية:

| الدولة | كود ISO | أمثلة للتنسيق المحلي | النتيجة (E.164) |
|---------|----------|-----------------------|----------------|
| **السنغال** | `SN` | `077 123 45 67`, `771234567` | `+221771234567` |
| **كوت ديفوار** | `CI` | `07 01 23 45 67`, `0102030405` | `+2250701234567` |
| **مالي** | `ML` | `07123456`, `6123456` | `+2237123456` |
| **بوركينا فاسو** | `BF` | `54123456`, `76123456` | `+22654123456` |
| **الكاميرون** | `CM` | `690123456` | `+237690123456` |
| **جمهورية الكونغو الديمقراطية** | `CD` | `810123456`, `990123456` | `+243810123456` |
| **المغرب** | `MA` | `06 12 34 56 78`, `612345678` | `+212612345678` |
| **الجزائر** | `DZ` | `05 12 34 56 78`, `512345678` | `+213512345678` |
| **تونس** | `TN` | `21 123 456`, `98123456` | `+21621123456` |
| **مصر** | `EG` | `010 1234 5678`, `1112345678` | `+201012345678` |
| **غانا** | `GH` | `024 123 4567`, `241234567` | `+233241234567` |
| **نيجيريا** | `NG` | `0803 123 4567`, `7012345678` | `+2348031234567` |

### تلميح الدولة الاختياري (`actor.region`)

إذا كان نمط رقم الهاتف غامضاً (مثلاً أنماط متداخلة بين المغرب والجزائر)، يمكنك توفير **تلميح دولة** اختياري باستخدام حقل `actor.region`.

::callout{icon="i-lucide-lightbulb" color="primary"}
**أفضل ممارسة**: قم دائماً بتوفير `actor.region` (ISO 3166-1 alpha-2) إذا كان معروفاً. هذا يضمن دقة توحيد بنسبة 100% حتى للتنسيقات المحلية المعقدة أو المتداخلة.
::

```json
{
  "actor": {
    "hashed_id": "0612345678",
    "region": "MA" // يضمن التوحيد كرقم مغربي (212+)
  }
}
```

## أمثلة

### 1. إرسال قياسي

```bash
curl -X POST "https://api.protegey.com/v1/signals" \
  -H "Content-Type: application/json" \
  -H "X-Centry-Key: cen_live_sk_..." \
  -d '{
    "actor": {
      "hashed_id": "e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855",
      "region": "US"
    },
    "event": {
      "type": "ACCOUNT_TAKEOVER",
      "timestamp": "2026-01-12T14:30:00Z",
      "channel": "MOBILE"
    },
    "source_confidence": 0.9,
    "metadata": {
      "detection_method": "behavioral_biometrics"
    }
  }'
```

### 2. إشارة معاملة

```bash
curl -X POST "https://api.protegey.com/v1/signals" \
  -H "Content-Type: application/json" \
  -H "X-Centry-Key: cen_live_..." \
  -d '{
    "actor": {
      "hashed_id": "user@example.com"
    },
    "event": {
      "type": "STOLEN_FINANCIALS",
      "timestamp": "2026-01-12T14:30:00Z"
    },
    "transaction": {
      "amount": 4500.00,
      "currency": "USD",
      "geo_location": {
        "lat": 37.7749,
        "lon": -122.4194
      }
    }
  }'
```

## الاستجابة (Response)

### استجابة ناجحة (`201 Created`)

```json
{
  "success": true,
  "data": {
    "signal_id": "9df4a3b1-...",
    "status": "received",
    "event_type": "ACCOUNT_TAKEOVER",
    "timestamp": "2026-01-12T14:30:00+00:00"
  },
  "message": "تم استلام الإشارة ووضعها في قائمة الانتظار للمعالجة"
}
```

### استجابة خطأ (`422 Unprocessable Content`)

```json
{
    "message": "حقل event.type مطلوب.",
    "errors": {
        "event.type": [
            "حقل event.type مطلوب."
        ]
    }
}
```

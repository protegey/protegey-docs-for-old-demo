تسمح واجهة برمجة تطبيقات الإشارات للشركاء بإرسال مؤشرات الاحتيال إلى شبكة Protegey. يتم **التحقق من صحة كل إشارة وتقييمها بشكل متزامن** — يُعاد حكم المخاطر في نفس استجابة HTTP. تستمر المعالجة غير المتزامنة (ربط الرسم البياني، وإثراء الكيانات، وتوليد التنبيهات) في الخلفية.

::callout{icon="i-lucide-shield-alert" color="amber"}
**الوصول إلى بيئة الإنتاج مطلوب**: يجب أن يكون لديك مفاتيح إنتاج نشطة لنشر الإشارات الحية. إشارات بيئة الاختبار (Sandbox) لا تؤثر على نتائج الشبكة.
::

## نقطة النهاية (Endpoint)

```http
POST /api/v1/signals
```

### الرؤوس (Headers)

| الرأس             | القيمة                        | مطلوب   |
| ----------------- | ----------------------------- | ------- |
| `Content-Type`    | `application/json`            | نعم     |
| `X-Centry-Key`    | `cen_live_sk_...`             | نعم     |
| `Idempotency-Key` | مفتاح فريد (حد أقصى 64 حرفًا) | موصى به |

## UFES v2 — الصيغة الوحيدة المدعومة

يجب أن تستخدم جميع عمليات التكامل الجديدة **UFES v2** (`schema_version: "2.0"`). تم حذف الصيغ القديمة وv1 من مسار الاستيعاب.

### الحقول المطلوبة

| الحقل                     | النوع   | الوصف                                                                    |
| ------------------------- | ------- | ------------------------------------------------------------------------ |
| `schema_version`          | `"2.0"` | يجب أن يكون `"2.0"` بالضبط                                               |
| `event_type`              | string  | نوع الحدث الحر (مثلاً: `MOBILE_MONEY_SEND`، `LOGIN_FAILURE`، `SIM_SWAP`) |
| `timestamp`               | string  | تاريخ ووقت بتنسيق ISO 8601                                               |
| `source`                  | object  | بيانات تعريفية لمصدر الإرسال                                             |
| `source.confidence_score` | number  | 0.0–1.0 — مستوى ثقتك في أن هذا الحدث ذو صلة بالاحتيال                    |
| `primary_actor`           | object  | الكيان المنفِّذ للإجراء                                                  |
| `primary_actor.entity_id` | string  | معرفك الداخلي الثابت لهذا الكيان                                         |

::callout{icon="i-lucide-info" color="blue"}
`event_category` **اختياري** — يُستنتج تلقائيًا من `event_type` عند حذفه (مثلاً: `TRANSFER` ← `transaction`، و`LOGIN` ← `auth`، و`SIM_SWAP` ← `auth`). أدرجه بشكل صريح فقط عندما يكون الاستنتاج التلقائي غير ملائم لحالة استخدامك.
::

### المخطط الكامل

```typescript
interface UFESv2Signal {
  // ── Envelope (required) ──────────────────────────────────────────
  schema_version: "2.0";
  event_type: string; // e.g. "MOBILE_MONEY_SEND", "SIM_SWAP", "LOGIN_FAILURE"
  timestamp: string; // ISO 8601

  // ── Envelope (optional) ──────────────────────────────────────────
  event_category?: "transaction" | "auth" | "kyc" | "fraud_signal" | "system";
  flow_type?: "payment" | "auth" | "kyc"; // auto-inferred from event_category if omitted
  trace_id?: string; // your cross-system trace ID

  // ── Source ───────────────────────────────────────────────────────
  source: {
    confidence_score: number; // 0.0–1.0, required
    integration_channel?: "api" | "batch" | "stream";
    partner_user_id?: string; // your internal user reference
    ip_address?: string; // submitting user's IP — feeds IMPOSSIBLE_TRAVEL detector
  };

  // ── Primary actor (required) ─────────────────────────────────────
  primary_actor: {
    entity_id: string; // required — your stable ID for this actor
    entity_type?: "individual" | "business" | "account" | "device";
    hashed_id?: string; // HMAC-SHA256 of canonical PII, for graph linking
    identifiers?: {
      region?: string; // ISO 3166-1 alpha-2 country code (e.g. "GH")
      sim_changed_at?: string; // ISO 8601 — feeds SIM_SWAP_PROXIMITY detector
      [key: string]: string | undefined;
    };
    device?: {
      fingerprint?: string; // device fingerprint (max 255 chars) — feeds NEW_DEVICE_ACCESS
      user_agent?: string; // raw UA string (max 512 chars), stored as audit trail
    };
    risk_flags?: string[]; // e.g. ["high_velocity", "new_device"]
  };

  // ── Related entities (optional) ──────────────────────────────────
  related_entities?: Array<{
    entity_id: string;
    entity_type?: string;
    relationship_type?:
      | "sender"
      | "receiver"
      | "beneficiary"
      | "shared_device"
      | "linked_account"
      | "mule"
      | "director"
      | "proxy";
  }>;

  // ── Event payload (optional, category-specific data) ─────────────
  event_payload?: {
    amount?: number;
    currency?: string;
    reference_id?: string;
    geo_location?: { lat: number; lng: number };
    [key: string]: any;
  };

  // ── Partner intelligence blocks (optional, audit trail only) ─────
  risk_intelligence?: {
    risk_score?: number;
    risk_level?: "low" | "medium" | "high" | "critical";
    risk_factors?: string[];
    model_version?: string;
  };
  compliance_context?: {
    jurisdiction?: string;
    regulatory_flags?: string[];
    screening_results?: Record<string, any>[];
  };
  decision_context?: {
    final_decision?: "approve" | "deny" | "review" | "block" | "escalate";
    decision_timestamp?: string;
    decision_rationale?: string;
    policy_id?: string;
  };

  metadata?: Record<string, any>;
}
```

### استنتاج فئة الحدث تلقائيًا

عند حذف `event_category`، تستنتجها Protegey من `event_type`:

| `event_category` | قيم `event_type` المربوطة تلقائيًا                                                                                                            |
| ---------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| `auth`           | `LOGIN`، `LOGIN_SUCCESS`، `LOGIN_FAILURE`، `SIM_SWAP`، `ACCOUNT_TAKEOVER`، `ACCOUNT_UPDATE`، `MFA_BYPASS`، `PASSWORD_RESET`، `DEVICE_ANOMALY` |
| `transaction`    | `PAYMENT`، `TRANSFER`، `WITHDRAWAL`، `MOBILE_MONEY_SEND`، `CARD_FRAUD`، `PAYMENT_FRAUD`                                                       |
| `kyc`            | `ACCOUNT_CREATE`، `ACCOUNT_OPENING`، `KYC_CHECK`، `DOCUMENT_VERIFY`، `IDENTITY_THEFT`                                                         |
| `fraud_signal`   | كل ما عدا ذلك                                                                                                                                 |

## الحقول المطلوبة لكل كاشف (Detector)

تشغِّل Protegey **خمسة كواشف** على كل إشارة. تستلزم بعض الكواشف حقولًا محددة كي تعمل. توفير هذه الحقول يزيد جودة تقييم المخاطر إلى أقصى حد.

| الكاشف                       | الحقل المطلوب                         | مكان تقديمه                                           |
| ---------------------------- | ------------------------------------- | ----------------------------------------------------- |
| `RAPID_TRANSACTION_VELOCITY` | معرف الجهة الفاعلة + الإشارات السابقة | `primary_actor.entity_id`                             |
| `LARGE_OUTLIER_TRANSACTION`  | مبلغ المعاملة                         | `event_payload.amount` + `event_payload.currency`     |
| `SIM_SWAP_PROXIMITY`         | طابع زمني لتغيير SIM                  | `primary_actor.identifiers.sim_changed_at` (ISO 8601) |
| `NEW_DEVICE_ACCESS`          | بصمة الجهاز                           | `primary_actor.device.fingerprint`                    |
| `IMPOSSIBLE_TRAVEL`          | عنوان IP للإرسال                      | `source.ip_address`                                   |

::callout{icon="i-lucide-zap" color="primary"}
**أثرِ كل إشارة**: توفير `source.ip_address` و`primary_actor.device.fingerprint` و`primary_actor.identifiers.sim_changed_at` حيثما ينطبق يزيد دقة الكشف بشكل ملحوظ — لا سيما لأنماط استبدال SIM والاستيلاء على الحسابات الشائعة في احتيال الأموال المحمولة في أفريقيا.
::

## تجزئة البيانات الشخصية (PII Hashing)

**لا تخزِّن Protegey أي بيانات شخصية (PII) بنص صريح**. يجب تجزئة جميع المعرِّفات الشخصية قبل الإرسال باستخدام **HMAC-SHA256 مع مفتاح الشبكة الخاص بك**.

::callout{icon="i-lucide-lock" color="amber"}
**مفتاح شبكتك ليس مفتاح API الخاص بك.** إنه سر منفصل متاح في بوابة الشريك ضمن **الإعدادات › الخصوصية › مفتاح الشبكة**. قم بتدويره بشكل مستقل عن مفاتيح API الخاصة بك.
::

### الشكل القانوني قبل التجزئة

طبِّع المعرِّفات دائمًا قبل التجزئة لضمان اتساق ربط الرسم البياني:

| النوع               | الشكل القانوني          | مثال               |
| ------------------- | ----------------------- | ------------------ |
| رقم الهاتف (MSISDN) | E.164                   | `+233241234567`    |
| البريد الإلكتروني   | حروف صغيرة، بدون مسافات | `user@example.com` |
| معرف الحساب         | كما هو (بدون تحويل)     | `ACC-00123456`     |
| الهوية الوطنية      | أحرف كبيرة، بدون مسافات | `GHA-12345678`     |

### أمثلة التعليمات البرمجية

**Node.js:**

```javascript
const crypto = require("crypto");

function hashIdentifier(value, networkKey) {
  const canonical = value.toLowerCase().trim(); // normalise first
  return crypto
    .createHmac("sha256", networkKey)
    .update(canonical)
    .digest("hex");
}

const networkKey = process.env.PROTEGEY_NETWORK_KEY;
const hashedPhone = hashIdentifier("+233241234567", networkKey);
// → 64-char hex string, e.g. "a3f8b2c1d9e7..."
```

**Python:**

```python
import hmac, hashlib, os

def hash_identifier(value: str, network_key: str) -> str:
    canonical = value.lower().strip()
    return hmac.new(network_key.encode(), canonical.encode(), hashlib.sha256).hexdigest()

network_key = os.environ["PROTEGEY_NETWORK_KEY"]
hashed_phone = hash_identifier("+233241234567", network_key)
```

**PHP:**

```php
function hashIdentifier(string $value, string $networkKey): string
{
    $canonical = strtolower(trim($value));
    return hash_hmac('sha256', $canonical, $networkKey);
}

$networkKey = env('PROTEGEY_NETWORK_KEY');
$hashedPhone = hashIdentifier('+233241234567', $networkKey);
```

## الاستجابة (Response)

### نجاح (`201 Created`)

استيعاب الإشارة **متزامن** — يعمل تقييم المخاطر بشكل مباشر ويُعاد فورًا.

```json
{
  "success": true,
  "data": {
    "signal_id": "9df4a3b1-c2e3-4f56-a789-b0c1d2e3f456",
    "event_type": "MOBILE_MONEY_SEND",
    "timestamp": "2026-02-25T10:30:00+00:00",
    "risk_score": 0.78,
    "risk_level": "high",
    "detectors_triggered": [
      "RAPID_TRANSACTION_VELOCITY",
      "LARGE_OUTLIER_TRANSACTION"
    ],
    "taxonomy": "mobile_money_fraud"
  },
  "message": "Signal received and assessed"
}
```

### مستويات المخاطر (Risk Levels)

| `risk_level` | نطاق `risk_score` | الإجراء الموصى به               |
| ------------ | ----------------- | ------------------------------- |
| `critical`   | ≥ 0.8             | الحجب الفوري وفتح تحقيق         |
| `high`       | 0.6 – 0.79        | طلب تحقق إضافي أو تعليق العملية |
| `medium`     | 0.4 – 0.59        | مصادقة متصاعدة أو مراجعة يدوية  |
| `low`        | 0.2 – 0.39        | السماح مع المراقبة              |
| `minimal`    | < 0.2             | السماح — إشارة احتيال منخفضة    |

### الكواشف (Detectors)

| معرف الكاشف                  | ما يكشفه                                                     |
| ---------------------------- | ------------------------------------------------------------ |
| `RAPID_TRANSACTION_VELOCITY` | تكرار معاملات مرتفع بشكل غير معتاد في نافذة زمنية قصيرة      |
| `LARGE_OUTLIER_TRANSACTION`  | مبلغ معاملة يتجاوز بكثير الخط الأساسي التاريخي للجهة الفاعلة |
| `SIM_SWAP_PROXIMITY`         | معاملة عالية القيمة خلال 24 ساعة من تغيير SIM                |
| `NEW_DEVICE_ACCESS`          | نشاط من بصمة جهاز لم يُرَ مسبقًا لهذه الجهة الفاعلة          |
| `IMPOSSIBLE_TRAVEL`          | استحالة جغرافية بين أحداث متتالية                            |

### خطأ في التحقق (`422 Unprocessable Content`)

```json
{
  "message": "The primary_actor.entity_id field is required.",
  "errors": {
    "primary_actor.entity_id": [
      "The primary_actor.entity_id field is required."
    ]
  }
}
```

### أخطاء التحقق الشائعة

| الخطأ                                                                         | السبب                                                   |
| ----------------------------------------------------------------------------- | ------------------------------------------------------- |
| `primary_actor.entity_id is required`                                         | حمولة UFES v2 تفتقر إلى `primary_actor.entity_id`       |
| `event_category must be one of: auth, transaction, kyc, fraud_signal, system` | قيمة فئة غير صالحة — أو احذفها كليًا للاستنتاج التلقائي |
| `flow_type must be one of: kyc, payment, auth`                                | `flow_type` الصريح خارج التعداد المسموح به              |
| `primary_actor.device.fingerprint may not be greater than 255 characters`     | اقطع بصمة الجهاز إلى 255 حرفًا                          |
| `related_entities.0.relationship_type is invalid`                             | نوع علاقة غير معروف                                     |
| `source.integration_channel is invalid`                                       | القناة غير موجودة في `api, batch, stream`               |

## الأمانة الإدارية (Idempotency)

استخدم رأس `Idempotency-Key` لإعادة محاولة الطلبات الفاشلة بأمان دون إنشاء إشارات مكررة.

**القواعد:**

- يجب أن يكون المفتاح فريدًا لكل إشارة منطقية (يُوصى باستخدام UUID)
- الحد الأقصى 64 حرفًا
- المفاتيح ذات نطاق الشريك وتنتهي صلاحيتها بعد 24 ساعة
- استجابات `4xx` لا تُخزَّن مؤقتًا — إعادة محاولة حمولة خاطئة لا تعيد تشغيل خطأ مخزن
- عند إعادة التشغيل، تتضمن الاستجابة `X-Idempotency-Replayed: true`

**مثال — إعادة المحاولة مع التراجع التدريجي:**

```javascript
async function submitSignal(payload, idempotencyKey, retries = 3) {
  for (let attempt = 0; attempt < retries; attempt++) {
    try {
      const response = await fetch("https://api.protegey.com/v1/signals", {
        method: "POST",
        headers: {
          "Content-Type": "application/json",
          "X-Centry-Key": process.env.PROTEGEY_SECRET_KEY,
          "Idempotency-Key": idempotencyKey, // same key on every retry
        },
        body: JSON.stringify(payload),
      });

      if (response.ok) return await response.json();
      if (response.status < 500)
        throw new Error(`Client error: ${response.status}`);

      // 5xx — wait and retry
      await new Promise((r) => setTimeout(r, Math.pow(2, attempt) * 1000));
    } catch (err) {
      if (attempt === retries - 1) throw err;
    }
  }
}

// Generate key once, before the first attempt
const signalKey = crypto.randomUUID();
await submitSignal(payload, signalKey);
```

::callout{icon="i-lucide-info" color="blue"}
**أفضل ممارسة**: أنشئ مفتاح الأمانة الإدارية **قبل** إرسال الطلب الأول. خزِّنه إلى جانب الإشارة في نظامك حتى تتمكن من إعادة استخدام نفس المفتاح في أي إعادة محاولة، بغض النظر عن مقدار الوقت المنقضي.
::

## توحيد أرقام الهاتف (Phone Normalization)

عند إرسال إشارة تحتوي على رقم هاتف عبر `primary_actor.identifiers.msisdn`، يقوم النظام تلقائيًا بتحويله إلى تنسيق E.164 القياسي قبل التجزئة وربط الرسم البياني.

### الأسواق المدعومة

| الدولة           | كود ISO | أمثلة للتنسيق المحلي          | النتيجة (E.164)  |
| ---------------- | ------- | ----------------------------- | ---------------- |
| **غانا**         | `GH`    | `024 123 4567`، `241234567`   | `+233241234567`  |
| **نيجيريا**      | `NG`    | `0803 123 4567`، `7012345678` | `+2348031234567` |
| **السنغال**      | `SN`    | `077 123 45 67`، `771234567`  | `+221771234567`  |
| **كوت ديفوار**   | `CI`    | `07 01 23 45 67`              | `+2250701234567` |
| **كينيا**        | `KE`    | `0712 345678`                 | `+254712345678`  |
| **جنوب أفريقيا** | `ZA`    | `082 123 4567`                | `+27821234567`   |
| **المغرب**       | `MA`    | `06 12 34 56 78`              | `+212612345678`  |
| **مصر**          | `EG`    | `010 1234 5678`               | `+201012345678`  |

::callout{icon="i-lucide-lightbulb" color="primary"}
**أفضل ممارسة**: قدِّم دائمًا `identifiers.region` للجهة الفاعلة (رمز ISO للدولة) عند إرسال أرقام الهاتف. هذا يضمن دقة توحيد بنسبة 100% للتنسيقات المحلية المتداخلة.
::

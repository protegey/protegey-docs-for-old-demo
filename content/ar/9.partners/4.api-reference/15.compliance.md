توفر واجهة برمجة تطبيقات Risk & Compliance as a Service (RCaaS) أدوات امتثال AML/مكافحة غسيل الأموال مدمجة مباشرةً في خط أنابيب إشارات Protegey. يتم تقييم كل إشارة تلقائياً مقابل قوائم العقوبات وقواعد بيانات الأشخاص السياسيين المعرضين للمخاطر وملفات المخاطر الجغرافية وقواعد مراقبة المعاملات AML.

## لوحة تحكم الامتثال

```http
GET /api/v1/partner/compliance/dashboard
Authorization: Bearer {token}
```

```json
{
  "open_sars": 3,
  "flags_last_30_days": 47,
  "screened_entities": 1240,
  "sanctions_matches": 2,
  "high_risk_jurisdictions_flagged": 8,
  "upcoming_calendar_events": 5
}
```


## تقارير الأنشطة المشبوهة (TMS)

### عرض قائمة التقارير

```http
GET /api/v1/partner/compliance/sars
Authorization: Bearer {token}
```

معاملات الاستعلام: `status` (`draft`, `under_review`, `filed`, `archived`)، `per_page`

```json
{
  "data": [
    {
      "id": "sar_abc123",
      "reference_number": "SAR-20260218-00042",
      "status": "under_review",
      "entity_id": 42,
      "narrative": "أظهر الكيان سلوك تجزئة عبر 3 حسابات...",
      "transaction_total": 45000.0,
      "currency": "EGP",
      "created_at": "2026-02-15T10:00:00Z",
      "filed_at": null
    }
  ]
}
```

### إنشاء تقرير (مسودة)

```http
POST /api/v1/partner/compliance/sars
Authorization: Bearer {token}
Content-Type: application/json
```

```json
{
  "entity_id": 42,
  "reason": "تم اكتشاف تجزئة: 12 معاملة أقل من عتبة الإبلاغ مباشرةً",
  "case_id": "case_uuid_اختياري"
}
```

يتم إنشاء السرد تلقائياً من سجلات `AmlTransactionFlag` للكيان. يمكنك تعديله قبل التقديم.

### تحديث سرد التقرير

```http
PUT /api/v1/partner/compliance/sars/{sarId}
Authorization: Bearer {token}
Content-Type: application/json
```

```json
{
  "narrative": "سرد التحقيق المحدث..."
}
```

### تقديم للمراجعة

```http
POST /api/v1/partner/compliance/sars/{sarId}/review
Authorization: Bearer {token}
```

### تقديم التقرير رسمياً

يتطلب دور `analyst` أو أعلى.

```http
POST /api/v1/partner/compliance/sars/{sarId}/file
Authorization: Bearer {token}
```

دورة حياة التقرير: `draft` → `under_review` → `filed` → `archived`

## إشارات المعاملات

يتم إنشاء الإشارات تلقائياً بواسطة `TransactionMonitoringRulesService` لكل إشارة معالجة.

### عرض قائمة الإشارات

```http
GET /api/v1/partner/compliance/transaction-flags
Authorization: Bearer {token}
```

معاملات الاستعلام: `rule_key`، `entity_id`، `from`، `to`، `per_page`

```json
{
  "data": [
    {
      "id": "flag_abc123",
      "signal_id": "sig_xyz789",
      "entity_id": 42,
      "rule_key": "structuring",
      "rule_description": "معاملات متعددة أقل من عتبة الإبلاغ مباشرةً",
      "risk_contribution": 0.85,
      "flagged_at": "2026-02-18T10:00:00Z",
      "metadata": {
        "transaction_count": 8,
        "window_hours": 24,
        "threshold": 500000
      }
    }
  ]
}
```

**مفاتيح القواعد:** `structuring`، `velocity_breach`، `round_number`، `high_risk_jurisdiction`

## دورة حياة SAR

تتبع تقارير SAR آلةً للحالات ذات قواعد صارمة. لكل انتقال نقطة نهاية مخصصة:

```
draft → under_review → filed
      ↘              ↘ closed
```

| الخطوة | نقطة النهاية | الوصف |
|------|----------|-------------|
| 1. الإنشاء | `POST /compliance/sars` | يحتسب تلقائيًا إجماليات المعاملات من علامات AML الحديثة للكيان |
| 2. السرد | `POST /compliance/sars/{id}/narrative` | يولّد سردًا من أحدث 10 أحداث علامات AML |
| 3. المراجعة | `POST /compliance/sars/{id}/review` | ينقل الحالة من `draft` إلى `under_review` |
| 4. التقديم | `POST /compliance/sars/{id}/file` | ينقل الحالة من `under_review` إلى `filed`، ويولّد حمولة الجهة التنظيمية + مسار التدقيق |
| 5. الأدلة | `GET /compliance/sars/{id}/evidence` | يصدّر مؤشرات المخاطر + علامات AML (آمن من حيث البيانات الشخصية) |

#### توليد السرد

```http
POST /api/v1/partner/compliance/sars/{uuid}/narrative
```

يولّد سردًا من أحدث 10 علامات AML للكيان. السرد قابل للتعديل — هذه نقطة بداية وليست مسودة نهائية.

#### تصدير الأدلة

```http
GET /api/v1/partner/compliance/sars/{uuid}/evidence
```

يُعيد حزمة أدلة JSON تحتوي على:
- مؤشرات المخاطر (نتائج الكاشفات، علامات AML، درجات المخاطر)
- معرفات UUID للإشارات المساهمة
- تجزئة الكيان (HMAC-SHA256 — **ليست** بيانات شخصية بنص صريح)

::callout{type="warning"}
**ملاحظة البيانات الشخصية**: تستخدم حزمة الأدلة معرفات الكيانات المجزَّأة بـ HMAC، لا الأسماء أو أرقام الحسابات بنص صريح. يجب استبدال التجزئات بالهويات الحقيقية من سجلات KYC قبل التقديم إلى وحدة الاستخبارات المالية (FIU).
::

## تشغيل STR التلقائي

عندما تنشأ علامتا AML `structuring` و`velocity_breach` معًا خلال **72 ساعة** على نفس الكيان، يُنشأ SAR تلقائيًا بحالة `draft`:

1. يتلقى فريقك حدث webhook بـ `compliance.sar.auto_drafted`
2. يظهر SAR ضمن **الامتثال ← تقارير SAR ← يتطلب مراجعة**
3. تشمل الحزمة إجماليات المعاملات المحتسبة مسبقًا وسردًا أوليًا
4. يجب على مسؤول الامتثال المراجعة والتعديل إذا لزم وإطلاق التقديم صراحةً

لا تُقدَّم تقارير SAR المُنشأة تلقائيًا قط. نافذة الـ 72 ساعة وفترة إزالة التكرار (7 أيام) قابلتان للتكوين عبر إعدادات الامتثال لديك.

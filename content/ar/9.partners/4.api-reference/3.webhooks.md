تسمح خطافات الويب (Webhooks) لـ Protegey بدفع المعلومات الاستخباراتية إلى أنظمتك في الوقت الفعلي. هذا مفيد لتدفقات العمل غير المتزامنة أو مراقبة تغييرات حالة الكيان.

## تصنيف الأحداث (Event Taxonomy)

نحن ندعم عدة أنواع من الأحداث التي يمكنك الاشتراك فيها عبر بوابة الشركاء (Partner Portal).

### الأحداث الرئيسية

| نوع الحدث | الوصف | مفتاح الحمولة |
|------------|-------------|-------------|
| `signal.created` | تم إضافة إشارة جديدة للشبكة لكيان تراقبه بنشاط. | `signal` |
| `risk_score.changed` | تجاوزت درجة المخاطر لكيان مراقب حداً معيناً (مثلاً أصبحت عالية - HIGH). | `risk_change` |
| `trust_score.updated` | تغيرت درجة ثقة الشريك الخاصة بك (مثلاً انخفضت بسبب الإيجابيات الكاذبة). | `trust_score` |
| `list.match` | طابق الكيان قائمة مراقبة (Watchlist) أو قائمة حظر (Blocklist) محددة. | `match` |

### أحداث إدارة الحالات (Case Management Events)

| نوع الحدث | الوصف | مفتاح الحمولة |
|------------|-------------|-------------|
| `case.created` | تم إنشاء حالة احتيال جديدة | `case` |
| `case.updated` | تغيرت حالة القضية أو أولويتها أو التعيين | `case` |
| `case.note_added` | أضيفت ملاحظة إلى القضية | `case`, `note` |
| `case.evidence_attached` | تم رفع أدلة إلى القضية | `case`, `evidence` |
| `case.resolved` | تم تمييز القضية بأنها محلولة | `case` |
| `case.closed` | تم إغلاق القضية | `case` |

### أحداث إدارة التنبيهات (Alert Management Events)

| نوع الحدث | الوصف | مفتاح الحمولة |
|------------|-------------|-------------|
| `alert.triggered` | تم إنشاء تنبيه جديد | `alert` |
| `alert.acknowledged` | تم الإقرار بالتنبيه من قبل المستخدم | `alert` |
| `alert.resolved` | تم تمييز التنبيه بأنه محلول | `alert` |
| `alert.false_positive` | تم تمييز التنبيه بأنه إيجابي كاذب | `alert` |

### أحداث إدارة الكيانات (Entity Management Events)

| نوع الحدث | الوصف | مفتاح الحمولة |
|------------|-------------|-------------|
| `entity.created` | تم إنشاء ملف تعريف كيان احتيال جديد | `entity` |
| `entity.status_updated` | تغيرت حالة الكيان | `entity` |
| `entity.risk_escalated` | تجاوزت درجة مخاطر الكيان الحد المسموح به | `entity` |

## مخطط الحمولة (Payload Schema)

تشترك جميع خطافات الويب في غلاف موحد.

```typescript
interface WebhookPayload {
  id: string; // معرف الحدث الفريد (evt_...)
  type: EventType;
  created_at: string; // ISO 8601
  data: Record<string, any>; // بيانات خاصة بالحدث
}
```

### مثال: تغيير درجة المخاطر

```json
{
  "id": "evt_abc123",
  "type": "risk_score.changed",
  "created_at": "2026-01-12T15:00:00Z",
  "data": {
    "entity_type": "email",
    "entity_value": "user@example.com",
    "old_score": 40,
    "new_score": 85,
    "trigger": "new_signal_received",
    "source_signal_id": "sig_8x9s7..."
  }
}
```

## الأمان: التحقق من التوقيع

تقوم Protegey بتوقيع كل طلب webhook للتحقق من أصالته.

### رؤوس التحقق (Verification Headers)

| الرأس | الوصف |
|--------|-------------|
| `X-Protegey-Signature` | توقيع HMAC-SHA256 لجسم الطلب. |
| `X-Protegey-Event` | نوع الحدث (مثل `case.created`). |
| `X-Protegey-Delivery-ID` | معرف UUID فريد لمحاولة التسليم. |
| `X-Protegey-Timestamp` | الطابع الزمني Unix لوقت إرسال الويب هوك. |

### التحقق من التواقيع

للتحقق من الويب هوك، قم بحساب توقيع HMAC-SHA256 لجسم الطلب الخام باستخدام **سر الويب هوك** الخاص بك (المتوفر في بوابة الشركاء).

## سياسة إعادة المحاولة (Retry Policy)

تستخدم Protegey استراتيجية التراجع الأسي (exponential backoff) لمحاولات تسليم الويب هوك الفاشلة.

| المحاولة | التأخير |
|---------|-------|
| 1 | فوري |
| 2 | دقيقة واحدة |
| 3 | 5 دقائق |
| 4 | 30 دقيقة |
| 5 | ساعة واحدة |
| 6 | 6 ساعات |

**ملاحظة**: يتم تعطيل نقطة النهاية تلقائياً بعد **3 فشلات متتالية** في التسليم. أعد تفعيلها عبر API بعد حل المشكلة.

## أفضل الممارسات

### المعالجة غير المتزامنة

استجب بسرعة بـ `200 OK` وقم بمعالجة الويب هوك بشكل غير متزامن لتجنب انقضاء مهلة الطلب (timeout).

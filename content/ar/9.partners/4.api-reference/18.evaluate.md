يوفر API التقييم تسجيل درجات المخاطر في الوقت الفعلي على البيانات الخام أو غير المرتبطة. إنه **عديم الحالة** — لا يُنشأ أي كيان ولا يُحدَّث. يمكن استدعاؤه عند كل طلب دون أي آثار جانبية على رسم بيانات كياناتك.

::callout{icon="i-lucide-zap" color="primary"}
**حالة الاستخدام الفوري**: `/evaluate` مُحسَّن لأوقات استجابة أقل من 100ms. استخدمه لفحص إنشاء الحسابات، والتفويض المسبق للمدفوعات، وتدفقات الإعداد.
::

> **هل تبحث عن شيء آخر؟**
> - التسجيل الفوري بدون حفظ → [API Evaluate](/partners/api-reference/evaluate)
> - ذكاء الكيانات المعمّق → [API Assess](/partners/api-reference/entities#assess)
> - استيعاب الإشارات في الرسم البياني → [API Signals](/partners/api-reference/signals)

## نقطة الوصول

```http
POST /api/v1/evaluate
```

### المصادقة

```http
X-Centry-Key: cen_live_sk_...
```

### حدود معدل الطلبات

- 300 طلب في الدقيقة (Standard)
- 1,000 طلب في الدقيقة (Enterprise)

---

## مخطط الطلب

```typescript
interface EvaluateRequest {
  // ── What you're evaluating (choose one or provide multiple for composite) ──
  email?: string;        // plaintext — hashed internally before scoring
  phone?: string;        // E.164 format (e.g. "+233244123456")
  device?: {
    fingerprint: string;      // device fingerprint string
    user_agent?: string;      // raw UA string
    ip_address?: string;      // submitting IP for geo enrichment
  };
  account?: {
    account_id: string;       // your internal account identifier
    account_type?: "individual" | "business" | "wallet";
  };
  composite?: {
    // Evaluate multiple identifiers together — higher confidence result
    email?: string;
    phone?: string;
    device_fingerprint?: string;
    account_id?: string;
  };

  // ── Options ──────────────────────────────────────────────────────────────
  options?: {
    resolve_entity?: boolean;      // default: false — link to existing entity if found
    detect_duplicates?: boolean;   // default: false — check for synthetic ID patterns
    include_explanations?: boolean; // default: true — include explanations[] in response
  };

  // ── سياق التقييم (اختياري، يحسّن الدقة) ─────────────────────
  context?: {
    event_type?: string;           // e.g. "ACCOUNT_CREATION", "PAYMENT"
    amount?: number;               // transaction amount if relevant
    currency?: string;             // ISO 4217
    ip_address?: string;           // end-user IP (if not in device block)
    region?: string;               // ISO 3166-1 alpha-2
  };
}
```

### أنواع التقييم

| النوع | الحقل(الحقول) المطلوبة | يُفوتَر بوصفه |
|---|---|---|
| `email` | `email` | `fraud_account_check` |
| `phone` | `phone` | `fraud_account_check` |
| `account` | `account.account_id` | `fraud_account_check` |
| `device` | `device.fingerprint` | `device_behavioral_signals` |
| `composite` | `composite.*` (على الأقل 2) | `fraud_account_check` |
| `identity_verification` | _(مخطط)_ | _(Phase 11)_ |

::callout{icon="i-lucide-info" color="blue"}
**التحقق من الهوية**: نوع `identity_verification` (وثيقة + بيومتري) مخطط للمرحلة 11. سيتبع نفس عقد الطلب/الاستجابة مع حقول إضافية. التكاملات الحالية لن تتأثر.
::

## أمثلة على الطلبات

### تقييم البريد الإلكتروني

```bash
curl -X POST "https://api.protegey.com/api/v1/evaluate" \
  -H "Content-Type: application/json" \
  -H "X-Centry-Key: cen_live_sk_..." \
  -d '{
    "email": "user@example.com",
    "options": {
      "include_explanations": true
    }
  }'
```

```bash

    "duplicate": {

      "total_signals": 0,
      "signals_last_24h": 0,
      "first_seen": null,

    "explanations": [
      {

        "category": "identity",

        "evidence": {
          "domain": "example.com",
          "domain_risk_score": 0.68
        }
      }
    ],

    "recommendation": {
      "action": "review",
      "priority": "high"
    }
  }

```

### حقول الاستجابة

| الحقل | النوع | الوصف |
|---|---|---|
| `risk_score` | float | درجة المخاطر بين 0.0 و1.0 |
| `risk_level` | string | `low`، أو `medium`، أو `high`، أو `critical` |
| `confidence` | float | مستوى الثقة في الدرجة، بين 0.0 و1.0 |
| `entity` | object\|null | الكيان المُحلَّل (فقط إذا كان `resolve_entity: true` ووُجدت مطابقة) |
| `entity.uuid` | string | UUID الكيان — يُستخدم مع `/risk/assess` للذكاء الكامل |
| `duplicate` | object\|null | نتيجة كشف التكرار (فقط إذا كان `detect_duplicates: true`) |
| `signals_summary` | object | سياق الإشارات المجمَّع للمعرّف المُقيَّم |
| `explanations` | array | قائمة مرتبة من الأسباب المُسجَّلة (الأشد خطورة أولاً) |
| `recommendation` | object | الإجراء المقترح والأولوية |

---

## مرجع مستويات المخاطر

| `risk_level` | `risk_score` | الاستجابة المقترحة |
|---|---|---|
| `low` | 0.00 – 0.20 | السماح — لا إشارات مقلقة |
| `medium` | 0.21 – 0.50 | مصادقة معزّزة أو رفض ناعم |
| `high` | 0.51 – 0.80 | مراجعة يدوية أو تدفق تحدٍّ |
| `critical` | 0.81 – 1.00 | الحجب والتحقيق |

## نمط الذكاء التدريجي

عند تعيين `resolve_entity: true` وتحليل كيان، استخدم `entity.uuid` المُعاد لاسترداد التقييم الكامل فوراً:

```javascript
const evalResult = await fetch("/api/v1/evaluate", {
  method: "POST",
  body: JSON.stringify({
    phone: "+233244123456",
    options: { resolve_entity: true }
  })
});

const { data } = await evalResult.json();

if (data.entity?.uuid && data.risk_level !== "low") {
  // التصعيد إلى التقييم الكامل
  const assessResult = await fetch(`/api/v1/risk/assess`, {
    method: "POST",
    body: JSON.stringify({ entity_uuid: data.entity.uuid })
  });
}
```

## التسعير

| نوع المدخل | المقياس | السعر |
|---|---|---|
| `email`، `phone`، `account`، `composite` | `fraud_account_check` | انظر [الخطط والتسعير](/partners/billing/plans) |
| `device` | `device_behavioral_signals` | انظر [الخطط والتسعير](/partners/billing/plans) |

كل استدعاء لـ `/evaluate` يُحسب وحدة واحدة قابلة للفوترة من المقياس المناسب. التقييمات المركّبة تُحسب كـ `fraud_account_check` واحد بصرف النظر عن عدد المعرّفات المقدَّمة.

## ردود الخطأ

### خطأ في التحقق (`422`)

```json
{
  "message": "At least one evaluation input is required.",
  "errors": {
    "input": ["Provide one of: email, phone, device, account, or composite."]
  }
}
```

### الأخطاء الشائعة

| الخطأ | السبب |
|---|---|
| `At least one evaluation input is required` | لم يُقدَّم أي حقل مدخل |
| `composite requires at least 2 identifiers` | حقل واحد فقط مُعيَّن في كتلة `composite` |
| `phone must be in E.164 format` | الهاتف بدون البادئة `+` ورمز الدولة |
| `device.fingerprint is required when using device evaluation` | بصمة الجهاز مفقودة في كتلة device |

تسمح لك واجهة برمجة تطبيقات تقييم المخاطر (Risk Assessment API) بالحصول على قرار مخاطر في الوقت الفعلي لكيان ما. تم تصميم نقطة النهاية هذه ليتم استدعاؤها بشكل متزامن خلال تدفقات المستخدم (مثل التسجيل، إتمام الشراء).

## نقطة النهاية (Endpoint)

```http
POST /api/v1/risk/assess
```

## مخطط الطلب (Request Schema)

### الرؤوس (Headers)

| الرأس | القيمة | مطلوب | الوصف |
|--------|-------|----------|-------------|
| `Content-Type` | `application/json` | نعم | حمولة JSON قياسية. |
| `X-Centry-Key` | `cen_live_sk_...` | نعم | مفتاح الإنتاج السري الخاص بك. |

### معلمات الجسم (Body Parameters)

```typescript
interface RiskAssessmentRequest {
  entity_type: 'email' | 'phone' | 'ip' | 'device_id' | 'crypto_address';
  identifier: string; // القيمة المراد تقييمها (مثل عنوان البريد الإلكتروني)
}
```

### مثال على الطلب

```bash
curl -X POST "https://api.protegey.com/v1/risk/assess" \
  -H "Content-Type: application/json" \
  -H "X-Centry-Key: cen_live_sk_..." \
  -d '{
    "entity_type": "email",
    "identifier": "fraudster@example.com"
  }'
```

## مخطط الاستجابة (Response Schema)

```typescript
interface RiskAssessmentResponse {
  decision: 'ALLOW' | 'REVIEW' | 'BLOCK';
  risk_score: number; // 0-100
  reasons: string[]; // قائمة العوامل المساهمة
}
```

### منطق القرار (Decision Logic)

| القرار | درجة المخاطر | المعنى | الإجراء المقترح |
|----------|------------|---------|------------------|
| `ALLOW` | < 50 | مخاطر منخفضة. | المتابعة في المعاملة. |
| `REVIEW` | 50 - 79 | مخاطر متوسطة. | تفعيل المصادقة القوية (2FA) أو المراجعة اليدوية. |
| `BLOCK` | >= 80 | مخاطر عالية/حرجة. | رفض المعاملة/التسجيل. |

### مثال على الاستجابة

```json
{
  "decision": "BLOCK",
  "risk_score": 85,
  "reasons": [
    "VELOCITY_HIGH",
    "NETWORK_BLOCKLIST_MATCH"
  ]
}
```

### استجابات الأخطاء

**400 Bad Request**
```json
{
    "message": "يجب أن يكون نوع الكيان أحد التالي: email, phone, ip, device_id, crypto_address."
}
```

**401 Unauthorized**
```json
{
    "message": "مصادقة الشريك مطلوبة"
}
```

## منهجية تسجيل نقاط المخاطر

### عوامل تسجيل النقاط

يأخذ تقييم المخاطر في Protegey عدة مؤشرات احتيال بعين الاعتبار:

| العامل | الوزن | الوصف |
|--------|--------|-------------|
| **السرعة (Velocity)** | عالٍ | تكرار المعاملات ضمن نوافذ زمنية (ساعة، 24 ساعة، 7 أيام) |
| **تحليل الشبكة** | عالٍ | الروابط مع المحتالين المعروفين أو الكيانات المشبوهة |
| **كشف الشذوذ** | متوسط | الانحراف عن أنماط السلوك التاريخي |
| **الإشارات الجغرافية** | متوسط | السفر المستحيل، الأنماط العابرة للحدود |
| **إشارات الجهاز** | متوسط | أجهزة جديدة، عدم تطابق بصمات الأجهزة |
| **السلوك التاريخي** | منخفض | التورط السابق في الاحتيال، عمر الحساب |

### نطاقات درجات المخاطر

| الدرجة | المستوى | توصية الإجراء |
|-------|-------|----------------------|
| **0-39** | منخفض | الموافقة تلقائياً |
| **40-59** | متوسط | المصادقة القوية (2FA, SMS OTP) |
| **60-79** | عالٍ | المراجعة اليدوية مطلوبة |
| **80-100** | حرج | حظر المعاملة، تمييز الكيان |

### رموز الأسباب (Reason Codes)

تحتوي مصفوفة `reasons` على مؤشرات احتيال محددة تم اكتشافها:

| رمز السبب | الوصف |
|-------------|-------------|
| `VELOCITY_HIGH` | تم اكتشاف تكرار مفرط للمعاملات |
| `AMOUNT_ANOMALY` | مبلغ المعاملة يتجاوز الأنماط العادية |
| `IMPOSSIBLE_TRAVEL` | تم اكتشاف عدم تناسق جغرافي |
| `DEVICE_NEW` | أول معاملة من هذا الجهاز |
| `DEVICE_MISMATCH` | بصمة الجهاز لا تطابق النمط التاريخي |
| `CROSS_BORDER` | معاملة دولية من بلد عالي المخاطر |
| `NETWORK_BLOCKLIST_MATCH` | كيان مرتبط بمحتال معروف |
| `NETWORK_FRAUD_RING` | جزء من شبكة احتيال مشتبه بها |
| `MULTIPLE_FAILED_ATTEMPTS` | فشل في المصادقة مؤخراً |
| `STOLEN_CREDENTIALS` | بيانات الاعتماد تطابق قاعدة بيانات الاختراقات |

## المصادقة

تقييم المخاطر يستخدم المصادقة عبر مفتاح API:

| بادئة المفتاح | البيئة | حالة الاستخدام |
|------------|-------------|----------|
| `cen_live_sk_` | الإنتاج | تقييمات الإنتاج في الوقت الفعلي |
| `cen_test_sk_` | البيئة التجريبية | الاختبار والتطوير |

---

## حدود المعدل (Rate Limits)

- **الإنتاج**: 1000 طلب في الدقيقة لكل شريك
- **البيئة التجريبية**: 100 طلب في الدقيقة لكل شريك

## أفضل الممارسات

### أنماط التكامل

**التقييم المتزامن (موصى به)**:
```javascript
// أثناء تدفق الدفع/التسجيل
async function processTransaction(user, transaction) {
  // 1. تقييم المخاطر في الوقت الفعلي
  const assessment = await protegey.riskAssess({
    entity_type: 'email',
    identifier: user.email
  });

  // 2. اتخاذ القرار بناءً على المخاطر
  if (assessment.decision === 'BLOCK') {
    return { success: false, reason: 'تم رفض المعاملة لأسباب أمنية' };
  }

  if (assessment.decision === 'REVIEW') {
    // تفعيل المصادقة القوية
    await sendTwoFactorCode(user.phone);
    return { success: false, reason: 'مطلوب تحقق إضافي' };
  }

  // 3. المتابعة في المعاملة
  return processPayment(transaction);
}
```

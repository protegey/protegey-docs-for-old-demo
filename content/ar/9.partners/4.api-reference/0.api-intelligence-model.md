تعرض Protegey ثلاث نقاط وصول لمراحل مختلفة من دورة حياة ذكاء مكافحة الاحتيال. إن فهم أيها تستخدم — ولماذا — هو أساس التكامل المحكم.

## طبقتا الذكاء

يتنظم الـ API حول طبقتَي ذكاء متمايزتَين:

### التقييم (عديم الحالة)

تسجيل درجات المخاطر في الوقت الفعلي على البيانات الخام أو غير المرتبطة. لا يُنشأ أي كيان ولا يُحدَّث. يمكن استدعاؤه عند كل طلب دون أي آثار جانبية.

- المدخل: معرّفات خام (بريد إلكتروني، هاتف، جهاز، حساب، مركّب)
- المخرج: `risk_score`، `risk_level`، `confidence`، `explanations[]`، `recommendation`
- هدف زمن الاستجابة: **< 100ms**
- يُستخدم عند: الفرز المسبق للمستخدمين الجدد، التسجيل قبل الإعداد، قرارات الدفع الفوري

### التقييم المعمّق (ذو الحالة)

ذكاء عميق حول كيان معروف في الرسم البياني. يستلزم وجود الكيان مسبقاً (من استيعاب إشارات سابقة أو تحليل هويات). يُعيد حزمة ذكاء كاملة تتضمن السجل السلوكي والجوار الشبكي وسياق الامتثال.

- المدخل: UUID الكيان أو معرّف مرتبط
- المخرج: عقد التسجيل الكامل + `profile`، `network`، `history`
- هدف زمن الاستجابة: **< 500ms**
- يُستخدم عند: التحقيق في مستخدم مُبلَّغ عنه، إثراء قضية، مراجعة معاملات عالية القيمة

---

## نظرة عامة على نقاط الوصول الثلاث

| نقطة الوصول | النوع | الغرض | زمن الاستجابة |
|---|---|---|---|
| `POST /api/v1/signals` | ذو حالة | استيعاب الأحداث في رسم بياني للكيانات | آمن للاستخدام الغير متزامن |
| `POST /api/v1/evaluate` | عديم الحالة | تسجيل البيانات الخام/غير المرتبطة في الوقت الفعلي | < 100ms |
| `POST /api/v1/risk/assess` | ذو حالة | حزمة ذكاء كيانات معمّقة | < 500ms |

## نموذج الرسم البياني للكيانات

الإشارات هي المادة الخام. الكيانات هي الذكاء الدائم.

عندما تصل إشارة، تقوم Protegey بما يلي:

1. **التحقق** من الحدث مقابل مخطط UFES v2
2. **تحليل** المعرّفات للعثور على الكيانات الموجودة (أو إنشاء كيانات جديدة)
3. **تشغيل أدوات الكشف** (السرعة، القيم الشاذة، استبدال بطاقة SIM، الجهاز، السفر)
4. **دمج الدرجات** عبر الأبعاد السلوكية والشبكية والسياقية والتاريخية
5. **تحديث** ملف المخاطر للكيان وحواف الرسم البياني

مع مرور الوقت، يتراكم لكل كيان سجل سلوكي وجوار شبكي وسجل امتثال — مما يجعل `/risk/assess` أكثر ثراءً تدريجياً.

## تدفق الذكاء التدريجي

```
Raw Input → POST /evaluate → (resolve_entity: true) → Entity → POST /risk/assess
                ↓ stateless                                          ↓ stateful
           Immediate verdict                               Full intelligence package
```

يُوجّه خيار `resolve_entity: true` في `/evaluate` Protegey لربط المدخل المُقيَّم بكيان موجود إن وُجد تطابق. يُعاد UUID الكيان المحلول ويمكن استخدامه فوراً مع `/risk/assess` للحصول على تقييم أعمق.

## متى تستخدم أي نقطة وصول

### استخدم `/signals` عندما:
- تُبلّغ عن حدث احتيال مؤكد أو رفض دفع
- تُغذّي الرسم البياني بالسياق السلوكي عبر الزمن
- تُرسل إشارات لمشاركة الذكاء على المستوى الشبكي
- لا تحتاج إلى حكم متزامن (أرسل وانسَ مع ضمان تكرار العملية)

### استخدم `/evaluate` عندما:
- تُسجّل درجة مخاطر بريد إلكتروني أو هاتف أو جهاز عند إنشاء الحساب
- تفرز مستخدماً مسبقاً قبل ظهوره في نظامك
- تتخذ قرارات الدفع أو الخروج في الوقت الفعلي
- تريد حكماً دون إنشاء كيان دائم

### استخدم `/risk/assess` عندما:
- تراجع كياناً مُبلَّغاً عنه من قائمة التنبيهات
- تُثري قضية احتيال مفتوحة بالسياق الكامل
- تبني سير عمل تحقيق يحتاج إلى السجل السلوكي
- تنطوي المعاملات عالية القيمة على حاجة لحزمة الذكاء الكاملة

## معاينة تجريد SDK

سيعرض SDK Protegey القادم أساليب مركّبة تتوافق مع هذا النموذج:

```typescript
// Stateless — wraps POST /evaluate
await protegey.evaluateEmail("user@example.com");
await protegey.evaluatePhone("+233244123456");
await protegey.evaluateDevice({ fingerprint: "fp_abc123" });

// Stateful — wraps POST /risk/assess
await protegey.assessEntity("ent_uuid_here");

// Composite — evaluate + resolve + assess in one call
await protegey.assessByEmail("user@example.com");
// → evaluate → resolve_entity: true → assess
```

تتولى الأساليب المركّبة سلسلة evaluate → resolve → assess تلقائياً، وتُعيد حزمة الذكاء الكاملة حتى للكيانات التي لم تُرَ من قبل.

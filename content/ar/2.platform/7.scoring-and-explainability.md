يجيب كل حكم مخاطر صادر عن Protegey على أربعة أسئلة:

1. **ما مستوى الخطورة؟** → `risk_score` + `risk_level`
2. **ما مدى يقيننا؟** → `confidence`
3. **لماذا؟** → `explanations[]`
4. **ماذا ينبغي لك أن تفعل؟** → `recommendation`

ينطبق هذا العقد الموحّد على كل من `/evaluate` و`/risk/assess`. استجابة `/evaluate` أخف (إشارات أقل، لا سجل كامل)؛ بينما `/risk/assess` مُثرى بعمق سلوكي. البنية متطابقة.

---

## risk_score

عدد عشري مستمر بين 0.0 و1.0 يمثل احتمالية الاحتيال أو إساءة الاستخدام. كلما ارتفعت القيمة، زادت المخاطر.

يُنتَج الدرجة بواسطة **محرك دمج المخاطر الموزون (NUFSS)**، الذي يُجمّع أربعة أبعاد:

| البُعد | الوزن | المصدر |
|---|---|---|
| السلوكي | 35% | تجميع أدوات الكشف (السرعة، القيم الشاذة، استبدال SIM، الجهاز، السفر) |
| الشبكي | 40% | المخاطر المنتشرة على مسافة قفزتَين في الرسم البياني الحار |
| السياقي | 15% | إثراء المحلِّلات (الموقع الجغرافي، الجهاز، المشغّل، وقت اليوم) |
| التاريخي | 10% | متوسط الكيان المتحرك على مدى 90 يوماً |

العدد العشري المدموج هو ما تراه بوصفه `risk_score`. إنه **حتمي** — المدخلات ذاتها تُنتج الدرجة ذاتها.

---

## risk_level

مستويات مُعيَّرة مشتقة من `risk_score`:

| `risk_level` | نطاق `risk_score` | المعنى |
|---|---|---|
| `low` | 0.00 – 0.20 | نشاط طبيعي، لا إشارات مقلقة |
| `medium` | 0.21 – 0.50 | أنماط مشبوهة؛ يُنصح بالمصادقة المعزّزة |
| `high` | 0.51 – 0.80 | مؤشرات احتيال قوية؛ مراجعة يدوية أو تحدٍّ |
| `critical` | 0.81 – 1.00 | ثقة عالية بوجود احتيال؛ حجب والتحقيق |

هذه المستويات مستقرة — لن تتغير بين إصدارات الـ API دون ترقية رئيسية وإشعار بالإهمال.

## confidence

عدد عشري بين 0.0 و1.0 يمثل مدى يقين Protegey في `risk_score`. درجة مخاطر عالية مع ثقة منخفضة تعني: "يبدو هذا محفوفاً بالمخاطر، لكن ليس لدينا بيانات كافية للتأكد."

**ما يحدد الثقة:**

- **حجم الإشارات**: كلما زادت الإشارات، زاد اليقين
- **حداثة الإشارات**: الإشارات الحديثة تحمل وزناً أكبر من القديمة
- **اتساق الأنماط**: الأنماط المتسقة عبر أدوات كشف متعددة ترفع الثقة
- **قوة التطابق**: المطابقات القوية في OSINT، والمطابقات الدقيقة في الرسم البياني، والمعرّفات عالية الجودة تزيد الثقة

### مربّع الثقة × المخاطر

استخدم هذه المصفوفة عند توجيه القرارات:

| | ثقة عالية | ثقة منخفضة |
|---|---|---|
| **مخاطر عالية** | تصرّف فوراً | تحقّق أكثر |
| **مخاطر منخفضة** | آمن للمتابعة | بيانات غير كافية |

::callout{icon="i-lucide-info" color="blue"}
**الكيانات الجديدة لديها ثقة منخفضة افتراضياً.** الكيان الذي يُرى لأول مرة اليوم سيحصل على `confidence` بحدود 0.3–0.5 حتى لو تفعّلت أدوات الكشف. هذا يمنع اتخاذ إجراءات مبالغ فيها ضد أطراف جديدة دون سجل سلوكي.
::

## explanations[]

قائمة منظّمة من الأسباب التي أسهمت في حكم المخاطر. كل تفسير قابل للقراءة آلياً وبشرياً.

### كائن التفسير

```json
{
  "code": "DEVICE_REUSE",
  "category": "device",
  "severity": "high",
  "message": "Device fingerprint linked to 3 flagged entities",
  "evidence": {
    "linked_entity_count": 3,
    "highest_linked_risk": 0.91
  }
}
```

### الحقول

| الحقل | النوع | الوصف |
|---|---|---|
| `code` | string | رمز قابل للقراءة الآلية (انظر المرجع أدناه) |
| `category` | string | فئة الإشارة (انظر الفئات أدناه) |
| `severity` | string | `low`، أو `medium`، أو `high`، أو `critical` |
| `message` | string | تفسير مقروء بالإنجليزية |
| `evidence` | object | البيانات الداعمة المستخدمة لتوليد هذا التفسير |

### الفئات القياسية

| الفئة | ما تشمله |
|---|---|
| `identity` | إشارات مخاطر الهاتف والبريد الإلكتروني والهوية الوطنية |
| `device` | شذوذات بصمة الجهاز وأنماط إعادة الاستخدام |
| `network` | مخاطر الجوار في الرسم البياني، الكيانات المرتبطة |
| `behavioral` | السرعة، المبالغ الشاذة، الشذوذات الزمنية |
| `historical` | تورط سابق في الاحتيال، تغييرات حالة سابقة |
| `synthetic_identity` | إشارات متوافقة مع احتيال الهوية الاصطناعية |
| `transactional` | أنماط على مستوى المعاملة (التهيكل، العابر للحدود) |

### مرجع رموز التفسير

| الرمز | الفئة | ما يعنيه |
|---|---|---|
| `DEVICE_REUSE` | device | بصمة الجهاز مرتبطة بكيانات متعددة ومتمايزة |
| `NEW_DEVICE` | device | أول جهاز يُستخدم لهذا الكيان مقترناً بموقع جغرافي عالي المخاطر |
| `RAPID_VELOCITY` | behavioral | تجاوزت تكرارية المعاملات العتبة ضمن النافذة المتحركة |
| `LARGE_OUTLIER` | behavioral | مبلغ المعاملة يُعدّ قيمة شاذة إحصائياً مقارنةً بخط الأساس للكيان |
| `SIM_SWAP_PROXIMITY` | behavioral | جرت المعاملة في غضون ساعات من حدث استبدال بطاقة SIM |
| `IMPOSSIBLE_TRAVEL` | behavioral | الكيان ذاته في موقعَين جغرافيَّين في وقت مستحيل فيزيائياً |
| `EMAIL_RISK_PATTERN` | identity | مزوّد البريد الإلكتروني أو نمطه مرتبط بهويات اصطناعية |
| `PHONE_NETWORK_RISK` | identity | المشغّل أو نوع الرقم مرتبط بأنماط احتيال |
| `NETWORK_CONTAMINATION` | network | الكيان مرتبط بمحتالين معروفين في الرسم البياني |
| `HIGH_RISK_NEIGHBORHOOD` | network | متوسط مخاطر الجوار على مسافة قفزتَين يتجاوز العتبة |
| `OSINT_MATCH` | identity | الكيان يطابق سجلاً في قوائم العقوبات أو الشخصيات السياسية البارزة أو وسائل الإعلام الضارة |

## recommendation

توجيه إجراء منظّم مبني على مزيج `risk_score` و`confidence`.

```json
{
  "action": "review",
  "priority": "high"
}
```

### أنواع الإجراءات

| `action` | متى يُستخدم | الاستجابة المقترحة |
|---|---|---|
| `allow` | مخاطر منخفضة، ثقة كافية | المتابعة بشكل طبيعي |
| `review` | مخاطر متوسطة أو ثقة منخفضة | قائمة المراجعة اليدوية |
| `challenge` | مخاطر عالية، ثقة معتدلة | مصادقة معزّزة (OTP، بيومترية) |
| `block` | مخاطر حرجة أو تطابق مؤكد | حجب المعاملة، فتح تحقيق |

### مستويات الأولوية

| `priority` | المعنى |
|---|---|
| `low` | إعلامي، لا استعجال |
| `medium` | مراجعة ضمن SLA الطبيعي |
| `high` | مراجعة سريعة (في غضون ساعات) |
| `critical` | مطلوب إجراء فوري |

## عقد الاستجابة الموحّد

يُعيد كل من `/evaluate` و`/risk/assess` نفس البنية على المستوى الأعلى. الفرق هو في العمق:

```json
{
  "risk_score": 0.73,
  "risk_level": "high",
  "confidence": 0.81,
  "explanations": [
    {
      "code": "RAPID_VELOCITY",
      "category": "behavioral",
      "severity": "high",
      "message": "12 transactions in the last hour — threshold is 10",
      "evidence": { "count_1h": 12, "threshold": 10 }
    },
    {
      "code": "NETWORK_CONTAMINATION",
      "category": "network",
      "severity": "medium",
      "message": "Shares device with 1 confirmed fraudster",
      "evidence": { "shared_with_confirmed": 1 }
    }
  ],
  "recommendation": {
    "action": "review",
    "priority": "high"
  }
}
```

يُعيد `/evaluate` هذه البنية مع السياق على مستوى الإشارة. أما `/risk/assess` فيضيف كتل `profile` و`network` و`history` مع حزمة الذكاء الكاملة للكيان.

## منطق التسجيل المركّب

هذا وصف مبسّط للشركاء. آليات التسجيل الداخلية سرية.

- **التلاشي بالحداثة**: الإشارات الأقدم من 90 يوماً تساهم بوزن أقل. إشارات الـ 24 ساعة الأخيرة تحمل وزناً كاملاً.
- **تنوع الإشارات**: تفعّل عدة أدوات كشف مستقلة يرفع `risk_score` و`confidence` أكثر من تفعّل أداة واحدة مرات متكررة.
- **التضخيم الشبكي**: الكيان المرتبط بمحتالين مؤكدين عبر الرسم البياني يرى مكوّن `network_score` لديه مُضخَّماً بشكل متناسب.
- **تقييد ثقة OSINT**: مطابقات OSINT ذات ثقة < 0.3 تظهر كتفسيرات `review` لكنها لا تدفع توصيات `block` الآلية.

## قواعد التصميم

هذه التزامات لا تطلعات:

- **لا صناديق سوداء**: كل درجة مخاطر غير تافهة تشمل إدخالاً واحداً على الأقل في `explanation`
- **مخرجات حتمية**: المدخلات ذاتها ← المخرج ذاته (باستثناء تغييرات حالة الرسم البياني بين الاستدعاءات)
- **التوافق مع الإصدارات السابقة**: رموز `explanation` الجديدة تضاف بشكل تراكمي؛ الرموز الموجودة لا تُزال أبداً دون إهمال
- **قابلية التدقيق**: جميع مدخلات ومخرجات التسجيل مُسجَّلة ومتاحة عبر API سجل التدقيق

# بنية الرسم البياني

## نظرة عامة

الرسم البياني الساخن هو مخزن علاقات الكيانات في الوقت الفعلي، مُنفَّذ على PostgreSQL (جدولا `graph_nodes` + `graph_edges`) مع ذاكرة تخزين مؤقت لقوائم التجاور في Redis لاجتياز أقل من 5 مللي ثانية. مُصمَّم لأداء مسار الاستيعاب — كل إشارة تدخل النظام تُحدِّث الرسم البياني بشكل متزامن ضمن خط أنابيب IngestSignalAction.

---

## نموذج البيانات

### `graph_nodes`

```sql
id              bigserial PRIMARY KEY
partner_uuid    uuid NOT NULL
entity_uuid     uuid REFERENCES fraud_entities(uuid)
node_type       varchar(50)  -- phone_number, device, ip_address, account_id
external_id     varchar(255) -- HMAC-SHA256 of the actual identifier
risk_score      int DEFAULT 0
metadata        jsonb
created_at      timestamptz
updated_at      timestamptz

INDEX: (partner_uuid, node_type, external_id)
INDEX: (partner_uuid, risk_score DESC)
```

### `graph_edges`

```sql
id              bigserial PRIMARY KEY
partner_uuid    uuid NOT NULL
source_node_id  bigint REFERENCES graph_nodes(id)
target_node_id  bigint REFERENCES graph_nodes(id)
edge_type       varchar(50)  -- shared_device, shared_ip, co_occurrence, etc.
weight          float        -- 0.0–1.0 relationship strength
metadata        jsonb
first_seen_at   timestamptz
last_seen_at    timestamptz
signal_count    int DEFAULT 1

INDEX: (partner_uuid, source_node_id)
INDEX: (partner_uuid, target_node_id)
INDEX: (partner_uuid, edge_type, weight DESC)
```

## ذاكرة التخزين المؤقت للتجاور في Redis

نمط مفتاح الذاكرة المؤقتة: `graph:adj:{partner_uuid}:{node_id}`

قيمة الذاكرة المؤقتة: مصفوفة JSON من التراكيب `[target_node_id, edge_type, weight]` لجميع الحواف الصادرة.

TTL: **15 دقيقة** (قابل للتكوين عبر `config/graph.php`).

تُملأ الذاكرة المؤقتة كسوليًا عند أول اجتياز وتُبطَل عند تحديث الحافة. تهيِّئ مهمة أسبوعية `graph:rebuild-cache` جميع رسوم بيانات الشركاء مسبقًا.

```php
// Cache key format
$key = "graph:adj:{$partnerUuid}:{$nodeId}";

// Read adjacency list
$adjacency = Cache::store('redis')->get($key);

// Write on cache miss
Cache::store('redis')->put($key, $adjacency, seconds: 900);
```

## اجتياز BFS

تستخدم طريقة `HotGraphService::getNeighborhood()` اجتيازًا BFS تكراريًا مع ذاكرة Redis المؤقتة كمسار قراءة رئيسي:

```php
public function getNeighborhood(string $partnerUuid, int $nodeId, int $depth = 2): array
{
    $visited = [$nodeId];
    $queue   = [[$nodeId, 0]];
    $nodes   = [];

    while (!empty($queue) && count($nodes) < 200) {
        [$current, $currentDepth] = array_shift($queue);

        if ($currentDepth >= $depth) {
            continue;
        }

        $adjacency = $this->getAdjacency($partnerUuid, $current); // Redis or DB

        foreach ($adjacency as [$targetId, $edgeType, $weight]) {
            if (!in_array($targetId, $visited) && $weight >= 0.3) {
                $visited[]  = $targetId;
                $nodes[]    = ['id' => $targetId, 'depth' => $currentDepth + 1];
                $queue[]    = [$targetId, $currentDepth + 1];
            }
        }
    }

    return ['nodes' => $nodes, 'truncated' => count($nodes) >= 200];
}
```

**تقليم الحواف**: تُستبعد الحواف بوزن < 0.3 من الاجتياز. يمنع ذلك الارتباطات الضعيفة (مثلًا: مزود خدمة إنترنت مشترك على مستوى البلد) من تضخيم حجم الجوار.

## حماية IDOR

تُكشف واجهة برمجة الرسم البياني قيم `external_id` للعقد (تجزئات HMAC للمعرفات الحقيقية). لمنع استنتاج كيانات بين الشركاء، تُقنَّع جميع قيم `external_id` قبل إعادتها إلى طبقة API:

```php
protected function maskExternalId(string $externalId): string
{
    return substr($externalId, 0, 8) . '****';
}
```

هذا يعني أن مستهلكي API يمكنهم التعرف على كياناتهم (بمقارنة أول 8 أحرف بسجلات التجزئة المحلية) لكن لا يمكنهم إعادة بناء التجزئات الكاملة أو مطابقة الكيانات عبر حسابات الشركاء.

جميع استعلامات الرسم البياني مقيّدة بـ `partner_uuid` على مستوى قاعدة البيانات — من المستحيل معماريًا الاجتياز داخل عقد رسم بياني خاصة بشريك آخر.

## صيغة انتشار المخاطر

```php
$propagatedRisk = 0;
$totalWeight    = 0;

foreach ($neighbors as $neighbor) {
    $hopDecay    = pow(0.7, $neighbor['depth']); // 0.7 per hop
    $edgeWeight  = $neighbor['weight'];
    $contribution = $neighbor['risk_score'] * $edgeWeight * $hopDecay;
    $propagatedRisk += $contribution;
    $totalWeight    += $edgeWeight * $hopDecay;
}

$propagatedRisk = $totalWeight > 0 ? $propagatedRisk / $totalWeight : 0;

// Apply amplifier if any direct neighbor is high-risk
$highRiskCount = count(array_filter($neighbors, fn($n) => $n['risk_score'] > 80 && $n['depth'] === 1));
$amplifier     = min(15, $highRiskCount * 5); // max +15 pts
$networkScore  = min(100, $propagatedRisk + $amplifier);
```

## التكامل مع WeightedRiskFusionEngine

يُسهم الرسم البياني الساخن بـ `network_score` (وزن 40%) في درجة المخاطر المدمجة النهائية:

```
fused_score = (behavioral × 0.35) + (network × 0.40) + (contextual × 0.15) + (historical × 0.10)
```

يُستدعى `HotGraphService` بشكل متزامن في مسار الاستيعاب، بعد `FeatureEngineeringService` وقبل `WeightedRiskFusionEngine`. يجب أن تكتمل عملية الرسم البياني ضمن هدف قابلية الشرح البالغ 50 مللي ثانية.

## ملاحظات تشغيلية

- **معدل فقدان ذاكرة مؤقتة الرسم البياني** مُتتبَّع في نقطة نهاية `/health` ضمن `graph_cache_hit_rate`
- **مهمة إعادة البناء الأسبوعية**: `graph:rebuild-adjacency-cache` — تعمل الأحد 02:00 UTC، تستخدم قائمة `graph`
- **تحلل وزن الحافة**: غير مُنفَّذ حاليًا — الحواف لا تتحلل بمرور الوقت. ستُقدِّم المرحلة 12 أوزان حواف متحللة زمنيًا في الرسم البياني البارد
- **إزالة ازدواج العقد**: العقد مفاتيحها `(partner_uuid, node_type, external_id)` — نفس الكيان الظاهر عبر إشارات مختلفة لا يُنشئ عقدًا مكررة

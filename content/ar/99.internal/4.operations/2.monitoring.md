# المراقبة والصحة

## نقاط نهاية الفحص الصحي

### مجسّ الاستعداد: `/ready`

```http
GET /ready
```

فحص استعداد خفيف الوزن. يتحقق من اتصال قاعدة البيانات فحسب. الهدف أن يكون زمن الاستجابة أقل من 100 ميلي ثانية. يُستخدم بواسطة موازنات التحميل ومنسّقات الحاويات لبوابات التحقق من الجاهزية.

**الاستجابة (سليم)**:
```json
{ "status": "ok", "db": "connected", "latency_ms": 4 }
```

**الاستجابة (متدهور)**:
```json
{ "status": "degraded", "db": "error", "error": "Connection timeout after 5000ms" }
```

HTTP 200 عند السلامة، HTTP 503 عند أي عطل.

### الفحص الصحي المعمّق: `/health`

```http
GET /health
Authorization: Bearer {internal-token}  # or admin session
```

فحص صحي شامل لجميع مكونات النظام. يُخزَّن الرد مؤقتاً لمدة 30 ثانية للحيلولة دون تدافع الطلبات خلال استطلاعات المراقبة.

**الاستجابة**:
```json
{
  "status": "ok",
  "timestamp": "2026-03-16T10:00:00Z",
  "cache_age_seconds": 12,
  "components": {
    "database": { "status": "ok", "latency_ms": 3, "pool_size": 10, "active_connections": 2 },
    "redis": { "status": "ok", "latency_ms": 1, "memory_used_mb": 142 },
    "queue": { "status": "ok", "pending": 14, "failed": 0, "workers": 4 },
    "reverb": { "status": "ok", "connections": 87 },
    "graph_cache": { "status": "ok", "hit_rate": 0.94, "keys": 2841 },
    "osint_ingestion": { "status": "ok", "last_run": "2026-03-16T03:00:00Z", "records_processed": 14209 }
  }
}
```

## مراقبة قوائم الانتظار

### لوحة تحكم قوائم الانتظار

متاحة في لوحة الإدارة عبر `/admin/queue`. توفر:
- عدادات الانتظار/المعالجة/الفاشلة/المكتملة لكل قائمة انتظار
- جدول المهام الفاشلة مع معاينة الاستثناء
- إعادة المحاولة بنقرة واحدة (مهمة واحدة أو مجمّعة حسب قائمة الانتظار)
- تنقية المهام الفاشلة (يستلزم دور `super_admin`)

### أسماء قوائم الانتظار

| قائمة الانتظار | الغرض | عدد العمال |
|----------------|--------|------------|
| `default` | الأعمال غير المتزامنة العامة | 2 |
| `signals` | مهام استيعاب الإشارات (أولوية عالية) | 4 |
| `graph` | تحديثات عقد وحواف الرسم البياني | 2 |
| `osint` | استيعاب OSINT وإعادة حساب الحداثة | 1 |
| `webhooks` | إرسال الـ webhooks الصادرة | 2 |
| `compliance` | معالجة SAR وعلامات AML | 1 |
| `notifications` | إرسال البريد الإلكتروني والدفع عبر Reverb | 2 |

### دليل تشغيل المهام الفاشلة

1. **مراجعة الاستثناء**: الإدارة ← قائمة الانتظار ← الفاشلة ← توسيع المهمة ← مطالعة حقل `exception`
2. **الأسباب الشائعة**:
   - `ModelNotFoundException`: حُذف الكيان بين وقت الإرسال والتنفيذ — يمكن تجاهله بأمان
   - `ConnectionException` (Redis): إعادة تشغيل حجرة Redis — إعادة المحاولة آمنة
   - `CentryContextException`: أُرسلت المهمة دون ربط سياق — يجب إصلاح المُرسِل، ولا تُعيد المحاولة دون إصلاح الكود
3. **إعادة محاولة مهمة واحدة**: `php artisan queue:retry {job-id}`
4. **إعادة محاولة الجميع**: `php artisan queue:retry all` — استخدم بحذر على قائمة `signals`
5. **التنقية بعد التحقيق**: `php artisan queue:flush`

## تتبع المهام السياقية

جميع المهام الممتدة من `ContextAwareJob` تُسلسل `CentryContext` (UUID الشريك + المخطط) وقت الإرسال. يضمن ذلك:
- تشغيل المهام على مخطط PostgreSQL الصحيح (`public` مقابل `sandbox`)
- إمكانية نسب المهام الفاشلة إلى الشريك الصحيح في السجلات
- إمكانية تقسيم مقاييس قائمة الانتظار حسب الشريك لمراقبة اتفاقيات مستوى الخدمة

**التحقق**: إذا كانت مهمة تفشل بأخطاء تتعلق بـ `search_path` أو `schema`، تحقق من أنها تمتد من `ContextAwareJob` (وليس الفئة الأساسية `Job` في Laravel).

```php
// صحيح
class ProcessSignalJob extends ContextAwareJob { ... }

// خطأ — سيستخدم search_path الافتراضي
class ProcessSignalJob extends Job { ... }
```

## مرجع المهام المجدولة

| المهمة | الجدول الزمني | قائمة الانتظار | الوصف |
|--------|--------------|----------------|-------|
| `osint:ingest` | يومياً 03:00 UTC | `osint` | استيعاب قوائم العقوبات للأمم المتحدة والاتحاد الأوروبي والاتحاد الأفريقي |
| `osint:recompute-freshness` | الأحد 05:00 UTC | `osint` | تراجع حداثة درجة ثقة OSINT |
| `sanctions:rescreen` | يومياً 04:00 UTC | `compliance` | إعادة فحص جميع الكيانات النشطة مقابل بيانات OSINT الحالية |
| `compliance:calendar` | يومياً 08:00 UTC | `compliance` | المواعيد التنظيمية القادمة |
| `compliance:anonymize-expired` | أسبوعياً الأحد 01:00 UTC | `compliance` | إخفاء هوية بيانات PII منتهية الاحتفاظ |
| `graph:rebuild-adjacency-cache` | أسبوعياً الأحد 02:00 UTC | `graph` | تسخين مسبق لذاكرة التخزين المؤقت لرسم بياني Redis |
| `webhooks:retry-failed` | كل 15 دقيقة | `webhooks` | إعادة محاولة تسليم الـ webhooks الفاشلة (حتى 3 محاولات) |

## عتبات التنبيه

اضبطها في نظام مراقبتك (Grafana / Datadog) مقابل نقطة النهاية `/health`:

| المقياس | تحذير | حرج |
|---------|-------|-----|
| `queue.failed` | > 10 | > 50 |
| `queue.pending` (signals) | > 500 | > 2000 |
| `graph_cache.hit_rate` | < 0.80 | < 0.60 |
| `database.latency_ms` | > 50 ms | > 200 ms |
| `redis.latency_ms` | > 10 ms | > 50 ms |
| عمر `osint_ingestion.last_run` | > 26 ساعة | > 50 ساعة |

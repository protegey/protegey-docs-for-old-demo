يُطبَّق KYB كنطاق مستقل تحت `apps/core/app/Domain/`. يمتلك طبقة خدمات خاصة به، ومنسِّقات أحداث، وخط أنابيب وظائف غير متزامنة. يستهلك `SanctionsMatchingService` و`PEPDetectionService` من نطاق الامتثال الحالي.

---

## خريطة الخدمات

| الخدمة | المسؤولية |
|---|---|
| `KybInviteService` | إنشاء الدعوات، التحقق من الرموز، تحليل الاستبيانات الافتراضية |
| `KybProgressService` | إنشاء/تحديث المسوَّدات، حفظ الإجابات بشكل تدريجي |
| `KybSubmissionService` | التحقق من اكتمال البيانات، التقديم، إدارة إعادة التقديم |
| `KybDecisionService` | تسجيل القرارات، حماية حالة النهاية، كتابة حدث التدقيق |
| `KybRiskScreeningService` | فرز اسم الشركة ضد العقوبات + PPE، حساب DTO `KybRiskProfile`، تجسيد الكيان، تشغيل EDD |
| `KybDocumentService` | تخزين S3 (قرص `kyb`)، حذف S3، إعادة البيانات الوصفية |
| `KybAuditService` | إضافة أحداث مكتوبة في `kyb_application_events` مع سياق الفاعل |

---

## منسِّقات الأحداث

الأحداث منسِّقات خفيفة — تستدعي الخدمات بالترتيب وترسِل وظائف غير متزامنة.

```
SendKybInviteAction
  └─ KybInviteService::createInvite()       [يُقفِل الاستبيان]
  └─ SendKybInviteEmailJob::dispatch()      [غير متزامن]

SubmitKybApplicationAction
  └─ KybSubmissionService::submit()         [يتحقق + يضع status=submitted]
  └─ NotifyPartnerNewApplicationJob::dispatch()   [غير متزامن]
  └─ ScreenKybApplicantJob::dispatch()      [غير متزامن — فرز المخاطر]

DecideKybApplicationAction
  └─ KybDecisionService::decide()           [القرار، سجل التدقيق]
  └─ عند الموافقة:
       KybRiskScreeningService::screen()    [متزامن — فرز نهائي]
       KybRiskScreeningService::materializeEntity()
       KybRiskScreeningService::triggerEddIfRequired()
  └─ NotifyApplicantDecisionJob::dispatch() [غير متزامن]
```

---

## الوظائف الغير المتزامنة

جميع الوظائف تمتد من `ContextAwareJob` — سياق الشريك مُسلسَل وقت الإرسال.

| الوظيفة | المحفِّز | ملاحظات |
|---|---|---|
| `SendKybInviteEmailJob` | إنشاء دعوة | يُرسل البريد برابط البوابة الموقَّع |
| `NotifyPartnerNewApplicationJob` | تقديم طلب | يُخطِر فريق الشريك |
| `ScreenKybApplicantJob` | تقديم طلب | فرز في الخلفية؛ النتيجة مُسجَّلة عبر `KybAuditService` |
| `NotifyApplicantDecisionJob` | تسجيل القرار | يُرسل بريد النتيجة للمتقدِّم |

### 9 عمليات هجرة

| الهجرة | الجدول | الأعمدة الرئيسية |

## تكامل فرز المخاطر

`KybRiskScreeningService::screen()`:
1. يستخرج اسم الشركة من الإجابة حيث `is_screening_identifier = true`
2. يستدعي `SanctionsMatchingService::screenName()` — يُعيد النتيجة ومستوى المخاطرة
3. يستدعي `PEPDetectionService::checkName()` — يُعيد `is_pep` والتسمية
4. يُعيد DTO `KybRiskProfile` غير القابل للتغيير

شرط تشغيل EDD: `risk_score > 0.75 OR is_pep = true OR sanctions_matched = true`

## أنواع أحداث التدقيق

| نوع الحدث | الفاعل | البيانات |
|---|---|---|
| `submitted` | applicant | — |
| `resubmitted` | applicant | — |
| `decided` | partner_user | `{ decision, old_status, new_status }` |
| `screened` | system | `{ risk_score, is_pep, sanctions_matched }` |
| `entity_created` | system | `{ entity_uuid }` |
| `edd_triggered` | system | `{ case_uuid, trigger_reason }` |
